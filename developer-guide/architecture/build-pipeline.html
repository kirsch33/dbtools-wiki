Build Pipeline

NAME

build pipeline - stage, validate and publish a dbtools distribution

SYNOPSIS

Graph     build/Build.proj
Task      dbtools.Build.Tasks.BuildPipelineStep
Source    build/Tasks/Pipeline/

DESCRIPTION

BuildApp stages the product for each selected Revit year. BuildAll validates and publishes the complete Release distribution. See Build commands for targets and options.

Desktop builds use the Nice3point Revit API packages pinned in Directory.Packages.props. These packages supply the metadata for compilation. The product tree excludes their runtime assets.

STRUCTURE

Owner Role
build/Build.proj Orders the targets and launches the child builds.
build/MSBuild/ProductOutput.proj Stages dbtools.dll (App), dbtools.Core.dll, dbtools.Presentation.dll and dbtools.addin at the year root. It stages the tool assemblies under Tools/.
build/Merging/AssemblyMerges.props Assigns each merged library to its owning assembly. See Assembly Loading Contract.
build/Distribution/ Defines and checks the distribution file set, assembly metadata and validation receipts.

CONTRACTS

  • A publication build requires a clean Git checkout and a Release build for Revit 2026 and 2027.
  • DistributionContract.ProductFiles defines the exact file set for each year. When adding a tool, include its Tools/<name>.dll path in this list. StageProductOutputTask rejects a mismatch.
  • Directory.Packages.props pins Protocol and DevMode.Testing to 0.22.14. The scenario and Windows acceptance builds check the vendored and restored DevMode.Testing packages against the SHA-256 in that file. testing/Daemon/Directory.Build.props pins the Revit test adapter to the same release and records its SHA-256.
  • Update the dbtools-daemon.Protocol version in Directory.Packages.props, the lock in build/Distribution/protocol-package-lock.json and the matching vendor/DaemonProtocol/dbtools-daemon.Protocol.<version>.nupkg together. The build checks the package version and SHA-256 against the pin.
  • Promotion requires a portable acceptance receipt for the same source, candidate bytes and validator.
  • In the runtime inputs, dbtools.dll retains its mapped CodeView path, GUID and stamp to pair with dbtools.pdb. The Core merge writes dbtools.Core.pdb and records that file name in its CodeView entry. Both PDBs retain mapped source documents.
  • Public merged types remain available to dependent product assemblies through their owning assembly.

Content versions

ContentVersion.targets derives product assembly versions from the SHA-256 of the build inputs. It includes source, resource names and bytes, resolved references and merge inputs. It records the hash in AssemblyInformationalVersion as <AssemblyVersion>+inputs.<hash>.

SourceVersionEvidence checks the version against the input hash. It also requires byte-identical Presentation assemblies across Revit years. To trace a version change, compare the input lists under .artifacts/obj/content-version/.

FLOW

  1. In the publication graph, Restore captures the clean Git commit and tree. BuildValidationRunner builds the Validation Runner and authenticates its Protocol package.
  2. BuildAppPerYear stages each year tree. AssembleDistributionCandidate copies the declared files into the candidate and writes its hashes and source identity to its build.json.
  3. StagePortableAcceptanceInput stages the Revit metadata references. ValidateDistributionCandidate checks assembly and manifest metadata and runs the Dev Mode preflight for each year.
  4. ValidateManifestTypes resolves the types named by tool manifests in the built assemblies. BuildDevModeScenario compiles the hosted scenario for each year.
  5. PromoteToDist replaces the distribution and acceptance trees. DistributionPublisher moves .artifacts/build.json into place last. Read the published files after the command succeeds.

Dev Mode preflight

DevModePreflightWorker calls DevModeStableGraphPreflight.Run for each year's App assembly. The pinned dbtools-daemon.Protocol package supplies policy devmode-stable-graph/v4 under schema 2 and contract devmode-preflight/v2. Each year has a three-minute runner limit. A collectible-boundary warning fails validation.

Inspect staged files after a failed or unpromoted run. After publication, PromoteToDist removes .artifacts/.staging/<build-id>/. A cleanup warning means the staging directory may remain.

Portable acceptance receipt

PromoteToDist embeds the staged receipt in the validation field of promotion-receipt.json. BuildBundle --candidate-dist rechecks it against the distribution bytes, source and Protocol pin.

The receipt covers metadata and static policy only. For Windows UI checks and tests in Revit, see Sandbox Validator and Test Pipeline.

Dev Mode scenario

testing/dbtools.DevMode.Scenario/ owns the on-demand Revit load, reload and window-open checks. Use the Sandbox capture fixture for UI review images. It compiles against dbtools-daemon.DevMode.Testing.Scenario from the dbtools-daemon.DevMode.Testing package. The daemon supplies bridge assembly version 2.0.0.0 at runtime. The scenario requires daemon 0.22.14 or later for DevModeControlNotFoundException. DevModeScenarioManifestWriter publishes its payload under .artifacts/acceptance/dev-mode-scenario/<year>/. The adjacent dev-mode-scenario.json binds it to the product, the model and the preflight result for each year. The writer reads bridge_contract_version from the scenario's bridge assembly reference and writes 2. See Test Pipeline for test execution.

Submit a published distribution with the two models that match its scenario manifest.

dbtools-daemon-cli devmode-submit \
  --archive path/to/published-distribution.tar.gz \
  --model 2026=testing/RevitTestModels/2026/GM/gm_test_model.rvt \
  --model 2027=testing/RevitTestModels/2027/GM/gm_test_model.rvt

The daemon also accepts --model YEAR=<directory>. The directory contains one top-level .rvt that matches the manifest's model hash. The daemon stages relative links and sidecars from the directory as executor.model_companions.

The scenario calls ExpectDialogs before it prepares a modal command. Each declaration matches the exact UI Automation name and native caption. The scope covers the interaction and window cleanup. Settings with Save declares dbtools - Settings, dbtools for its alerts, and dbtools Notification for its feedback banner. TDV declares the library selection and transfer windows.

Window searches omit closed windows. The close wait searches until the original window token is absent. Cleanup handles DevModeWindowClosedException when a window closes before the close request reaches it.

When an action rebuilds controls, the scenario polls InspectControlAsync with the selector of the next control it uses. DevModeControlNotFoundException means the control is absent. A control wait has a deadline. Its timeout names the scenario step and the selector.

Tool contract

build/Distribution/tool-contracts.json lists the ribbon command types and the UI text the Dev Mode scenario checks. The Sgt and ErftNew entries identify command proxies. DevModeScenarioTests.Routes excludes their interactive picks, which wait for Revit user input. PromoteToDist copies the contract to .artifacts/acceptance/.

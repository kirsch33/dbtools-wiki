Sandbox Validator

NAME

sandbox validator - check a product year and construct its WPF windows

SYNOPSIS

Source    src/dbtools.Sandbox/
Program   dbtools.Sandbox.exe
Entry     dbtools.Sandbox.App.Startup.SandboxEntry

dbtools.Sandbox.exe [--dist-dir DIR] [--headless --revit-reference-dir DIR]

DESCRIPTION

Sandbox validates one product year in a standalone x64 Windows process. See dbtools.Sandbox for interactive previews.

Option Effect
--dist-dir DIR Selects a directory named for its Revit year or a root that contains year directories. For a root, Sandbox chooses the highest supported year that contains dbtools.dll.
--headless Runs validation and exits. The default mode opens the window catalog.
--revit-reference-dir DIR Supplies the Revit metadata references. This option is required in headless mode and reserved for that mode.

The path options accept --option DIR and --option=DIR. The default distribution root is .artifacts/dist/Release/ in the checkout that contains the executable under .artifacts/sandbox/. Outside that layout, Sandbox resolves the default relative to the working directory.

CONTRACTS

  • A candidate contains dbtools.addin, dbtools.dll, dbtools.Core.dll, dbtools.Presentation.dll and a flat Tools/ directory. SandboxCandidate rejects unexpected root DLLs and mismatched assembly names. See Assembly Loading Contract.
  • Both modes require the matching Revit installation. RevitRuntimeResolver uses ricaun.Revit.Installation to locate it. It checks AdWindows.dll, RevitAPI.dll, RevitAPIUI.dll and UIFramework.dll against the selected references. Interactive mode uses the installed files as its references.

FLOW

  1. SandboxEntry resolves and checks the candidate before WPF starts. It loads Presentation, Core and App from the candidate into the default assembly load context. SandboxDistributionContext resolves each tool assembly from the candidate when needed.
  2. HeadlessValidationWorkflow checks add-in metadata, theme resources and the catalog. ManifestValidator checks tool modules, command and availability types, and icon resources.
  3. ToolWindowValidator opens each manifest window with its design-time view model and checks layout, tab changes and row details. SandboxCatalog also supplies alert requests, VTC alert bodies and color picker, Settings packs, notification banners, progress overlays, and the Change Review, Manage Items, Revit Link Settings, and Duplicate Type Mapping dialogs. Manifest and contributed cases use production sessions with sample inputs. Modeless sessions open with Show. Modal sessions open with ShowDialog and run a posted validation callback inside the dialog loop before closing with a dialog result. Settings uses sample library file years and spot elevation types. The FoundationTags pack requires the active Revit project and is excluded from this check. The validator subscribes to each window's production error path. Manifest windows and contributed cases with an error boundary report handled errors. Notification banners report errors through Dispatcher.UnhandledException. The expanded notification stack check observes layout updates at ApplicationIdle until the banner reaches its height cap and the vertical scrollbar is visible. The check has a 15-second deadline and reports the measured height, cap and scroll state on failure. The validator checks WPF binding errors while the window and each selected tab are loaded and the dispatcher has reached ApplicationIdle. Error 2 clears when the same binding expression reaches Active with a value. During retirement, the validator uses that expression's recorded loaded state. Every other binding error fails validation. The validator waits for ApplicationIdle after close. A missing required boundary, a window error, or a close or retirement failure also fails validation.
  4. After the window checks, the workflow rejects any loaded Revit host assembly from the reference set. It closes remaining windows and disposes the candidate's window runtime.

Build the matching Sandbox executable before validating a staged year. These commands validate a promoted Revit 2026 distribution from the checkout root on Windows.

pwsh -NoProfile -File build.ps1 BuildSandbox -y 2026
.\.artifacts\sandbox\Release\2026\net10.0-windows\dbtools.Sandbox.exe --headless `
  --dist-dir .artifacts\dist\Release\2026 `
  --revit-reference-dir 'C:\Program Files\Autodesk\Revit 2026'

DATA

From a clean checkout, PackageSandboxValidationInput builds a Release candidate and Sandbox for both supported years. It writes validate-dist-<sha256>.zip under .artifacts/.staging/<build-id>/native-validation-input/. The archive carries the candidate, Sandbox and Revit reference files under candidate/<year>/, sandbox/<year>/net10-0-windows/ and revit-refs/<year>/. Its root manifest.json records the payload paths and SHA-256 hashes.

Run DIST before staging another candidate. StageDistributionCandidate tries to delete earlier staging directories and their archives.

DIAGNOSTICS

Headless mode returns 0 on success and 1 on failure. Startup errors and the validation result go to standard error. In a DIST run, SandboxLauncher includes that output in the failing test message.

Message Meaning and action
Unable to infer Revit year from dist dir: '<path>'. RevitRuntimeResolver.ResolveRuntimeDirOrThrow raises this when the final directory name fails to parse as a year. Use a year directory such as 2026.
Revit <year> install was not found. Install Revit <year>. Match the installed Revit year to the candidate year.
Headless Sandbox validation requires --revit-reference-dir. Pass a directory with the four Revit metadata references for the candidate year.
Tool UI validation failed: Find the window ID, XAML resource and view model in the Sandbox standard error output.

TESTS

WindowsAcceptanceTests provides ValidatesTheStagedCandidateFor2026 and ValidatesTheStagedCandidateFor2027. Each DIST request runs one year in its own process and verifies the complete archive. DevModeGenerationProbe from dbtools-daemon.DevMode.Testing loads that year's candidate. The test opens and closes each SandboxCatalog window and requires the generation to retire. It then runs the staged Sandbox with --headless against the candidate and its archived Revit references. See Distribution acceptance.

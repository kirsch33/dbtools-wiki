Theme System

dbtools.Presentation.dll holds the compiled WPF resources that must stay loaded for the life of the Revit process: theme dictionaries, stable controls and window shells, and settings views that register WPF dependency properties. Other tool views are raw XAML that Presentation parses at run time, so App, Core and tool assemblies contain no BAML or .g.resources. Each window merges the theme into its own resources, never into Application.Resources, so dbtools does not change the appearance of other add-ins.

Assembly roles

Assembly Compiled WPF content
dbtools.Presentation Theme dictionaries, stable windows, controls, tool behaviors, converters, ElevationTags and FoundationTags settings views, and the merged Helix theme
dbtools.Core None. Window lifecycle, error boundaries, registry, commands and runtime hosts can be reloaded
Tool assemblies None. Tool views and markup-only settings views are embedded as raw XAML

Presentation lists its Page and EmbeddedResource items explicitly (EnableDefaultPageItems=false); default Compile inclusion picks up their code-behind. Tool assemblies contain no compiled WPF pages. A compiled settings view lives in Presentation under Tools/<TOOL>/, in namespace dbtools.Presentation.Tools.<TOOL>, when its code-behind registers WPF dependency properties. ElevationTags and FoundationTags use this form. DialogSuppression and JoistGirderWeight embed markup-only settings views in their tool assemblies as raw XAML.

Settings pack views

AddDbtSettingsPackDefinition<TOptions, TContext> accepts a view factory with the type Func<ISettingsPackContext<TOptions>, FrameworkElement>. A tool module supplies the view in one of two forms:

  • a compiled view from dbtools.Presentation.Tools.<TOOL>, created with new and given the context as DataContext;
  • a markup-only view embedded in the tool as raw XAML with the logical name dbtools.ToolViews.<TOOL>.<View>.xaml, which the factory loads with ToolWindowXaml.LoadElement before it assigns the DataContext. TDV's LibrarySettingsView uses this form through TdvToolModule.LoadLibrarySettingsView.

A view that registers dependency properties or needs code-behind uses the compiled form.

Tool views

A tool embeds each view as an EmbeddedResource with the logical name dbtools.ToolViews.<TOOL>.<View>.xaml. ToolWindowFactory.CreateModal or CreateModeless (Core) opens a view in a stable shell.

The modal factory returns IModalToolWindowSession with ShowDialog and HideForPick. The modeless factory returns IModelessToolWindowSession with Show. Both inherit the common lifecycle surface from IToolWindowSession. Creation runs these steps:

  1. ToolWindowHost.CreateModal or CreateModeless (Presentation) creates a stable shell, ToolWindowModalShell or ToolWindowModelessShell.
  2. The shell initializer runs before the view is parsed. The default is WindowInitializer.Initialize or InitializeModeless, which applies the theme, binds the owner window, registers the progress overlay and installs the error boundary and logging.
  3. ToolWindowXaml.LoadElement parses the raw view inside ToolWindowReflectionScope, and the view and shell receive the tool's view model as DataContext.
  4. The factory registers the session in ToolWindowRegistry.

The caller shows the window with session.ShowDialog() or session.Show() and gets named controls with session.Require<T>(name). The Settings, Alert, Logger and notification banner windows are raw resources in Presentation and use the same loader; so do tool template dictionaries such as the View Template Comparer (VTC) diff templates and the Super Girt Tool (SGT) opening view. For these windows Core keeps the state, commands and lifecycle and event handling; the controls need no typed constructor from a reloadable assembly and do no type discovery at run time.

Retirement tears down bindings, automation roots, resources and callbacks. Core lifecycle handlers are released through BehaviorState and session cleanup before the shell closes. A custom shell initializer releases its own handles.

Raw views name only framework types or public stable Presentation types and merge the theme through Presentation's ResourceUri markup extension before they use static theme keys. Tool content uses explicit keyed templates. SGT's opening and girt grids use stable behaviors over tool row state. The Extreme Roof Framing Tool (ERFT) and SGT pass immutable scene data to the stable 3D viewport, which owns camera, material, picking and device state (see Structural Preview).

Theme dictionaries

The root dictionary is:

/dbtools.Presentation;V<PresentationVersion>;component/Resources/Theme.xaml

<PresentationVersion> is the content version of the Presentation assembly (see Build Pipeline). The root merges, in this order:

  1. /dbtools.Presentation;V<PresentationVersion>;component/Resources/Tokens.xaml
  2. /dbtools.Presentation;V<PresentationVersion>;component/Resources/Brushes.Dark.xaml or Brushes.Light.xaml, the brushes of the current color theme
  3. /dbtools.Presentation;V<PresentationVersion>;component/Resources/Converters.xaml
  4. /dbtools.Presentation;V<PresentationVersion>;component/Resources/Controls.xaml
  5. /dbtools.Presentation;V<PresentationVersion>;component/Resources/DataGrid.xaml
  6. /dbtools.Presentation;V<PresentationVersion>;component/Resources/Menus.xaml
  7. /dbtools.Presentation;V<PresentationVersion>;component/Resources/Components.xaml

The theme uses plain WPF controls and no control library. Each implicit style that changes the look of a control supplies the control's whole template, so no WPF system theme template draws a dbtools control. A style that extends another dbtools style uses BasedOn only within the same dictionary file: when WPF loads a dictionary from its Source, a StaticResource in that file sees only the file, the dictionaries that the file merges itself and the system theme, not the other dictionaries that Theme.xaml merges. {StaticResource {x:Type Button}} in Components.xaml, for example, finds the system theme's Button style. Across files, a style or template uses DynamicResource; the TreeView style of VTC sets Template to {DynamicResource TreeViewTemplate} from Controls.xaml.

ThemeResourceLoader (Core) checks this order. At startup ThemeValidator.ValidateOrThrow registers the pack URI scheme, loads each dictionary separately for both color themes and freezes its freezables, loads the root and checks its merged dictionaries, and then measures and arranges a probe tree of standard controls. A failure stops startup; see Troubleshooting.

Color themes

dbtools has two color themes, Dark and Light. One theme applies to every dbtools window. The user chooses it under General > Appearance in Settings. The initial theme follows the Revit UI theme that UIThemeManager.CurrentTheme reports at startup.

  • ColorThemeState (Presentation) holds Current and Default. At startup AppStartupPreparationWorkflow sets Default from the Revit UI theme and starts ColorThemeSettingsObserver (Core) with the saved SettingsFlags.Theme. The observer applies the theme again on each published flag change, so a change in the Settings window shows at once; Save keeps it.
  • Theme.xaml merges the brush dictionary of Current through {dbtResources:ThemeBrushesUri}: Resources/Brushes.Dark.xaml or Resources/Brushes.Light.xaml. Both define the same keys. ColorThemeState.Apply reloads every loaded brush dictionary, and open windows take the new brushes through their DynamicResource references. It runs on the Revit UI thread, which every dbtools window shares; a brush dictionary of another UI thread keeps its brushes. A brush that code reads once with FindResource keeps its old value until the code reads it again.
  • ThemeValidator loads both brush dictionaries at startup, so a broken dictionary stops startup and not a later theme switch.

SurfaceWell, SurfaceOverlay A list or grid inset in a card; popups, menus and tooltips
FillHover, FillPressed Opaque hover and pressed fills of controls
FillSubtleHover, FillSubtlePressed Translucent overlays for rows, tabs and borderless buttons

StrokeDivider, StrokeControl, StrokeField, StrokeFocus, StrokeWindow, StrokeDisabled Hairlines, button borders, field borders (3:1), the gold focus ring, window edges

The older hue- and feature-named keys (Paper, Surface, Body, ButtonPrimary and the others) remain for existing XAML. Where a role has the same meaning, the older key holds the role's value.

Tokens

Tokens.xaml holds the compact density and the ramps:

  • Density: Size.Control and Size.Row are the compact 28 px control and row height; MinHeight.Button, MinHeight.Control and Size.DataGridRow.MinHeight equal them. Size.ControlSmall (24 px) is for header actions.
  • Type: FontFamily.UI (Segoe UI) and FontFamily.Icon; sizes 12, 13, 15 and 20 (FontSize.Caption, FontSize.Body, FontSize.Subtitle and FontSize.Title, FontSize.Header), with LineHeight.*. WindowThemeApplicator sets each window's font to FontFamily.UI and FontSize.Body, so text does not follow the system message font.
  • Spacing: the 4 px ramp Spacing4 to Spacing32, and role insets and gaps (Inset.Button, Inset.Input, Inset.Row, Inset.Card, Inset.Dialog, Inset.Footer, Gap.Stack, Gap.Section, Gap.Label).
  • Radius: Radius4 for controls, Radius8 for cards and dialogs.

Shared controls

dbtools.Presentation.Controls holds the controls that views share. Raw views reach them with xmlns:controls="clr-namespace:dbtools.Presentation.Controls;assembly=dbtools.Presentation". Their styles are in the theme.

Control Use
DialogFooter The buttons at the bottom of a dialog. The theme sets each action button's Height to Size.Control (28 device-independent pixels). DialogFooter.Role places each child: Tertiary at the left (Reset All, Copy Details), then at the right Secondary (Cancel, Validate) and the one Primary, which is rightmost whatever the declaration order. The tab order follows. In a destructive confirmation the danger button takes Primary and Cancel sets IsDefault, so Enter cancels
SearchBox A filter text box with a magnifier, a Placeholder that names what it filters, an optional ResultText such as 2 of 12 and a clear button while there is text. Escape clears; the clear button and Escape update the Text binding at once. It is a TextBox, so its Text binding and automation id work as before
SettingsPack A flat card with a Title. IsModified shows Modified and enables Reset to Defaults, which runs ResetCommand. HasPendingChanges shows Unsaved independently. UI Automation sees a group and ResetAutomationId names the button.
ToolbarRow Commands that act on the list or content next to them, left to right with an 8 px gap
InlineMessage An in-window notice with an accent bar, icon, tint, and optional heading. Info uses amber. Warning, Error, and Success use their theme colors.
EmptyState A centered icon with a sentence-case heading and optional hint. ListEmptyState.Text and ListEmptyState.Hint apply it to an empty ListBox, TreeView, or DataGrid.
LoadingText Upright loading text in the secondary text color.

AlertWindowViewModel orders the alert footer the same way: secondary and Cancel buttons, then the primary button, then a danger button at the right. An alert with a danger button makes its Cancel button the default.

Every AlertWindow uses the same variant brush for its top stripe and header icon. Info uses Secondary, Warning uses Warning, Error uses Error, and Success uses Success. By default, the dialog measures its height from the body and sizes short messages to their content within the work area.

Every window that WindowInitializer sets up gets a title bar in the colors of the color theme (WindowCaption): dark or light caption, the SurfaceWindow caption fill, Text caption text and the StrokeWindow border. On Windows 10 the window keeps the system caption. A theme change repaints open windows.

Control behaviors

The theme sets three behaviors on standard controls:

  • Nested scrolling. The implicit ScrollViewer style sets WheelForwarding.IsEnabled. A scroll viewer that cannot move in the direction of a wheel turn passes the turn to the scroll viewer around it. This covers the viewers in the templates of TextBox, ListBox, ListView and TreeView, so a short list, tree or text box inside a scrolling page does not stop the page. DataGridMouseWheelBehavior does the same for a grid at the end of its range. A viewer in a popup keeps its wheel. A ScrollViewer with its own keyed style gets the behavior only if that style is based on the implicit one.
  • Long text in grids. DataGridTextCell cuts long text with an ellipsis. While the text is cut, CutTextToolTip shows the whole text in the tool tip; a tool tip that the cell sets itself stays. DataGridColumnsBehavior gives generated text columns this style. A declared column sets ElementStyle="{StaticResource DataGridTextCell}": a grid column is not in the element tree, so a DynamicResource on a column property finds only application resources and the cell keeps the default style. DataGridTextCell.Wrap wraps a message column; give that column Width="*", so rows grow and the grid does not scroll sideways.
  • Validation errors. A TextBox, ComboBox, CheckBox or RadioButton with a validation error draws its border in the Error brush and shows the first error in its tool tip. The theme replaces the WPF error adorner with ValidationErrorTemplate, which draws nothing, so the border is the only outline.

Resource URIs

Every compiled resource URI contains the assembly's version. A changed stable assembly therefore has a new identity, and WPF cannot select an older copy of Presentation that an earlier dbtools version has already loaded.

The component URI is relative, so Application.LoadComponent does not need the pack scheme to be registered.

  • Use ResourceUri.CreateResourceUri for Application.LoadComponent, dictionary sources and the dictionary markup extensions.
  • Use ResourceUri.CreateAbsoluteResourceUri for images and icons created in code without a WPF base URI. It registers the pack scheme and returns pack://application:,,,/<assembly>;V<version>;component/<path>.

WindowInitializer loads the window icon with BitmapCacheOption.OnLoad inside its warning boundary; otherwise WPF can defer the file lookup until it creates the window handle.

XAML namespaces

XAML outside Presentation refers to stable types with clr-namespace:...;assembly=dbtools.Presentation. XAML compiled by Presentation uses the namespace form without assembly=. This keeps the BAML compiler from resolving Presentation types through a reloadable assembly.

BAML assembly versions

The BAML assembly table must contain the final assembly version, because WPF resolves local markup extensions through that table separately from the outer pack URI. Keep SDK assembly-info generation on in WPF temporary projects. With it off, BAML references Version=0.0.0.0; if an older Presentation is already loaded in the default context, the CLR can satisfy that request with the older copy. When that copy lacks a markup extension type that the current BAML names, WPF throws NotImplementedException before it opens the merged dictionaries. WPF's local-assembly fallback runs only when loading throws, so a successful bind to the older copy bypasses it. See .NET 10 WPF assembly and type resolution and CoreCLR version compatibility.

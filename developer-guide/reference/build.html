Build commands

NAME

build/Build.proj - build the product and its test assemblies

SYNOPSIS

dotnet build build/Build.proj [-t:TARGET] [-p:NAME=VALUE]...
./build.sh [TARGET] [OPTION]...
pwsh -NoProfile -File build.ps1 [TARGET] [OPTION]...

DESCRIPTION

Install the .NET SDK 10.0.401 or a newer 10.0 patch in the 10.0.4xx feature band. Run dotnet build build/Build.proj from the repository root on Linux, WSL 2 or native Windows. The default BuildAll target validates and publishes the complete Release distribution from a clean Git checkout. With -p:RevitYear=2026 or -p:RevitYear=2027, BuildAll runs BuildApp for that year and skips distribution validation and publication.

Content versions include the .NET SDK version. Builds of the same commit with different SDK patches have different content versions.

build.sh and build.ps1 pass targets and options to build/Build.proj. Both map the Restore target to _DBT_Restore. MSBuild reserves Restore for package restore.

PREFLIGHT

dotnet build build/Build.proj -t:Preflight

Preflight reports Git LFS, model file hydration, python3 at version 3.10 or newer, Inno Setup on Windows, the dbtools-daemon CLI and relay settings, and the DocFX local tool. Each missing tool gets an install command or download URL. Preflight reports could not check when a probe cannot finish. A Git LFS pointer in testing/RevitTestModels/ gets the commands git lfs install and git lfs pull.

BuildAll runs the informational report before product restore. The CANON gate, build-docs.sh, and compile-installer.ps1 enforce their own tool requirements. BuildInstaller requires Inno Setup 6.7.1 or later in the 6.x series.

OPTIONS

Both wrappers print the full list of targets, options and defaults from build/Usage.txt.

./build.sh --help
pwsh -NoProfile -File build.ps1 --help
Task Target and options
Publish the distribution Use the default BuildAll target.
Stage a product year Use -p:RevitYear=2026 or -p:RevitYear=2027. Set -p:Configuration=Debug for Debug output.
Compile test projects Use -t:BuildTests for Pure, Local and Design Automation. Use -t:BuildSelectedPureTests -p:TestProjects=A%2CB to compile selected Pure projects.
Package the Autodesk bundle Use -t:BuildBundle. Set -p:CandidateDistributionPath=DIR to use a promoted distribution.
Compile the Windows installer Use -t:BuildInstaller with an existing bundle.
Print the build settings Use -t:Info.

BuildTests and the selected-test targets reject --clean and --DryRun true. Use the standalone Clean target to clear build output first.

Clean keeps build/, build-tasks/, dist/, acceptance/, test-results/ and build.json under .artifacts/. It deletes all other entries there, including .artifacts/bin/. It also deletes build bin/ and obj/ directories and *_wpftmp.csproj files left in the source tree. The source scan skips build/, docs/, vendor/, .git/, nested Git checkouts and symbolic links.

--Revit2026Dir and --Revit2027Dir select the installed metadata files for validation. The default reference source is the Revit API packages.

EXIT STATUS

The Exit status paragraph of ./build.sh --help (build/Usage.txt) lists the exit codes.

ENVIRONMENT

Variable Effect
DOTNET Selects the dotnet executable used by a wrapper if it resolves an SDK that satisfies global.json.
DBT_BUILD_SERVERS In build.sh, 1 enables compiler and MSBuild servers scoped to the invocation. Set 0 to disable them. The default is 1. PowerShell builds run with servers disabled.
DBT_MSBUILD_MAX_CPU_COUNT Sets the MSBuild CPU count for child graphs. The default is 2.
DBT_BUILD_CONSOLE_LOG Sets the destination for the copy of the latest detailed log.

FILES

Path Use
global.json Sets the minimum SDK patch and its feature band.
~/.dotnet/pinned-sdk-<version>/ Holds the verified SDK that the wrappers download if system installations lack a compatible SDK.
.artifacts/build/<build-id>/ Holds the child build binlogs. The wrappers also write a detailed console.log here.
.artifacts/build/console.log Default path for the copy of the latest run log.
.artifacts/bundle/dbtools.bundle Autodesk bundle from BuildBundle.
.artifacts/bundle/installer-defines.json Supplies the bundle path, product files, version and years to the installer compiler.

EXAMPLES

Use CandidateDistributionPath with DryRun to check a promoted distribution and skip writing the bundle.

dotnet build build/Build.proj -t:BuildBundle -p:CandidateDistributionPath=.artifacts/dist/Release -p:DryRun=true

On Windows, use Inno Setup 6.7.1 or later in the 6.x series. Build the bundle, then compile .artifacts/release-assets/dbtools-Setup-<version>.exe.

dotnet build build/Build.proj -t:BuildBundle
dotnet build build/Build.proj -t:BuildInstaller

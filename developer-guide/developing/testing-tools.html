Testing Tools

Use test.sh to select, build, and execute repository tests. Use build.sh on Linux/WSL or build.ps1 on Windows to compile product and test graphs. Static discovery and request validation do not execute tests.

Run commands from the repository root. Pure means execution without Revit. It does not imply Linux support. Most tool, App, and Core Pure tests target Windows. Hosted tests run in Revit on the daemon fleet. APS Design Automation runs separately through a real cloud WorkItem.

Execution hosts

Marker/project Execution host
Plain [Test] in .Pure.Tests NUnit/VSTest without Revit. Windows-only fixtures may use WPF.
.Portable.Pure.Tests Linux-native tests of an owner's portable production target.
[RevitLocal] in .Local.Tests Revit on a daemon worker.
[RevitDA] in a WorkItem-backed DA project HTTP client on the invoking host and Revit in APS.
BUILD Linux-native build/distribution contract projects plus Windows Sandbox Pure tests.
DIST Explicit daemon-required Windows distribution acceptance.

The routing marker describes behavior. Project membership supplies the matching compile/runtime dependencies. A .DA.Tests name alone does not establish cloud coverage. Local, Both, and DA execution categories are invalid. Orthogonal NUnit categories may describe other properties.

Daemon-routed Pure and hosted runs use the daemon's hidden desktop. An interactive private desktop requirement never permits tests on the user's visible desktop. Windows Pure tests can also run locally on Windows when their required runtimes are installed.

Pure execution routing

run_pure_scope routes each selected project to the daemon when:

  • The project appears in PURE_SUITE_REQUIRES_DAEMON, as DIST does.
  • The request supplies --machine.
  • The project declares Windows execution and the invoking host is not Windows.
  • Local runtime inspection finds Microsoft.WindowsDesktop.App missing.

During local runtime inspection, any other missing framework fails the request rather than selecting the daemon. All remaining projects run locally through dotnet vstest over frozen artifacts. A compile followed by a routing failure is not test execution evidence.

Source gates

Compilation, source checks, and distribution acceptance are separate checks:

python3 .agents/work/canon_source_maps.py --check
python3 .agents/work/canon_source_fidelity.py --gate --mechanical-root testing --mechanical-root build
.githooks/pre-push

Regenerate maps with python3 .agents/work/canon_source_maps.py after source moves. BuildAll does not generate them or run CANON. The pre-push hook checks governance structure, full CANON, map freshness, interpolated resource URIs, and ValidatePrePush. A manual hook run has no Git LFS upload. An actual push passes its refs to LFS after the gates succeed.

Run one build or test command at a time in a worktree. The wrappers take no worktree lock and check no free memory. build.sh and test.sh manage scoped compiler/MSBuild servers through build/Coordination/build-server-scope.sh. Each invocation owns its server identities and shutdown. DBT_BUILD_SERVERS=0 disables scoped servers. build.ps1 runs without build servers.

Dev Mode preflight

Distribution validation runs a separate policy worker for the candidate and authenticates its pinned policy identity. It checks the direct product metadata, references, manifests, and collectible/stable assembly boundary for every supported year. A worker has a three-minute limit. A CollectibleThreadStatic warning counts as a blocking failure.

Each year prints this summary:

Revit <year> Dev Mode preflight: <n> failures, <m> warnings; outcome=<value>

The portable acceptance result binds source identity, candidate fingerprints, references, and validator identity. Promotion requires that current result. A successful static preflight does not prove native WPF execution or a live inject/reload. See Sandbox Integration and Assembly Loading.

Distribution acceptance

DIST is a closed acceptance command, not an ordinary tool suite. It requires test --tool DIST --scope pure, automatic machine selection, and the exact filter FullyQualifiedName=DBTools.Distribution.Windows.Tests.WindowsAcceptanceTests.ValidatesTheStagedCandidate. Supply --result-json and exactly one --include file named validate-dist-<64 lowercase hex digits>.zip. The archive contains the complete candidate, references, and Sandbox payload. Other tools, fixture selectors, explicit machine pins, and arbitrary include files are rejected.

Build the archive with PackageSandboxValidationInput. The acceptance test validates it before launching a fresh Sandbox for every supported year. Its compile-only selection builds the test graph without requiring an archive or executing acceptance.

Discovery and examples

These commands inspect selections without submitting tests:

./test.sh --help
./test.sh list --tool GM --scope pure --fixture DuplicateDetectionEngineTests
./test.sh list --tool APP,CORE --scope local --projects
./test.sh list --tool GM,SGT --scope pure --summary
./test.sh validate-request --tool GM --scope pure --fixture DuplicateDetectionEngineTests

Local validate-request checks CLI availability, a selected year, selector translation, and model metadata. It does not require or validate a relay URL, connect to the relay, or submit a job:

./test.sh validate-request --tool GM --scope local -y 2026 \
  --queue-timeout 00:05:00 --execution-timeout 00:30:00

Run tests with:

./test.sh test --tool GM --scope pure --fixture DuplicateDetectionEngineTests
./test.sh test --tool GM,RecordSet --scope pure
./test.sh test --tool APP --scope local -y 2026
./test.sh test --tool GM --scope local --years 2026,2027

Do not use --scope all as a routine catch-all: it includes the credentialed APS scope and requests each selected owner's corresponding projects. Use explicit scopes and the smallest relevant fixture while iterating.

BUILD selects two Linux-native contract projects and Sandbox's Windows Pure project. To run only the Linux-native projects:

./test.sh test --tool BUILD --scope pure \
  --project testing/DBTools.Build.Tests/DBTools.Build.Tests.csproj,testing/DBTools.Distribution.Tests/DBTools.Distribution.Tests.csproj

On Windows, Linux-native BUILD projects and *.Portable.Pure.Tests are skipped before compilation with a notice. Explicitly selecting only native projects fails. A changed-owner request with no runnable Windows projects and no explicit project selection skips with a notice. DIST remains daemon-routed on every OS.

Build records and frozen inputs

Normal test resolves ownership and builds all requested graphs before the first submission. Each selection writes a schema-2 prepared-artifact record under .artifacts/tests/build-record-<lane>-<year>-<selection>.json. The record contains source content identity, selected projects, and output, model, and include hashes. Pure is year-free. Local records are per year. DA uses its 2026 graph.

Separate project sets have separate records. Editing an already-dirty source file invalidates its content identity. Source changes during compilation refuse a record. Git filters preserve source identity across tracked LFS hydration, while model hashes still verify payload bytes.

./test.sh test --tool GM --scope local -y 2026 --compile-only
./test.sh test --tool GM --scope local -y 2026 --no-build

The second command requires the matching project set, current source, and exact recorded output bytes. It fails rather than rebuilding stale inputs. rerun reuses previously submitted bytes and does not test edited source.

Before execution/upload, the wrapper freezes verified bytes in:

${TMPDIR:-/tmp}/dbtools-test-inputs/<worktree-sha256>/objects/<sha256>

It rechecks cache hashes and stages a private run directory on that filesystem, using hard links when possible and copying otherwise. Later builds cannot change submitted bytes. Native Pure runs execute frozen assemblies with dotnet vstest. DBT_TEST_REPO_ROOT supplies repository/restore lookup for relocated Pure outputs. Direct callers can use embedded DBTools.RepoRoot metadata. The testhost working directory does not select restore inputs.

Local submits one request per selected year. Daemon Pure submits one request per selected project with that project's exact fixture selectors, forwarded as repeatable --fixture-fqn arguments. All selected projects run despite independent execution failures, and the aggregate returns nonzero when any fails. Native Linux Pure projects run serially. Daemon Pure concurrency defaults to two. Linux signal/exit cleanup terminates owned submit process groups. TERM also stops owned graph builds and local tests. Independent scopes continue after execution failure. A failed shared build prerequisite stops dependent execution.

CI artifact transfer

CI uses test.sh selectors for both producer and consumer. After product-only BuildAll, compile each Windows scope with test --compile-only. Preserve its exact list --projects selection and transfer that selection's build records and union of recorded outputs, models, and includes to identical relative paths in a clean checkout.

Consume with test --no-build and the same scope, project set, selectors, and hosted year. Source/output mismatches fail. Linux-native CI builds its selected graph normally. validate-request --no-build validates the request surface and model metadata without reading test results or copying model payloads. CI has no APS credentials. A real Sentinel selection fails at its credential check.

Model paths

TestPathResolver reads DBTOOLS_DAEMON_REVIT_MODELS_DIR on every call. The daemon supplies the staged root. Relative paths retain their year, tool, shared-directory, and filename segments. Rooted paths and ./.. traversal segments fail. There is no fallback to a user model cache.

var model = TestPathResolver.ResolveTestModelPath("2026", "GM", "gm_test_model.rvt");

A model under <year>/Regression/ is a staged working copy whose external links are not included. DocumentLease disables link loading before opening that copy and refuses regression paths outside the staged root.

RevitFamilyTemplateResolver searches only requested template names beneath CommonApplicationData/Autodesk/RVT <running-year>/Family Templates. It orders English-Imperial candidates first, then paths deterministically. BasicFileInfo.Extract(...).Format must equal the running Revit year. No matching installed template yields Inconclusive with observed formats/errors. Repository-controlled models and assets are different: missing staged files must fail the test.

Hosted context and cleanup

Use RevitHost.RunAsync(...) for the daemon-provided UIApplication. It initializes year, ambient call-gate state, the App host, and runtime assembly context. WPF name-only product loads resolve with the active App assembly. RevitAmbientScope owns publication/restoration of the ambient UIApplication. A native callback's API scope applies only to its synchronous prefix. Later continuations use a fresh product probe or gate.

DBT_TEST_RUN_ID identifies automation so startup errors remain headless. Fixtures release only runtime/task hosts, owners, static state, documents, and overlays they own. The daemon terminal owns final release of its active Autodesk document. Use document leases rather than closing unrelated documents.

When work and cleanup fail, preserve both. Attempt every owned document close, UIDocument disposal, logging shutdown, transaction-group finalization, and window/session disposal. A production launch smoke must use the production session owner and await its exact startup and failure-bearing completion. Window.Close() alone is not proof that Closed, ViewModel cleanup, and scope disposal finished.

Failed, canceled, or absent startup selects rollback. After successful startup, persistence or cosmetic cleanup errors do not change the requested model outcome. Broken group health still selects rollback. Await persistence, preview/effects release, transaction finalization, actual window closure, handler detach, and ViewModel disposal before disposing the App run scope. If the dispatcher lifetime is gone, retain the broken-lifetime failure, select rollback, and continue safe cleanup without awaiting an impossible UI Task. Background persistence logs and propagates its contextual failure without issuing window-affine notifications. The command boundary reports it.

Writing tests

Write the failing test before the fix. Trace real callers and correct the production cause before changing expectations. Use real product workflows, matchers, planners, and persistence. Stub true externals such as Revit, network, filesystem, time, or random input. Do not embed domain decisions in doubles or assert only that an owned mock was called.

Pure tests cover native DTO/value behavior and Windows UI behavior without Revit. Local tests cover actual Revit API/document/session behavior. APS tests must submit a WorkItem and assert real output/report/model artifacts. Missing repository prerequisites and unexpected exceptions are failures. Skip only for a probed host capability that the supported runtime lacks, naming the missing member/capability and running year.

Example: native duplicate detection

DuplicateDetectionEngineTests.DetectAsync_HigherScore_WithParameterOverlap uses real duplicate matchers and asserts their returned pairs. The fixture's setup supplies _svc and the external element-name query _names. SetFamilyParameterDiscovery constructs the native discovery state:

[Test]
public async Task DetectAsync_HigherScore_WithParameterOverlap()
{
    var projectState = new ProjectState
    {
        Families = new Dictionary<long, ProjectStateFamilyRecord>
        {
            [100] = new ProjectStateFamilyRecord { ElementId = 100, Name = "Door Type" },
            [101] = new ProjectStateFamilyRecord { ElementId = 101, Name = "Door Type 1" }
        }
    };
    SetFamilyParameterDiscovery(projectState.Families[100], "Width", "Height", "Frame Depth");
    SetFamilyParameterDiscovery(projectState.Families[101], "Width", "Height", "Frame Depth");
    _names.AddName(100, "Door Type");
    _names.AddName(101, "Door Type 1");

    var result = await _svc.DetectAsync(projectState);
    var pairs = result.Groups
        .Where(group => group.Kind == DuplicateKind.Families)
        .SelectMany(group => group.Pairs)
        .Where(pair => (pair.FromId == 100 && pair.ToId == 101) ||
                       (pair.FromId == 101 && pair.ToId == 100))
        .ToList();

    Assert.That(pairs, Is.Not.Empty);
    Assert.That(pairs.All(pair => pair.Score >= 90), Is.True);
}

For an actual Revit boundary, VTC's CategoryTabClassifierTests opens the staged SGT model and classifies real Revit categories. That fixture remains [RevitLocal]; replacing the categories with invented data would not test the adapter. The two fixtures illustrate different execution requirements.

Hosted UI restrictions

Revit-hosted tests cannot display blocking modals. The daemon rejects modal dialogs, disabled native owners, and Revit unhandled-exception windows. A short-lived dialog is still a violation.

Show hosted sessions modelessly with Show and bounded DispatcherDrain or DispatcherFaultScope helpers. Keep API, assembly-context, theme, and real Revit owner checks hosted. Test ShowDialog results, modal-loop exit, native owner disable/restore, and modal-child refusal in Windows Pure tests with real WPF windows and stand-in owners. Audit indirect alert and file-picker calls too.

ToolWindowDialog rejects Revit processes/routing categories before using the session. Its bounded watchdog supports Windows Pure tests, including a beforeShow callback. Hosted assembly setup also installs a modal tripwire on Revit's UI dispatcher: it records WPF ShowDialog entry and posts a Send-priority close of that exact dialog. The test fails even after Pass, Ignore, or Inconclusive. The tripwire does not authorize a modal, and the daemon can detect one first.

CommonDialog may raise the event without a WPF Window. The tripwire records it without closing an unrelated window. Native message boxes, TaskDialog, disabled owners, and separate STA dispatchers remain outside that backstop. The daemon's window probe is authoritative.

Exceptional closure tests use Core's per-window error boundary. Assert that only the exact attached window receives a classified handled-error signal, foreign failures remain unhandled, and unsubscribe/detach remove the observer. Hosted sessions consume that signal through a bounded modeless pump, finalize, and surface the original error before cleanup/lifetime assertions. Modal-frame behavior remains Windows Pure coverage.

APS Design Automation Sentinel

LightweightSentinel_ExecutesRealDesignAutomationWorkItem is the real APS test. Its net8.0 client loads no Revit or Windows API. It uploads a zipped Sentinel appbundle and seed model, executes a Revit 2026 WorkItem, and asserts the Revit version and returned output. The daemon does not run it.

A real Sentinel run requires APS app credentials in the environment:

./test.sh test --tool DA-SENTINEL --scope da
Variable Meaning
APS_CLIENT_ID Required app client ID.
APS_CLIENT_SECRET Required app secret.
APS_BUCKET Optional OSS bucket. Default dbtools-tests.

Missing credentials fail rather than skip. The CLI estimates 5–12 minutes per WorkItem, and the test's wait is bounded at 12 minutes. Each run consumes APS processing time. Account allowances and billing must be checked separately. They are not repository configuration.

Each run creates appbundle/activity versions, binds unique run<32 hex digits> aliases, and uses an output object with that identity. The activity references this run's uploaded bundle version. Cleanup runs on success or failure, keeps the newest two versions, and prunes at most 25 versions of each resource per run.

Activities are pruned first. Appbundle aliases/versions referenced by remaining activities are retained. Missing resources need no pruning. Both resources receive cleanup attempts. If activity references cannot be read, keep all appbundle aliases and delete only unaliased versions. Already-deleted versions and aliases count as removed. Cleanup and primary failures remain visible together.

APS error bodies, SDK messages, and WorkItem reports pass through redaction before logs, exceptions, and TRX output. The client removes known credentials, issued/bearer tokens, authorization/cookie headers, credential fields, and signed URL secrets, and truncates long text.

The project also has network-free tests using a fake HTTP handler for version binding, pagination, token renewal, redaction, pruning, cleanup, run identity, bundle layout, and credential errors. Their selection is:

./test.sh test --tool DA-SENTINEL --scope da -f 'TestCategory!=RevitDA'

The wrapper builds the frozen 2026 graph and runs its client locally. DA rejects daemon submit/rerun routing and result-JSON options. Evidence includes result.trx, uploaded bundle work files, and downloaded output under .artifacts/test-results/<run>/DBTools.DesignAutomation.Sentinel.DA.Tests/.

Results and troubleshooting

Use runtime results, not static discovery counts, as pass evidence. Record test counts, request IDs for daemon runs, and the source/artifact selection. Local Pure runs use TRX counters and preserve a failing TRX under .artifacts/test-results/<run>/<project>/result.trx. Daemon runs print the underlying job output and collect terminal reports. --result-json is daemon evidence, not a local Pure result file.

Failure Action
Missing model/params Check the project-declared model closure and daemon-staged paths. Do not search alternate models.
Stale/missing build record Run normal test for the selected current source. --no-build intentionally refuses stale bytes.
Relay/host initialization Check CLI/relay configuration. Compilation alone is not a test result.
Windows Desktop runtime unavailable locally The wrapper selects the daemon. Check its CLI and relay configuration.
Hidden-desktop refusal Inspect the daemon report and request ID for visible_desktop_violation or private_desktop_unavailable.
Batch-only failure Isolate shared state in setup/teardown and inspect cleanup errors.
BUILD artifact prerequisite Build the required product/test years explicitly. Artifact tests do not create prerequisites.

Candidate-consuming BUILD fixtures additionally require AssembleDistributionCandidate. Their filters do not infer it. Acceptance checks require clean source. DistributionContractTests inspect real output references and reject bundled Revit host DLLs. Revit supplies those DLLs at runtime.

Inspect %APPDATA%/DBTools/Logs/ first for reported application failures. Hosted job output returns application logs. Use the selected Revit year's journal for a crash only when those logs are inconclusive.

Test Refactoring Strategy

Refactor tests according to the execution host their behavior requires. Keep pure logic tests separate from Revit integration and real APS WorkItem tests. Use real product services and assert their outcomes.

Host classification

Marker Host and purpose
Plain NUnit [Test] Pure execution without Revit. Windows Pure fixtures may use WPF.
[RevitLocal] Real Revit UI, documents, API callbacks, and add-in lifetime on the daemon fleet.
[RevitDA] Real APS Design Automation WorkItem execution and output validation.

A .DA.Tests filename does not establish APS coverage. Local, Both, and DA categories are invalid routing metadata. Orthogonal categories may describe other test properties without changing the execution host.

Refactoring procedure

  1. Reproduce the failure and trace the product boundary. Correct product behavior before adjusting a test expectation.
  2. Replace Revit types used only as data carriers with native values or snapshots when the product exposes that boundary.
  3. Exercise real matchers, planners, workflows, and persistence. Stub only true externals such as Revit, network, filesystem, or time.
  4. Put portable behavior in a Pure project. Keep actual WPF behavior in Windows Pure tests and actual Revit behavior in Local tests.
  5. Assert the observable result, failure, and cleanup. Remove redundant or misleading tests only when their behavior has no useful independent coverage.
  6. Compile and run the affected tests through the repository entrypoints. Report separately any hosted behavior that was compiled but not executed.

Do not replace an owned workflow with canned outcomes, loosen assertions to match a defect, catch arbitrary exceptions as inconclusive, or repair missing fixture data dynamically.

Project membership and placement

Tests mirror the production owner beneath Tests/. Revit fixtures mirror it beneath Tests/Integration/Revit/. Reusable external doubles, construction helpers, and assertions belong under the applicable Tests/Support/ owner or shared testing/TestSupport/ source links.

Use separate .Pure.Tests, .Local.Tests, and actual WorkItem-backed DA projects. Local projects disable default compile items and explicitly include hosted fixtures and required support. Do not subtract Pure fixtures from broad Local globs. A shared helper must be neutral. Linking it must not pull Pure fixtures into the hosted assembly.

Split directories around coherent owners before they exceed roughly 12 fixture/support files. Remove empty directories and avoid placeholders.

When adding, deleting, or renaming testing/**/*.cs files, update their exact paths in .desloppify/config.json zone_overrides with value "test". Pre-push rejects missing, invalid, or stale entries for testing/ files.

GM

Use Pure tests for native mapping state, persistence, saved mappings, similarity, usage normalization/projection, selection clearing, and planning. Use FamilyMappingOptionProjector for nested family option projection instead of constructing the complete application window. Keep preview state as native values until the WPF presentation boundary.

Keep document adapters, shared parameters, deep scans, actual window composition, owner wiring, and active-view/document behavior hosted when they require Revit. An integration test does not become Pure merely because it avoids showing a window. APS coverage needs a product entry and real WorkItem outputs without UIApplication, UIDocument, selection, or interactive session assumptions.

SGT

Use Pure tests for native domain values, feature decisions, undo/redo history, and file-backed UI state. Use the portable target for inward behavior that runs on Linux. Replace incidental Revit geometry carriers with native snapshots where the product boundary permits it.

Keep real geometry/document adapters, placement parity, Revit selection, window composition, and host-dependent preview behavior Local. WPF behavior that needs no Revit belongs in Windows Pure tests. Classify each fixture by what it actually executes rather than by a directory's historical name. SGT APS coverage requires its own product entry and WorkItem test. UIStateStoreTests is Windows Pure, while ExtentResolverTests and MemberResolutionSpanIndexTests exercise the portable domain. PreviewPlacementParityTests remains hosted.

Validation

Inspect selections, then execute or compile the affected tests:

./test.sh list --tool GM,SGT --scope pure --summary
./test.sh list --tool GM,SGT --scope local --projects
./test.sh test --tool GM --scope pure --fixture DuplicateDetectionEngineTests
./build.sh BuildSelectedLocalTests --TestProjects DBTools.GM.Local.Tests -y 2026

Run the affected full Pure suites after focused checks. Testing Tools documents execution routing, build commands, model prerequisites, and failure evidence. APS Design Automation Sentinel describes the separate credentialed cloud test.

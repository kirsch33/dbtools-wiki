Test Refactoring Strategy

This page records the current test-refactoring direction for DBTools. The older GM/SGT Both / Local / DA-compatible strategy has been superseded by the current-dev Revit test taxonomy plan.

Core Rule

Tests must be labeled by the host they truly require:

Marker Meaning
plain [Test] Pure/off-Revit test
[RevitLocal] Local Revit-hosted execution
[RevitDA] True Autodesk APS Design Automation WorkItem execution

The old Category("Both"), TestCategories.Both, Category("DA"), and TestCategories.DA markers have been removed. .DA.Tests project names are not routing truth and do not prove DA execution unless the selected tests submit and validate a real APS WorkItem.

Refactoring Priorities

  1. Move pure logic to plain [Test] and remove Revit/WPF/add-in-host closure from those projects.
  2. Rewrite tests that use Revit API types only as convenient data carriers into native C# DTO/value/snapshot tests.
  3. Keep [RevitLocal] only for tests that genuinely require local Revit UI/session/add-in-host behavior.
  4. Use [RevitDA] only for tests that execute through APS Design Automation WorkItems and assert real outputs.
  5. Delete fake, mock-call-only, redundant, stale, or misleading tests instead of preserving old coverage names.
  6. Keep owner tests colocated under the owning Tests/ directory, but keep pure, local, and DA execution hosts separated by positive project membership until a single project can preserve those host contracts without dependency leakage.
  7. Split test directories before they exceed roughly 12 files, delete empty test directories, and avoid placeholder folders.

Local Revit test projects must disable default compile items and explicitly include only the [RevitLocal] fixtures plus local-only support files they own. App and Core project-suite local projects follow the same rule as tool-owned local projects. They must not use broad default globs with large Compile Remove lists to subtract pure tests. If a local project needs a pure support helper, move the helper to a shared neutral location or duplicate no behavior; do not pull pure-only fixtures into the local assembly.

GM Direction

GM pure kernel, persistence, saved-mapping, similarity, usage-normalization, usage projection, usage-pane selection clearing, and planning tests should become plain [Test] after their Revit/WPF/App closure is removed. Nested family object-style/material projection is now covered through FamilyMappingOptionProjector without constructing the shell or usage pane view model, and usage-pane preview state flows through native values before WPF presentation is applied at the pane edge. Real document adapter, shared parameter, deep-scan, shell/window, owner wiring, and active view/document tests remain [RevitLocal] unless rewritten around native snapshots. DA coverage must wait for true WorkItem execution and must avoid WPF, UIApplication, UIDocument, selection, and interactive add-in-session assumptions.

SGT Direction

Most SGT package-mirrored unit tests are pure and should stay plain [Test]. The current pure set includes feature tests under Unit/Features/*, shared-domain tests under Unit/Shared/*, and undo/redo history plus file-backed UI-state persistence because those assert native service outcomes, not Revit host behavior.

Tests that currently use Revit DB types for geometry or document state must be rewritten to native geometry/value snapshots where practical. UI smoke, parity harness, preview rendering, remaining shell command/view-model behavior, active-document, and selection behavior remains [RevitLocal] until each fixture proves it can be split. SGT DA coverage needs a product DA entry and a WorkItem test of its own, like the Sentinel's, and the test must obey DA host constraints.

Validation

Use canonical commands only:

bash build.sh BuildAll
dotnet test --list-tests                       # static discovery via the daemon adapter
dotnet test --filter "TestCategory=GM" --list-tests
dotnet test --filter "TestCategory=GM"
dotnet test --filter "TestCategory=SGT"

dotnet test discovers tests statically and dispatches [RevitLocal] work to the dbtools-daemon fleet; pure [Test] fixtures run in-process. APS WorkItem tests never go through the daemon. The one such test, the DA Sentinel, runs on the operator's host with the operator's APS credentials, and agents never run it; see APS Design Automation Sentinel.

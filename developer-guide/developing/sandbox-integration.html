Sandbox Integration

Sandbox previews tool windows and validates a staged distribution without starting Revit. Native validation runs on Windows and constructs real WPF windows. Run one fresh Sandbox process for each candidate year.

Use this page to register a preview, build Sandbox, and run it on Windows. See Sandbox Validator for candidate loading, assembly boundaries, and the validation sequence. Portable build validation checks metadata, raw XAML, and Dev Mode policy on Linux. Native WPF validation and live Dev Mode injection require Windows.

Register a window

Declare a raw view in the tool's manifest.yml:

sandboxWindows:
  - id: DBTools.MyTool.Main
    displayName: "My Tool"
    group: "Common"
    xamlResource: "DBTools.ToolViews.MyTool.MyToolWindow.xaml"
    windowKind: Modal
    width: 1200
    height: 700
    minWidth: 900
    minHeight: 500
    startupLocation: CenterScreen
    designTimeViewModelType: "DBTools.MyTool.App.DesignTime.MyToolWindowDesignTimeViewModel"
    designTimeViewModelAssembly: "DBTools.MyTool"
    designTimeViewModelVisibility: Public

Embed the matching resource in the owning tool project:

<EmbeddedResource Include="App\Views\MyToolWindow.xaml"
                  LogicalName="DBTools.ToolViews.MyTool.MyToolWindow.xaml" />
Field Requirement and meaning
id Required stable window identity.
displayName Required catalog/window title.
group Required catalog group.
assembly Optional raw-view assembly override. Otherwise the tool's manifest owner.
xamlResource Required exact embedded logical resource name.
windowKind Modal by default, or Modeless.
designTimeViewModelType Required fully qualified design-time type.
designTimeViewModelAssembly Required simple assembly name.
designTimeViewModelVisibility Required Public or Internal, matching the type.
width, height, minWidth, minHeight Optional finite dimensions. Width/height must be positive. Minimum sizes may be zero.
showInTaskbar Optional Boolean. Defaults to false.
startupLocation Optional WPF startup location. Defaults to CenterOwner.
titleBindingPath, titleStringFormat Optional title binding and format.

The parser rejects unknown fields and blank required values. Use exact enum spellings. Multiple entries can share a design-time type while using different stable IDs and raw resources. The manifest owns this metadata. Sandbox does not infer a Window type from a filename.

Raw views and runtime ownership

Use a stable root such as Grid. Raw views have no Window root, x:Class, code-behind, event attributes, tool CLR namespaces, payload pack URIs, payload BAML, or implicit templates for tool types. Bind visible text, headers, items, and tooltips explicitly. Use explicit templates, selectors, and display paths for bound content.

Use tool-window sessions to open the same raw view in the product. Settings pack views supplied by pack factories are a separate embedded editor surface.

Design-time ViewModels

A Public type needs a public parameterless constructor. An Internal type must be non-public and have a public or non-public parameterless constructor. The manifest must select the matching visibility. The type must be constructible. Keep construction independent of Revit documents, external events, network services, and production settings.

namespace DBTools.MyTool.App.DesignTime;

public sealed class MyToolWindowDesignTimeViewModel
{
    public string Title => "My Tool";
    public IReadOnlyList<string> Rows { get; } = new[] { "Example", "Preview" };
}

Populate the ViewModel with sample state and commands. A display-only action can use NoOpCommand from DBTools.Core.UI.Commanding.DesignTime.NoOp.

Use Global Mapper (GM) and Super Girt Tool (SGT) manifests under src/Tools/ as examples of raw-view and design-time ViewModel registration.

Build and run

Build a product candidate and Sandbox:

./build.sh AssembleDistributionCandidate -y 2026
./build.sh BuildSandbox -y 2026

Candidate assembly can compile edited source. Acceptance targets require a clean committed tree. Read the build output for its build ID and use that invocation's candidate directory:

.artifacts/.staging/<build-id>/distribution-candidate/Release/2026/
.artifacts/sandbox/Release/2026/net10.0-windows/

Run Sandbox on Windows with the matching Revit year installed. Both modes resolve that installation, require its runtime files, and check metadata/runtime compatibility. Run these commands from the repository root:

dotnet run --project src/DBTools.Sandbox/DBTools.Sandbox.csproj -p:RevitYear=2026 -- --dist-dir .artifacts/.staging/<build-id>/distribution-candidate/Release/2026

Replace <build-id> with the ID printed by the candidate build. To validate without the interactive catalog, add headless mode and the matching installed Revit reference directory:

dotnet run --project src/DBTools.Sandbox/DBTools.Sandbox.csproj -p:RevitYear=2026 -- --headless --dist-dir .artifacts/.staging/<build-id>/distribution-candidate/Release/2026 --revit-reference-dir 'C:\Program Files\Autodesk\Revit 2026'

These are native Windows commands. Daemon-routed acceptance uses its hidden desktop. See Testing Tools for routing.

Options

Sandbox [--dist-dir PATH] [--headless --revit-reference-dir PATH]
Option Default and behavior
--dist-dir PATH .artifacts/dist/Release. Accept a year directory or a root containing supported year directories.
--headless Disabled. Run native validation without the interactive catalog.
--revit-reference-dir PATH Required with --headless. Invalid without it.

Both path options also accept --name=value. Blank values and unknown arguments fail. A distribution root selects the newest supported year containing DBTools.dll. It does not reject a root merely because both years are present. Use an explicit year directory to select 2026 when 2027 also exists. A missing candidate fails before WPF startup.

Headless mode suppresses interactive UI but still creates native WPF windows, checks layout and bindings, exercises supported interactions, and closes owned windows. It requires Windows Desktop. It is not a Linux metadata-only mode.

Package native validation inputs

Run PackageSandboxValidationInput to package the current candidate and Sandbox for Windows distribution acceptance:

./build.sh PackageSandboxValidationInput

This target requires a clean committed source tree and every supported year. Sandbox output and archive paths include the year:

.artifacts/sandbox/<configuration>/<year>/<tfm>/
sandbox/<year>/<sanitized-tfm>/

Use the archive with the distribution acceptance command. For validation checks, failure handling, and the distinction between portable, native, and live Dev Mode validation, see Sandbox Validator.

Troubleshooting

Failure Action
Missing view resource Match xamlResource to the owning project's LogicalName.
ViewModel construction failure Check assembly/type names, declared visibility, and parameterless constructor access.
Binding errors Read binding-listener output and supply explicit display bindings.
Candidate file/identity mismatch Rebuild the selected candidate and inspect its recursive file set.
Wrong candidate year Pass an explicit year directory rather than the distribution root.
Reference mismatch Supply matching installed-year Revit references in headless mode.
Cleanup failure Inspect the window/session cleanup failure before terminating the process.

See Sandbox Validator, Assembly Loading, and Creating New Tools.

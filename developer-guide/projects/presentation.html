DBTools.Presentation

DBTools.Presentation.dll is the WPF assembly that stays loaded for the life of the Revit process. It is staged at the root of each product year, beside DBTools.dll, DBTools.Core.dll and DBTools.HandyControl.dll.

Contents

Presentation holds only types that must live for the whole process:

  • theme dictionaries, resource keys, styles, converters and pack resources;
  • controls whose code-behind is limited to binding, dependency-property, routed-event, input and lifecycle mechanics;
  • the ModalWindow and ModelessWindow base types with their owner-handle contracts, and the tool window shells ToolWindowModalShell and ToolWindowModelessShell;
  • tool-specific behaviors, converters and controls under Tools/<TOOL>/;
  • the structural 3D viewport (see Structural Preview).

Production source is under src/DBTools.Presentation, with namespaces DBTools.Presentation.* that follow the folder tree. Compiled tool settings views live under Tools/<TOOL>/ in DBTools.Presentation.Tools.<TOOL>: the views of DialogSuppression, ElevationTags, FoundationTags and JoistGirderWeight. They bind to their tool contexts by property path, so Presentation does not depend on the tool assemblies. The project lists each Page and EmbeddedResource item; default Compile inclusion owns the code-behind. See Theme System for the two supported settings view forms.

Presentation does not reference DBTools.dll, Core, tool types, view models, commands, services or the Revit API. App, Core and the tools may reference Presentation.

ColorPickerPopup exposes and binds dependency properties by property path, and popup dismissal updates the stable IsPopupOpen property. ProgressOverlayControl binds to the command that the host supplies.

Tool windows

Tool views are raw embedded XAML. ToolWindowHost creates a modal or modeless shell, parses the view inside ToolWindowReflectionScope and sets the tool's view model. Core's ToolWindowFactory runs WindowInitializer on the shell first, which installs owner, theme, progress and error handling, and then registers the session. Hosts call session.ShowDialog() or session.Show() and get named controls with session.Require<T>(name). When a session closes or is retired, Presentation tears down bindings, automation roots, resources and callbacks. See Theme System.

UI Automation item lifetime

Retirement does not clear cached automation peers. In WPF 10.0.0, item peers hold reference-type rows weakly (ItemAutomationPeer._item uses ItemWeakReference, and DataGridCellItemAutomationPeer._item is weak), and teardown cuts the strong column, row-item and DataContext references. Tool items in a DataGrid, ListBox or TreeView, their types and a collectible tool context can therefore be released after retirement, also while a UI Automation client is attached.

Rows are held strongly, and a collectible tool assembly stays loaded, in these cases:

  • the first item cached by a peer store has an unreliable hash code (for example ComponentResourceKey); the store switches to list mode and holds every later key strongly;
  • the items are boxed value types;
  • the ItemAutomationPeerKeepsItsItemAlive switch makes _item strong;
  • a UI Automation client holds an item element, which keeps its control alive through ElementProxy._peer.

Enumerating ItemPeersStorage or _WeakRefElementProxyStorage materializes the weak keys, so their contents do not show an owning reference.

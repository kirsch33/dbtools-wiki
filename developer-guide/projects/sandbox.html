dbtools.Sandbox

NAME

dbtools.Sandbox - preview tool windows with design-time view models

SYNOPSIS

Source    src/dbtools.Sandbox/
Project   dbtools.Sandbox.csproj
Assembly  dbtools.Sandbox.dll
Entry     dbtools.Sandbox.App.Startup.SandboxEntry

DESCRIPTION

dbtools.Sandbox is a Windows process that runs WPF on an STA dispatcher. Application.Current is null. The dbtools UI Sandbox catalog groups previews by the manifest group and labels each button with the displayName. Select a button to open its preview.

See Sandbox Validator for candidate requirements, startup and headless validation.

STRUCTURE

Paths are relative to src/dbtools.Sandbox/.

Path Role
App/ Contains the entry point, option parser and dispatcher host.
Composition/ Creates the Sandbox runtime and window sessions.
Features/WindowCatalog/ Lists the windows and launches previews.
Runtime/ Configures logging, window ownership and window cleanup.
Validation/ Checks product metadata and windows.

CONTRACTS

  • The project references Core and Presentation with Private="false" and ExcludeAssets="runtime". Sandbox loads both from the selected year.
  • SandboxCatalog discovers sandboxWindows entries in the manifests embedded in App. Each entry names the raw XAML resource and its design-time view model. See Sandbox Integration for the registration rules.
  • SandboxWindowFactory constructs the view model with its parameterless constructor and uses Core's ToolWindowFactory to create a session and register it with ToolWindowRegistry. If the view model implements IToolWindowSandboxComposer, the factory calls ConfigureWindowOptions before it creates the session and ComposeView after creation.
  • WindowStaticRuntimeConfigurator registers the host HWND through WindowOwnerRegistry. Interactive mode uses the WPF catalog window and retires sessions before closing it. Headless mode uses a hidden Win32 window and destroys it when the window runtime is disposed. WindowInitializer applies the theme to each tool window.

FLOW

For a manual preview, use the staged Revit 2026 product on Windows with Revit 2026 installed. Run the commands from the checkout root.

dotnet build build/Build.proj -t:BuildSandbox -p:RevitYear=2026
.\.artifacts\bin\dbtools.Sandbox\release_2026_win-x64\dbtools.Sandbox.exe `
  --dist-dir .artifacts\dist\Release\2026

DATA

BuildSandbox writes to .artifacts/bin/dbtools.Sandbox/<configuration>_<year>_win-x64/.

Window captures

Select the render entry by its fully qualified name from the checkout root.

dotnet test testing/Daemon/Pure/Sandbox.Pure.Entry.csproj --filter 'FullyQualifiedName=dbtools.Sandbox.Tests.Features.WindowCatalog.WindowCatalogCaptureTests.Capture_windows'

Use the Windows Pure job ID from the test result to download its PNGs.

dbtools-daemon-cli report --job '<id>' --attachments --out ./sandbox-captures

The render entry opens the catalog windows and contributed cases on the daemon's hidden desktop. A duplicate capture name or a timeout while a banner or flyout opens fails the render request. Review the attached WPF client-area PNGs, named <Tool>--<state>.png.

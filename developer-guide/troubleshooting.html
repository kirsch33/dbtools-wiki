Troubleshooting

This page lists common build, runtime and tool errors, and how to read the DBTools logs. For a reported failure, read the logs in %APPDATA%\DBTools\Logs\ first.

Build

Choosing a build command

Build one project or test project with plain MSBuild:

dotnet build path/to/project.csproj -c Release

This computes content versions, restores only the selected year and stages the project's runtime inputs. It does not validate or publish a distribution. ./build.sh BuildAll builds, validates and publishes the complete distribution for every supported year, including the Dev Mode preflight and manifest checks. BuildAll compiles no tests; use ./build.sh BuildTests or a selected-test target. See Build Pipeline.

Python 3.10 or later is required

Python 3.10 or later is required. Install it with: sudo apt-get install python3

On Linux and WSL, build/DotNet/sdk.sh uses Python to verify and install the pinned SDK when the private SDK root is incomplete; test.sh also uses it for test discovery. Install Python and rerun the command:

sudo apt-get update && sudo apt-get install -y python3
bash build/DotNet/sdk.sh

On Windows, build.ps1 installs and verifies the SDK without Python.

DbToolsDaemon.Protocol package missing or mismatched

BuildAll requires the DbToolsDaemon.Protocol package version pinned in build/Distribution/protocol-package-lock.json, with the SHA-256 recorded there. The Validation Runner loads the package after the build tasks verify it. If the package is missing or its bytes differ from the lock, obtain the pinned package and update the lock. sourceKind is github-release for a published release, or local-candidate for an approved local candidate with its candidate-<version> tag, daemon commit, and copies of the bundle README and SHA256SUMS. Do not point the build at a daemon checkout or bypass the check.

BuildAll does not need the daemon CLI or an installed Revit. The DIST suite and hosted Revit tests use the daemon CLI.

Dev Mode preflight fails

ValidateDistributionCandidate runs the Dev Mode policy on each year and prints:

Revit <year> Dev Mode preflight: <n> failures, <m> warnings; outcome=<x>

Both years must pass. A CollectibleThreadStatic warning counts as a failure. A failed policy, boundary, graph, identity or candidate-byte check needs a source fix and a new build.

HandyControl output missing

A missing vendor import, resource or DBTools.HandyControl output means the vendor/HandyControl submodule is not initialized. build.sh and build.ps1 initialize it automatically, which requires a Git checkout and network access:

git submodule update --init --recursive vendor/HandyControl
./build.sh BuildAll

The output is .artifacts/vendor/<Configuration>/handycontrol/net10.0-windows/DBTools.HandyControl.dll.

Revit backup files in test models

Revit writes backup copies (*.0001.rvt, *.00001.rvt) when it saves a model. Under testing/RevitTestModels/ these files are ignored by Git. The build does not delete them; remove them by hand when you no longer need them.

Runtime

Tool assembly fails to load

InvalidOperationException: Failed to load tool assembly 'DBTools.GM' from the declared Tools path '<path>' in ALC rooted at 'DBTools'.

Related errors from ToolAssemblyResolver:

  • Tool assembly '<name>' was not found at the declared Tools path '<path>'.
  • Tool assembly path '<path>' declares simple name '<x>', expected '<name>'.
  • Tool assembly '<name>' is already loaded from '<path>', but the declared Tools path is '<path>'.

App loads each tool from Tools/<name>.dll beside DBTools.dll. Check that the year directory has the complete product tree (see Assembly Loading Contract) and that the manifest's assembly name matches the file. Rebuild with ./build.sh BuildAll.

"Assembly already loaded" during Dev Mode reload

Revit shows a popup about an assembly that is already loaded during or after BuildAll, while the dbtools-daemon Dev Mode driver watches the distribution. Causes:

  • The driver watches the multi-year root .artifacts/dist/Release instead of one year directory.
  • A reload starts while promotion replaces the files.
  • DBTools code loaded or resolved a DBTools.* assembly or type outside the driver's collectible AssemblyLoadContext (for example through an AppDomain-wide scan or Assembly.Load), so the context cannot unload.

Point the driver directly at one year directory, .artifacts/dist/Release/2026 or .artifacts/dist/Release/2027, never at a copy, and publish with ./build.sh BuildAll. Promotion keeps each unchanged file as the same file (a hard link), so Windows Defender does not scan it again. A copied directory is a set of new files that Defender scans again, which can add tens of seconds to each Dev Mode inspection.

The supported desktop years are Revit 2026.5 and later, and Revit 2027; the distribution and reference metadata use the year keys 2026 and 2027. A candidate for any other year is rejected; there is no fallback framework.

Theme validation

Startup validates the theme with ThemeValidator.ValidateOrThrow; a failure stops startup. In a Revit-hosted test run, read the daemon job's startup failure output instead of waiting for a dialog.

Theme dictionary merge failed

InvalidOperationException: Theme dictionary merge failed at '/DBTools.Presentation;V<PresentationVersion>;component/Resources/Brushes.xaml'.

A resource dictionary did not load: a missing assembly reference, a broken StaticResource chain or invalid XAML. Rebuild with ./build.sh BuildAll and check that the year directory contains DBTools.Presentation.dll and DBTools.HandyControl.dll from the same build.

Theme resource freeze failed

InvalidOperationException: Theme resource freeze failed for key '<key>' in '<source>'.

A Freezable resource (brush, geometry) cannot be frozen, usually because it has a binding or a dynamic reference. Make its values static.

Theme merged dictionary contract mismatch

InvalidOperationException: Theme merged dictionary contract mismatch: expected 9 dictionaries but found 8 in '<root>'.
InvalidOperationException: Theme merged dictionary contract mismatch at index <i>: expected '<uri>' but found '<uri>'.

Resources/Theme.xaml must merge these dictionaries in this order: HandyControl Themes/SkinDark.xaml, HandyControl Themes/Theme.xaml, then Tokens.xaml, Brushes.xaml, Converters.xaml, Controls.xaml, DataGrid.xaml, Menus.xaml and Components.xaml. See Theme System.

Revit API context errors

ContextUnavailableException: No UIApplication in current gate scope.
InvalidOperationException: ActiveUIDocument is null.

Code used the Revit API outside a valid API context, for example from a modeless window without the call gate, after the document closed, or during shutdown. Run Revit API work through IRevitCallGate.RunAsync, check that a document is open, and handle cancellation when a document closes.

WPF Dispatcher errors

InvalidOperationException: No WPF Dispatcher is available (Application.Current is null and no Revit window dispatcher could be resolved).
InvalidOperationException: WPF Dispatcher is shutting down.

UI work ran during early startup or late shutdown, when no dispatcher is available. Check for a dispatcher and for Dispatcher.HasShutdownStarted before UI work, and use BeginInvoke where the caller need not wait.

Unhandled UI exception from a window command

A WPF command that calls ISafeExecutor.RunAsync and lets the exception propagate into an AsyncRelayCommand raises a Dispatcher unhandled exception, which the Dev Mode driver host can also show. In window commands, use ISafeExecutor.RunWithoutThrowingAsync: it logs and notifies but does not rethrow. Use RunAsync where the caller must receive the exception.

XamlParseException on a read-only binding

System.Windows.Markup.XamlParseException: A TwoWay or OneWayToSource binding cannot work on the read-only property '<name>' ...

Run.Text binds TwoWay by default. Binding it to a get-only property fails when the window loads. Set Mode=OneWay, or bind a TextBlock.Text instead. Raw VTC XAML uses OneTime bindings for immutable record values.

Contextual ribbon layout changes

A contextual ribbon injector that modifies Revit's contextual tabs eagerly (for example the Multi-Select tab) or inserts at index 0 shifts the native buttons. Inject only when the selection contains matching elements, append panels and buttons with Add, and remove them when the selection no longer matches. Core's ContextualRibbonInjector follows these rules.

Transfer Drafting Views (TDV)

TransferException carries a TransferErrorCode:

Code Meaning Action
DestinationTypeMissing The destination has no matching drafting view type Create the view type in the destination
SourceTypeNameUnavailable The source view type name cannot be read Check that the source is a valid drafting view
CreateViewFailed The destination view could not be created Check write access and view limits
CopyElementsFailed The view elements could not be copied Check the elements and the target view
OverridesFailed The view overrides could not be copied Some overrides cannot be transferred

View Template Comparer (VTC): raw XAML resource not found

System.IO.FileNotFoundException: Embedded tool XAML resource 'DBTools.ToolViews.VTC.AlertBodyTemplates.xaml' was not found.

The VTC alert body templates are an EmbeddedResource with the logical name DBTools.ToolViews.VTC.AlertBodyTemplates.xaml, read with ToolWindowXaml.ReadEmbeddedResource. Check the item and its LogicalName in DBTools.VTC.csproj. The shared VTC dictionaries are in src/DBTools.Presentation/Tools/VTC.

Logs

Log files

Logs are written to %APPDATA%\DBTools\Logs\. File names use Eastern time:

dbtools-<RevitYear>-<InstanceId>-<Timestamp>-<Nonce>.log
dbtools-<RevitYear>-<InstanceId>-<Timestamp>-<Nonce>-manual-<ManualTimestamp>.log

The second form is written after Start New Log File in the logger window. Example: dbtools-2026-ABC123-20260124-143022345-a1b2c3d4.log.

Startup cleans up old files: at most 50 files across all instances, at most 14 days old, and at most 100 MB in total while more than one file remains (the newest file is kept even if it alone is larger).

Failures that occur before logging starts are written to %APPDATA%\DBTools\Logs\DBTools.Fallback.log.

Debug mode

Debug mode lowers the minimum log level from Information to Debug, shows the logger window and flushes the log buffer every 120 ms instead of 600 ms. It is off at every startup and is not saved. It turns on when:

  • you enable it in the Settings window or open the logger window;
  • an Error-level entry is logged and the logger window can be shown. An error logged before the Revit main window exists opens the window once deferred startup can show it.

Closing the logger window turns debug mode off.

Logger window

The title is DB Tools Log - Revit <Year> [<InstanceId>]. The window is a modeless utility window. The logger host applies pin mode changes centrally: a change that keeps the owner mode only updates Topmost, and a change of owner mode closes and recreates the window. Code must not change the owner of the live window directly. The window provides:

  • level filters for INFO, WARN, ERROR and DEBUG, and a text search;
  • Copy All and Export, which save every retained entry in arrival order regardless of the filters. Export writes DBToolsLog_<yyyyMMdd_hhmmss><AM|PM>.txt;
  • auto-scroll, which follows new entries. Scrolling up pauses it until you scroll back to the bottom or until a new entry arrives after 15 s idle; turning it off keeps it off;
  • Start New Log File (in the danger menu), which starts a new file, clears the window and logs a confirmation with the same instance ID. If closing the previous file fails, the new file stays active and a warning is logged.

Correlation IDs and execution phases

ISafeExecutor gives every operation a GUID correlation ID and logs its phases:

[Start] GM Apply starting (CorrelationId=...)
[Complete] GM Apply completed in 1234ms (CorrelationId=...)
Phase Level Meaning
[Start] Information The operation started
[Complete] Information The operation finished
[Cancel] Warning The operation was cancelled
[Error] Error The operation failed

Search for the correlation ID to find every entry of one operation and its duration.

Reporting a problem

Include:

  1. the log file from %APPDATA%\DBTools\Logs\, or a logger window export;
  2. the Revit version (year and build number);
  3. the DBTools version;
  4. the correlation ID of the failed operation;
  5. the steps to reproduce;
  6. a screenshot of any error dialog.

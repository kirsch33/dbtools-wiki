ERFT technical specification

Overview

The Extreme Roof Framing Tool (ERFT) calculates vertical offset changes for structural columns and beams against a triangulated floor or roof bottom surface. It modifies offset parameters, not level parameters. All lengths and coordinates in domain calculations use feet. Source: src/Tools/Experimental/ERFT/. See ERFT for composition, presentation ownership, and use.

Architecture

Selection and Planning prepare AdjustmentPlan; Execution writes offsets and Persistence stores the system. ERFT architecture lists owners and the preview host.

Data and contracts

Plan and identity

Features/Domain/Adjustment/AdjustmentPlan contains:

State Contents
Target HostTargetId, LinkedTargetId, LinkInstanceId, TargetGeometry, TargetDisplayName
Sources Lists of ColumnAdjustment and BeamAdjustment
Hierarchy FramingGraph
Rounding ToleranceFeet, default 1/48 ft. RoundingMode, default Nearest
Profiles ProfilesByTypeId and ProfileExtractionFailuresByTypeId
Storage SystemId, initialized from a GUID

Revit element, type, level, link, and graph identities use long. Target IDs and connection IDs are nullable where absent. Mesh indices and counts use int. JSON numeric IDs in the 32-bit range deserialize as long.

ColumnAdjustment retains element/type identity, type name, base/top points, original top offset, and top-level identity/name. Calculation supplies target elevation, raw delta, rounded delta, new offset, status, and optional error text.

BeamAdjustment retains element/type identity, type name, endpoints, original endpoint offsets, and reference-level identity/name. Each endpoint has a Free, ToColumn, or ToBeam connection and optional owner ID. Calculation supplies endpoint target elevations, deltas, rounded deltas, new offsets, status, and optional error text. Hybrid means one ToColumn end and one ToBeam end.

Statuses are Pending, NoChangeNeeded, and Error. RequiresModification requires Pending and a rounded delta magnitude greater than 1e-9 at an affected end. Plan pending counts include only rows requiring modification. A Pending row without a required write contributes to no-change counts.

Target geometry

Features/Operations/TargetGeometry/Revit/TargetGeometryReader resolves host or linked targets. A linked target uses RevitLinkInstance.GetTotalTransform and requires a loaded link document. Geometry extraction uses Medium detail and ComputeReferences = false. It traverses solids, triangulates faces, and retains separate bottom-surface and full-element meshes. A bottom face has host-transformed normal Z at most -0.1, sampled at the midpoint of its UV bounds. No usable bottom surface returns no target geometry. Unexpected geometry faults log context and propagate.

TargetSurface contains Vertices, TriangleIndices, Bounds, display/category names, ElementVertices, ElementTriangleIndices, and optional LinkTransformMatrix. Coordinates used by calculation are in the host frame. The link matrix contains 16 doubles in column-major order:

[basisX.X, basisX.Y, basisX.Z, 0,
 basisY.X, basisY.Y, basisY.Z, 0,
 basisZ.X, basisZ.Y, basisZ.Z, 0,
 origin.X, origin.Y, origin.Z, 1]

TransformLinkPointToHost requires exactly 16 values and applies the upper 3×3 basis plus translation.

Features/Domain/TargetSurfaceProjector.ProjectToSurface visits every triangle, finds its nearest vertex, edge, or interior point, and retains the nearest point by squared 3D distance. GetTargetElevation returns that point's Z. An empty mesh returns no projection. See Limitations for projection behavior outside a triangle and mesh traversal cost.

Framing graph

FramingGraphBuilder.ResolveConnectionsAndBuildGraph resolves connections and emits ColumnToBeams, BeamToBeams, and ProcessingOrder. Connection tolerance is 0.5/12 feet (half an inch).

  1. Connect free beam ends to column top points within the tolerance, inclusive.
  2. For remaining free ends, find the closest other beam segment at a strictly smaller distance than the tolerance.
  3. Reject an edge that would form a dependency cycle, log a warning, and leave that end Free.
  4. Emit columns first, then topologically sort beam dependencies.

Column connections use the first qualifying column in input order. Beam candidates use 3D distance to a segment with the projection parameter clamped to [0,1]. A nearly degenerate segment uses its start point. Each endpoint is independent, so hybrid connections are supported.

Ready beams that frame to columns precede other ready beams. Element ID breaks ties. If unresolved dependencies remain, the builder logs and appends remaining beam IDs in sorted order.

Adjustment and rounding

Features/Planning/Adjustment/AdjustmentEvaluator.CalculateAdjustments follows ProcessingOrder. It keeps adjusted column-top and beam-end elevations in dictionaries without mutating Revit.

For a column:

targetZ = nearest surface point Z
delta = targetZ - originalTopZ
roundedDelta = round(delta, tolerance, mode)
newTopOffset = originalTopOffset + roundedDelta
adjustedTopZ = originalTopZ + roundedDelta

For each beam end:

Connection Target elevation
ToColumn The connected column's adjusted top Z
ToBeam Interpolated Z on the supporting beam's adjusted segment
Free Nearest target-surface point Z

Missing dependency elevations produce Error. For beam interpolation, only XY determines the segment parameter:

dx = supportEnd.X - supportStart.X
dy = supportEnd.Y - supportStart.Y
t = clamp(((query.X - supportStart.X)*dx + (query.Y - supportStart.Y)*dy) / (dx*dx + dy*dy), 0, 1)
Z = adjustedStartZ + (adjustedEndZ - adjustedStartZ)*t

When XY length squared is less than 1e-10, use adjustedStartZ. The query's Z does not influence interpolation. Each new endpoint offset is its original offset plus rounded target-minus-original-Z delta.

RoundingEvaluator.ApplyRounding uses:

Mode Rounded delta
Nearest Math.Round(delta / tolerance) * tolerance, including .NET's midpoint-to-even rule
Up Math.Ceiling(delta / tolerance) * tolerance
Down Math.Floor(delta / tolerance) * tolerance

Up and Down refer to signed numeric direction, including negative deltas. At helper level, nonpositive tolerance or an undefined mode returns the raw delta. UI and stored-data admission reject invalid settings before normal use. IsWithinTolerance tests abs(delta) < tolerance/2. Columns with a rounded delta within that interval become NoChangeNeeded. Beams become NoChangeNeeded when both rounded deltas satisfy it. Missing target geometry marks every row Error.

Profiles and preview

MemberProfileExtractor creates temporary placements for unique source types and extracts section loops. It owns each temporary instance immediately after creation, before commit and geometry bake. Creation, bake, and cleanup transaction starts/commits must return Started/Committed. Any subsequent creation, commit, disposal, bake, or extraction fault reaches cleanup. Concurrent extraction and cleanup failures preserve both causes. Expected ProfileLoops/* conditions return structured per-type failures. Unexpected faults and cancellation propagate. One Info summary reports total, extracted, and unsupported counts. Per-type progress uses Debug.

PreviewSceneBuilder.Build renders adjusted endpoints using extracted profiles. Missing profiles omit affected members and log counts. No successful profile still permits target-only preview. Target selection prefers bottom-surface TargetSurface. Full TargetElement is a fallback only when that mesh is unavailable. No usable mesh throws Preview/TargetMeshMissing.

Mesh Color Opacity
Target #4080C0 0.12
Pending member #00CC00 1.0
No-change member #808080 0.7
Error member #CC0000 1.0

PreviewProjector maps meshes, colors, tooltips, IDs, and bounds into immutable StructuralScene3D snapshots. It clamps opacity to [0,1] and uses a fixed Vector3.UnitZ exterior normal. A null mesh, empty vertices, incomplete triangle indices, out-of-range indices, or non-finite vertices throws InvalidOperationException. Missing or invalid RGB/ARGB hexadecimal color text throws FormatException. RGB input receives an opaque FF alpha prefix. A leading # is optional. The projector does not replace invalid mesh or color input with default data. The Presentation presenter owns camera/navigation, device lifetime, hit testing, and cleanup. ERFT selects PreserveAngle and FitRedefinesHome. See preview interaction.

Storage formats

Features/Persistence/StorageSchema/Revit/StorageSchema defines public-read/public-write String fields:

Schema GUID Fields
DBTools_ERFT_V2 C736C6F5-34C8-4E50-A890-E5420C3E5391 Tag, SystemId, MemberRole, OriginalOffset, Timestamp
DBTools_ERFT_System_V2 06C087B9-DA5B-4E3B-9496-13C7C8732B0E SystemIdString, DataJson

Vendor is DBTools. Element Tag is ERFT, MemberRole is Column or Beam, and Timestamp is UTC round-trip text. OriginalOffset contains an invariant number for columns or start;end invariant numbers for beams. Lookup validates schema name and required simple String fields before use.

Apply removes legacy element entities at B2C3D4E5-F6A7-4B8C-9D0E-1F2A3B4C5D6E and legacy system entities at C3D4E5F6-A7B8-4C9D-0E1F-2A3B4C5D6E7F only when vendor/name identify DBTools_ERFT or DBTools_ERFT_System respectively. It deletes an emptied DataStorage carrier and logs removals. Foreign registrations under those GUIDs remain untouched and log a warning. This cleanup shares the apply transaction.

SystemPlanRepository.Save(Document, StoredPlan) and Load(Document, systemId) return structured failures for expected missing/duplicate/incompatible storage states. Duplicate records for a system fail explicitly. Unexpected Revit repository faults log the system ID and propagate.

StoredPlan serializes target IDs/name, ToleranceFeet, RoundingMode, Columns, Beams, SystemId, and Timestamp. Stored columns retain ElementId, OriginalTopOffsetFeet, NewTopOffsetFeet, and AppliedDeltaFeet. Stored beams retain ElementId, original/new endpoint offsets, and applied endpoint deltas. CreateSnapshot includes rows with Pending status before the writer changes statuses after commit. It does not store geometry or profiles.

StoredPlanMapper.Deserialize requires serialized tolerance, mode, both collections, and SystemId. Both collections and every member must be non-null. Element IDs must be positive. SystemId must be nonblank and match the DataStorage key ignoring case. A positive host target or a positive link-instance/linked-target pair is required. Tolerance must be positive and rounding mode defined. No schema-version migration participates in admission. Null display name or timestamp normalizes to empty text.

Workflows

Selection and preparation

Features/Selection/Revit/TargetSelectionPicker first picks a linked Floor or RoofBase. Esc switches to host selection through Selection/HostTarget/Revit/HostTargetSelectionFilter. Esc during host selection cancels launch. Each picker owns a yellow guidance banner and disposes its handle in finally.

SourceSelectionFilter admits host FamilyInstance elements with:

Category Requirement
Structural Columns LocationPoint
Structural Framing LocationCurve containing a Line, and StructuralType other than Brace

SourceSelectionPicker excludes structural materials matching \bconcrete\b, case-insensitively, and reports the filtered count. It reads the instance material, then the type material when absent. Missing or blank material names do not match. Unexpected inspection failures retain element context and propagate.

SourceSelectionCollector compares selected and extracted counts. Any extraction mismatch fails with Selection/SourceExtractionFailed. SourceSelectionValidator requires a selected column or a selected beam connected to a column. Beam-only validation extracts model columns and evaluates cloned beam values, so validation does not alter the live plan's connections. No connection produces Selection/NoColumnConnection.

Features/Planning/PlanPreparation/Revit/PlanPreparationBuilder prepares the target, source values, framing graph, profiles, and initial adjustments before opening the window.

Tolerance and window behavior

Presets are 1/16, 1/8, 1/4, 1/2, and 1 inch, plus Custom. The default is 1/4 inch. Custom text parses with invariant culture and must be finite and at least 0.01 inch. Invalid input appears inline and disables Apply. ErftWindowViewModel.CanApply also requires a positive pending count and zero errors.

The modal window contains the target/re-pick control, rounding controls, 3D preview, column/beam comparison grids, summary, Cancel, and Apply. Both grids end with a stretch Status column and a minimum width. Re-pick calls HideForPick, performs selection, recomputes the plan, and shows the same shell and preview presenter. An expected apply failure leaves the dialog available with error feedback. Successful apply reports modified and unchanged element counts, then closes the window. WindowSession.Interaction ignores duplicate Apply and Re-pick requests while IsApplyInProgress is true. The view model's close gate blocks Cancel and ordinary close during that interval. An apply exception triggers a gated-close bypass and propagates when the interaction result is collected. A concurrent close failure is retained with the apply exception.

Escape clears both grid selections and marks the key event handled, so it never closes the window. The Cancel button has no IsCancel route. A mouse-down outside a grid row clears both selections regardless of button.

Alerts

WindowSession uses the active ERFT window as the owner for apply alerts. If that session is absent or retired, it uses the injected owner-handle provider. Selection diagnostics always use the injected provider.

Apply transaction

AdjustmentPlanExecutor rejects row errors with Apply/PlanHasErrors. With no pending writes it returns all elements unchanged without invoking the writer. AdjustmentWriter selects RequiresModification rows, sorts columns by ID, and applies beams in graph order followed by any omitted beams in ID order.

One ERFT Apply Adjustments transaction performs:

  1. Purge recognized legacy ERFT entities.
  2. Obtain and validate the element schema.
  3. Set column FAMILY_TOP_LEVEL_OFFSET_PARAM.
  4. Set beam STRUCTURAL_BEAM_END0_ELEVATION and STRUCTURAL_BEAM_END1_ELEVATION.
  5. Tag changed elements and save the system snapshot in DataStorage.

Missing elements/parameters, read-only or wrong-storage parameters, and a false Set result fail apply. Offset, tag, and storage writes must all succeed or the transaction rolls back. After commit, changed rows become NoChangeNeeded. Cancellation propagates. Expected FramingAdjustmentFailureException becomes a structured result. Other exceptions retain their chain and reach the safe-execution boundary.

Contextual edit

App/Composition/ErftContextualRibbonInjector adapts Core's contextual ribbon runtime. It targets Modify tabs for Structural Columns, Structural Framing, Multi-Select, Multi, or Multi-Category. Eligible selected elements have a supported category, compatible V2 entity, Tag ERFT, and a SystemId. Selection evaluation logs only when (hasErftElements, systemCount, buttonCount) changes. Missing-schema logging occurs once until a schema becomes available again. Selection-hook safe execution suppresses start/completion noise and banners.

Edit clicks require a system ID, an initialized ExternalEvent, and an Accepted raise result. The event executes through ISafeExecutor with ErrorOnly notification and an owned InlineUi App run scope. Multiple systems use the system selector. The repository loads the chosen system. A failed repository load logs its code/context and shows this banner before returning:

Cannot edit the selected ERFT system because stored plan data is missing or invalid. {Error.Tag}

The banner retains the repository failure tag. Edit does not enter new-flow selection. The scope resolves FramingAdjustmentWorkflow and clears its current RevitRunScope before disposal.

EditReconstructionBuilder resolves stored source IDs and reads current geometry/offsets. Partially missing sources produce diagnostics and permit remaining sources. No resolvable sources prevents reconstruction. EditReconstructionValidator rejects nonpositive tolerance and undefined modes with Edit/InvalidStoredTolerance or Edit/InvalidStoredRoundingMode. Reconstruction retains SystemId and stored rounding settings, then recomputes adjustments against the target. Re-apply uses current offsets, rather than adding a stored applied delta again.

Failures

FramingAdjustmentFailure carries expected codes, messages, and context, formatted with [SpecFail/*] tags. These results represent expected contract failures, not every runtime exception. Unexpected selection, material inspection, extraction, cleanup, reconstruction, repository, and apply failures propagate with context. Cancellation is not converted to failed data.

Testing

See ERFT testing for the single fixture inventory, model requirements, and commands.

Limitations

Target elevation uses the nearest point in 3D, including triangle edges and vertices; it does not use a vertical intersection. Projection visits every triangle. Legacy storage is removed in the apply transaction without migration.

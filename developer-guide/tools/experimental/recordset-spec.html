Record Set technical specification

Overview

Record Set builds a package from selected RVT host files and their file-based external references. It copies files, optionally processes DWG Xrefs, and rewrites references in copied RVT files through TransmissionData. The source is src/Tools/Experimental/RecordSet/. Record Set describes application composition and window interactions.

Architecture

Domain values describe files and plans. Planning constructs ordered work; Execution dispatches filesystem, CAD, and Revit operations. Record Set architecture lists composition and presentation owners.

The UI initially shows unchecked flags, publishes their effective values after preview, and preserves explicit user choices for the window lifetime. These options are not persisted.

Destination rules

PlanningService.BuildContext counts normalized source-path/type occurrences. Keys appearing at least twice become common links. Identity uses the complete normalized path and type, not just a filename. The count includes repeated references within one host.

TargetPathRules computes intended paths:

File Destination
Host with building {target}/{building}/{discipline}/{name}
Host without building {target}/{discipline}/{name}
Noncommon link with building {target}/{building}/{discipline}/Linked Files/{name}
Noncommon link without building {target}/{discipline}/Linked Files/{name}
Common link {target}/Common Linked Files/{name}

Blank or - building omits that segment. Empty discipline adds no directory segment. The destination allocator compares normalized paths. Reusing the same source/destination needs no extra copy. A different source colliding with a destination receives name (2).ext, then (3), and so on, with a warning. Allocation fails when the counter exceeds 10,000. Mappings and preview projections use the allocated destination.

Safety policy

PolicyReader loads the embedded resource DBTools.ToolConfigs.RecordSet.recordset_policy.json from Policies/recordset_policy.json. It does not load a user-side policy file.

JSON member Shipped value or rule
allowed_target_roots Nonempty required list. Shipped root is \\fileserver\Projects
verify_after_copy Required Boolean, shipped false
min_free_bytes Required nonnegative number, shipped 10,737,418,240
denied_extensions .dwl, .dwl2, .tmp, .bak, .lnk, .exe
allowed_extensions Optional
deny_globs Required list, shipped *backup*.rvt, *.old, ~$*
paths.enable_long_paths Required Boolean in required paths object, shipped false
delete_mode Defaults to quarantine. No plan action consumes it
require_sentinel_for_delete Defaults true. No delete action consumes it

Configured string entries must be nonblank. Roots must be absolute Windows drive-letter paths or complete UNC server/share paths. Relative, drive-relative, root-relative, and incomplete UNC roots fail admission. Malformed or incompatible policy throws. It is not normalized into valid data.

Preview checks the target against admitted roots. Execution reloads policy and checks it again. The containment predicate admits equality with the root and descendants. Before acquiring the lock, execution checks every output-bearing plan path: directories, copy destinations, CAD repath hosts/roots, bind hosts, Revit hosts, and mapping destinations. Copy sources, mapping keys, Revit source hosts, and Bind All source paths remain source paths.

Execution requires free space minus max(TotalBytes, PredictedOutputBytes) to meet MinFreeBytes. Safe filesystem operations resolve existing file and directory redirects before checking containment. Recursive copies carry destination checks into every nested operation. Lock, sentinel, and manifest mutations repeat containment checks.

Copies overwrite existing destination files and preserve the source file's UTC creation, last-access, and last-write timestamps. Optional verification compares SHA-256 hashes, including every allowed file in a copied directory. It verifies copied bytes before later CAD/Revit mutations.

Workflows

Host import and reference reading

FileSelectionWorkflow owns OS pickers. HostImporter normalizes picks, rejects existing or repeated hosts, and calls PlanningService.ScanHost with empty discipline and building -. A RevitOperationException or scan warning rejects that host and returns an ordered issue. Owner-token cancellation propagates. The application displays issues and adds only accepted hosts.

RevitOperations implements IExternalReferenceReader and ITransmissionWriter. It strips long-path prefixes before passing paths to Revit. Missing TransmissionData or external-reference collections fail with operation and host context.

Reference reading uses desired data when IsTransmitted is true and last-saved data otherwise. Library references (PathType.Content, including library-located keynote or assembly-code tables) are omitted. Absolute references retain their stored path. Relative references resolve against the source host folder. For a workshared local, the base is the file-system central folder from BasicFileInfo.CentralPath. Without a usable file-system central path, resolution uses the reference's saved absolute path. A moved package with intact relative structure therefore resolves its own files.

The scan creates discovered links using their resolved paths and host metadata. It classifies RVT, DWG, and Other external references. It does not recursively scan linked RVT models.

Plan construction and limits

Features/Planning/Preview/PreviewPlanBuilder.BuildPlanAsync runs these stages in order on one PreviewPlanState:

  1. PreviewPlanState.Create finds Core Console and resolves nullable CAD flags.
  2. PreviewHostPlanner.PlanHostsAndLinks plans hosts and non-CAD links under the file policy.
  3. PreviewCadPlanner.PlanAsync plans each distinct DWG destination once, using its first occurrence's CAD options.
  4. PreviewHostPlanner.PlanRevitRepaths appends Revit repath operations for copied hosts with allowed mappings.
  5. PreviewPlanTotals.CountCopyBytes checks sources and counts copy bytes.
  6. PreviewCadPlanner.PredictOutputBytesAsync estimates bound output.
  7. PreviewPlanTotals.Complete enforces limits and records the summary and the fingerprint.

PreviewDestinationAllocator keeps each destination path for one source path. When another source holds the intended destination, the source gets name (n).ext, or name (n) without an extension, with the lowest n from 2 that is free or that the source already holds. A new rename adds a Warning message and a UIWarnItem.

Denied hosts or links produce warnings. Missing planned source paths produce Block messages. Directory copies count only policy-allowed files. TotalBytes counts each distinct source/destination copy pair, including repeated copies of one source to different destinations. PlanSummary.UniqueLinks is the number of distinct copy-source paths, including host paths. Hosts is the selected-host count. Items includes directory and message items.

Limit Value Result when exceeded
PlanningLimits.MaxTotalBytes 80 × 1024³ bytes Block
PlanningLimits.MaxTotalItems 10,000 Block

PredictedOutputBytes starts at TotalBytes. For Bind All, the estimate adds allowed discovered Xref sizes beyond the copied host DWG size. Estimate failure produces a warning and retains the existing estimate. These are preview limits, not guarantees of final package size.

Plan items and progress

Plan items are typed records. PlanAction supplies their dispatch identity.

Record Data Fingerprint action Fingerprint keys Weight
FsCreateDirItem Path fs_create_dir path 1
FsCopyItem Source, Destination fs_copy src, dst 3
CadCopyItem Source, Destination cad_copy src, dst 3
CadRepathItem Host, Xrefs (CadXrefRepath Name, StoredPath, NewPath) cad_repath host, xref:{name} as {stored}>{new} per Xref 2
CadBindAllItem Host, BindType, Xrefs (CadXrefRepath) cad_bind_all host, bindtype as invariant numeric enum text, xref:{name} as {stored}>{new} per Xref 4
RevitRepathItem Host, SourceHost, Mapping revit_repath host, source_host, map:{source} per mapping 2
UIWarnItem Message ui_warn msg 0
UIInfoItem Message ui_info msg 0

Progress increases after an item completes, using its weight divided by the total weight, with a minimum denominator of 1. It is an operation estimate, not byte progress.

Each item emits an action string and ordinally sorted key=value fields separated by |. Revit mappings use map:{source} keys. Fingerprinting hashes successive UTF-8 item segments with SHA-256, without an extra separator between segments, and keeps the first 16 lowercase hexadecimal characters. It records plan identity for the audit output. Execution does not use it as a content checksum.

CAD planning

For AddXrefs, the planner copies the DWG and allowed manual Xrefs beside it. With discovery enabled and Core Console available, CadXrefDiscovery lists the Xrefs of the DWG, then of every found Xref DWG, breadth first. Each DWG gets one ICadPreviewer.ListXrefsAsync run per preview, also when several linked DWGs or the Bind All estimate reach it, and a cycle ends at a DWG already listed. Paths compare without case.

A block table also lists the Xrefs nested in its attached Xrefs. CadXrefDiscovery keeps an entry for a DWG when the DWG inserts it in model space, a layout (Inserted) or one of its own block definitions (InsertedInBlock), or when no such referenced, attached, found Xref of the DWG lists an entry with the same name. Other entries belong to the Xref that lists them.

PreviewCadPlanner then walks the result from the linked DWG:

  1. A not-found Xref adds the Warning Xref {name} in {dwg} not found: {stored path}.
  2. A policy-denied Xref adds Policy denied CAD Xref: {file}.
  3. Every other Xref file is copied once, as CadCopyItem, into the folder of the linked DWG copy, with collision suffixes when necessary, and appears in the preview tree as a discovered DWG.
  4. Each Xref adds the Info Xref {name} in {dwg} ({stored path}): copy to {target-relative copy}, repath to {new path}., or ..., path unchanged. when repath is disabled.
  5. With repath enabled, each copied DWG with at least one copied Xref gets one CadRepathItem. Its entries map the stored path, exactly as discovery reported it, to the copy relative to the folder of the DWG copy, with a .\ prefix for the same folder.

A copied Xref DWG whose destination is also the destination of a linked DWG is not walked further; the linked DWG's own planning owns its CAD mode. Other Xref DWG copies join PlannedCadDestinations. Preview tree CAD actions apply only to linked DWGs and their manual Xrefs.

Discovery failure adds a Warning message, uses heuristic copying and plans no repath. Disabled discovery or unavailable Core Console also uses heuristic copying: copy existing sibling directories named xrefs, xref, refs, ref, external, dwg, or cad. Each source/destination directory pair is copied once. Heuristic copying does not rewrite Xrefs. The planner emits Info messages Auto-discover CAD Xrefs disabled. when discovery is disabled with Core Console present, or AutoCAD Core Console not found. DWG Xrefs copied by heuristic only. when Core Console is absent. Explicitly enabling both discovery and repath without Core Console produces Block.

BindAll requires Core Console. Without it, preview produces Block and schedules no bind operation. With it, the plan copies the DWG and runs discovery for it, also when AutoDiscoverCadXrefs and AllowCadRepath are false. rs-bind-all-xrefs binds every Xref of the copy, so the plan approves the bind only when discovery lists the complete graph and the file policy admits the found file of every direct and nested Xref, also when the stored path already equals the found path. An empty graph and a graph with cycles can be approved. Each refusal adds a Block that names the linked DWG path:

  • Bind All blocked for {dwg}: CAD Xref discovery failed: {error} for a failed listing of any reached DWG;
  • Bind All blocked for {dwg}: Xref {name} in {drawing} not found: {stored path} for a null or blank found path;
  • Bind All blocked for {dwg}: Policy denied Xref {name} in {drawing} ({stored path}): {found path}.

{drawing} is the full path of the DWG that owns the Xref. A refused DWG gets no bind work and no size estimate, and its Block prevents execution. Approved bind work has no manual or discovered Xref copy work.

The source drawings can change after the preview, so ExecutionPlanExecutor checks the graph again before each BindAllAsync call. A new CadXrefDiscovery lists the copy and every DWG that its Xrefs reach. The bind work's source paths first apply to the Xrefs of the copy, with the name and stored-path match of rs-apply-paths. The file policy of the run must admit every Xref, with the preview rules. Otherwise the item throws InvalidOperationException before the bind, with Bind All blocked for {copy}: {reasons}, reasons joined by ; , or Bind All blocked for {copy}: CAD Xref discovery failed: {error}. The run then fails and the copy stays unbound. The check and the bind are separate Core Console runs, so a source change between them can race the check. It lists each Xref that the DWG itself owns and that stores a path other than its found full path, mapped to the found source path: a relative path does not resolve from the copy, and nested Xrefs then resolve from the source folder of their parent. The bound-output estimate reuses the discovery listings of approved bind work. An estimate failure adds the Warning Bind selected for {dwg}, but size estimate unavailable: {error}. Selecting BindAll clears manual children. Bind and Insert select AutoCAD BINDTYPE 0 and 1 respectively. Bind preserves Xref-prefixed names. Insert merges names and can produce naming conflicts.

Core Console boundary

CoreConsoleRuntime.FindCoreConsole searches:

  1. An existing path from ACCORECONSOLE.
  2. accoreconsole.exe in PATH order.
  3. AutoCAD 2026, 2025, and 2024 under C:\Program Files\Autodesk.
  4. DWG TrueView 2025 under the same directory.

Each run extracts the embedded DBTools.ToolCad.RecordSet.rs_xrefs.lsp to a unique temporary .lsp file and attempts deletion in finally. Deletion failures log a Warning. CoreConsoleRunner writes its other temporary files under one stem in the temporary folder: {stem}.scr, {stem}.input.txt and {stem}.result.json. The .scr file loads the script and calls one function:

accoreconsole.exe /i "<input.dwg>" /s "<stem>.scr"
(load "<script.lsp>") (princ) (<function> "<stem>.result.json" ["<stem>.input.txt"] [<arguments>]) (princ)

Arguments use forward slashes and cannot contain a double quote; input lines cannot contain a line break. The input and result files are UTF-8 without a byte order mark. The runner starts both redirected reads immediately, returns standard output, standard error, the exit code and the result text, and deletes the temporary files. Cancellation terminates the owned process tree, observes terminal stream completion and deletes the files.

CoreConsoleRuntime.RunScriptAsync accepts a run only when the exit code is 0 and the result file holds a JSON object with "ok": true and the members the caller reads. A missing, empty, malformed or failed result throws InvalidOperationException with the function, DWG, reason, exit code, result text, standard error and standard output. Standard output and standard error are diagnostics only: their encoding is not fixed, and NUL characters are removed and each is cut to its last 2,000 characters in the message.

Function Input Result file
rs-list-xrefs none xrefs: name, path (stored), found (full path or empty), overlay, inserted, inblock
rs-repath-xrefs Three lines per Xref: name, stored path, new path changed, unmatched, failed (name and stored path after the change)
rs-bind-all-xrefs The same lines, with source paths; argument BIND or INSERT changed, unmatched, failed, bound, unbound

The script uses core AutoLISP and AutoCAD commands only, because Core Console has no ActiveX layer. It writes the result with (open result "w" "utf8"), which needs the Unicode AutoLISP engine (LISPSYS 1 or 2).

  • rs-list-xrefs reads the block table with tblnext. Group 70 flag 4 marks an Xref and flag 8 an overlay; group 1 is the stored path. found is findfile of the stored path (relative paths from DWGPREFIX), then of the file name in DWGPREFIX. inserted is true when ssget "X" finds an INSERT of the block name, with wild-card characters escaped. inblock is true when a block definition of the drawing has an INSERT of it; the script walks each block definition with entnext from its -2 group and skips Xref blocks, blocks from an Xref (group 70 flags 4 and 16) and the layout blocks.
  • rs-repath-xrefs reads the input with read-line. For each entry whose block is an Xref with the given stored path, it runs -XREF Path with the escaped name and the new path, cancels a command that is still active, and reads the stored path back. A changed path must equal the new path, without case. Only when every entry changed does it run QSAVE and check that DBMOD is 0; then ok is true.
  • rs-bind-all-xrefs first changes the listed paths as rs-repath-xrefs does. Only when every entry changed does it set BINDTYPE and run -XREF Bind *. It then lists the Xrefs that remain, and only when none remain does it run QSAVE and check DBMOD.

CadPreviewer requires every listed Xref to have a nonblank name and an empty or fully qualified found path, which it normalizes. CadExecutor.RepathXrefsAsync and BindAllAsync also require changed to name every listed Xref, and BindAllAsync requires an empty unbound. Execution rechecks Core Console availability for each CAD repath or bind item. If it is missing, the executor logs the affected DWG path and throws InvalidOperationException rather than using heuristic copying. Before the lock, execution checks that each repath host and each Xref copy that a new path names are under the target.

Revit repath

RevitRepathItem.SourceHost preserves the source reference base while Host names the copied RVT. Mapping keys are normalized source paths and values are allocated output paths. The writer reads effective references, skips Content references, and matches against the source base. It sets desired paths while preserving effective loaded/unloaded state.

TransmissionWriteResult.UpdatedCount is zero for no matching changes. The writer leaves the copied RVT untouched in that case. A positive count causes TransmissionData to be written with IsTransmitted = true. A rewritten workshared copy opens detached and cannot create new locals while transmitted. Reference failures preserve operation, host, reference ID, old/new path context, and original causes through RevitOperationException. Owner cancellation remains cancellation.

Execution, cancellation, and audit files

ExecutionPlanExecutor.ExecuteAsync validates preconditions, creates runtime metadata, acquires the lock, writes the sentinel, executes items in order, and writes an outcome manifest. It always attempts lock release after successful acquisition. The UI passes CancellationToken.None and shows a non-cancelable overlay. Lower owners honor supplied cancellation at work boundaries. Execution is not dispatched to a worker thread.

Outcome Result
Successful execution ExecutionStatus.Ok, ok manifest
Owner cancellation before lock acquisition Cancelled, empty run ID and manifest path
Owner cancellation after acquisition Cancelled, cancelled manifest, lock release
Unexpected fault or foreign cancellation Attempt failed manifest, release lock, propagate failure

Manifest-write, diagnostic, or lock-release failures remain visible with the primary failure. A cancellation-manifest failure preserves both cancellation and write exceptions. Preflight failures fault the returned task and create no manifest. The UI displays (none) when no manifest exists and preserves known sentinel state for pre-lock cancellation.

Runtime paths are:

{target}/.recordset.lock
{target}/.recordset_sentinel
{target}/_recordset_manifests/{run_id}.json

Run IDs use UTC yyyyMMdd-HHmmss plus four random lowercase hex characters. The lock uses FileMode.CreateNew, FileShare.None, and UTF-8 contents:

run_id={run_id}
fingerprint={fingerprint}

Acquisition invokes no external log callback after creation. A write/dispose failure attempts partial-lock deletion before propagating. After acquisition, logging and all later work are inside the release boundary. The sentinel is opened or created and remains after completion. There is no package deletion or quarantine plan action. SafeOperationRuntime.TrashRoot names _RS_TRASH/{run_id} but execution does not use it.

The manifest has this shape:

{
  "run_id": "20260113-154200-a1b2",
  "fingerprint": "0123456789abcdef",
  "target_root": "C:\\Output",
  "utc": "2026-01-13T15:42:00Z",
  "summary": {
    "hosts": 1,
    "unique_links": 3,
    "copy_bytes": 1000000,
    "predicted_output_bytes": 1500000,
    "items": 8
  },
  "status": "ok"
}

SafeWriteManifestRequest carries only the five summary scalars and Status. Execution projects these from PlanSummary. Operations does not depend on the planning aggregate. The manifest records summary and status.

The lock prevents concurrent Record Set executions at one target. Inspect the log and manifest before cleaning output or retrying a failed run. Remove a stale lock only after establishing that its execution is no longer active.

Manage Items

The Options menu opens discipline or building catalogs through ManageDisciplinesCommand and ManageBuildingsCommand. ManageItemsWindowViewModel exposes AddCommand, RenameCommand, and DeleteCommand. Add trims NewName and requires nonblank input. It ignores case-insensitive duplicates and clears NewName after adding. Rename requires a selected item and nonblank RenameTo, trims the replacement, and rejects case-insensitive duplicates. It replaces the item in place, invokes the rename callback, selects the replacement, and clears RenameTo. Delete requires a selection, removes the item, invokes the delete callback, and clears selection and RenameTo. MetadataCatalogWorkflow returns the ordered catalog edits for the App view model to apply to host/link metadata. The dialog's default Close button closes without accepting a separate result payload.

UI contracts

PreviewWorkflowState requires a current preview, allowed target, and no Block messages before Execute can run. Async Add Hosts, Sync Preview, and Execute commands use nonthrowing safe execution and restore busy state. Debounced preview handles expected owner cancellation separately. For Ok and Cancelled results, the production overlay reports completion and an alert shows status and manifest path. An execution failure shows no completion alert. RecordSetWindowViewModel runs Execute through RunWithoutThrowingAsync with SafeExecutionOptions.ErrorBanner and a null notifier, so the failure is logged and the logger window is surfaced, but no banner appears and the exception does not propagate. Execution progress appears in the main window overlay.

Limitations

CadLiveTests exercises rs_xrefs.lsp in AutoCAD Core Console when ACCORECONSOLE names an existing file. See Record Set testing for selection and generated drawings. The AutoCAD command reference does not list the -XREF Path prompts; the script answers with the Xref name and then the new path, cancels a command that is still active, and accepts a change only when the block table reads back the new path. Bind is accepted only when no Xref block remains.

Execution leaves completed file mutations in place after a failure; its manifest is not a rollback journal. Containment checks and filesystem writes are separate operations, so concurrent path replacement can race validation.

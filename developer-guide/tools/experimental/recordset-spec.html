Record Set technical specification

Overview

Record Set builds a package from selected RVT host files and their file-based external references. It copies files, optionally processes DWG Xrefs, and rewrites references in copied RVT files through TransmissionData. The source is src/Tools/Experimental/RecordSet/. Record Set describes application composition and window interactions.

Architecture

Domain values describe files and plans. Planning constructs ordered work; Execution dispatches filesystem, CAD, and Revit operations. Record Set architecture lists composition and presentation owners.

Inherit resolves to AddXrefs during planning. A null PlanOptions flag follows Core Console availability independently for each preview. The UI initially shows unchecked flags, publishes their effective values after preview, and preserves explicit user choices for the window lifetime. These options are not persisted.

Destination rules

PlanningService.BuildContext counts normalized source-path/type occurrences. Keys appearing at least twice become common links. Identity uses the complete normalized path and type, not just a filename. The count includes repeated references within one host.

TargetPathRules computes intended paths:

File Destination
Host with building {target}/{building}/{discipline}/{name}
Host without building {target}/{discipline}/{name}
Noncommon link with building {target}/{building}/{discipline}/Linked Files/{name}
Noncommon link without building {target}/{discipline}/Linked Files/{name}
Common link {target}/Common Linked Files/{name}

Blank or - building omits that segment. Empty discipline adds no directory segment. The destination allocator compares normalized paths. Reusing the same source/destination needs no extra copy. A different source colliding with a destination receives name (2).ext, then (3), and so on, with a warning. Allocation fails when the counter exceeds 10,000. Mappings and preview projections use the allocated destination.

Safety policy

PolicyReader loads the embedded resource DBTools.ToolConfigs.RecordSet.recordset_policy.json from Policies/recordset_policy.json. It does not load a user-side policy file.

JSON member Shipped value or rule
allowed_target_roots Nonempty required list. Shipped root is \\fileserver\Projects
verify_after_copy Required Boolean, shipped false
min_free_bytes Required nonnegative number, shipped 10,737,418,240
denied_extensions .dwl, .dwl2, .tmp, .bak, .lnk, .exe
allowed_extensions Optional
deny_globs Required list, shipped *backup*.rvt, *.old, ~$*
paths.enable_long_paths Required Boolean in required paths object, shipped false
delete_mode Defaults to quarantine. No plan action consumes it
require_sentinel_for_delete Defaults true. No delete action consumes it

Configured string entries must be nonblank. Roots must be absolute Windows drive-letter paths or complete UNC server/share paths. Relative, drive-relative, root-relative, and incomplete UNC roots fail admission. Malformed or incompatible policy throws. It is not normalized into valid data.

Preview checks the target against admitted roots. Execution reloads policy and checks it again. The containment predicate admits equality with the root and descendants. Before acquiring the lock, execution checks every output-bearing plan path: directories, copy destinations, CAD repath hosts/roots, bind hosts, Revit hosts, and mapping destinations. Copy sources, mapping keys, and Revit source hosts remain source paths.

Execution requires free space minus max(TotalBytes, PredictedOutputBytes) to meet MinFreeBytes. Safe filesystem operations resolve existing file and directory redirects before checking containment. Recursive copies carry destination checks into every nested operation. Lock, sentinel, and manifest mutations repeat containment checks.

Copies overwrite existing destination files and preserve the source file's UTC creation, last-access, and last-write timestamps. Optional verification compares SHA-256 hashes, including every allowed file in a copied directory. It verifies copied bytes before later CAD/Revit mutations.

Workflows

Host import and reference reading

FileSelectionWorkflow owns OS pickers. HostImporter normalizes picks, rejects existing or repeated hosts, and calls PlanningService.ScanHost with empty discipline and building -. A RevitOperationException or scan warning rejects that host and returns an ordered issue. Owner-token cancellation propagates. The application displays issues and adds only accepted hosts.

RevitOperations implements IExternalReferenceReader and ITransmissionWriter. It strips long-path prefixes before passing paths to Revit. Missing TransmissionData or external-reference collections fail with operation and host context.

Reference reading uses desired data when IsTransmitted is true and last-saved data otherwise. Library references (PathType.Content, including library-located keynote or assembly-code tables) are omitted. Absolute references retain their stored path. Relative references resolve against the source host folder. For a workshared local, the base is the file-system central folder from BasicFileInfo.CentralPath. Without a usable file-system central path, resolution uses the reference's saved absolute path. A moved package with intact relative structure therefore resolves its own files.

The scan creates discovered links using their resolved paths and host metadata. It classifies RVT, DWG, and Other external references. It does not recursively scan linked RVT models.

Plan construction and limits

Features/Planning/Preview/PreviewPlanBuilder.BuildPlanAsync performs these stages:

  1. Find Core Console and resolve nullable CAD flags.
  2. Plan hosts and non-CAD links under the file policy.
  3. Plan each distinct DWG destination once, using its first occurrence's CAD options.
  4. Append Revit repath operations for copied hosts with allowed mappings.
  5. Check sources, count bytes, estimate bound output, enforce limits, and compute the fingerprint.

Denied hosts or links produce warnings. Missing planned source paths produce Block messages. Directory copies count only policy-allowed files. TotalBytes counts each distinct source/destination copy pair, including repeated copies of one source to different destinations. PlanSummary.UniqueLinks is the number of distinct copy-source paths, including host paths. Hosts is the selected-host count. Items includes directory and message items.

Limit Value Result when exceeded
PlanningLimits.MaxTotalBytes 80 × 1024³ bytes Block
PlanningLimits.MaxTotalItems 10,000 Block

PredictedOutputBytes starts at TotalBytes. For Bind All, the estimate adds allowed discovered Xref sizes beyond the copied host DWG size. Estimate failure produces a warning and retains the existing estimate. These are preview limits, not guarantees of final package size.

Plan items and progress

Plan items are typed records. PlanAction supplies their dispatch identity.

Record Data Fingerprint action Fingerprint keys Weight
FsCreateDirItem Path fs_create_dir path 1
FsCopyItem Source, Destination fs_copy src, dst 3
CadCopyItem Source, Destination cad_copy src, dst 3
CadRepathItem Host, NewRoot cad_repath host, new_root 2
CadBindAllItem Host, BindType cad_bind_all host, bindtype as invariant numeric enum text 4
RevitRepathItem Host, SourceHost, Mapping revit_repath host, source_host, map:{source} per mapping 2
UIWarnItem Message ui_warn msg 0
UIInfoItem Message ui_info msg 0

Progress increases after an item completes, using its weight divided by the total weight, with a minimum denominator of 1. It is an operation estimate, not byte progress.

Each item emits an action string and ordinally sorted key=value fields separated by |. Revit mappings use map:{source} keys. Fingerprinting hashes successive UTF-8 item segments with SHA-256, without an extra separator between segments, and keeps the first 16 lowercase hexadecimal characters. It records plan identity for the audit output. Execution does not use it as a content checksum.

CAD planning

For AddXrefs, the planner copies the DWG and allowed manual Xrefs beside it. With discovery enabled and Core Console available, it scans the tree and copies unique referenced paths beside the destination DWG, allocating collision suffixes when necessary. When repath is enabled, it appends CadRepathItem using the destination DWG directory as NewRoot.

Discovery failure logs a warning and uses heuristic copying. Disabled discovery or unavailable Core Console also uses heuristic copying: copy existing sibling directories named xrefs, xref, refs, ref, external, dwg, or cad. Each source/destination directory pair is copied once. Heuristic copying does not rewrite Xrefs. The planner emits Info messages Auto-discover CAD Xrefs disabled. when discovery is disabled with Core Console present, or AutoCAD Core Console not found. DWG Xrefs copied by heuristic only. when Core Console is absent. Explicitly enabling both discovery and repath without Core Console produces Block.

BindAll requires Core Console. Without it, preview produces Block and schedules no bind operation. With it, the plan copies the DWG and appends bind work, without manual or discovered Xref copy work. Selecting BindAll clears manual children. Bind and Insert select AutoCAD BINDTYPE 0 and 1 respectively. Bind preserves Xref-prefixed names. Insert merges names and can produce naming conflicts.

Core Console boundary

CoreConsoleRuntime.FindCoreConsole searches:

  1. An existing path from ACCORECONSOLE.
  2. accoreconsole.exe in PATH order.
  3. AutoCAD 2026, 2025, and 2024 under C:\Program Files\Autodesk.
  4. DWG TrueView 2025 under the same directory.

Each run extracts an embedded DBTools.ToolCad.RecordSet.* script to a unique temporary .lsp file and attempts deletion in finally. Deletion failures log a Warning. CoreConsoleRunner starts both redirected reads immediately and returns immutable standard output, standard error, and exit code. It creates a temporary .scr file that loads and invokes the extracted LISP script:

accoreconsole.exe /i "<input.dwg>" /s "<temporary.scr>"

Cancellation terminates the owned process tree and observes terminal stream completion. The runner attempts .scr cleanup on every exit and logs deletion failures. Execution rechecks Core Console availability for each CAD repath or bind item. If it is missing, the executor logs the affected DWG path and throws InvalidOperationException rather than using heuristic copying.

Script and function Argument Behavior
rs_list_xrefs.lsp, rs-list-xrefs Host DWG path Enumerates Xref blocks and emits nested JSON
rs_repath_xrefs.lsp, rs-repath-xrefs host.dwg\|new_root Strips matching root prefixes from Xref paths and saves
rs_bind_all_xrefs.lsp, rs-bind-all-xrefs host.dwg\|BIND or host.dwg\|INSERT Sets BINDTYPE, binds *, purges three times, quick-saves

Discovery requires a zero exit code and parseable JSON between the first { and last } in output. The root requires an xrefs array. Every node requires a non-null children array with non-null nodes. Host, node name, and node path can be blank. Blank paths do not expand into copy work. The JSON fields are host, xrefs, name, path, overlay, and children. The shipped scanner emits overlay: false rather than detecting overlay state.

See Limitations for the scanner failure and the paths repath cannot resolve. The repath script receives a root rather than the planner's source-to-copy mapping and strips a case-insensitive matching root prefix. CadExecutor checks only the repath process exit code. Bind requires both a zero exit code and an output marker containing "ok":true.

Revit repath

RevitRepathItem.SourceHost preserves the source reference base while Host names the copied RVT. Mapping keys are normalized source paths and values are allocated output paths. The writer reads effective references, skips Content references, and matches against the source base. It sets desired paths while preserving effective loaded/unloaded state.

TransmissionWriteResult.UpdatedCount is zero for no matching changes. The writer leaves the copied RVT untouched in that case. A positive count causes TransmissionData to be written with IsTransmitted = true. A rewritten workshared copy opens detached and cannot create new locals while transmitted. Reference failures preserve operation, host, reference ID, old/new path context, and original causes through RevitOperationException. Owner cancellation remains cancellation.

Execution, cancellation, and audit files

ExecutionPlanExecutor.ExecuteAsync validates preconditions, creates runtime metadata, acquires the lock, writes the sentinel, executes items in order, and writes an outcome manifest. It always attempts lock release after successful acquisition. The UI passes CancellationToken.None and shows a non-cancelable overlay. Lower owners honor supplied cancellation at work boundaries. Execution is not dispatched to a worker thread.

Outcome Result
Successful execution ExecutionStatus.Ok, ok manifest
Owner cancellation before lock acquisition Cancelled, empty run ID and manifest path
Owner cancellation after acquisition Cancelled, cancelled manifest, lock release
Unexpected fault or foreign cancellation Attempt failed manifest, release lock, propagate failure

Manifest-write, diagnostic, or lock-release failures remain visible with the primary failure. A cancellation-manifest failure preserves both cancellation and write exceptions. Preflight failures fault the returned task and create no manifest. The UI displays (none) when no manifest exists and preserves known sentinel state for pre-lock cancellation.

Runtime paths are:

{target}/.recordset.lock
{target}/.recordset_sentinel
{target}/_recordset_manifests/{run_id}.json

Run IDs use UTC yyyyMMdd-HHmmss plus four random lowercase hex characters. The lock uses FileMode.CreateNew, FileShare.None, and UTF-8 contents:

run_id={run_id}
fingerprint={fingerprint}

Acquisition invokes no external log callback after creation. A write/dispose failure attempts partial-lock deletion before propagating. After acquisition, logging and all later work are inside the release boundary. The sentinel is opened or created and remains after completion. There is no package deletion or quarantine plan action. SafeOperationRuntime.TrashRoot names _RS_TRASH/{run_id} but execution does not use it.

The manifest has this shape:

{
  "run_id": "20260113-154200-a1b2",
  "fingerprint": "0123456789abcdef",
  "target_root": "C:\\Output",
  "utc": "2026-01-13T15:42:00Z",
  "summary": {
    "hosts": 1,
    "unique_links": 3,
    "copy_bytes": 1000000,
    "predicted_output_bytes": 1500000,
    "items": 8
  },
  "status": "ok"
}

SafeWriteManifestRequest carries only the five summary scalars and Status. Execution projects these from PlanSummary. Operations does not depend on the planning aggregate. The manifest records summary and status.

The lock prevents concurrent Record Set executions at one target. Inspect the log and manifest before cleaning output or retrying a failed run. Remove a stale lock only after establishing that its execution is no longer active.

Manage Items

The Options menu opens discipline or building catalogs through ManageDisciplinesCommand and ManageBuildingsCommand. ManageItemsWindowViewModel exposes AddCommand, RenameCommand, and DeleteCommand. Add trims NewName and requires nonblank input. It ignores case-insensitive duplicates and clears NewName after adding. Rename requires a selected item and nonblank RenameTo, trims the replacement, and rejects case-insensitive duplicates. It replaces the item in place, invokes the rename callback, selects the replacement, and clears RenameTo. Delete requires a selection, removes the item, invokes the delete callback, and clears selection and RenameTo. MetadataCatalogWorkflow returns the ordered catalog edits for the App view model to apply to host/link metadata. The dialog's default Close button closes without accepting a separate result payload.

UI contracts

PreviewWorkflowState requires a current preview, allowed target, and no Block messages before Process can run. Async Add Hosts, Sync Preview, and Execute commands use nonthrowing safe execution and restore busy state. Debounced preview handles expected owner cancellation separately. For Ok and Cancelled results, the production overlay reports completion and an alert shows status and manifest path. An execution failure shows no completion alert. RecordSetWindowViewModel runs Execute through RunWithoutThrowingAsync with SafeExecutionOptions.ErrorBanner and a null notifier, so the failure is logged and the logger window is surfaced, but no banner appears and the exception does not propagate. Execution progress appears in the main window overlay.

Limitations

The scanner calls the undefined AutoLISP function vl-file-syst-exists-p before opening an Xref. DWGs with Xref paths therefore fail discovery and use heuristic copying. CAD repath cannot repair relocated or collision-renamed Xrefs.

Execution leaves completed file mutations in place after a failure; its manifest is not a rollback journal. Containment checks and filesystem writes are separate operations, so concurrent path replacement can race validation.

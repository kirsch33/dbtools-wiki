View Template Comparer (VTC)

Overview

View Template Comparer (VTC) compares two Revit view templates of the current document, stages category edits locally, and applies the selected differences and eligible pending overrides through one command, ApplySelectedChangesCommand (button label "Process"). It can also create a merged template and save templates to a local library.

The data contract (tabs, imported categories, Revit-link settings, keys, apply and copy rules, library storage) is in the VTC specification.

Architecture

Source: src/Tools/Experimental/VTC/. The manifest registers DBTools.VTC on the Testing ribbon panel with InlineUi, order 50, and icon key vtc.

Command and composition

  • VtcCommand is the Revit entry point. It validates the command context and calls App/Composition/VtcWindowLauncher.
  • VtcWindowLauncher owns the modal launch: it resolves the document's templates, shows an alert when there are none, has VtcWindowCompositionFactory build the collaborators, and creates VtcWindowSession through Core's ToolWindowFactory. After the dialog closes it opens the logger window when Debug Mode is on. It always retires the comparer and linked-file windows; a dialog failure is reported before any retirement failure.
  • VtcWindowCompositionFactory creates one graph per document: TemplateExtractor, RevitLinkSettingsAdapter, TemplateDifferenceEvaluator, TemplateApplier, TemplateMaterializer, TemplateStorage (cache directory AppPaths.GetToolCacheDir("VTC")) and the one document facade, TemplateRuntime.
  • TemplateRuntime (Revit/Template) resolves template IDs and exposes compare, extract, batch apply, create merged, apply model, Revit-link targets and copy, and line and fill pattern queries. App batch-session code depends on the App/Sessions/ITemplateSessionRuntime port, which TemplateRuntime implements.
  • VtcWindowSession owns the modal window session. ToolWindowFactory supplies the stable shell for the raw VTC view. Comparison owns the workspace, Inspector and Preview views; Library owns its workspace view; the Revit-link modal reuses the Comparison diff control.
  • AlertPresenter is the only alert boundary in App. Composition gives the alert service only to the presenter; view models and workflows use the presenter for standard alerts, custom requests and selections.
  • VtcWindowBatchWorkflow handles App session reactions for Process and Library work. The App view model owns Revit-link prompts, modal hosting, refresh and result presentation. TemplateRuntime passes Revit-link batch apply and copy, and the classification of expected conflicts, to Template Apply.
  • VtcWindowCommandRuntime reports a refused operation through SafeExecutionRefusalReporter as VTC {operation}.

Sources: src/Tools/Experimental/VTC/Revit/Template/TemplateRuntime.cs, src/Tools/Experimental/VTC/Features/TemplateApply/Execution/TemplateApplier.Operations.cs, src/Tools/Experimental/VTC/App/Composition/VtcWindowCompositionFactory.cs.

  • TemplateDifferenceEvaluator is host-neutral. TemplateExtractor and RevitLinkSettingsAdapter own the Revit mechanics behind TemplateRuntime.
  • SettingDifference.LeftValue and RightValue hold typed SettingValue cases. Compare, apply and App code pattern-match these cases.
  • Display settings use VTC enums (DetailLevel, DisplayStyle, PartsVisibility, ViewDiscipline, ShowHiddenLinesMode); conversion to Revit enums happens only at the Revit API boundary.
  • SettingPreviewItem and DiffTreeProjector.ViewFilter are Comparison contracts, so feature projections do not import App view models.
  • DiffTreeNode holds comparison and display state only. PendingOverrideState holds pending override DTOs with no tree or UI dependency. TemplateApplyResult is the only apply outcome; the App view model (TemplateApplyOutcomeProjection) projects it onto setting keys for row feedback and filters and stores no outcome on comparison nodes.
  • DiffTreeBuilder only builds a tree from differences. DiffTreeIndex keeps the rebuilt roots and owns key lookup, canonical node paths, selection collection in tree order and Revit-link subtree queries for the coordinator, the preview projection and the Revit-link modal.
  • MergedTemplateBuilder (Features/TemplateApply/Planning/MergedTemplate) builds the merged TemplateSnapshot from the comparison result, the selections, the base side and the name. View-model operations only orchestrate effects.
  • App composes outcome templates into Comparison views at runtime; Comparison raises only selected-node, override-edit and preview-setting requests for App to coordinate across panes and modals.

VTC views are raw XAML EmbeddedResource items with explicit logical names:

  • DBTools.ToolViews.VTC.VtcWindow.xaml (main view)
  • DBTools.ToolViews.VTC.AlertBodyTemplates.xaml
  • DBTools.ToolViews.VTC.ComparisonWorkspaceView.xaml
  • DBTools.ToolViews.VTC.ComparisonInspectorView.xaml
  • DBTools.ToolViews.VTC.ComparisonPreviewView.xaml
  • DBTools.ToolViews.VTC.DiffViewControl.xaml
  • DBTools.ToolViews.VTC.LibraryView.xaml
  • DBTools.ToolViews.VTC.RevitLinkSettingsWindow.xaml

VtcWindowSession loads the main resource through ToolWindowFactory and owns the one-time owner attachment and cleanup. VTC has no custom close gate and no native pick loop.

Shared resource dictionaries are in DBTools.Presentation/Tools/VTC/: VtcDiffViewStyles.xaml and VtcComparisonViewStyles.xaml. The namespace DBTools.Presentation.Tools.VTC holds the converters VtcConflictConverter and VtcRawViewConverter. VtcResourceTemplateSelector resolves App outcome templates and returns an empty template in a standalone view. Alert bodies use full type-name string keys with TypeNameTemplateSelector. Every content and item slot has an explicit template; immutable record values bind OneTime and mutable view-model state uses INotifyPropertyChanged.

  • Each raw view merges Theme once, before the VTC dictionaries; the shared dictionaries do not merge Theme. Vtc.TreeView is based on the implicit TreeView style with VTC overrides; each tree sets its own scrolling and virtualization.
  • Named item selectors set TextSearch.TextPath for prefix typing and automation names on their template text. SavedTemplateInfo, ViewFilterOption, LinePattern, FillPatternData and TemplateOption return their display label from ToString(), so automation peers and text fallbacks show the label.
  • Preview navigation is available only for navigable setting keys. Double-click override editing responds to the left mouse button only, on eligible rows.
  • Keyboard focus moves to the comparison row after the Inspector tab loads. Pending focus and close requests are canceled on retirement.
  • The linked dialog's context-menu selection commands bind to its own view model. The raw linked view has the automation name "Linked file override differences". The main window initializer uses the log prefix VtcWindow.

Data and contracts

The specification defines tabs, typed setting values, imported categories, Revit-link identity, and library storage.

Workflows

Process and merged templates

  • ApplySelectedChangesCommand applies the selections and eligible pending category overrides in one VTC Process Apply transaction, with one SubTransaction per setting so an expected conflict rolls back only that setting.
  • Category application checks CanCategoryBeHidden and IsCategoryOverridable before changing visibility or graphics. Unsupported visibility is skipped with a warning. When graphics overrides are unsupported, empty overrides are skipped with a warning. Required overrides produce a [VTC_READ_ONLY] conflict with kind ReadOnlyParameter.
  • An apply failure becomes a per-setting conflict only after its sub-transaction confirms RolledBack. If the rollback throws or reports another status, the batch stops with a BatchApplyException that contains the apply failure and then the rollback failure. An unconfirmed rollback never publishes a pending-override conflict key.
  • Create Merged (TemplateRuntime.CreateMergedTemplate) runs template creation and the pending-override batch in one transaction group, Create Merged View Template, started through RevitTransactionGroups.Begin and assimilated into one Undo entry. Expected per-setting conflicts are reported and the new template is kept. Any other fault rolls the group back and leaves no template, so a retry with the same name works.
  • TemplateMaterializer copies the Left template with ElementTransformUtils.CopyElements and a duplicate-type handler that keeps destination types, so Revit shows no dialog. It catches no copy failure: a fault rolls back the group and reaches RunOrReport as an Error alert.
  • VtcWindowBatchWorkflow.SavedTemplates treats template extraction or merge and the cache save or delete as the change. After that change, the list refresh has its own error boundary: a refresh failure is logged with the template name and shows one warning that the cache operation succeeded; success is shown only after the refresh succeeds. Both save commands ask Replace saved template 'X'? through AlertPresenter before they overwrite an existing name; Cancel writes nothing.

Testing

DBTools.VTC.Pure.Tests (no Revit host):

  • DiffTreeBuilderTests, DiffTreeIndexTests, DiffTreeNode*Tests, DiffTreeProjectorTests: grouping, selection state and change notification, including imported-category tabs and Revit-link grouping by link name.
  • PendingOverrideStateTests, PendingCategoryOverrideTests: staging, eligibility, restore, clear, merge-save application and failed-pending collection.
  • TemplateApplyOutcomeProjectionTests: keyed conflict and success projection for row feedback and result filters.
  • TemplateStorageTests: the real storage service with a temporary cache directory, including imported-category data and RevitLinks rows. The project references the VTC product assembly directly, not DBTools.App.
  • TemplateDiffEvaluatorTests, RevitLinkDiffEvaluatorTests: snapshot comparison over SettingDifference rows.
  • RevitLinkActionSourceResolverTests: sole-side, selected-side, ambiguous-side and no-value resolution.
  • AlertBodyTemplateProviderTests: the provider and its raw DBTools.ToolViews.VTC.AlertBodyTemplates.xaml resource (WPF only).
  • VtcRawXamlParseTests: the linked-file view's accessible name and its view model passed to the composed diff view. Raw comparison view tests use the registered ToolWindowFactory session and the stable behavior bindings.

Revit-hosted tests (the local scope) in DBTools.VTC.Local.Tests open the Global Mapper (GM) and Super Girt Tool (SGT) test models, create temporary templates and roll back every change after each run:

  • VtcWindowViewModelTests: Process, Create and link flows around real template extraction, apply and creation, alert orchestration and the Revit-link modal and copy.
  • RevitLinkBaselineTests: extract and apply round trips of LinkVisibilityType and LinkedViewId on RevitLinkType and RevitLinkInstance targets in sgt_test_model.rvt.
  • RevitLinkExtendedTests: the other RevitLinkGraphicsSettings members on the SGT linked model.
  • RevitLinkSnapshotRemapTests: snapshot compare and apply with deliberately mismatched target and linked-element IDs, LinkName pairing and linked-element-name remap failures.
  • ImportedCategoryRoundTripTests: imports a shared CAD file inside the rollback scope and checks that imported categories use the normal category compare and apply path.
  • SgtModelExtractionTests, GmModelExtractionTests: extraction from existing views and presence of link targets in the open models.

Limitations

Comparison requires two view templates in the same document. Revit-link settings are restricted to the public API; linked-element remapping requires a resolvable name or the same-model ID condition in the specification.

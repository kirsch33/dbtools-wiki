View Template Comparer (VTC)

NAME

dbtools.VTC - compare and apply Revit view templates

SYNOPSIS

source    src/Tools/Experimental/VTC/
assembly  dbtools.VTC
entry     VtcToolModule
command   VtcCommand (InlineUi)

DESCRIPTION

VTC compares two templates in one Revit document. The user guide describes comparison, Process, and the Library. The specification defines snapshot data, remapping, apply behavior, and Revit API limits.

STRUCTURE

Path Owner
App/Composition/ VtcToolModule registers VTC services. manifest.yml declares the ribbon command.
App/Sessions/ VtcWindowSession owns window setup and cleanup. VtcWindowBatchWorkflow runs Process and library operations.
Revit/Template/ TemplateRuntime implements ITemplateSessionRuntime and resolves template IDs.
Features/Comparison/ DiffTreeBuilder groups rows. DiffTreeIndex resolves keys and paths. VtcWindowComparisonCoordinator owns the live comparison.
Features/TemplateApply/ TemplateApplier writes settings. PendingOverrideState holds staged category edits. MergedTemplateBuilder builds the merged snapshot.
Features/Library/ and Features/RevitLinks/ TemplateStorage owns the library. RevitLinkSettingsAdapter reads and writes link settings.

CONTRACTS

  1. Window resources. VTC embeds the raw views under dbtools.ToolViews.VTC.*.xaml. Workspace and Inspector use VtcResourceTemplateSelector from VtcComparisonViewStyles.xaml. Each selector resolves its keyed outcome template in VtcWindow.xaml. A standalone view uses the empty fallback.
  2. Comparison state. DiffTreeNode holds comparison and selection state. TemplateApplyOutcomeProjection maps TemplateApplyResult to setting keys for row feedback and filtering.
  3. Apply. TemplateApplier.BatchApply runs one transaction with one subtransaction per setting. It reports an expected failure after confirming rollback of that row. An unconfirmed rollback raises BatchApplyException. An unsupported category visibility change can report a conflict and keep a successful graphics write.
  4. Create Merged. TemplateMaterializer copies the Left template and keeps destination types on duplicate-type conflicts. TemplateRuntime groups template creation, selected rows, and pending edits into one Create Merged View Template Undo entry. An unexpected failure rolls back the group.
  5. Library. TemplateStorage owns paths under AppPaths.GetToolDataDir("VTC"). Load applies captured differences in its own transaction and refuses a document with an open transaction.

FLOW

  1. VtcCommand resolves VtcWindowLauncher and ITransactionRunner from the command context and constructs TemplateRuntime.
  2. TemplateRuntime constructs TemplateExtractor, RevitLinkSettingsAdapter, TemplateDifferenceEvaluator, TemplateApplier, and TemplateMaterializer. GetTemplateOptions lists templates in name order.
  3. VtcWindowLauncher receives the options. It shows No view templates found in the document. when the list is empty.
  4. VtcWindowCompositionFactory.Create takes the runtime, alert service, and library. It returns the VtcWindowComposition used by VtcWindowViewModel.
  5. The launcher creates VtcWindowSession through ToolWindowFactory. On Loaded, the session attaches its owner and initializes the comparison once. The launcher retires each modal session and gives dialog failures precedence over retirement failures.

DATA

TemplateSnapshot holds the source document GUID and captured settings. SettingDifference carries typed SettingValue cases for each side. TemplateDifferenceEvaluator compares them. TemplateStorage saves snapshots as JSON and accepts omitted optional members.

DIAGNOSTICS

VtcWindowCommandRuntime reports refusals as VTC <operation>. Apply errors include the exception message and any underlying Revit reason. VtcWindowBatchWorkflowApplyTests checks both messages in the error alert. A library load alert combines apply results with any comparison refresh failure. If saving or deleting succeeds and the list refresh fails, the warning names the affected template.

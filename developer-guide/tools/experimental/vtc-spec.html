View Template Comparer (VTC) specification

Overview

This page specifies the data contract of View Template Comparer (VTC): what it reads from a view template, how it keys and compares settings, and how it applies, copies and stores them. The VTC developer guide describes the architecture.

Architecture

TemplateExtractor and RevitLinkSettingsAdapter read snapshots. TemplateDifferenceEvaluator compares them; TemplateApplier applies selected changes. TemplateStorage owns cached JSON. See VTC architecture for composition and views.

Data and contracts

Scope

  • VTC compares two view templates of the current document.
  • Category edits stay staged locally until Process.
  • Imported categories are ordinary category rows on their own tab.
  • Revit-link settings are limited to settings that the public Revit API can both read and write. VTC reads and writes a setting through the public API or does not handle it.

Tabs

The tree follows the Visibility/Graphics dialog. SettingTab values:

  • ModelCategories
  • AnnotationCategories
  • AnalyticalModelCategories
  • ImportedCategories
  • Filters
  • RevitLinks
  • Worksets
  • DesignOptions

CategoryTabClassifier sends a model category with a positive ID (an imported DWG, SAT or similar category) to ImportedCategories. Internal categories, which the dialog does not show, are classified as model categories. Other category types keep their native tab.

Imported categories

  • Extraction emits imported parents and their layers and subcategories as CategoryGraphicsData. Layers and subcategories inherit the imported parent's tab.
  • Imported rows keep SettingType=CategoryOverride and use the same compare pipeline as every other category. There is no import-specific apply path.
  • Inline edit, Inspector edit, Preview, pending overrides, batch apply, merged save and snapshot apply all use the standard category path.
  • A selection whose side is missing resets visibility and graphics as for any other category row.

Revit links

Data

TemplateSnapshot.RevitLinks is a list of RevitLinkSetting records:

public sealed record RevitLinkSetting(
    long LinkElementId,
    RevitLinkTargetKind TargetKind,     // RevitLinkType or RevitLinkInstance
    string LinkName,
    string LinkDisplayName,
    RevitLinkSettingKind SettingKind,
    RevitLinkSettingValue Value);

Each row is one target and one native setting. VTC extracts both RevitLinkType and RevitLinkInstance targets; they are keyed, labeled and copied separately.

Setting kinds

RevitLinkSettingKind has 11 values, all members of RevitLinkGraphicsSettings:

Kind Kind
LinkVisibilityType ColorFill
LinkedViewId ViewRange
ViewFilterType Phase
NestedLinks PhaseFilter
ObjectStyles ViewDetailLevel
Discipline

The adapter binds all 11 kinds directly to typed public API members for Revit 2026 (2026.5 or later) and Revit 2027.

Extraction

  • RevitLinkSettingsAdapter.Extract enumerates link targets, reads View.GetLinkOverrides(...) (a new RevitLinkGraphicsSettings when there are none) and emits one row per setting kind.
  • Simple settings use the native LinkVisibility or ElementId value. Phase, Phase Filter, Detail Level and Discipline use their public getter and setter and are stored as one row each.
  • Linked element names are read from the linked document when it is loaded. These names identify Linked View, Phase and Phase Filter across models.

Keys and comparison

  • RevitLinkDiffEvaluator keys each row as link.{type|instance}.name.{LinkName}.{SettingKind}, for example link.type.name.ARCH_Model.rvt.LinkVisibilityType.
  • LinkName is the only cross-model key. Compare, save, load and apply all use it; there is no element-ID key. If a key is ambiguous within a target kind, compare throws InvalidOperationException ("Revit link key '...' is ambiguous. ...").
  • TemplateDifferenceEvaluator compares typed SettingValue cases.
  • DiffTreeBuilder groups the rows under Revit Links by LinkDisplayName, with one leaf per setting kind.

Library storage

TemplateStorage stores saved templates as JSON in the VTC cache directory (AppPaths.GetToolCacheDir("VTC")).

  • It is the only code that derives cache file paths. Callers use logical template names. A rooted name, or a name with a path separator, is rejected before any path is derived. SavedTemplateInfo exposes only the name and modification time.
  • Load and save accept only one complete TemplateSnapshot shape: required top-level members and collections must be present, explicit nulls and invalid nested elements are rejected, and the same validation runs before an in-memory snapshot is saved. There is no normalization and no recovery of other formats; incompatible data raises TemplateStorageException.
  • Saved Revit-link rows must have a non-blank LinkName and LinkDisplayName, defined TargetKind and SettingKind values and a value valid for the kind: a visibility mode from 0 to 2, no mode for linked-view IDs, a detail level from 0 to 3, a defined discipline, and no enum value for other kinds.
  • GetSavedTemplates returns an empty list when the cache directory does not exist, without creating it. Other enumeration failures raise TemplateStorageException (operation enumerate).
  • TemplateExists returns false for a missing file or directory. Other probe failures raise TemplateStorageException (operation probe), so the save is refused instead of overwriting.
  • Only SaveTemplate creates the directory. An existing name is replaced only after the user answers Replace; otherwise the file is written with overwrite disabled, so a template that another process saved under the name after the probe is kept and the save fails with TemplateStorageException.
  • MergedTemplateBuilder writes RevitLinks rows like any other diff rows. Revit-link rows take part in Preview, Process, Create Merged and merged save.

Sources: src/Tools/Experimental/VTC/Domain/Template/TemplateSnapshot.cs, src/Tools/Experimental/VTC/Features/Library/Operations/TemplateStorage.cs, src/Tools/Experimental/VTC/Features/RevitLinks/.

Workflows

Apply and copy

Apply

  • Applying a Revit-link row reads the current link overrides, changes only the selected setting and writes the settings back with View.SetLinkOverrides(...).
  • Targets are resolved by LinkName only.
  • Linked View, Phase and Phase Filter are remapped by linked-element name. Dependent rows first set the required top-level visibility mode.
  • A selection whose side is missing resets only that setting to its host default.
  • Applying from the Revit-link modal uses BatchApply in one VTC Process Apply transaction, with one sub-transaction per setting and one Undo entry. A missing comparison key is an ElementNotFound conflict; an unexpected fault rolls back the whole apply.

Copy

  • The context menu of a concrete link group or leaf row (not the Revit Links tab root) has Open Revit Link Settings... and Copy Revit Link Settings To....
  • Opening the modal from a leaf row shows the full group of that link target, so the modal always shows all 11 kinds. A successful modal apply refreshes the main comparison.
  • The modal and the copy command work on one template side. RevitLinkActionSourceResolver selects the only side with a value, or a viable selected side, and reports "no Revit-link value" or a real two-sided ambiguity without showing UI. On ambiguity App asks which template to use; it never defaults to Left.
  • Copy uses TemplateRuntime.GetRevitLinkTargets() and CopyRevitLinkSettings(...) and always copies all 11 kinds. Each target is copied in its own transaction; the transactions run in the Copy Revit Link Settings transaction group (started through RevitTransactionGroups.Begin) and are assimilated into one Undo entry. An expected failure skips only that target and is logged; an unexpected fault rolls back every target.
  • Linked View, Phase and Phase Filter are copied by finding the source linked-element name in the target linked model; raw linked-document IDs are not copied across models. If the source linked document is unloaded and the name is not available, the raw ID is reused only when source and target reference the same linked model. Otherwise copy fails.

Testing

See VTC testing for Pure and Revit-hosted fixture inventories.

Limitations

A Revit-link key must be unique within its target kind. Cross-model Linked View, Phase, and Phase Filter remapping requires the linked-element name. When the source link is unloaded, raw IDs are reused only for the same linked model; copying to a different linked model fails.

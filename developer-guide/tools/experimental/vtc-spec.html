View Template Comparer (VTC) specification

This page defines the VTC snapshot, comparison, apply, copy and library contracts. The developer guide describes the implementation.

Scope and tabs

VTC compares view templates in the open document. It applies selected differences, stages category edits until Process, creates merged templates and stores snapshots in the local library.

The tree follows the Visibility/Graphics dialog. SettingTab contains ModelCategories, AnnotationCategories, AnalyticalModelCategories, ImportedCategories, Filters, RevitLinks and Worksets. It has no Design Options tab because the public API exposes document options, not per-template option visibility.

CategoryTabClassifier sends model categories with positive IDs, such as DWG and SAT imports, to ImportedCategories. Internal categories that the Visibility/Graphics dialog does not show use ModelCategories. Other category types retain their native tabs. Imported parents, layers and subcategories follow the same category compare, edit, preview, apply, merge and snapshot paths as other categories. Imported layers and subcategories use the imported parent's tab.

Snapshot data

TemplateSnapshot requires Name, Display, Includes, Categories, Filters, RevitLinks and Worksets. Other snapshot members are optional. A missing optional member means that the snapshot did not capture that value.

Member Data

FilterOrder Ordered filter IDs and names.
TemplateIncludeData.SpecId and SharedParameterGuid Parameter identity used to verify a cross-project match.
TemplateIncludeData.Value A writable number, whole number, text or ElementId value, captured only for included parameters that are not owned by a display row.
TemplateIncludeData.ParameterValueData.CategoryParentName Parent category name for a category-valued parameter.
FilterGraphicsData.IsEnabled Filter enabled state.
Pattern names and FillPatternTarget Names and kinds for line and fill pattern references.

VTC captures Detail Level, Display Style and Discipline only when the matching View.Has... method returns true. VTC does not capture extended display members for schedule, legend or drafting views. A null optional member means that the snapshot did not capture that setting.

VTC captures a parameter value only when the parameter is writable, included and has a value. A captured value also requires a captured data spec. Revit compares ForgeTypeId values without the version suffix, and VTC uses the same comparison. A shared parameter with captured identity matches by GUID and spec. Other parameters with captured identity match by unique name and spec. A legacy parameter row without identity data maps by unique name and applies only its inclusion flag. VTC stores an ElementId value's name and type when available. Category values also store the parent category name when available. Built-in and sentinel IDs can remain negative IDs.

Some built-in parameters return an empty ForgeTypeId. The library preserves that empty spec and requires the same spec on the target.

Identity and comparison

For project-local ElementId references, VTC uses an ID when the source and target are the same document and the element kind matches. Across documents, VTC maps by unique name and kind. Fill patterns use FillPatternTarget. Worksets use name and workset kind. Linked views use name and ViewType. A missing or ambiguous required match is a row conflict. The negative Solid line-pattern ID maps to Solid. A positive pattern ID without a name means that reference was not captured, so VTC keeps the target value. VTC does not substitute another named element.

Silhouettes use the captured graphics style kind and category for name mapping. Older snapshots without a silhouette category map names within Lines. Revit determines whether the resolved graphics style is valid for the target view.

Template parameter resolution searches only View.GetTemplateParameterIds(). A shared parameter with a captured GUID matches by GUID. Other parameters match by unique name. VTC checks every captured data spec and shared GUID, using Revit's version-insensitive ForgeTypeId equality. A value write occurs only when the selected side includes the parameter and captures a value.

Parameter rows always apply the inclusion flag. VTC writes a captured parameter value only when the selected side includes the parameter and the snapshot contains its data spec and value. A null value or missing optional identity data does not capture a writable value.

Filter order compares the ordered filter names. The target's filter set must equal the selected order's set before VTC changes precedence. Two comparison rows with the same key are conflicts for both rows. VTC does not select the first row silently.

Revit-link settings

TemplateSnapshot.RevitLinks contains one row per link type or instance and supported setting. The row key uses target kind, link name and setting kind. Link names must be unique within a target kind.

VTC supports Visibility Mode, Linked View, Filters, Nested Links, Object Styles, Color Fill, View Range, Phase, Phase Filter, Detail Level and Discipline in Revit 2026 and 2027. Revit 2027 also exposes Line Weights. The 2026 extractor omits that setting.

RevitLinkDiffEvaluator keys each row as link.{type|instance}.name.{LinkName}.{SettingKind}, for example link.type.name.ARCH_Model.rvt.LinkVisibilityType. A link ID is used only for a matching same-document link of the same target kind. Across documents, the link name and target kind must resolve uniquely. Duplicate names within one target kind are refused with Revit link key '<key>' is ambiguous. Link names must resolve uniquely per target kind and setting. Linked views use their saved view type. VTC refuses an ambiguous linked-view name and type.

Link setting values use the fields and ranges in this table. Revit 2027 Line Weights accepts only modes 0 or 1.

VTC reads and writes supported link settings through View.GetLinkOverrides and View.SetLinkOverrides. It does not copy the complete V/G Overrides RVT Links template-parameter group.

Setting Valid saved values
Link Visibility Type, Filters, Nested Links, Object Styles, Color Fill, View Range, Phase and Phase Filter ModeValue is 0 (By Host View), 1 (By Link View) or 2 (Custom). EnumValue is null.
Linked View ElementIdValue, ElementName and ElementViewType are optional. ModeValue and EnumValue are null. A captured ElementViewType must name a defined ViewType.
View Detail Level ModeValue is 0, 1 or 2. EnumValue is 0 through 3.
Discipline ModeValue is 0, 1 or 2. EnumValue is Architectural (1), Structural (2), Mechanical (4), Electrical (8), Plumbing (16) or Coordination (4095).
Line Weights Revit 2027 only. ModeValue is 0 or 1. EnumValue is null.

Phase and Phase Filter also store optional ElementIdValue and ElementName values. VTC parses a captured linked-view type as a defined ViewType before mapping the saved view.

Before it applies a Custom dependent link setting, VTC sets the link visibility mode to Custom. Line Weights accepts By Host View or By Link View. When that value differs from the current visibility mode, VTC sets the visibility mode to Custom.

Apply and copy

VTC applies each selected row in its own subtransaction and reads the setting back through the public Revit API. A mismatch rolls back that row and returns a conflict. For a category with unsupported visibility, VTC keeps any successful graphics write and flags the row as a conflict. An unexpected failure rolls back the batch.

Library Load and Create Merged write only rows that differ from the target template. They report expected conflicts per row. They also validate saved linked-view names and types when the displayed values compare equal. A missing or ambiguous linked-view match is a row conflict. Missing optional snapshot members are skipped. For template parameters, a missing value skips the value write while the inclusion flag still applies. A filter row absent on the selected side removes that filter. A template-parameter row absent on the selected side excludes that parameter. A display value unsupported by the target view type produces a row conflict. For a link present on both sides, VTC skips a Line Weights row captured on only one side.

Filter rows apply before Filter Order. VTC refuses Filter Order if the target and selected filter sets differ. Otherwise it removes and re-adds filters in source order, restores each filter's visibility, graphic overrides and enabled state, and reads back the order by source names.

Category rows absent on the selected side reset target visibility and graphic overrides. Workset and Revit-link rows absent on the selected side reset only the selected setting to its host default. Missing optional display values do not reset the target.

The Revit-link modal applies selected settings in one VTC Process Apply transaction with one subtransaction per setting. A missing comparison key is an ElementNotFound conflict. An unexpected fault rolls back the batch.

The context menu of a concrete Revit-link group or leaf row, not the Revit Links root, provides Open Revit Link Settings... and Copy Revit Link Settings To.... Opening the modal from a leaf shows all supported settings for that target. A successful modal apply refreshes the main comparison.

The modal and copy command use one template side. RevitLinkActionSourceResolver selects the only side with a value or a viable selected side. When both sides are possible, App asks which template to use. It does not default to Left.

Copy writes all supported settings to each target in a separate transaction inside one Copy Revit Link Settings transaction group. Expected failures skip only that target. An unexpected fault rolls back all copied targets. Linked View maps by name and view type. Phase and Phase Filter map by name. If the source link is unloaded, VTC reuses a raw ID only when source and target refer to the same linked model. Otherwise copy fails.

Library storage

TemplateStorage stores saved templates as JSON in AppPaths.GetToolDataDir("VTC"), normally %APPDATA%\dbtools\VTC\.

TemplateStorage alone derives file paths. Callers use logical template names. Rooted names and names containing path separators are rejected. SavedTemplateInfo exposes only the name and modification time.

Required top-level members and nested values are validated on save and load. Optional members may be absent. Null entries, invalid enums and malformed nested collections are rejected with TemplateStorageException. VTC does not normalize or repair incompatible files.

GetSavedTemplates returns an empty list for a missing library directory. Other enumeration errors raise TemplateStorageException with operation enumerate. TemplateExists returns false for a missing file or directory. Other probe errors raise TemplateStorageException with operation probe, so saving does not overwrite an unverified path.

Only SaveTemplate creates the directory. Replacing an existing name requires the user's Replace choice. Without replacement, atomic creation keeps a file saved concurrently by another process and reports a storage error.

MergedTemplateBuilder writes RevitLinks rows like other diff rows. Link rows participate in Preview, Process, Create Merged and merged save.

Limitations

  • VTC compares templates in one open document. The library stores snapshots for use in another project.
  • The public API path does not expose the complete Revit-link Custom-tab category tables, link Visible, Halftone and Underlay values, per-template Design Option visibility, shadow on/off, ambient shadows, lighting scheme, exposure or coordination-model reference-level overrides.
  • Revit exposes no public setter for a background of type None. VTC extracts and compares that value but refuses to apply it.
  • VTC does not use Revit's whole-tab ApplyViewTemplateParameters route for Revit links.
  • Library Load requires a saved name and kind to map linked elements. A row without that identity is refused. Copy can reuse an ID only when both link targets reference the same linked model; otherwise copy fails.

Record Set

Overview

Record Set copies Revit host files and external references into a target directory and rewrites copied references. It previews an ordered plan before executing filesystem, CAD, and Revit TransmissionData operations. Execution copies files and rewrites references in plan order.

See the technical specification for formats, ordering, safety checks, and CAD limitations, and the user guide page for the window.

Architecture

Source ownership

Source and manifest: src/Tools/Experimental/RecordSet/. The manifest places Record Set on the Testing panel with InlineUi, order 60, and icon key recordset. Command and availability use DBTools.RecordSet.App.Composition.RecordSetCommand. The module is DBTools.RecordSet.App.Composition.RecordSetToolModule.

AppLauncher constructs RecordSetWindowServices beside its consumer, RecordSetWindowViewModel. MetadataCatalogWorkflow returns ordered edits. The App view model applies them to host rows and linked-file metadata. Feature workflows do not import App row types. Stable controls and the byte converter live in src/DBTools.Presentation/Tools/RecordSet/. Raw views merge the versioned Presentation theme and contain stable WPF types. Designer sample construction reuses PreviewTreeBuilder and locates the selected DWG by file identity at any depth.

Presentation and lifetime

The main modal shell loads DBTools.ToolViews.RecordSet.RecordSetWindow.xaml through ToolWindowFactory. It uses title Record Set, size 1240 × 780, minimum 980 × 640, CenterScreen placement, and a taskbar entry. Manage Items loads DBTools.ToolViews.RecordSet.ManageItemsWindow.xaml with a bound title, size 520 × 420, minimum 420 × 300, CenterOwner placement, and a taskbar entry. Its Close button is the default button, so Enter closes the dialog. Both Close buttons use ButtonCommandCloseBehavior.ExecuteAndClose and honor the session close gate. User close returns false. With Debug Mode on, the logger window opens after the main dialog closes.

Tree containers bind IsSelected and IsExpanded two-way. The stable selected-item behavior reports view selection through a OneWayToSource binding to SelectedTreeNode. A rebuilt preview reselects the same SourceFile and expands only its ancestor chain. Explicit selection changes or a missing file cancel pending reselection. Right-click selects and focuses a row or tree item. Right-clicking a Hosts row other than the current item makes it the sole selection, including when it already belongs to a multi-selection. Rows allow logical focus but remain outside Tab navigation.

Options opens below its button. CAD actions require a selected DWG leaf. Manage Disciplines, Manage Buildings, Auto-discover CAD Xrefs, and Allow CAD repath remain disabled until hosts exist. Metadata Add new choices defer the prompt, preserve the prior value on cancellation, and never store the sentinel as metadata. Plan-message bindings use OneTime. CAD bind commands accept the view's string values Bind and Insert.

Retirement releases the preview timer and deferred prompts synchronously. Active preview or execution work produces a Dev Mode retirement failure. Idle retirement disposes the view model and services without a dispatcher frame.

Workflows

Use

  1. Choose an allowed target folder.
  2. Add host RVT files.
  3. Assign discipline and building metadata in the Hosts grid.
  4. Review the destination tree and Info, Warning, or Block messages.
  5. Configure DWG actions through the selected DWG's context menu.
  6. Run Execute when the preview is current and has no blocking messages.

Duplicate host picks produce issues and are skipped. A host with a failed reference scan is rejected. It does not become an empty row. Canceling a file or folder picker preserves the current state.

Target, host, metadata, and CAD changes invalidate the preview immediately. RecordSetPreviewSyncCoordinator debounces automatic refresh by 350 ms at DispatcherPriority.Normal. Preview planning runs through Task.Run and publishes on the UI context. Execution remains on its caller context and uses a non-cancelable progress overlay. Busy state disables editing, CAD actions, options, and ordinary window close. The footer reports Root, Free, ACAD, and Sentinel status. Root is Pending, Allowed, or Blocked; Sentinel is Pending, Present, or Missing. ACAD shows the Core Console path or Unavailable.

Testing

The Pure project references the normal desktop tool project, which owns its source and resource mapping. Pure fixtures cover domain, planning, preview, execution, filesystem policy, CAD process handling, view models, and catalog editing. Most CAD fixtures replace accoreconsole.exe with a .cmd file that copies a prepared result file to {stem}.result.json and the input file to the scratch folder, and the planner fixtures use a fake ICadPreviewer. CadLiveTests runs the embedded rs_xrefs.lsp through CadPreviewer, CadXrefDiscovery, PreviewPlanBuilder and CadExecutor with real AutoCAD Core Console. Each test is ignored unless ACCORECONSOLE names an existing file. The fixture does not search PATH or Autodesk installation folders. Select it with ./test.sh test --tool RECORDSET --scope pure --fixture CadLiveTests on a machine with AutoCAD. The fixture creates DWGs in a temporary folder and removes that folder in teardown. It checks a relative attachment, a nested attachment and an Xref inserted only inside a local block, their planned copies and stored-path maps, repath readback, and Bind All from source-relative paths. Readback occurs after removing the source drawings. It exercises CAD plan items directly, without opening a Revit host.

The fixture script uses these AutoCAD command sequences:

  • LINE: first point, next point, end input.
  • SAVEAS: default file format, filename, with FILEDIA=0.
  • -XREF Attach: filename, insertion point, X scale, Y scale, rotation. REFPATHTYPE=1 selects relative paths after the host has a filename.
  • -BLOCK: name, Mode/Convert, base point, selected Xref insert, end selection.
  • QSAVE: save the named drawing without a filename prompt.

Revit-hosted tests under Tests/Integration/Revit/ cover TransmissionData and WPF application behavior.

WPF fixtures share WindowRuntimeScope, which releases only runtime state it installs. The hosted bootstrap supplies the Revit owner. Modal tests use ToolWindowDialog.Show with synchronous callbacks and a ten-second watchdog. The watchdog cannot interrupt native code or callbacks that do not pump the dispatcher.

The CAD selection test uses a modeless test session to await preview/edit cycles outside a modal callback. It checks the selected node, ancestor expansion, CAD state, and manual Xrefs after rebuilds. Production remains modal. The execution fixture checks real copied bytes, the manifest, and lock release. Filesystem tests cover destination junctions and redirected manifest paths.

Limitations

Execution has no UI cancellation action and can leave partial output on failure. Inspect the log and outcome manifest before retrying or removing output. CAD script limitations are specified in the technical specification.

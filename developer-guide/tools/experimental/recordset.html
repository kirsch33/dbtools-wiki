DBTools.RecordSet - the assembly behind Record Set

SYNOPSIS

DESCRIPTION

RecordSetCommand calls AppLauncher.Launch, which opens the modal Record Set window. The window builds an ExecutionPlan, an ordered list of PlanItem records, and shows it as a tree. Planning reads files, Revit TransmissionData and Core Console listings, and writes nothing to the target. ExecutionPlanExecutor runs the plan and is the only writer there. The user page describes the behavior.

CONTRACTS

  1. Common links. PlanningService.BuildContext counts links by ExternalReferenceKey: the full path from WindowsPathOperations.NormalizeCaseFullPath, and the LinkType. A key that occurs twice or more is common, and TargetPathRules.ComputeLinkTargetPath puts it in Common Linked Files. PlanningWorkflowTests and TargetPathRulesTests check this.
  2. Destinations. PreviewDestinationAllocator keeps one source for each destination. Another source gets name (n).ext, with the lowest free n from 2, and the plan gets a Warning. PreviewDestinationAllocatorTests checks this.
  3. Embedded policy. PolicyReader reads only the embedded resource. ValidatePolicy throws for a policy that breaks its schema, and for a root that is not a drive path or a complete UNC share. No code reads delete_mode, require_sentinel_for_delete or SafeOperationRuntime.TrashRoot. PolicyReaderTests checks this.
  4. Preflight. Before the lock, ValidatePreconditions reloads the policy, checks the root, and checks that each output path of each item is under the target. It requires free space minus max(TotalBytes, PredictedOutputBytes) to be at least min_free_bytes (10 GiB in the shipped policy). A failure writes no lock and no manifest. ExecutionPlanExecutorTests checks this.
  5. Contained writes. SafeFileSystemOperations resolves junctions and other redirects before each containment check. CAD and Revit items check their host path again directly before the adapter call. The check and the write are separate operations, so a path that changes between them is not caught. SafeFileSystemOperationsTests checks the redirects.
  6. Lock and manifest. The lock uses FileMode.CreateNew. After the lock, the executor writes a manifest with the status ok, cancelled or failed, and always tries to release the lock. cancelled needs owner cancellation, and the window passes CancellationToken.None. FailurePrecedence rethrows a single failure, or throws an AggregateException of all failures, the first one first. ExecutionPlanExecutorTests checks this.
  7. Bind All. The preview plans CadBindAllItem only when CadXrefDiscovery.BindRefusals is empty for the whole Xref graph. Before each bind, the executor lists the graph again and throws on a refusal. PreviewPlanBuilderTests and PlanExecutionWorkflowTests check this.
  8. Core Console results. CoreConsoleRuntime.RunScriptAsync accepts a run only with exit code 0 and a result file whose JSON has "ok": true. CadExecutor also requires changed to name every planned Xref, and unbound to be empty. CadExecutorTests checks this.
  9. Revit repath. RevitOperations reads desired reference data when the file is transmitted, else last-saved data. It skips PathType.Content. It resolves a relative path from the host folder, or from the central folder for a workshared local. It keeps the path type and the load state. It writes only when a reference changes, and then sets IsTransmitted = true. The Revit test TransmissionDataAdapterTests checks all but the central folder.
  10. CAD options. A null PlanOptions member follows Core Console availability in each preview, until the user changes an option. PreviewPlanStateTests and RecordSetWindowViewModelTests check this.
  11. Execute failures. ExecuteAsync runs through RunWithoutThrowingAsync with a null notifier, so no banner appears. A failure is logged once and opens the logger window. ExecuteCommand_WhenCompletionAlertFails_ContainsFailureAndRestoresBusyState checks this for one failure.

FLOW

  1. HostImporter.ImportHosts calls PlanningService.ScanHost for each host. A RevitOperationException rejects only that host.
  2. Each edit clears the preview. The debounced sync calls PlanExecutionWorkflow.SyncPreviewAsync in Task.Run.
  3. PreviewPlanBuilder.BuildPlanAsync runs PreviewPlanState.Create (finds Core Console), PreviewHostPlanner.PlanHostsAndLinks, PreviewCadPlanner.PlanAsync (each DWG destination once, with the CAD settings of its first host), PlanRevitRepaths, PreviewPlanTotals.CountCopyBytes, PredictOutputBytesAsync and PreviewPlanTotals.Complete (limits, summary, fingerprint).
  4. PlanExecutionWorkflow.ExecuteAsync opens a progress overlay that cannot be canceled. The executor writes the lock and the sentinel, runs the items in order, writes the manifest and releases the lock. Progress is the weight of the completed items over the total weight.
Item Segment action Weight
FsCreateDirItem fs_create_dir 1
FsCopyItem, CadCopyItem fs_copy, cad_copy 3
CadRepathItem cad_repath 2
CadBindAllItem cad_bind_all 4
RevitRepathItem revit_repath 2
UIWarnItem, UIInfoItem ui_warn, ui_info 0

Each item record in Features/Domain/ passes its PlanAction and weight to PlanItem and builds its ToFingerprintSegment text. An added item type needs a case in ExecutionPlanExecutor.ExecutePlanItemAsync, which throws for an unknown item, and in ValidatePreconditions for its output paths. The fingerprint is the SHA-256 of the segments in plan order, cut to 16 lowercase hexadecimal characters. It identifies the plan in the lock and the manifest.

Core Console

CoreConsoleRunner writes <stem>.scr, <stem>.input.txt and <stem>.result.json in the temporary folder. The .scr file holds the script lines and then one call of an entry function. It does not load the script, because SECURELOAD refuses a file from the temporary folder. After accoreconsole.exe exits, the runner stops the Autodesk helper processes that remain in its process tree.

accoreconsole.exe /i "<dwg>" /s "<stem>.scr"
rs-list-xrefs       result: xrefs (name, path, found, overlay, inserted, inblock)
rs-repath-xrefs     input: name, stored path, new path; result: changed, unmatched, failed
rs-bind-all-xrefs   input as above, argument BIND or INSERT; result adds bound, unbound

The script writes its result with (open result "w" "utf8"), which needs the Unicode AutoLISP engine (LISPSYS 1 or 2).

DIAGNOSTICS

Log lines start with [RecordSet]. A Revit failure reads Revit operation '<operation>' failed for host '<path>': <reason>. A Core Console failure names the function, the DWG, the exit code, the result text, standard error and standard output, each cut to its last 2,000 characters.

TESTS

./test.sh test --tool RecordSet                            # pure: DBTools.RecordSet.Pure.Tests
./test.sh test --tool RecordSet --scope local -y 2026      # -y 2027 for Revit 2027
./test.sh test --tool RecordSet --fixture CadLiveTests     # DBTools.RecordSet.Cad.Pure.Tests

Pure tests cover planning, the policy, execution, the file system, the CAD adapters with a fake accoreconsole.exe .cmd file, and the view models. CadLiveTests is in its own project in the pure scope, so the default run skips it. It runs rs_xrefs.lsp in a real Core Console on generated drawings, and it is ignored unless ACCORECONSOLE names an existing file. Local tests cover composition, the view model in Revit and TransmissionDataAdapterTests, which opens sgt_test_model.rvt and its linked model (Model paths).

Global Mapper (GM)

Overview

Global Mapper finds duplicate or related Revit content, captures mapping intent, and previews and applies replacements through Commit Review. Its main window is modeless. Commit Review is modal and keeps a reversible apply group open until the user keeps or rolls back changes. The architecture specification defines state, capture, execution, and lifetime contracts. The user guide describes mapping workflows.

WPF presentation

GmWindowPresenter loads App/Views/GmWindow.xaml through ToolWindowFactory. Its binding source is App/ViewModels/GmWindowViewModel. Commit Review binds to Features/CommitReview/ViewModels/GmCommitReviewWindowViewModel. The runtime and design-time view models expose raw fragment bytes for six feature panes. Stable GmRawViewConverter parses those fragments. OneTime fragment bindings use the nearest categoryTabs ancestor. The host assigns shell and raw-root DataContext synchronously before the first dispatcher pump, so the first DataBind/layout pass can materialize each pane. OneTime retains it across tab switches. Feature panes bind to their feature view models. Parent commands, category selection, and empty-state labels address the shell DataContext.

Stable WPF registrations, controls, converters, selectors, attached behaviors, and shared resources live in src/DBTools.Presentation/Tools/GM/, namespace DBTools.Presentation.Tools.GM. Each raw view merges Presentation’s Resources/Theme.xaml and references stable dictionaries with versioned ResourceUri values. GmViewResources.xaml owns Mapping and Similarity styles without a second theme merge. Payload views have no code-behind, dependency properties, or implicit payload-type templates. Bindings use INotifyPropertyChanged sources or OneTime for immutable values. Raw templates use string keys with explicit fallbacks. GmViewXaml exposes embedded bytes for raw-XAML tests and hosted views. App Pure reads the GM assembly's fixed logical resources directly.

Mapping target ComboBoxes use GmComboBoxDropDownCommandBehavior. It runs the selection command at Background priority when an open drop-down closes with a different logical item. It also runs the command when WPF changes a closed combo's selection through keyboard navigation or TextSearch. WPF uses Up and Down to select adjacent items while the drop-down is closed. For noneditable combos, Left and Right also select adjacent items, and Home and End select the first and last items. Page Up and Page Down navigate only while the drop-down item host is visible. Binding, refresh, and option-population changes outside those input routes do not run the command. The open command supplies lazy options when the user opens a target combo.

Commit Review owns one Revit callback around planning, ShowDialog, finalization, and refresh. Core WindowOwnerModalityScope disables Revit and other top-level windows through that callback and restores only the windows it disabled. During planning, the GM owner remains available for its overlay and Cancel action. ShowDialog disables that owner while the review dialog is visible. User close returns the session finalization. Forced retirement returns none. IsRetired is true for both outcomes and cannot distinguish them. Keep triggered from WPF Closing queues the final Close because WPF rejects reentrant Close there.

Duplicate Type Mapping uses a registered modeless shell owned by GM, with Manual startup and a taskbar entry. Commit Review also retains Manual startup, an explicit finalization decision, and a cleanup close gate. Cleanup requests cancellation, waits for a safe rollback boundary, and propagates cancellation, timeout, or rollback failures. A failed cleanup leaves the review window open. Row refresh and owner closure follow successful cleanup.

Design-time shared-parameter composition uses the production feature/projection graph with explicit host replacements, including NoopFamilyParameterQuery. Authoring receives a registered parameter-signature provider.

Workflows

Startup performance

Startup logs Information-level elapsed time for five overlay steps. Usage indexing logs each catalog/index source duration and completion state. Failure or cancellation records the interrupted step and elapsed time, including queued Revit-call time. Overlay visibility is not the timing source.

Family population counts use one symbol-count sweep. Type IDs retain collector order and cache per project state. View-owned collection discovers owner IDs through a quick filter, then visits eligible owners with instances, retaining Revit view-visibility filtering. Style/material indexing share one capped sample and 25-instance chunks with separate geometry options. Family-dependent styles are visited once per usage build. Each option-building pass owns immutable name profiles and retains numeric-suffix and multiset-bigram scoring.

Features/Usage/FamilyFastIndex/UsageFamilyFastIndexCollector records material and object-style evidence without Revit types. It keeps distinct paths, direct and nested usage flags, and maximum depth for each positive ID. UsageFamilyFastIndexBuilder reads a placed instance through Revit and supplies traversal contexts to the collector.

Row refresh and UI dispatch

App/Sessions/RowRefresh/CrossPaneRowRefresh owns every cross-pane row refresh trigger and its order: filter change, Usage page activation, startup, Usage publication, category change, Deep Scan, saved-mapping clear, and commit with Continue or Close. Each trigger is a named method that documents its order. FilterRefreshWorkflow, PageActivationWorkflow, and StartupRowWorkflow call these methods.

Domain/ProjectState/ProjectStateStore owns the family inventory: FamilyIds, the positive SymbolIds, FamilyInstanceCounts, and SymbolToFamily. A project-state replacement derives the inventory from the new state. A fresh family scan and a category snapshot restore replace it through ReplaceFamilyInventory. Name resolution, initialization, Deep Scan, and snapshot storage read the store when they run.

The session operation gate, pending page selection, Duplicates pane rebuilds, Usage publication, option rendering, and Family Mapping inline previews dispatch UI work through the GM window's dispatcher, which WindowSessionServices provides after the window exists. They do not use the ambient application dispatcher or the default owner registry.

A failed option-rendering refresh shows one "GM Option Rendering" error banner. A replacement refresh and the close drain do not report it again. A failed debounced Duplicates rebuild shows one "GM Duplicates Rebuild" error banner.

Testing

Pure tests mirror App, Domain, and Features owners. Test builders, external fakes, and assertions live in Tests/Support. Project-state and name-cache tests live under Tests/Domain. Duplicate projection tests live under Tests/Features/Duplicates. The root Revit name adapter mirrors its complete path at Tests/Integration/Revit/Revit/ElementName/ElementNameQueryTests.cs. CommitReviewPlanContextTests mirrors Features/CommitReview/Planning. Saved mappings, authoring, and usage matching also mirror their subjects.

UsageFamilyFastIndexCollectorTests directly tests fast-index aggregation in the Pure suite. UsageFamilyFastIndexBuilderTests checks extraction from placed instances and missing-sample handling in Revit.

Tests/Integration/Revit/App/Sessions/Revit/GmModelessSessionTests.cs launches the production session through its queued App run scope and GmWindowViewModelBuilder. It observes the raw view in the stable shell on the dispatcher. Normal-close tests overlap close requests and await shared completion, shutdown, one Closed event, cleanup, and scope disposal. Retirement tests wait for Idle, retire synchronously, and check collection without another dispatcher pump. ForcedRetirement_AfterApply_RollsBackTheOpenGroupAndReturnsWithoutHanging retires after a real apply and checks model restoration and group finalization before child-scope disposal in the same Revit turn.

Revit-hosted Commit Review tests use testing/TestSupport/GM/Fakes/HiddenCommitReviewDialogHost in place of ShowDialog to satisfy hidden-desktop window ownership. Its dispatcher frame ends on retirement. IToolWindowSession.Closed does not complete after forced retirement, so awaiting that event would retain the Revit callback until timeout. A 60-second deadline retires a session left open and fails the test.

GM Revit-hosted fixture models, named views, family symbols, line styles, materials, and expected production outcomes are required repository baselines. Missing baselines and false production results fail with the model path and running year. Fixture teardown and transaction-group finalization failures also fail and are aggregated with a primary test failure when both occur.

DBTools.GM.Pure.Tests.csproj contains owner-local fixtures and shared test support and references the desktop DBTools.GM.csproj. The production assembly grants the Pure assembly internal access. Revit references are compile-only; loading a Revit-typed member requires a Revit host.

The repository wrappers run the GM checks. Run the ones that the change can affect (Choosing checks):

./build.sh BuildApp
./build.sh BuildTests
./test.sh test --tool GM --scope pure
./test.sh test --tool GM --scope local -y 2026

The Pure project targets net10.0-windows and requires Microsoft.WindowsDesktop.App. Revit-hosted tests use the local scope through the daemon fleet.

Limitations

The session key uses the document hash code, which can collide. The specification describes family-document and line-style limits.

Global Mapper architecture specification

Overview

Global Mapper (GM) collects Revit content, builds mapping intent, and executes reviewed replacement plans. This specification describes its state, execution, persistence, and lifetime contracts. Source: src/Tools/Common/GM/. GM describes entry points and test surfaces.

Architecture

Composition and document scope

App/Composition/Revit/GmModelessSessionFactory captures the launch UIDocument and Document and creates a QueuedModeless App run scope through GmSessionDocumentGate.CreateBoundScope. That helper binds the scope's concrete gate to the launch document before it returns the scope, so no consumer resolves an unbound gate. A binding failure disposes the new scope. The gate compares DocumentSessionKey values on each callback. The key uses the document hash code for session scoping. It does not guarantee collision-free identity. The persistence key is the nonblank document path, or the title|path|hash text of that captured session key for an unsaved document. Unsaved documents load saved data only under their captured session key.

AddGm() registers the concrete GM gate without replacing shared IRevitCallGate registrations. Each feature registers its host-neutral services through a *ServiceCollectionExtensions class in its Composition folder and its Revit adapters through a *RevitServiceCollectionExtensions class in its Revit/Composition folder. AddGm() reaches them through two lists: AddGmFeatureServices() in App/Composition and AddGmRevitFeatureServices() in App/Composition/Revit. The Revit list registers Mapping's IChangeWriter implementations before Shared Parameters adds its own. App registers only project state, UI state, session composition, and the gate. GM Revit readers, writers, family batches, transaction runners, and Commit Review consume the concrete gate. RevitMappingPlanExecutor rejects an invalid document or session-key mismatch before writers begin. RunCleanupAsync uses the underlying gate with CancellationToken.None so owned documents can close after authority or work cancellation ends.

Commit Review uses the bound parent gate to create an InlineUi child scope through the same helper, bound to the expected document. It resolves apply services only after the helper returns. One outer Revit callback contains planning, modal review, apply, finalization, and refresh. During that modal session, forced-queue, off-thread, or second-callback work is refused.

AppSessionProjectionBuilder.CreateProjection receives the host-neutral SessionExecutionContext, the dialog context, the mapping session, the workspace (including a required IViewOps implementation), and feature services. It returns AppSessionProjection: the panes, the session's one MappingConflictViewModel, type creation, the shared-parameter loader, and the row refresh graph. Runtime and design-time composition use that conflict instance. SessionExecutionContext carries the session's executor, logger, error notifier, operation gate, workspace signals, row signals, live-plan update suppression, and origin-clear suppression. The runtime wraps that same session context in MappingDocumentExecutionContext, exposed as Session, with its ExpectedDocument. The bound gate carries the session authorization key. Host-neutral panes and rows receive the session execution context. Commit Review receives the document execution context. Authorization identity and persistence identity have separate consumers. WindowSessionServices supplies the attached owner and progress overlay. BannerNotifierFactory uses that owner. Before Attach, every overlay member, CancelRequested included, throws InvalidOperationException. Dispose is idempotent and terminal: overlay members and Attach then throw ObjectDisposedException. The owner provider outlives disposal, so a failure notification queued after the window closes still resolves its owner. GmWindowAttachment supplies feature dialogs with a late-bound getter for the attached window. Design-time composition uses explicit host-neutral collaborators, including DesignTimeViewOps.

AppSessionBuilder constructs startup, initialization, Deep Scan, preference clearing, background prewarm, Family Mapping commands, pane lifecycle, disposal workflows, and the AppSessionRuntime with its OperationStateReaction and GmWindowPresentationProjector. It passes UIStateSession.Create and SessionWorkflows.Create the session's executor, logger, and error notifier, plus the operation gate for UI state, rather than the session execution context. PaneViewModelBuilder returns PaneComposition: the panes and the Family Mapping scan, row refresh, type creation, and row set. RowRefreshFactory builds one row collaboration graph per session and returns RowRefreshComposition: CrossPaneRowRefresh, RowRefreshCoreServices, CommitReviewRowServices, UIStateFactory, and OptionRenderingRefresh.

App/Sessions/RowRefresh/CrossPaneRowRefresh sequences Usage rows, Family Mapping refresh, indicators, live-update suppression, row locks, and workspace events. Each cross-pane trigger is one named method on it: RefreshRowsAfterFilterChange, RefreshRowsAfterUsagePageActivationAsync, RebuildRowsAfterInitialLoad, RefreshRowsAfterUsagePublication, ScanFamiliesAsync, RebuildRowsAfterDeepScanAsync, RefreshRowsAfterSavedMappingClear, RefreshRowsAfterCommitAndContinueAsync, and RefreshRowsAfterCommitAndClose. It implements feature-owned ICommitReviewRowRefresh, IFamilyMappingCrossPaneCommands, and IDeepScanUsageRefresh. FilterRefreshWorkflow, StartupRowWorkflow, and PageActivationWorkflow call those triggers. App/Sessions owns session records and runtime lifetime. Composition owns construction. Feature implementations do not import DBTools.GM.App.

FamilyMappingFactory returns FamilyMappingComposition: FamilyMappingViewModel, FamilyMappingScanWorkflow, FamilyMappingRowRefresh, FamilyMappingTypeCreation, and one MappingRowSet spanning family/type and supplied Usage rows. FamilyMappingScanStateApplier belongs to scan sequencing. The row builders and refresh owners receive the same row set. The factory shares one FamilyMappingState across these objects. FamilyMappingState.SelectedFamilyRow holds the selected family row. FamilyMappingViewModel.SelectedFamilyRow reads and writes it, raises one notification per change, and loads the row's views when the workspace is ready and the row is not null. FamilyMappingScanWorkflow and FamilyMappingScanStateApplier capture and restore the selection on the state.

Public surface and resources

GM production payload types default to internal. Manifest activation requires public GmToolModule and GmCommand. Public conflict projection values retain their public binding properties. Dependency objects, converters, selectors, and attached behaviors are stable public Presentation types. The design-time view models are internal with public binding/fragment properties. Sandbox and production consume the same raw resources and fragments. Compiled resource validation checks manifest logical names. Materials and Object Styles reuse UsageFamilyListStyle, UsageFamilyItemContainerStyle, and UsageFamilyRowTemplate from Presentation/Tools/GM/GmViewResources.xaml. Each pane supplies its own family list and selection. The shell supplies double-click navigation. The row supplies the context-menu apply command. Mapping options expose nullable SimilarityScore values. Presentation GmSimilarityBrushConverter owns the brush bands: 90–100 Success, 70–89 Secondary, 50–69 Warning, and 0–49 Muted. A null score uses Body. Alphabetical rendering retains ranking Score values but leaves SimilarityScore null. The converter resolves score brushes through the owning Window resource dictionary. Missing keys yield Gray. Detached elements use their own resource scope. Blank, disabled, separator, and Deep Scan template states use DynamicResource brushes.

Data and contracts

Domain and feature contracts

Shared value language

Domain/ owns the value language that several features share, and it imports no feature namespace. Domain/Mapping owns MappingKind and its extensions. Domain/MatchingOption owns MatchingOptionKind, MatchingOptionCandidate, and MatchingOptionSortMode. Domain/Categories owns CategoryOption and CategoryReference. Mapping keeps the WPF-bearing MappingRow and MappingOption presentation types and the intent, conflict, operation, plan, and execution behavior.

Project state

Domain/ProjectState owns ProjectState, family/type records, reference index/values, project parameters, scan state, projection, and the scoped ProjectStateStore. The store imports no feature or App namespace. CurrentProjectState and CurrentProjectStateCategoryId identify the loaded snapshot and its category in one replacement operation. IProjectStateBuilder and ProjectStateBuildRequest are inward contracts. App/State/ProjectStateBuilder queries Families, Usage, Shared Parameters, and Previews and projects their results into those values.

Family-only refresh retains loaded Usage and Shared Parameters sections and invalidates derived usage caches before preparing rows. A failed build preserves published state. Commit Review planning builds the selected category plus pending-intent owner families without publishing. CarryForwardInto supplies loaded sections and unchanged-family Deep Scan evidence to that planning state. Duplicate detection also stays unpublished. CarryDeepScanEvidenceInto supplies only unchanged-family evidence to its fresh full state.

The ProjectStateStore retains evidence across category-filtered state replacement. A rebuild restores it only when the family's type set and per-type instance counts remain unchanged. After commit, ReplaceProjectStateAfterCommit discards directly changed families and containing ancestors across all categories. Direct changes include mapped/owning families, families of mapped types, and material/object-style families found by AffectedFamilyResolver. Commit Review planning uses that same resolver. Its plan context owns planning identity and evidence. Discarding evidence removes scan state, type payloads, DeepScanResults, and fast parameter discovery together.

Element names and categories

Domain/ElementNames owns IElementNameQuery, ElementNamesCache, and ElementNameLookupKind. Revit/ElementName/ElementNameQuery implements the Revit adapter. App registers it with state/cache wiring. Categories registers curated-category services. ElementNamesCache exposes read-only family, type, style, material, and category name views. Each view reflects later merges and clears. Only the cache writes names: MergeNames, MergeFamilyAndTypeNames, name loading, Clear, and ClearFamilyAndTypeNames. A merged nonblank name inserts or overwrites the entry. A blank or omitted name keeps the cached entry. Strict name loading requires a nonblank cached name for every requested ID. The cache stores no blank name, so a missing name is queried again. Omitted/blank provider values stay unresolved. GetResolvedFamilyName prefers cache, then project-state family name, and throws if neither exists. GetCachedFamilyName uses the same order and returns null instead. GetCachedTypeName, GetCachedMaterialName, and GetCachedStyleName return the nonblank cached name or null. A name equal to its ID text is a name. Display getters retain explicit ID/unavailable-name fallbacks. Duplicate family and type names prefer the names captured with the detection, then cached names. A missing family, style, or material name falls back to a nonblank candidate name, then the ID text. A missing type name shows Type <id> (name unavailable).

WorkspaceState.SelectedCategory is the single typed CategoryOption value exposed by IWorkspaceState. CategoryFilter derives its display label. Null and Id zero select every family. Other signed IDs select exactly that category, including negative built-in Revit IDs. Both IFamilyQuery methods use those rules. GetFamiliesAsync reuses state only when category identity matches, families exist, and all family names are nonblank. It still filters the reused result by the requested category.

WorkspaceState.SortMode uses MatchingOptionSortMode through mutation, persistence, restoration, and option projection. CurrentProjectStateCategoryId identifies loaded state. FamilyMappingState.AppliedCategoryId identifies applied rows. Applying a different category resets category-scoped rows before application and records the category only after rows apply. Cancellation between state publication and row application therefore causes a reset on retry.

Mapping intent, rows, and conflicts

Features/Mapping/Domain owns immutable intent, conflict, operation, plan, and host-free execution values. It uses the shared kinds from Domain/ and does not import mutable Rows types. MappingIntentKey validates its nine-field shape through named factories and FromPersisted. It rejects invalid zero identities while retaining signed category IDs such as -2000011. MappingIntentStore stores a ParameterMappingIntentSnapshot for a Parameter key, a SharedParameterMappingIntentSnapshot for a SharedParameter key, and an ElementMappingIntentSnapshot for every other kind. An update with another snapshot type throws ArgumentException before it runs the callback or changes the store. Style and material source and target IDs are positive. AffectedFamilyResolver returns no families for a nonpositive ID. Commit Review planning fails an applied style mapping with a nonpositive source or target as an invalid mapping.

The Rows package owns row-to-intent translation, projection, origin mutation, and family-apply behavior. Conflict/Rows owns row conflict matching. Detection consumes an immutable MappingSelectionSnapshot. MappingConflictWorkflow hydrates returned MappingIntentKey values into loaded rows. MappingConflictTarget defines three closed variants: a positive element selection, a type-parameter policy, or a display-only message. Resolution chooses an original side or an explicit MappingConflictBulkAction. Display labels and sentinel IDs do not encode executable policy. Duplicates implements Mapping-owned neutral selection/resolution contracts without exporting its own selection types.

Mapping owns the session and document execution contexts, row signals, navigation values/lifetimes, MappingUpdateSuppression, and OriginClearSuppression. Mapping Domain/Planning owns nested-family, style, and type-reference plan language. Commit Review's CommitReviewDocumentEditBuilder owns mutable family-batch assembly. Mapping's neutral composition registers MappingIntentStore. Commit Review composition registers CommitReviewPlanVerifier. Revit/Composition registers mutation adapters, attached through AddGmRevitFeatureServices. Shared Parameters implements Mapping's focused embed port and uses Mapping operation identities.

Domain/Parameters/FamilyParameterDiscoveryResult carries normalized ScopedParameterName values, complete/partial state, and contextual read errors. ProjectStateStore.GetDeepScanParameterDiscoveryForFamily uses completed family scan state first, then DeepScanResults. Family Mapping uses that lookup for both scan availability and parameter names. Complete discovery supplies names. Partial discovery uses complete fast discovery when available, otherwise it clears the names. Family Mapping and Shared Parameters publish choices only from complete discovery. Their factories and consumers require IFamilyParameterQuery and ISharedParameterQuery. Shared Parameters also requires ICuratedCategoryQuery. Duplicate parameter scoring requires complete discovery on both sides. Instance/Type suffixes are display labels. Parameter mappings retain scope and require equal source/target scope.

Element identities

Revit family, type, instance, material, style, view, and category IDs use long. Revit boundaries use ElementIdConverter.ToLong and FromLong. Saved-mapping and UI-state JSON accept integer-valued number tokens, including values in the 32-bit range. Family-document materials resolve by name rather than host numeric ID.

Counts, indexes, depths, enum/order casts, synthetic duplicate group IDs, SharedParameterDuplicateMatcher sequence IDs, and MappingOption.StableStringId hashes use int. SharedParameterValueCopier rejects Map From values outside Int32 for Revit Integer storage. ElementId parameter destinations parse Map From text as long.

Persistence and saved mappings

Domain/Cache owns tool-wide cache results and metadata. Persistence adapters derive the GM root with AppPaths.GetToolCacheDir("GM"). UI-state and saved-mapping stores create their directories when writing. App/Persistence owns document UI-state storage. App/Sessions/UIStateLifecycle sequences the session's startup restore and close persistence. StatePersistence requires both IUIStateCache and ISavedMappingStore in production. Design-time projection does not construct unused persistence.

JSON writes flush a unique sibling temporary file and publish it atomically. Cancellation or I/O failure preserves the last good snapshot. Only confirmed missing files/directories count as absent. Access, sharing, invalid-path, and other I/O faults propagate. UI-state and Deep Scan snapshots are disposable caches: malformed, invalid, or old snapshots are discarded and logged. Saved mappings are user data and use strict nullable-ingress validation with contextual failures. Cache results are immutable hit/miss values. Hits always contain data. Persistence and cache stores propagate unhandled failures to the operation boundary for logging. DeepScanCacheCoordinator retains warnings for hydration failures, key preparation failures, and optional cache writes.

DocumentPersistenceCoordinator is a root-provider singleton shared by scoped StatePersistence and IUIStateCache instances. It owns the document gate, cache mutation gate, and separate UI-state/saved-mapping clear generations. IUIStateCache serializes asynchronous writes and document clears with the cache mutation gate. StatePersistence serializes document loads, clears, and saves and tracks separate UI-state/saved-mapping clear generations. An older open session cannot restore either snapshot after another window clears it. A freshly loaded window can persist new state. UIStateLifecycle attempts enabled close writes independently, retains failures in write order, and resets one-shot suppression even on failure. Confirmed clears drain before close persistence and disposal. PaneStateProjector supplies SavedAt. Saving preserves the supplied timestamp.

Saved Mappings validates exact document identity and every persisted key before admission. Parameter mappings retain ScopedParameterName scope. The persistence port exposes load, save, and clear. MappingIntentStore owns merging. Commit Review constructs the restore workflow, merges persisted intent, and reapplies through row owners.

Clearing saved mappings follows this order:

  1. Remove saved origins/selections from loaded rows.
  2. Clear mapping intent, duplicate intent, and the in-memory persisted list.
  3. Clear storage.
  4. Run the required App-bound refreshRowsAfterSavedMappingClear operation.

CrossPaneRowRefresh rebuilds loaded Usage rows, refreshes Family Mapping rows, reconciles indicators under suppression, releases suppression, refreshes locks, and publishes cache status. Reapply calls Usage, FamilyMappingRowRefresh, Shared Parameters, and row locks directly.

Option cache and similarity

MappingOptionCache keys candidates by mapping kind, source ID, category, ordered target ID/name pairs, and source label. Category lookup does not fall back to general entries. Prewarm uses the same identity. Candidate snapshots use private read-only lists, so replacing entries cannot mutate earlier results.

NamingSimilarity.Normalize and numeric-suffix stem comparison retain letters/digits in invariant lowercase. Numeric-suffix siblings with equal cleaned stems score 1.0 before Dice evaluation. Dice uses lowercased raw-name bigrams, including punctuation and whitespace, with multiplicities. Its score is twice the multiset intersection divided by the sum of raw lengths minus two. For a raw length below two, equal raw lengths score 1.0 only with equal nonempty cleaned stems. Other short-name pairs score zero. Each scoring pass owns its immutable name-profile cache.

Deep Scan

Deep Scan owns family scans, projection, usage resolution, feature cache, and refresh workflow. DeepScanCacheCoordinator requires DeepScanCache, IFamilyParameterQuery, and IDeepScanUsageResolver. Successful usage resolution carries Resolution, which requires its style, material, and nested-family ID collections. Failed resolution carries FailureReason. Family scan StyleIds and MaterialIds contain element IDs. ProjectStateStore.InvalidateDeepScanUsageProjections invalidates cached projections, which recompute on the next read. A user scan collects a complete family batch and finishes cache preparation before one validated ApplyBatch admission. Usage refresh data is prepared before completed scan state publishes. Cancellation or required failure before admission preserves the prior projection.

Host lookup completeness is separate for styles, materials, and families. An item failure marks only its domain incomplete and prevents partial singleton-name resolution or resolver-cache reuse. Other complete requested domains remain usable. Affected families retain warning diagnostics and incomplete usage. Unexpected collector/category traversal failures abort construction. Partial parameter discovery invalidates fast choices, is omitted from duplicate scoring, and removes prior reusable cache entries before admission. A later complete query can repopulate choices. Partial usage remains visible but cannot become reusable complete cache data. DeepScanCacheCoordinator removes prior reusable entries for incomplete parameter discovery or usage scans before admission. Failure to resolve a removal identity or remove an entry propagates and prevents admission. A cache write failure without required removals logs a warning.

Cache operations use a local persistence gate plus an exclusive per-file process lock. Each batch reloads authoritative disk state once while holding both. Startup hydration reads eligible families against one load. User scan removes/writes its family batch with one load and one atomic save. This serializes owners across Revit processes. Disposal drains persistence before releasing the DI-root owner. Snapshot admission validates entries and parameter/usage completeness flags as a whole. It discards incompatible snapshots rather than salvaging entries.

Clear Cache holds a session-lifetime registration through deletion, projection/UI refresh, and completion. It shares session-operation admission with scans. Shutdown drains it before disposing collaborators. A confirmed clear increments DeepScanOrchestrator's generation after disk deletion and before projection clearing. Hydration rejects its whole candidate batch if that generation changes or the captured ProjectState reference changes during reading. It never replaces an already completed family scan.

CrossPaneRowRefresh implements IDeepScanUsageRefresh: apply Usage data, rebuild loaded rows when needed, reconcile Family Mapping state/indicators under suppression, refresh locks, then await the Shared Parameters authoring rebuild. DeepScanRefreshWorkflow invalidates options and awaits that refresh. That rebuild evicts authoring snapshots and rebuilds the loaded tree with pending intent and selection. Completion events describe changed cache state and publish even when rebuilding faults or cancels. The outcome then propagates to the operation boundary. Eligible-cache hydration finishes only after its queued UI refresh runs.

AuthoringRebuildWorkflow serializes rebuild and application. If evidence invalidates during a build, including the first build, it builds again before applying. Disposal cancels held/queued rebuilds and prevents later application.

Duplicates

The Duplicates feature owns detection, selections, rows, resolution, tree, pane state, and type mapping. Detection/DuplicateDetectionEngine calls the family, style, material, and shared-parameter matchers, assigns aggregate group IDs, and returns DuplicateDetectionResult. The feature's Domain, Selection, Rows, Resolution, Tree, Pane, and TypeMapping folders own their respective contracts and behavior. SharedParameterDuplicateMatcher lives beside family/style/material matchers under Detection/Matching. CurrentDuplicateDetection owns the last fully completed artifact. Detection collects its unpublished full state, executes stable DuplicateKind stages, hydrates names, then publishes and returns the same artifact reference. Earlier failure/cancellation preserves the prior artifact. Family-row counts use that same detection state.

The immediate rebuild receives the artifact explicitly. Other readers inject CurrentDuplicateDetection. Cached refresh runs a worker request on the GM window's dispatcher and waits for it. A reentrant request replaces the queued request. The outer refresh runs the latest queued rebuild before returning, including propagating its failure. The debounced rebuild runs in the pane's safe-execution boundary. A failure shows one "GM Duplicates Rebuild" error banner; rows that the rebuild cleared stay cleared. Cancellation, during the delay or inside the boundary, logs at debug level and shows no banner. Each request ends its pending state, IsRebuildPending, whatever its outcome. PreviewDuplicateMatcher matches style/material candidates only when both resolve to the same signature. Unavailable previews never match, including each other. Duplicates imports neither Shared Parameters nor Commit Review.

Families and Family Mapping

Families' neutral composition registers FamilyQuery and IFamilyQuery. Its Revit composition registers FamilyDocumentService, FamilyScanner, and scanner ports. IFamilyScanner has two operations, GetProjectSnapshotAsync and GetFamilyIdsAsync. Both select a category with one nullable signed ID: null or 0 selects every family. Any other value, including a negative built-in Revit category ID, selects exactly that category. The snapshot's includedFamilyIds add those document families to a category scope; they do not filter. FamilyQuery converts a null CategoryOption or an Id of 0 to a null ID. FamilyDocumentService owns document lifecycle/query, not Mapping material preparation. Families consumes its own IFamilyInstanceCountQuery, implemented by Usage's live source. A thrown Document.Close or false result is a cleanup failure under the shared strict close policy.

FamilyMappingViewModel owns binding state and interactions. FamilyMappingScanWorkflow owns asynchronous scan/cache/post-commit sequencing and its private scan-state applier. FamilyMappingRowRefresh owns row build/refresh, saved-mapping reapply, and usage reconciliation. PaneViewModelBuilder creates one FamilyApplyIntent and one UsageIntentReconciler on the session MappingIntentStore. The Usage pane, family presentation, and family selection receive FamilyApplyIntent. Only FamilyMappingRowRefresh receives UsageIntentReconciler. Type rows read ProjectStateStore.SymbolIds. A project-state replacement derives the store's family inventory and symbol-to-family map; a fresh scan replaces the inventory with the scanned families, their counts, and the positive type IDs of the current state; a category snapshot restore replaces it with the snapshot's copies. Ordinary category navigation reuses a category snapshot or matching loaded state. RescanFamiliesAfterCommitAsync discards every category snapshot and rebuilds from the document, including when category identity stays unchanged, so newly created types reach rows. App's CrossPaneRowRefresh sequences cross-pane work.

Usage

Usage owns indexing, matching/options, preview cache/versioning, rows, selection, traversal, and pane state. AppSessionProjectionBuilder constructs one UsageIndexLoader and FamilyUsage after session state, names, and operation gate exist. The loader retains those collaborators. It is not a context-free service. RebuildPlanningUsageIfNeededAsync returns Task and builds only a missing index when usage intent exists. RebuildUsageAfterCommitIfNeededAsync returns true only when it builds the index.

UsageIndexSnapshotBuilder starts and drains five catalog/index tasks, aggregates non-cancellation faults, and creates an unpublished candidate without touching the match index. Name resolution, project-state usage storage, and Deep Scan refresh preparation precede publication. Index publication aligns the match index, target universe, hydration generation, and option cache. UsageMatchIndex shares one in-flight family hydration among concurrent callers. An index publication invalidates hydration started against the prior generation.

UsageIndexPublished runs synchronously on the publishing thread, including workers. RowRefreshPublicationWiring dispatches row projection to the GM window's dispatcher and calls CrossPaneRowRefresh.RefreshRowsAfterUsagePublication, then the duplicate rebuild. Rows track publication version. Detect suppresses publication-driven duplicate rebuild and rebuilds once after scanning, retaining the keep target. Passive option projection suppresses intent capture. An unavailable saved target remains disabled for review. An explicit edit can clear or replace it.

UsageViewModel owns target selection and bound collection/preview mutation. Selection-family flow performs one family lookup, name hydration, and row population. UsagePreviewService owns calculation, caching, and request-version order. UsageWorkflow consumes IUsageIndexLoader and its own rows without App/Family Mapping imports or row locks. CrossPaneRowRefresh.RefreshRowsAfterUsagePageActivationAsync suppresses live-plan updates across loading, reconciliation, and indicators, then refreshes locks and cache state after suppression.

Shared Parameters and UI execution

Shared Parameters owns domain values, authoring, formulas, Revit adapters, rows, tree, views, and pane state. SharedParameterDuplicateReconciler owns stateful duplicate-row mutation and reentrancy. SharedParameterConflictProjector performs stateless tree/Commit Review projection.

Map From reads numeric formula inputs at the Revit boundary. The preview evaluator does not parse displayed parameter text. Measured values use Revit's display unit. Preview output uses 15 significant digits. Numeric preview accepts signed/unsigned E/e exponents, including substituted invariant G15 values. An unresolved parameter reference or function call fails the preview, and its error names the identifier. The projector shows that error as preview-unavailable text and leaves Revit formula validation unchanged. Formula mode returns zero from the value copier without target resolution or writes. The embed applier counts authored formulas separately from value updates: one formula has authored=1, updated=0, affected=1. MapFrom retains copied-value counts.

Detached Usage selection-preview and authoring property notifications use ISafeExecutor.RunWithoutThrowingAsync. The shared boundary owns logging/banners without rethrowing into WPF dispatch. Shared-parameter group/category/authoring work and contested overlay admission retain the UI context before collection mutation. Preview failures propagate to their owning command/tree-selection boundary for one report.

Commit Review planning and continuation

Commit Review planning resolves names, builds planning state, loads parameter groups, and prepares rows/usage inside one ISessionOperationGate operation. Collaborators do not reacquire that non-reentrant gate. The gate releases before the review dialog opens. Refresh takes a separate operation. Planning cancellation remains control flow. Other faults can produce invalid-plan state. Commit Review receives closing state and MappingSessionContext with IWorkspaceState rather than mutable App state. Planning/DocumentEdit owns mutable batch assembly. Report/OperationRows/OperationRowProjector produces family, pending, result, and error rows. Workflow owns apply/finalization. Revit/CommitReviewSessionFactory composes the child scope, planning, transaction groups, and modal presenter through the bound document gate. CommitReviewRowServices is feature-owned and constructed by App's row composition.

Commit continuation uses ICommitReviewRowRefresh, implemented by CrossPaneRowRefresh. It returns Refreshed, Canceled, or NoSelectedCategory. Only a successful family scan proceeds to usage preparation, family reconciliation, and row locks. Canceled stops through cancellation. NoSelectedCategory skips refresh without a success log. Committed mappings remain persisted in either case. The refresh workflow consumes ISessionOperationGate for busy state.

Commit-and-continue invalidates authoring snapshots, duplicates, and cached family views before rescanning. Returned outcomes rebuild the applied Shared Parameters tree. A successful continuation rescans Duplicates immediately when that page is active.

View operations and catalogs

ViewOps owns navigation. A positive missing element ID returns false without changing view or selection. Nonpositive IDs are argument errors. Unexpected Revit faults propagate. Previews owns cross-feature material/style catalogs and preview values.

Line-style eligibility

The shared line-style query checks the capability required by Revit commit. A grouped curve is restylable only when its group and every enclosing group have exactly one placed instance of their type. Attached detail groups also check their parent model group. Multi-instance groups are excluded before capture with their type name, placed count and Edit Group reason. GM never enters Edit Group mode and never ungroups elements. A style used only by those excluded members has no selectable source targets, even when the style remains available as a target for other sources.

The writer captures every pair's population before the first pair mutates the document. Curves with no alternate Lines projection style, no resolvable projection or a non-Lines current style are also excluded. The query retains scalar curve IDs and per-source target intersections for restylable curves. It does not retain Revit wrappers for excluded members, and readback never revisits them. Each successful pair's affected count equals its pre-apply Usage quantity. A defensive group-edit failure at commit rolls back only that pair and surfaces the reason. GroupEditErrorMatcher recognizes such a failure by the failure-definition GUIDs of the commit exception (ITransactionFailureDefinitionSource), not by message text: Revit's BuiltInFailures.GroupFailures GroupPropagationFailedUngroup, GroupPropagationFailedSketch, ModifyingMultiGroups and AtomViolationWhenMultiPlacedInstances.

Workflows

Session operations and shutdown

Domain/SessionOperation/ISessionOperationGate exposes serialized work, overlay progress, busy state, and UI cancellation. App/Sessions/SessionOperationGate implements admission and cancel-and-drain, and logs busy-step timing through its injected ILogger<SessionOperationGate>. The gate has two runners. RunImmediateOverlayAsync shows a cancelable overlay at once, renders it before the work starts, and takes no caller token. RunWithOverlayAsync takes the caller's cancelable flag, overlay options, and token. Its cancelable default is false, as for IProgressOverlay.RunAsync, so a cancelable overlay is an explicit argument. CancelActiveOperation cancels the active work token whatever the overlay flag. MappingUpdateSuppression separately controls nested live-plan suppression. Work reports progress only through the SessionOperationProgress that CreateProgressScope returns. That scope forwards steps, step advances, text, and reported steps to the gate's busy state and overlay. The Hidden (default) value ignores every call. The Domain/Workspace IWorkspaceSignals port carries feature requests for whole-window refresh. App/Sessions/WorkspaceSignals implements that port, alongside WorkspaceState implementing IWorkspaceState. An operation failure remains primary. Caller cancellation propagated through the linked work token is translated back to the caller token.

Teardown independently attempts stopped-step logging, busy-state reset, and busy-text reset. The resets run directly or in one call to the GM window's dispatcher. An aborted or unscheduled dispatcher call produces one teardown failure. The linked cancellation source is always released. One failure propagates unchanged. Multiple failures aggregate in primary-first order with contextual teardown wrappers. A failing StateChanged subscriber cannot hide the work failure or skip the other reset.

BackgroundPrewarm and OptionRenderingRefresh retain their transitive task and cancellation source. Replacement cancels and drains the active pair before starting the next. Each option-rendering refresh runs in a "GM Option Rendering" safe-execution boundary that waits for and disposes its predecessor even when its own token is already canceled. A refresh failure is reported once; a replacement and the close drain treat the predecessor's result as reported. The close drain throws only new cancellation or disposal failures and unexpected task faults. The session refuses ordinary close while Commit Review or Type Mapping owns an interaction. The first admitted close publishes closing state, cancels Mapping/startup, observes startup, and retains one terminal shutdown task. Repeated closes join that completion.

The shutdown workflow independently attempts prewarm drain, option-rendering drain, confirmed preference-clear drain, session-operation cancel-and-drain, close persistence, and synchronous graph disposal, in that order. It then issues one terminal Close. Closed performs idempotent view-model cleanup and App run-scope disposal. Failures retain lifecycle order and do not skip later cleanup. Pane and scope collaborators remain alive until running work drains.

Dev Mode retirement is synchronous and requires Idle for immediate collection. Commit Review reports Busy, so reload waits for Keep, Roll back, X, or cancellation followed by close. Revit shutdown can force ToolWindowRegistry.RetireAll. Retirement diagnoses pending work, aborts owned dispatcher operations, cancels without draining, rolls back an open apply group through the inline commit gate, disposes child/session scopes, and skips close persistence with a log entry. It opens no dispatcher frame. An existing normal-close task stops before its next stage when retirement takes over.

DevModeStatus exposes Idle or Busy: <operations> in the root UI Automation ItemStatus. It includes name lookup, navigation, both auto-zoom debounces, duplicate rebuilds, Type Mapping, Commit Review, cache posts, and pending page selection. App, Family Mapping, and Shared Parameters navigation use Mapping-owned NavigationLifetime leases. Leases start inside admitted callbacks or around awaited execution. Both feature auto-zoom debounces use 200 ms and the lease token. Disposal cancels outside the lifetime lock and prevents later selection, activation, or zoom. Core alerts use observed nested modal loops and diagnose reload during a dialog.

Mapping execution

RevitMappingPlanExecutor validates document identity and supplies document operations to MappingPlanExecutor. MappingPlanExecutor owns the stage loop, capture boundaries, and result builder.

Result accounting

The MappingApplyResult constructor validates and snapshots recorded operation results. Succeeded operations require positive affected counts. Skips require zero. Failed operations can retain counts for writes completed before failure. Root succeeded/failed/skipped and affected totals derive from one recorded-result snapshot. Caller collections cannot mutate the completed result. Family success requires changed work and a successful reload. Failed-rule totals and fatal operation diagnostics must agree.

Exception-backed diagnostics retain the original exception internally. MappingApplyResultBuilder logs each exception reference once with operation context. Commit Review receives stable operation text, codes, IDs, and family context. Exception types, messages, and stacks stay in logs. Writer exceptions are attributed to every unrecorded operation owned by that writer. Family cleanup always attempts close and retains close diagnostics after primary errors. Cancellation plus cleanup failures propagate primary-first through family-batch and outer writer containment.

Skipped group-owned references produce Mapping warnings. An Edit Group restriction rejecting a line-style transaction at commit fails that pair. Successful sibling results retain their affected counts, but Commit Review rolls back an attempt with fatal mapping diagnostics.

Writer failures

A writer exception after all owned operations are recorded is a workflow failure. The result builder logs writer/stage context once and rethrows the original exception with its stack. Recorded operations alone cannot produce a successful final result in this case. With unrecorded owned operations, the executor records their failures and continues to later writers.

Population capture

Replacement capture precedes the first mutation that can change its population. ApplyContext captures the original symbol populations, target occupancy and type-parameter source values before the writer loop. Host material references are captured at the fixed boundary after Host recreation and before Nested Families or Type Replacements, including plans with no Host operations. They refer to recreated element IDs without consuming values introduced by later type-parameter migration or family reloads. Each family document captures all applicable material, object-style and nested-symbol references before its operation loop. Missing sources are explicit capture results. An absent source in a traversed family is zero work with a non-fatal reason. A missing host source or an ambiguous family material name remains an error. Apply never discovers an incoming population. Family material capture includes writable type parameters and the per-type defaults of instance material parameters. Revit does not allow formulas on Material data type parameters. Formula-determined parameters are outside this material replacement population. Reference kinds are explicit. Blank type names are valid and match ordinally. Capture does not change FamilyManager.CurrentType. Transactional apply restores the captured type. Object-style capture identifies the actual subcategory parameter or boundary curves of each filled region.

Family-owned execution uses BatchOperationSet keyed by MappingOperation.OperationId and FamilyBatchResult.ResultsByOperationId. Style and prepared-material payloads use the same IDs. Nested, style, material, and embed dispatch uses canonical operation types and direct appliers. Each applier receives a FamilyBatchApplyContext for its family-tree node: the apply context, host document, retained family document, root family ID, path summary and family identity. The family document is null after its retained document closes; an applier requires it only when it writes. Intermediate counts must be nonnegative, and succeeded plus failed documents cannot exceed attempted. Invalid producer output fails validation.

Family document lifetime

Family-owned batch execution discovers the complete applicable family tree and captures each original population before applying any family mutation. IFamilyDocumentService.DescribeRootFamilyAsync returns a FamilyDocumentReference (ID, name, identity and category key), and OpenRootFamilyDocumentAsync opens the edit document from that reference. The open rejects a modifiable host document and requires the family to match the reference identity and category. When the ID no longer resolves to a matching family after a reload, a unique match by name is used. FamilyBatchDocuments retains one edit document for each family identity through capture, apply, and reload. Discovery spans the whole commit. After discovery, documents with no applicable work in themselves or their descendants are closed before apply. Remaining documents close after their last root-batch use. Final cleanup closes anything left, including after cancellation. Each release closes in reverse open order and reports individual close failures. Discovery logs the peak and retained counts and reports progress per root. Cleanup uses the underlying Revit gate without requiring the launch document to remain active or the work token to remain uncanceled. EditFamily creates independent copies, so no captured element key is carried into a second edit session. Family element references use UniqueId within their retained document plus parameter identity. Family type references use explicit reference kind, family type name, and family parameter name. Built-in parameter identity uses the typed Revit enum without narrowing its underlying 64-bit value. Document-local ElementId values remain diagnostics and population indexes only. Missing keys produce a diagnostic and do not trigger a live rescan.

Shared family identity and reload

Shared nested families use a name/category identity. Nonshared copies include their embedding path. Discovery opens the project's shared definition when one exists, so a parent's stale embedded copy cannot become the original population for another root. If the same shared family is reached through several roots, applicable operation populations are merged and each normalized operation is applied once. An equivalent alias receives a merged notice. If its representative fails, the alias is reported as failed as well. Conflicting targets for the same source fail preflight. After a nested or root reload, the load allowlist selects FamilySource.Family only for shared identities changed by that target traversal. Unchanged shared children use FamilySource.Project, which preserves the target document's existing child instead of reloading a stale source copy. Parent material capture excludes shared-symbol projections: the child owns those values and only surviving writes count. Before reload, project-owned shared material projections are restored from the target document explicitly. Revit can otherwise propagate those type values even when the shared-family load callback selects Project. Nonshared symbol overrides remain part of the parent population.

Family results

Family-document success requires both changed work and a successful reload. A failed family traversal or reload marks every operation actually executed in that traversal as failed, including merged aliases. An affected count can show writes made before the failure. The original exception remains attached to the diagnostic for logging and review.

Family-document attempt/success/failure counts include every examined root and child document, including zero-work captures. A reload or close failure keeps the completed affected counts and marks the affected document operation results failed.

Material projection ownership

A parent FamilySymbol's material type value is a projection of the child's authored FamilyType value. When that child has the same planned material operation, the child owns the write and its count. For nonshared children, root-only operations and traversal-depth leaves retain their parent-side references. Shared projections are always child-owned. Missing captured host references produce a nonfatal diagnostic.

Line-style verification

Line-style query snapshots retain curve IDs and per-source offered intersections, not Revit element wrappers or target sets per curve. A line-style apply performs one fresh discovery sweep, then verifies actual styles by reading the captured IDs. Complete original-source intersections are regrouped under the final source styles. Unexpected population splits or missing curves fail verification for the committed pairs. Their operation results retain the committed affected counts, and the writer returns the errors instead of throwing away those operation results. Commit Review and the subsequent accepted Usage refresh share this result. A rollback does not publish it. CommitReviewLineStyleLifecycle exports it once, and only while the session's query cache still holds the snapshot that was current when post-apply verification succeeded. Explicit Detect and Usage refresh boundaries invalidate prior snapshots.

Object-style attribution identifies the family returned by LoadFamily, its retained name, and its ownership of original instances. Style availability depends on the family category and kind.

Post-apply verification

Commit Review checks operation identity and successful operation results for all replacement kinds, including runtime replacements created by Create Type. Symbol and line-style counts can be checked against incoming populations. Family material and object-style Usage count families while operation results count references. An overlapping successful target is therefore checked through its operation result and writer readback, not by equating those different quantities.

One Global Mapper: Apply session group stays open through modal review. Type replacements retain their selecting intent key, so acceptance records intent for its actual owner. Apply transactions log each Revit failure at Warning with definition ID and failing elements. Pre-commit issues retain their validation label.

Family-document material replacement resolves source and target by material name. Errors retain planned operation ID and host source/target IDs. Family-document material IDs and affected elements are diagnostic details. Report grouping uses the owning operation even when operations share a host pair or family documents assign different IDs.

Reloaded family identity

Family-owned apply retains the family ID returned by Revit reload. Accepted mappings use that identity, including existing saved and pending mappings for the same family. Rollback leaves mapping identities unchanged. MappingApplyResult.ReloadedFamilyIds snapshots changed root identities. Finalization remaps applied/persistable family keys and targets before merging. MappingIntentStore also remaps existing saved/pending intents, manual family-apply state, and usage links. One replaced identity must not retain a second saved mapping.

Host replacement

Each host replacement is atomic per instance. Placement and required facing, hand, and point-rotation transfer must finish before source deletion. Ordinary parameter copies use best-effort transfer. A failed replacement becomes an item error only after its subtransaction reports a completed rollback. If rollback throws or reports any other status, the primary and rollback failures escape together so the enclosing transaction aborts instead of committing an uncertain document state.

ParameterValueTransfer reads the target after Parameter.Set returns false. It accepts the copy as a no-op only when its storage type and value exactly match the requested source value. It applies no numeric tolerance to Double values. A remaining mismatch becomes a nonfatal HostParameterCopyWarning with the source instance, parameter, and reason. Setter exceptions remain failures. These warnings appear only after the replacement subtransaction commits. A later required-state failure rolls back and retains the fatal replacement error. Commit Review preserves each distinct diagnostic, opens the operation diagnostics section, and reports Completed with Warnings. It counts nonfatal diagnostics. Within each diagnostic-code group, it includes distinct messages in first-seen order. Code groups sort by descending diagnostic count, then by code ignoring case.

Host parameter transfer treats a writable instance Phase Created value as instance-owned even when the family symbol exposes the same built-in parameter ID. The type-bound rule excludes generated IfcGUID.

Revit read scheduling

GmSessionDocumentGate validates Action callbacks as synchronous before wrapping their launch-document check. It rejects async void before Core can see only the synchronous decorator. Generic results also undergo synchronous-result validation.

Independent reads for one action start together. Startup waits for every family-category, shared-parameter-category, and parameter-group read to settle. Ordinary startup faults take priority over cancellation. Aggregate faults contribute their non-cancellation leaves recursively. A single ordinary fault keeps its identity and stack. Multiple ordinary faults form an aggregate in family-category, shared-parameter-category, then parameter-group order, regardless of completion order. Other exception wrappers keep their context. With cancellation alone, the first cancellation in that order keeps its token. Family expansion starts view and parameter-name reads together and awaits them in original order, so the first read's failure or cancellation remains primary. Selected-type instance examples are read once through type selection. Core's queued-turn policy determines which waiting calls share a callback.

Limitations

Family-tree discovery retains edit documents through capture and applicable writes, so peak open-document count grows with the discovered tree. Grouped curves are eligible only when each enclosing group type has one placed instance. Family-document material replacement resolves by name, not host numeric ID.

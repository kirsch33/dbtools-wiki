Transfer Drafting Views (TDV)

Overview

Transfer Drafting Views (TDV) copies drafting views between the active Revit document and a library .rvt file. Teams keep standard drafting views in the library and import them into projects.

  • Export to Library copies drafting views from the active document to a library file.
  • Import from Library copies drafting views from a library file to the active document.

For a workshared library, TDV creates a local copy, and after an export it synchronizes the changes with central.

App/Composition holds the manifest entry points and DI. App/Sessions/WindowSession creates a registered stable modal shell through Core's ToolWindowFactory and owns the owner provider, logger display, alerts, banners, initial load, cleanup on close and result projection. WindowSessionDialogRunner owns the modal-loop result and retirement. App/Views/TdvWindow.xaml is embedded raw XAML with the header, grid, preview and actions sections inline. The library settings view (Features/Library/Settings/Views/LibrarySettingsView.xaml) is also raw XAML, loaded with ToolWindowXaml.LoadElement. Both resources have explicit logical names and contain only stable or framework WPF types. TdvWindowViewModel is the App orchestration edge. CachePaths supplies cache roots to the Library and Preview features.

Transfer is one Revit-facing service split over partial files: shared guards (Transfer.cs), catalog queries (Transfer.Queries.cs), apply-selection orchestration (Transfer.ApplySelection.cs), per-row steps (Transfer.Execution.cs) and per-run accounting (Transfer.RunState.cs). The run state holds duplicate destination names, deferred successes, cancellation, rollback and unknown-finalization reporting and the final TransferResult. The split adds no service or transaction boundary.

The drafting-view operations are in Features/Transfer/Operations/DraftingView: DraftingViewReader (enumeration and name lookup), DraftingViewTypeResolver (type lookup and creation of missing destination types) and DraftingViewWriter (create, copy, clear and overrides). Features/Preview/Operations/PreviewExporter and PreviewImageExporter export previews. TransferSession binds one Transfer to a destination and source document for the window.

Transfer commands are split by direction. ExportTransferWorkflow and ImportTransferWorkflow make the document and outcome decisions of their direction. LibraryTransferWorkflow owns catalog selection, library open, close warnings and host reactivation. The Library workflow uses the ILibrarySelectionDialog port; the Transfer workflows use the ITransferDialog port. WindowSession implements both: it presents library selection, loads the embedded TDV view, shows the shell modally with the application IWindowOwnerHandleProvider and projects the window counts and errors into TransferDialogResult. LibraryDocumentService does the Revit document open, save, sync and close calls; LibraryCatalog validates library paths from the current settings snapshot.

Service registration

TdvToolModule registers the services through ServiceCollectionExtensions.AddTdv(). Registrations are scoped because they depend on run-scope services (IRevitCallGate, ITransactionRunner). The composition root supplies the current Revit year and the library-file year probe.

Data and contracts

Capabilities

  • Import and export of drafting views, several views in one batch.
  • View type mapping: each row selects a destination drafting view type, or Retain Original.
  • Conflict detection while editing: names that exist in the destination, and duplicate destination names in the current selection.
  • Replace mode for views with the same name.
  • A preview of the selected view, with pan and zoom.
  • One destination transaction group per batch, bound to the explicit destination document (also a non-active library).
  • Per-view progress during transfer.

Callback requirement

Transfer.ApplySelectionAsync must start inside an active Revit API callback, and the supplied call gate and transaction runner must keep the whole transfer in that callback. Before it reads a document or starts the destination group, it throws OperationCanceledException if the request token is canceled and InvalidOperationException ("TDV transfer requires one continuous Revit API callback.") if RevitCallGateApiContext.IsActive is false. Both ribbon commands use the InlineUi profile. The query methods (BuildViewItemsAsync, WouldConflictAsync, ExportPreviewAsync) can each queue as one complete operation.

ApplySelectionAsync also checks that the source and destination are valid, open documents and not the same document. The run-start log entry contains a run ID and the title and path of the source and destination.

Destination names

TDV does not add suffixes to destination names. A row fails when its destination name is blank (DestinationNameRequired), exists in the destination while Replace is off (DestinationNameConflict), or duplicates the destination name of another selected row (DuplicateTargetName).

View types

The row View Type list contains the drafting view types of the destination: the host document for an import, the library document for an export.

Retain Original resolves to the drafting type name of the source view. If the destination has no type with that name, TDV duplicates an existing destination drafting ViewFamilyType and gives the duplicate that name. If the source type name cannot be read, the row fails with SourceTypeNameUnavailable.

Settings

Library options

The Core.MasterLibrary section stores LibraryOptions:

public sealed class LibraryOptions
{
    public IList<LibraryFile> Files { get; set; } = new List<LibraryFile>();
}

public sealed class LibraryFile
{
    public string? MainPath { get; set; }      // primary library .rvt path
    public string? FallbackPath { get; set; }  // alternative path, for example another network location

}

Settings pack

LibrarySettingsContext gives the settings page a tree of library files with add and remove for files and fallback paths, path validation as the user edits, and pending-change tracking. The settings-pack factory receives the Revit year and year probe from the TDV composition root, so settings validation matches the runtime checks. LibraryTransferWorkflow receives a Func<LibraryCatalog> from the composition root and does not read the settings type.

Each tree row shows a validation icon (green check or red error), its DisplayText (the alias, else the file name; a fallback row shows Fallback: <file name>) and, below it, the full path (Title). Both lines wrap, so the whole path reads without a tooltip or horizontal scrolling.

Path validation

LibraryCatalog marks a path invalid, with a failure reason, when:

  • the file does not exist (File not found);
  • the extension is not .rvt (Not a .rvt file);
  • the year probe cannot read the saved Revit version (the probe's failure reason; TDV logs the exception);
  • the saved version differs from the session (Revit version mismatch (file: {0}, current: {1})).

An invalid path raises the core.library.invalid settings warning, which disables both ribbon commands. Warnings are evaluated at startup, so the commands can be disabled as soon as Revit starts.

LibraryDocumentService.OpenLibraryAsync checks the version again before it opens the file and throws InvalidOperationException ("Library file was saved in Revit {0} but the current session is Revit {1}. ...") on a mismatch. The command's ISafeExecutor boundary shows it as a banner. The check prevents two failures:

  • for a workshared file, WorksharingUtils.CreateNewLocal() fails with a version error;
  • for a non-workshared file, Revit upgrades the library file when it opens it.

Open failures propagate through the import or export workflow to the command boundary; they are not treated as a canceled library selection.

Result reporting

After each transfer, TDV shows:

  • a banner on the TDV window (success or warning) with the selected, processed and result counts;
  • a summary alert with the selected, processed, added, replaced, failed and not-attempted counts, a table of per-view issues when there are failures (rows can be copied to the clipboard), and the buttons Accept and Transfer More and Close Tool.

TransferResult carries SelectedCount, ProcessedCount, Added, Replaced, FailedCount, UnprocessedCount, Cancelled, FinalizationOutcome (Unknown, Committed, RolledBack), Errors and ErrorDetails. AllChangesDiscarded is true only for RolledBack.

  • Transfer logs include the identifiers and names of the selected views (a bounded list).
  • Row state flows from Transfer to the row view models and XAML triggers as TransferRowState.
  • TDV logs each per-view failure with its exception and records only the stable code and message in the row result.
  • Success callbacks and committed add and replace counts are published only after a Committed outcome. A rollback marks attempted rows discarded. An unknown finalization sets the projected successes to zero, marks attempted rows failed with Unknown and reports that the destination state is not verified.

Library close

  • Save and sync always attempt to close the library document. Document.Close(...) == false is a failure of a required close.
  • A single save, sync or close failure keeps its original exception. When the operation and the close both fail, TDV throws one ordered AggregateException with the operation failure first.
  • Best-effort cleanup (TryCloseAsync) returns false only when Revit refuses to close the active document. Other cleanup failures propagate; after a failed export, TDV reports one ordered AggregateException with the export failure first and the cleanup failure second.

Workflows

Per-view steps

For each selected row, TDV:

  1. validates the destination name before the transfer transaction;
  2. creates or prepares the destination view with the selected view type;
  3. copies the view scale and description parameters;
  4. copies the elements of the source view, except skipped categories;
  5. copies element graphic overrides from source to destination.

If a step fails, the per-view transaction rolls back and the row is recorded as failed.

DestinationTransactionGroup receives the destination Document at begin, rejects item and finalization calls for any other document and runs each item transaction against that document. Import (library to host) and export (host to a non-active library) therefore use the same real Revit group; the group is never resolved from ActiveUIDocument. It creates the Revit group through RevitTransactionGroups.Begin.

  • Successful row states and the add and replace counts are held until the group reports Committed.
  • A RolledBack outcome marks the attempted rows discarded.
  • An unknown or failed finalization withholds success and claims neither commit nor rollback.
  • Operation, finalization and disposal failures stay ordered in the logged exception chain; the row result keeps its stable per-view error code and message.

Sources: src/Tools/Common/TDV/Features/Transfer/Execution/{DestinationTransactionGroup,Transfer.ApplySelection,Transfer.RunState}.cs, src/Tools/Common/TDV/Features/Transfer/Domain/TransferResult.cs.

Copying view contents

TDV collects the elements owned by the source view and copies them with ElementTransformUtils.CopyElements and a UseDestinationTypesHandler (an IDuplicateTypeNamesHandler that keeps destination types when type names collide). Groups are copied before other elements; group members are paired with their copies so overrides apply to them.

Skipped elements: viewports, elements whose category name is Title Blocks, Viewports, Views, Schedules or Guide Grids, and elements whose name contains ExtentElem. The category check compares English category names.

Drafting views are collected with:

new FilteredElementCollector(doc)
    .OfClass(typeof(View))
    .WhereElementIsNotElementType()
    .Cast<View>()
    .Where(v => v.ViewType == ViewType.DraftingView && !v.IsTemplate)

UI

Main window (TdvWindow)

The registered modal shell has the title "Transfer Drafting Views", an initial size of 1400 × 700, a minimum size of 1200 × 600, centered placement, a taskbar entry and a resizable layout. The Sandbox manifest declares the same dimensions, taskbar visibility and placement. The raw view has these sections:

  • TransferHeaderView: conflict warning, type filter, search and separator.
  • TransferGridView: the transfer grid and row visuals.
  • TransferActionsView: status, selection and transfer actions, and errors.
  • TransferPreviewView: the preview panel, cursor-relative wheel zoom, mouse panning, a zoom button and zoom on image update.

The main view merges Presentation's theme once at its root; the library settings view merges its own. String item lists and tooltips use explicit text templates. Row-state triggers compare enum names as strings. PreviewZoomBehavior (Presentation) zooms on image update, deferred until layout. DBTools.Presentation.Tools.TDV.TdvPanZoomBehavior handles mouse pan and zoom and releases capture, cursor state and subscriptions on retirement.

Window lifetime

ProgressOverlay.For(session.Window) attaches after the view loads and before the dialog shows. The normal Closed notification clears UI actions, cancels outdated preview and conflict requests, disposes the view model and deletes its cache files. The host then retires the session and releases subscriptions, behavior state, the initializer, the overlay registration and the owner.

  • Cleanup and the result depend on the Closed notification, also for a window closed before ShowDialog; an early normal close still allows library-document cleanup.
  • Late callbacks and catalog results do not touch a disposed view model. A load failure after close shows no alert and logs no load error. If the load-error alert cannot be shown, the window still requests close.
  • Dev Mode retirement logs a pending load, preview, conflict refresh or transfer instead of canceling it. Idle retirement is synchronous and does not pump the dispatcher.

The library settings page uses stable tree selection and a focus-request counter. Selecting a main library entry whose alias is empty or whitespace focuses and selects the alias text at Background priority. Entries with an alias, and fallback entries, do not take focus.

Preview

  • Loading is debounced by 200 ms.
  • PreviewCache keeps up to 32 exported images in first-in-first-out order; a cache hit does not refresh its position.
  • Zoom Extents fits and centers the image in the viewport.
  • Exports are cropped to the non-background pixels, so extents-based zoom targets the real content. The background is RGB 43, 44, 61.
  • The placeholder text distinguishes "no row selected" from "preview export failed".
  • Each debounced request owns one cancellation source. Every result (image, unavailable, exception) checks that token and the request sequence before it publishes, so a superseded request can log its fault but cannot replace the latest preview. Expected cancellation logs no stack trace.

Source: src/Tools/Common/TDV/App/ViewModels/TdvWindowViewModel.Preview.cs.

Cache locations

Transient files are under %APPDATA%\DBTools\Cache\TDV\ (AppPaths.GetToolCacheDir("TDV")):

  • LibraryLocals\: workshared local copies, one per operation, deleted after the operation closes the library document.
  • Preview\: preview images of one window.

Command flows

The library picker is an alert sized 520 × 420 (minimum 480 × 340). Each entry shows <name> - <path>: the name is the alias, or the file name up to the first _R (LibraryCatalog.TrimLibraryName) when there is no alias, and the path is shortened to its last two folders (LibraryPathFormatter.FormatPath). When some configured paths are invalid, the message reports how many.

TDV opens library files with Application.OpenDocumentFile(...), without activating them, so the host model stays active during transfer and cleanup.

Export

  1. Check that library paths are configured.
  2. Select a library file.
  3. For a workshared library, create a local copy under LibraryLocals\.
  4. Open the library document.
  5. Show the TDV modal session for view selection and run the transfer to the library.
  6. If views were added or replaced: for a workshared library, synchronize with central with the comment DB TOOLS - ADDED [n] DETAILS AND REPLACED [n] DETAILS. and close; otherwise save and close. If nothing changed, close without saving.
  7. Reactivate the original document.
  8. Show a warning only when Revit refuses to close the library because it is active. Any other close failure propagates, so an export is never reported as successful after a required close failed.

Import

  1. Check that library paths are configured.
  2. Select a library file.
  3. For a workshared library, create a local copy under LibraryLocals\.
  4. Open the library document.
  5. Show the TDV modal session for view selection and run the transfer to the active document.
  6. Close the library without saving.
  7. Show a cleanup warning if the library document could not be closed.

Testing

DBTools.TDV.Pure.Tests and DBTools.TDV.Local.Tests cover, among others:

  • TransferRowViewModelTests, TransferProjectorTests: row state, duplicate and blank names, and result projection.
  • LibraryCatalogTests: path validation and catalog projection.
  • TransferTests and the Transfer fixture in Transfer.ExecutionTests.cs: Revit-hosted transfers between source and destination documents.
  • The Transfer fixture in Transfer.ApplySelectionTests.cs: Revit-hosted admission tests with real scopes, gates, transaction runners and destination groups: an off-thread call with an inherited API context, a canceled request, and a drafting-view transfer between two models.
  • LibraryDocumentServiceTests: Revit-hosted document lifecycle: non-workshared library open, rejection of a Revit-year mismatch (through the injected year probe), aggregation of save-and-close failures, refusal to close the active library, and host reactivation. The workshared round-trip fixture creates a temporary central model, opens a local workspace, creates a drafting view, calls SyncAndCloseAsync, reopens the central through the service, checks the saved view, and verifies local-workspace removal. Non-workshared cases use temporary copies of test models.

Limitations

Library files must be saved in the running Revit year. Transfer requires one continuous Revit API callback and distinct open source and destination documents. Category exclusions compare English category names. Destination-name conflicts require a rename or Replace; TDV does not allocate suffixes.

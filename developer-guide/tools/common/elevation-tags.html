Elevation Tags

Elevation Tags aligns spot elevation text relative to leader endpoints in floor, structural, and ceiling plans. Manual alignment runs on the active view. Automatic alignment runs when a supported view activates.

Use and settings

  1. Open a FloorPlan, EngineeringPlan, or CeilingPlan view.
  2. Configure Elevation Tags in Settings.
  3. Run Align Elevation Tags, or enable automatic updates.

The command requires an active view. An unsupported view produces a warning toast without running alignment. The settings preview redraws as per-type offsets change.

Settings use configuration section Tools.ElevationTags and pack key common.elevation_tags.

Property Default Meaning
AutoUpdateEnabled true Run on supported view activation
TagNamePatterns Empty list Regex patterns. An empty or all-blank list uses the static defaults
TypeOffsets Empty dictionary TypeAlignmentOffsets keyed by spot elevation type name

The default pattern is:

^DB Elevation Tag - (?:Concrete|Steel|Wall) Label$

The UI permits up to three patterns and validates their syntax. At least one nonblank pattern is required to save settings. Runtime compiles nonblank patterns case-insensitively. Invalid patterns log warnings and are skipped. With no valid compiled patterns, no tags match.

TypeAlignmentOffsets contains AlongLeaderOffset and PerpendicularOffset. Both default to zero for an unconfigured type. Runtime multiplies these values by view.Scale / 12. The signs follow the computed text side relative to the leader endpoint.

Filtering

AutoUpdater collects non-type OST_SpotElevations elements from the active view as SpotDimension instances. A match against any configured regex includes the spot. Candidate strings include the spot name, spot type and family names, and resolved marker-symbol type and family names. The matcher tests these strings separately.

A failure reading a spot's names increments FailedCount. The first such failure in a run logs its exception. Leaderless spots, missing types, and Relative-base spots require no update.

Alignment algorithm

  1. Read the origin, leader end, current text position, and spot type.
  2. Resolve elevation and format its text using document units and the type's unit options.
  3. Measure the text with GDI+ using font, text size, width scale, and display DPI.
  4. Compute placement relative to the leader end and current above/below text side.
  5. Apply the configured per-type offsets.
  6. Write TextPosition when X or Y differs after rounding to two decimal places in internal coordinates.

Z remains the existing text Z. The view factor is view.Scale / 12. The measured horizontal half-width receives margins of 2 * factor / 128 + factor / 8. The vertical margin is factor / 64. Placement below the leader also accounts for measured text height.

The elevation base uses the type's displayed SPOT_ELEV_BASE value:

Display value Calculation
Project Base Point Subtract project base point Z only when project and survey point positions differ by at least 1e-9 on an axis
Relative Skip alignment
Other values, including Survey Point Use spot origin Z

These comparisons use English display strings with ordinal matching. An Elevation Indicator becomes the prefix only when Elevation Indicator as Prefix/Suffix equals Prefix and the indicator is nonblank. Otherwise the measured prefix is EL. . The calculation does not append a configured suffix. Font defaults to Arial and width scale defaults to 1 when their parameters are absent. A units-format lookup failure logs once and uses default formatting.

Results and errors

AutoUpdater.Run() returns ElevationTagRunResult with:

Field Meaning
TotalSpotsInView Collected spots
PatternMatches Spots accepted by name patterns
UpdatedCount Spots whose position changed
FailedCount Name-reading or per-spot update failures

Candidate updates share DB Tools - Autoupdating spot elevations. The updater catches per-spot update faults, counts them, and continues. The first update fault logs its exception. Collection, layout preparation, and transaction-level failures can propagate.

The manual workflow shows a Warning toast when failures exist, Success when tags change, and Info for no spots, no pattern matches, or matching spots requiring no changes. The last case includes already aligned, leaderless, and Relative-base spots. Counts do not distinguish those cases. Automatic updates log a summary warning for partial failures. Uncaught automatic-update failures reach Core's view-activation handling, which shows a runtime-failure banner and skips that task for the document session. This runtime failure does not set a persistent settings warning.

Warning core.structural.elevation_tags disables DBTools.AlignElevationTagsInView and automatic updates. The settings context exposes the warning state and disables its automatic-update toggle while the warning is active.

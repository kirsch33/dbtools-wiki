Elevation Tags

Overview

Elevation Tags aligns spot elevation text relative to leader endpoints in floor, structural, and ceiling plans. Manual alignment runs on the active view. Automatic alignment runs when a supported view activates.

Symbol text

App/Composition/ElevationTagsSymbolTextCommand registers DBTools.SetElevationSymbolText on the Common panel, order 21. The command is available only in a project document while the selection contains a spot elevation (CommandAvailability.HasCategorySelection with OST_SpotElevations), so Revit greys out the button otherwise. The command uses InlineUi and requires a project with an active view. Features/SymbolText/SymbolTextWorkflow validates the selection before opening the existing AlertBodySpec.TextInput alert. Cancel returns without opening a transaction. SymbolTextPolicy owns trimming, single-line and name-character validation, variant names, text comparison, and reuse decisions. Only terminal CR/LF characters added by Revit are ignored when comparing family text.

Features/SymbolText/Revit/SymbolTextEditor filters the supplied selection to OST_SpotElevations owned by the active view. For each current spot type, it reads SPOT_ELEV_SYMBOL and edits the symbol's family through Document.EditFamily. Exactly one TextElement is required. It changes that element's plain text in a family transaction, saves an RFA in a unique temporary directory with the variant name, then loads the RFA in a project transaction. Saving under a new filename and loading the RFA follows Autodesk’s family-copy procedure. The edited family document closes before the saved RFA loads through the path-based Document.LoadFamily overload. SymbolTextTemporaryDirectory removes the temporary directory on success or failure. An I/O or access failure during directory removal logs a warning and preserves the operation result or original exception. New families retain the source symbol type name. Reused families prefer that name and otherwise use their sole symbol type. Families with multiple types and no matching type name cause a refusal. Source families must contain exactly one plain text element even when the target variant already exists.

Variant families and spot types use <original name> - <text>. An existing family is reused only when it has exactly one plain text element with the requested text and a symbol type with the source symbol type name, or exactly one symbol type. An existing spot type is reused only when its SPOT_ELEV_SYMBOL references that symbol. Name collisions with different content cause a refusal. Existing content is never overwritten or marked as command-owned. A newly duplicated spot type preserves the current type's other parameters.

New project families and spot types carry Extensible Storage schema DBToolsElevationSymbolTextV1, GUID 535cae92-1d19-45ed-98ee-d06c501980ea, vendor DBTools. Its string fields are:

Field Meaning
ElementId Created element's UniqueId; a copy does not inherit ownership
SourceId Original source element's UniqueId
SourceName Original source name, retained across text changes
Text Requested plain text

The marker is recognized only when ElementId matches the current element and its name equals SourceName + " - " + Text. A recognized source variant supplies its original name and provenance for the next variant. Cleanup examines only marked spot elevation types that the selected spots leave and their marked symbol families. A run with no departed marked type starts no cleanup transaction and performs no cleanup scan. Spot use is checked in OST_SpotElevations across all views. Family use is checked through spot-symbol parameters on dimension types, including unused user types, and through family-instance filters for the candidate symbols. Unused candidate spot types are removed before their marked families. Cleanup reads each type's logical children with Element.GetDependentElements. The ownership marker must validate, and SourceId must identify an existing source type. Cleanup logs the source type's dependents at Information with each ID, class and category before it checks the candidate's dependents. It does not compare the source and candidate dependents. Excluding the candidate type itself, every candidate dependent must resolve to an element whose exact class is Element or GraphicsStyle and whose category is null. The deletion set may contain only the candidate type, those dependents, and other IDs already owned for deletion. The set includes a marked family and its symbols only when no other spot type or family instance uses them. Worksharing ownership is checked for every allowed element. Cleanup records element descriptions before deletion. Each deletion rolls back if Revit returns an ID outside the allowed set or does not delete the candidate type. Revit deletion refusals also log a warning and keep the candidate. Before it attempts to delete a marked family, cleanup logs the family's dependent IDs, classes, and categories at Information. If Revit's deletion set includes elements beyond the family and its symbols, cleanup keeps the family and logs an Information message. User copies, renamed variants, unmarked content, unrelated variants, and referenced variants remain. Unused symbol-text copies of a family can remain, and Revit's Purge Unused removes them.

The project transaction group is DB Tools - Set elevation symbol text. It contains family loads, type duplication, selected-spot reassignment, and cleanup. The group assimilates into one Undo entry on success and rolls back on failure. No project transaction remains open during EditFamily. Family-document transactions do not modify the project until the variant RFA loads inside the group.

SymbolTextPolicyTests covers off-Revit validation, names, family/type reuse decisions, and exact-name or sole-symbol selection. SymbolTextTemporaryDirectoryTests covers successful removal and a locked RFA that produces a warning without changing the caller result. The hosted SymbolTextEditorTests fixture creates a plain-text spot symbol from the installed spot elevation template, places spots on a temporary floor, and exercises reassignment, reuse, original preservation, refusal, rollback, and scoped cleanup. It also checks copied marker identity, vendor identity, unrelated variants, native deletion rollback, and a refused spot-type deletion that preserves the type's symbol. Fixture output includes cleanup decisions and extra deleted IDs, classes and categories, plus the source type's dependent IDs, classes and categories. Run that fixture in Revit 2026 and 2027.

Data and contracts

Settings

Settings use configuration section Tools.ElevationTags and pack key common.elevation_tags.

Property Default Meaning
AutoUpdateEnabled true Run on supported view activation
TagNamePatterns Empty list Regex patterns. An empty or all-blank list uses the static defaults
TypeOffsets Empty dictionary TypeAlignmentOffsets keyed by spot elevation type name

The default pattern is:

^DB Elevation Tag - (?:Concrete|Steel|Wall) Label$

The UI permits up to three patterns and validates their syntax. At least one nonblank pattern is required to save settings. Runtime compiles nonblank patterns case-insensitively. Invalid patterns log warnings and are skipped. With no valid compiled patterns, no tags match.

TypeAlignmentOffsets contains AlongLeaderOffset and PerpendicularOffset. Both default to zero for an unconfigured type. Runtime multiplies these values by view.Scale / 12. The signs follow the computed text side relative to the leader endpoint.

Filtering

SpotElevationTextAligner collects non-type OST_SpotElevations elements from the active view as SpotDimension instances. A match against any configured regex includes the spot. Candidate strings include the spot name, spot type and family names, and resolved marker-symbol type and family names. The matcher tests these strings separately.

A failure reading a spot's names increments FailedCount. The first such failure in a run logs its exception. Leaderless spots, missing types, and Relative-base spots require no update.

Results and errors

ElevationTagAlignmentService.Run() returns ElevationTagAlignmentResult with:

Field Meaning
TotalSpotsInView Collected spots
PatternMatches Spots accepted by name patterns
UpdatedCount Spots whose position changed
FailedCount Name-reading or per-spot update failures

Candidate updates share the undo entry DB Tools - Align spot elevations, for both the Align command and the update on view activation. The aligner catches per-spot update faults, counts them, and continues. The first update fault logs its exception. Collection, layout preparation, and transaction-level failures can propagate.

The manual workflow shows a Warning toast when failures exist, Success when tags change, and Info for no spots, no pattern matches, or matching spots requiring no changes. See Limitations for cases that require no position change. Automatic updates log a summary warning for partial failures. Uncaught automatic-update failures reach Core's view-activation handling, which shows a runtime-failure banner and skips that task for the document session. This runtime failure does not set a persistent settings warning.

Warning core.common.elevation_tags disables DBTools.AlignElevationTagsInView and automatic updates. The settings context exposes the warning state and disables its automatic-update toggle while the warning is active.

Workflows

Use

  1. Open a FloorPlan, EngineeringPlan, or CeilingPlan view.
  2. Configure Elevation Tags in Settings.
  3. Run Align Elevation Tags, or enable automatic updates.

The command requires an active view. An unsupported view produces a warning toast without running alignment. The settings preview redraws as per-type offsets change.

Alignment algorithm

  1. Read the origin, leader end, current text position, spot type, and the type's Text Location.
  2. Resolve the elevation. BuildTagText composes a configured indicator as a prefix or suffix around the elevation in document units with the type's unit options. When the indicator is blank, Align measures EL. followed by the elevation.
  3. SpotElevationTextFont sets the font em size so its capital height equals the Revit type's TEXT_SIZE. The preview and Align use this same rule. MeasureTag measures width and height with GDI+ at the display DPI.
  4. ComputeTextOffset computes placement relative to the leader end from the leader direction, the Text Location, and the configured per-type offsets.
  5. Write TextPosition when X or Y differs after rounding to two decimal places in internal coordinates.

Z remains the existing text Z. The view factor is view.Scale / 12. Placement works along the view's RightDirection and UpDirection, so it follows rotated plans. SpotElevationTextAligner.ComputeTextOffset in Features/SpotElevationTextAligner.Run.cs owns the placement rule. The margin from the leader end is 2 * factor / 128 + factor / 8; the gap from the leader is factor / 64. Align scales both measured paper dimensions by the view factor.

SpotElevationTextAligner.Run owns one screen Graphics for the run. It creates it once spots match, reads both display DPI values from it, measures every spot's text with it, and disposes it when the run returns or throws. An unsupported view or a run without matching spots creates no graphics. MeasureTag creates and disposes the cap-height-scaled font for each measurement.

The Text Location comes from the type's SPOT_ELEV_TEXT_LOCATION value: 0 is Above Leader, 1 is Below Leader, and 2 is In-line with Leader. Any other value or a missing parameter fails that spot.

Text Location Revit's own placement TextPosition marks Align places the text
Above Leader Above the leader on screen, for either leader direction Bottom center On the point's side of the leader, centered over the shoulder
Below Leader Below the leader on screen, for either leader direction Top center On the point's side of the leader, centered over the shoulder
In-line with Leader Centered on the leader, past the leader end, no symbol Top corner nearest the leader end Centered on the leader, past the leader end on the side away from the shoulder

The point's side is above the leader when the leader end is below the spot origin along the up direction, and below the leader otherwise. A leader whose rise along the up direction is at most 1e-9 times its length counts as level and takes the below placement in every view rotation. Revit mirrors the marker symbol across the leader when the leader runs up the screen. A symbol that draws its text above its origin, as the DB Elevation Tag label symbols do, therefore shows that text on the side away from the point. Revit's own side would put the elevation text on the symbol text for Above Leader with a leader running down and for Below Leader with a leader running up; Align uses the point's side for both locations instead. The Text Location still sets which edge TextPosition marks, so the text keeps the same gap from the leader. The current text position does not select the side, so a second run leaves an aligned spot unchanged.

The offsets then move the text along the same axes. A positive AlongLeaderOffset moves it further from the leader end. A positive PerpendicularOffset moves Above Leader and Below Leader text further from the leader, and moves in-line text up. A negative PerpendicularOffset larger than the gap puts the text on or across the leader; Align does not prevent that.

The elevation base uses the type's displayed SPOT_ELEV_BASE value:

Display value Calculation
Project Base Point Subtract project base point Z only when project and survey point positions differ by at least 1e-9 on an axis
Relative Skip alignment
Other values, including Survey Point Use spot origin Z

Align reads Elevation Indicator and Elevation Indicator as Prefix/Suffix by built-in parameter identity. It composes nonblank indicators as prefixes or suffixes. When the indicator is blank, Align measures EL. before the elevation. Font defaults to Arial and width scale defaults to 1 when their parameters are absent. A units-format lookup failure logs once and uses default formatting.

Settings preview

PreviewContext draws the selected type at twice print size, 192 canvas units per paper inch, or smaller when the viewport that the view reports cannot hold the drawing. The view also reports its device pixels per unit. Strokes are a whole number of device pixels thick. The shoulders and label outlines align to device pixels, so they stay sharp at any display scale. The drawing shows two spots of the type on one square element: one whose leader runs down to the element point and one whose leader runs up to it. SpotElevationPreviewLayout places the parts in paper inches, from each leader end:

  • the symbol family drawing, except for In-line with Leader. The projector reads visible family curves, filled-region boundaries and plain text from the family view. It tessellates curves into paths and samples arcs to a 1/192" paper-space chord tolerance, one canvas unit at full scale, with exact projected extrema. It skips masking regions and invisible curve strokes. For filled regions, it reads each boundary curve's CurveElement.LineStyle through the region's dependent elements and sketch. It adds visible boundary curves to outlines and keeps closed loops for fills. Solid fill patterns render filled; other fill patterns render as outlines. Text uses the family text type's font, size, width scale, bold and italic settings, plus its horizontal and vertical alignment and rotation. The family origin is the leader end, X follows the shoulder, and Y points up. The preview mirrors symbol positions and text boxes for the up leader. It mirrors the text angle while keeping glyphs readable. Revit placement for rotated family text is unverified. A type without a symbol family has no symbol drawing. If Revit cannot open a family, the preview omits its drawing and still shows the symbol name;
  • the shoulder from the leader end to 1/16" past the label, or 3/8" long for In-line with Leader, then the leader to the element point;
  • the label, in the type's font, style and width factor, with capitals as high as the type's text size.

The label follows SpotElevationTextAligner.ComputeTextOffset at a view factor of 1: a margin of 2/128 + 1/8 inch from the leader end and a gap of 1/64 inch from the leader. Revit's TextElement.Coord anchors the content area, not its border. Horizontal alignment selects the left, center, or right anchor. Vertical alignment selects the top, centerline, or bottom anchor. TextElement.Height measures the content area and excludes the border. For unrotated text, the family view bounding box includes the type's shared border offset. Its top edge is that offset above Coord for Top alignment, the offset plus half the content height for Middle, and the offset plus the full content height for Bottom. The preview recovers the content area's top from Coord and TextElement.Height, then places glyphs using the recorded alignment and rotation. The projector reads SPOT_ELEV_TEXT_LOCATION by built-in parameter identity. SpotTextLocationParser.ParseTextLocation maps its integer value to the SpotTextLocation enum shared with Align: 0 Above Leader, 1 Below Leader, 2 In-line with Leader. Missing or unknown values log a warning with the type name and value, and exclude that type from the preview. The snapshot keeps AsValueString() as TextLocationName for the label only.

Text Location Label in the preview
Above Leader, Below Leader Over the shoulder, its near edge the margin from the leader end; a gap below the shoulder where the leader runs down, a gap above it where the leader runs up
In-line with Leader Centered on the leader, its near edge the margin past the leader end on the side away from the shoulder; no symbol

Text Location only changes which label edge Align's TextPosition marks, so Above Leader and Below Leader draw alike. Along Leader moves the label away from the leader end. Perpendicular moves Above Leader and Below Leader labels away from the shoulder, and in-line labels up. A dashed outline shows each label without offsets. Like the alignment, the preview ignores Text Offset from Leader, Text Offset from Symbol and Text Orientation. Under the drawing, the view shows the font, Text Location, elevation indicator, elevation base and symbol name.

Without a matching type the view draws nothing. It shows No project open when the project supplies no spot elevation types, and No spot elevation type matches the patterns with the nonblank patterns (TypeContext.ActivePatterns) when none of them matches.

Testing

Pure tests cover the runner, including a run without matching spots that prepares no layout and starts no transaction, symbol resolution, settings state, preview layout and drawing, the settings view's bindings, and manual summaries. Revit-hosted tests under Tests/Integration/Revit/ cover the command, module, workflow, view activation, live alignment service, and type projection. Pure tests pin ComputeTextOffset for each Text Location and leader direction. Pure tests also cover level leaders with rounding residuals of both signs and the rejection of a missing or unknown Text Location value. The workflow tests build a spot elevation symbol with text above its origin. For each Text Location, they align spots whose leaders run up, down, and level, to the left and right, in a Project North plan and in plans turned 30 and 90 degrees. They compare screen-axis offsets between Project North and the 30-degree plan. Axis-aligned Arial and Courier New cases check the drawn text box and its margin from the leader end. They measure the elevation text and the symbol text from the spot's box in the view. They check the edge TextPosition marks, that above and below text lies on the other side of the leader from the symbol text, that level leaders put above and below text below the leader, that in-line text is centered on the leader with its near edge one margin past the leader end, that a second run moves nothing, and that the text keeps its Z. Further Below Leader cases set the EL. prefix and change the font, the width factor, the document units or the type's units; the near edge of the text Revit draws must lie one margin past the leader end, within 15 percent of the text width.

SpotElevationTypeProjectorTests reports bounding-box offsets for all nine horizontal and vertical text-note alignments. It checks the shared border and Top, Middle and Bottom anchor offsets to 1e-6 ft.

Limitations

The side rule assumes the marker symbol draws its text above its origin. With a symbol that draws its text below its origin, the elevation text lands on the symbol text. For an exactly level leader, Align puts the text below the leader, but Revit's own symbol orientation changes with rounding: a test plan turned 90 degrees showed the symbol mirrored where Project North did not. Elevation-base and prefix comparisons require English display strings and use ordinal matching. No-change counts combine already aligned spots, leaderless spots, and spots with a Relative elevation base.

dbtools.OrganizeFoundationTypes

NAME

dbtools.OrganizeFoundationTypes - name, mark and merge foundation types

SYNOPSIS

source    src/Tools/Structural/OrganizeFoundationTypes/ (manifest.yml)
assembly  dbtools.OrganizeFoundationTypes
entry     OrganizeFoundationTypesCommand

DESCRIPTION

The organizer renames foundation types, sets their Type Mark and merges types with equal dimensions. The user page lists the families and output formats.

STRUCTURE

Path Owner
App/Composition/ OrganizeFoundationTypesCommand declares its workflow with CommandService. App registers the service when it loads the ribbon item.
Features/FoundationType/ OrganizeFoundationTypesWorkflow chooses the policy. FoundationTypePlanner selects renames and merges. FoundationTypeOrganizer reads and edits Revit types.
Features/TypeMark/ TypeMarkPolicy selects overwrite or preserve. TypeMarkGenerator makes the marks.

CONTRACTS

  1. CollectTypes matches FamilySymbol types in the document by category and exact family name using StringComparison.Ordinal.
  2. The workflow prompts only when a collected type has a nonblank Type Mark. Cancel or closing the alert returns before the workflow calls FoundationTypeOrganizer.Run. OrganizeFoundationTypesWorkflowTests checks the choices and dismissal. OrganizeFoundationTypesTests checks the resulting types for each policy and for Cancel.
  3. Inside dbtools - Organize Foundation Types, the organizer calls ApplyAtomicTypeChange once for a retained type's mark and rename. MergeInstances calls it once per duplicate source type for all its ChangeTypeId calls. TransactionExecutor.RunSubTransaction handles each nested call. OrganizeFoundationTypesTests.Workflow_WhenTypeRenameFails_KeepsSourceAndReportsSkippedType checks the skip reported for a rejected name.
  4. A merge requires all dimensions to have values. Overwrite groups by exact stored dimensions. Preserve also groups by exact mark. Blank types join a marked group when the size has one distinct mark. The merge target is the type with the lowest element ID. In Preserve groups with marked types, the target is the marked type with the lowest element ID. MergeInstances must succeed before the organizer deletes a source type. The organizer merges the group before attempting to rename the target. FoundationTypePlannerTests checks the mark and dimension rules. OrganizeFoundationTypesTests checks that placed pier and footing instances survive a merge and reference the retained type. It also checks that the retained pier type can take the name of the merged type.

FLOW

  1. ResolveTypeMarkPolicy maps Overwrite Existing Marks and Preserve Existing Marks to TypeMarkPolicy. With all marks blank, Execute selects OverwriteExistingTypeMarks directly.

  2. Each family scheme supplies the dimension parameters, sort key, mark generator and name format. The organizer sorts the types in ascending order for each family and uses the element ID to break ties.

    Family Dimension key Sort
    Foundation Pier b, h b × h, then the dimensions in key order
    Foundation Pier - Round d d
    Footing-Rectangular, Pile Cap-Rectangular Width, Length, Foundation Thickness The dimensions in key order

  3. Preserve reserves existing marks across all four families and processes marked types before blank types. Overwrite assigns marks in size order and reserves the old mark of a type when a rename or merge fails. Rename and merge callbacks apply each change once.

  4. The workflow shows renamed, merged and skipped counts. If a skipped type keeps a mark already assigned in the run, the dialog and log report the mark and both type IDs.

DATA

FoundationTypeOrganizer.SetParam requires writable text storage for an assigned Type Mark and reports a rejected write. FormatLength requests UnitTypeId.FeetFractionalInches for the name. Grouping uses the stored dimensions to preserve instance geometry. If a dimension is missing or unreadable, the rename stops before the organizer writes the name or mark. The skip detail identifies the parameter. The organizer shares the warning defined by dbtools.FoundationTags.

The OrganizeFoundationTypes entry in build/Distribution/tool-contracts.json records the family names in column_families and foundation_families, plus type_mark_parameter and skipped_log. ToolContractsTests.EveryTextEqualsAStringValueOfItsToolSourceFiles searches the entry's full source_files list for each contract string. The list includes manifest.yml and FoundationTypeOrganizer.cs. Each value must match a string in at least one listed file.

DIAGNOSTICS

[OrganizeFoundations] reports the skipped count at Warning with up to five type IDs and reasons. A deletion error is logged and aborts the transaction.

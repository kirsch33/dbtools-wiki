Organize Foundation Types

Overview

Organize Foundation Types renames foundation family types, assigns type marks, and merges types with equal dimensions. It processes all matching types in the active document. It does not use the current selection or persistent settings.

Data and contracts

Families and parameters

The family-name comparison uses StringComparison.Ordinal.

Family Category Dimensions Prefix Sort order
Foundation Pier Structural Columns b, h P b * h
Foundation Pier - Round Structural Columns d RP Diameter
Footing-Rectangular Structural Foundation Width, Length, Foundation Thickness F Width, length, thickness
Pile Cap-Rectangular Structural Foundation Width, Length, Foundation Thickness CAP Width, length, thickness

All sorts are ascending. Dimensions use Double parameters. Type marks use the String parameter Type Mark. Dimension text uses Revit's feet-and-fractional-inches formatter. Missing dimension parameters display ?. Duplicate keys use the nullable raw dimension values.

Marks and names

Family group Mark format Name format Example
Rectangular pier P-{n}, starting at 1 {b}x{h} ({mark}) 2'-6"x2'-6" (P-1)
Round pier RP-{n}, starting at 1 {d} DIA. ({mark}) 2'-0" DIA. (RP-1)
Footing or pile cap {prefix}-{widthFeet}.{n}, starting at 0 {width}x{length}x{thickness} ({mark}) 3'-0"x3'-0"x1'-0" (F-3.0)

widthFeet is the floor of the width in internal feet. Each family group maintains its own ordinal set of marks encountered during processing. Generation searches from the starting counter for an unused mark in that set. It does not reserve marks on types that have not yet been processed.

The confirmation asks whether to overwrite existing marks. Yes selects TypeMarkPolicy.OverwriteExistingTypeMarks. No selects PreserveExistingTypeMarks. Preserve mode generates marks only for blank values, but still renames types and merges duplicates. SetParam leaves a missing, non-String, or read-only Type Mark unchanged, so a generated name does not guarantee a mark write.

Workflows

Processing and transactions

  1. Collect and sort the four family groups.
  2. Compare each type's dimension tuple with retained types in its group.
  3. For a duplicate, reassign its instances to the retained type.
  4. For a retained type, assign its mark when permitted and rename it.
  5. Delete successfully merged source types after processing the group.

The first successfully retained type for a dimension tuple becomes the merge target. Dimension comparison is exact. Each rename/mark operation and duplicate reassignment runs through a nested transaction-runner call. A failed reassignment rolls back that type's changes and records a skip. The organizer deletes a duplicate only after all its instances change type.

All groups share the outer DB Tools - Organize Foundation Types transaction. A deletion error logs at Error and propagates, rolling back the complete operation. Per-type failures log at Debug and increment the skip count. The final warning and completion alert include skipped totals and up to five type id: reason samples. The alert also reports renamed and merged counts.

Testing

Pure TypeMarkGeneratorTests covers sequential numbering, gaps, width groups, prefixes, and invalid arguments. Revit-hosted OrganizeFoundationTypesTests covers confirmation, completion reporting, duplicate merges, and document changes inside a rolled-back fixture transaction group.

Limitations

Family names must match the four listed names exactly. Dimension equality is exact, including missing values; missing dimensions can therefore cause types to merge.

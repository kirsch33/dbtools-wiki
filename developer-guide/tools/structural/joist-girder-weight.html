dbtools.JoistGirderWeight

NAME

dbtools.JoistGirderWeight - the assembly behind Update Joist Girder Weights

SYNOPSIS

source    src/Tools/Structural/JoistGirderWeight/   (manifest.yml)
assembly  dbtools.JoistGirderWeight
entry     JoistGirderWeightToolModule
command   UpdateJoistGirderWeightsCommand           (run profile InlineUi)
view      src/Tools/Structural/JoistGirderWeight/Settings/Views/JoistGirderWeightSettingsView.xaml

DESCRIPTION

The ribbon command and the auto-update task both call JoistGirderWeightUpdater.UpdateAll. It estimates Wt for each girder that matches the family pattern and writes it. The four patterns are .NET regular expressions from the settings. The user page describes the behavior, and Revit Execution the Core types.

STRUCTURE

Paths are under src/Tools/Structural/JoistGirderWeight/.

Path Contents
App/Composition/ JoistGirderWeightToolModule registers the settings section and pack. ServiceCollectionExtensions registers the auto-update task and the workflow.
Features/Workflow/ WeightUpdateWorkflow runs the command and shows the banner.
Features/AutoUpdate/ AutoUpdateTask is the view-activation task.
Features/JoistGirder/ JoistGirderWeightUpdater collects, checks and writes. JoistGirderClassifier compiles the patterns. JoistGirderWeightEvaluator holds the formula.
Features/Load/ Operations/ElementLoadReader reads Force and text parameters. LoadParser parses load text. LoadResolutionEvaluator picks the total or dead plus live.
Settings/ JoistGirderWeightSettings and SettingsPackContext, which holds the pack state and validation. Features/DefaultPatterns.cs holds the defaults.

CONTRACTS

  1. One transaction. UpdateAll checks every candidate and writes changed Wt values in one transaction named Auto Update Joist Girder Weights. A type parameter shared by several candidates is written once.
  2. Bad pattern. A pattern that does not compile throws JoistGirderConfigurationException before any write. The workflow shows it in a banner. AutoUpdateTask also activates the pack warning. UpdateJoistGirderWeightsWorkflowTests and AutoUpdateTaskTests check this.
  3. Other auto-update failures. ViewActivationHook skips the task for the rest of the document session, keyed by DocumentSessionKey. Core's ViewActivationHookTests check the mechanism. AutoUpdateTask admits the first run for a document, then compares its Core DocumentChangeStamp and the saved classifier patterns with the last successful run. It takes the stamp after any weight writes commit.
  4. Load groups. The same patterns find and classify the loads. ClassifyLoadGroup tries Dead, then Live, then Total, and throws if none matches. JoistGirderClassifierTests checks the groups but not the order. ElementLoadReader reads Double parameters with the Force spec and String parameters. It converts Force values to kips and compares spec names independent of version. LoadParser reads load text as a nonnegative number with an optional unit. The user guide lists the units. Blank Force and text inputs are unpopulated. Only populated inputs count toward ambiguity. A populated total takes precedence over the dead and live sum. Otherwise, both groups need an input and at least one group needs a value. A group with only blank inputs contributes zero. An instance input takes precedence over a same-named type input, including when the instance input is blank. Unsupported storage and invalid load text stay out of resolution. If neither load source resolves, the tool reports missing or blank loads and lists excluded matches and their reasons in the same issue. The diagnostic includes unparseable text.
  5. Empty and invalid patterns. An empty pattern means the default, in JoistGirderClassifier and SettingsPackContext.LoadCore. The context displays the defaults. It stores an empty string when the trimmed text matches the default and saves other pattern text as entered. CollectValidationErrors reports bad patterns, and the inherited BlockSaveOnInvalid makes Save refuse them. SettingsPackContextTests checks the errors, but no test checks the refusal for this pack.
  6. Admission. ViewActivationTask.AdmitAsync reads the settings once. It skips the task when auto-update is off or the pack warning is active. AutoUpdateTask runs with that copy. AutoUpdateTaskTests checks this.
  7. One warning. GetSingleWarning requires exactly one pack warning in manifest.yml. JoistGirderWeightToolModuleTests checks its ID, pack and disabled tool.

FLOW

  1. The command calls WeightUpdateWorkflow.Execute, which calls JoistGirderWeightUpdater.UpdateAll.
  2. UpdateAll collects the OST_StructuralFraming instances whose family name matches. It uses the type name only when the family name is empty.
  3. TryBuildUpdate checks Wt, number of joists, load, length and depth, in that order. The first failure is the skip reason.
  4. One transaction sets Wt. Updated counts the Set calls that do not throw, and ignores their bool result.
  5. The workflow shows the summary in a banner. Auto-update runs UpdateAll through its own TransactionRunner and InlineRevitCallGate, and discards the summary.

Formula

JoistGirderWeightEvaluator.EstimateWeight takes feet and works in inches. Its factors are local constants, such as allowableStress (50 ksi) and connectionFactor (0.6).

N  Number of Joists, used as the number of equal spaces
P  point load, kips, at each of the N - 1 panel points
L  length, in            D  depth, in

s      = L / N                         panel spacing
R      = P (N - 1) / 2                 end reaction
M      = R L / 2 - sum of P x (distance to midspan),
         over the panel loads between one support and midspan
F      = M / (0.95 D)                  chord force
A      = F / (50 ksi x 0.6)            chord area
top    = A L x 0.28356 lb/in^3 x 1.06  top chord weight
bottom = 1.13 x top
web    = 0.7 x top
Wt     = (top + bottom + web) / (L / 12), in lb/ft

DIAGNOSTICS

Log lines start with [JoistGirder]. Debug level adds the counts and up to five sample skips. Auto-update samples issues that are new since the last run for the same document. A bad pattern logs a Warning: Update failed for document … from the command, or Auto-update disabled due to configuration: … from auto-update.

dbtools.FramingJoins

NAME

dbtools.FramingJoins - the assembly behind Allow Join and Disallow Join

SYNOPSIS

source    src/Tools/Structural/FramingJoins/   (MAP.md, manifest.yml)
assembly  dbtools.FramingJoins
entry     manifest.yml ribbon tools, no moduleType
commands  AllowJoinSelectedCommand, DisallowJoinSelectedCommand
          (run profile InlineUi, split button group framing_joins)

DESCRIPTION

Both commands resolve FramingJoinsWorkflow and call ExecuteAsync with a FramingJoinOperation. The tool has no settings, hooks or warnings. The user page describes the behavior.

STRUCTURE

Paths are under src/Tools/Structural/FramingJoins/.

Path Contents
App/Composition/ The two commands, available through CommandAvailability.HasStructuralFramingSelection
Features/FramingJoinsWorkflow.cs ExecuteAsync: the selection, the filter, the transaction and the banner
Features/FramingJoinsWorkflow.Core.cs ExecuteCore, the loop over JoinOperationTarget delegates
Features/FramingJoinTargetBuilder.cs The category filter on plain IDs

CONTRACTS

  1. No module. The manifest has no moduleType. Each command adds the workflow through [CommandService], as in dbtools.AnalyticalSnapToLevel. FramingJoinsCommandTests checks the attribute on both commands.
  2. Targets. CollectStructuralFramingIds keeps only IDs in OST_StructuralFraming, without duplicates. The workflow keeps only FamilyInstance elements. Neither step reports what it drops. FramingJoinTargetBuilderTests checks the filter.
  3. Both ends. ExecuteCore calls the operation for end 0, then end 1, and counts a target after both calls. FramingJoinsWorkflowTests checks the calls and the count. FramingJoinsWorkflowRevitTests checks the Revit join state of a temporary beam.
  4. Failure. A failed call logs an error and throws InvalidOperationException with the element ID and the cause. The transaction then rolls back every target. FramingJoinsWorkflowTests checks the exception. No test checks the rollback.
  5. Refusals. The workflow throws SafeExecutionRefusedException for an empty selection (Select structural framing elements.) and for a selection without a framing instance (No structural framing elements in selection.). ExecuteCore rejects an empty target list. FramingJoinsWorkflowTests checks that guard. No test checks the selection refusals.

FLOW

  1. ExecuteAsync collects the targets, and builds a JoinOperationTarget for each with StructuralFramingUtils.AllowJoinAtEnd and DisallowJoinAtEnd.
  2. One transaction runs ExecuteCore: dbtools - Allow Join Selected or dbtools - Disallow Join Selected.
  3. NotificationBannerService.ShowToast shows a Success banner, such as Allow Join Selected with Allowed joins on <n> element(s). Then it calls EnsureWindowIfDebugMode.

DATA

Item Value
Reads The selection and the category of each element
Writes The join state at ends 0 and 1 of each framing instance

DIAGNOSTICS

Log lines start with [AllowJoin] or [DisallowJoin]. A failure logs Failed to apply <operation> join operation for element <id>. as an Error. Debug level adds the count.

TESTS

./test.sh test --tool FramingJoins                         # pure scope, the default
./test.sh test --tool FramingJoins --scope local -y 2026   # -y 2027 for Revit 2027

Pure tests cover the filter and ExecuteCore. Local tests cover the command attributes and one run in gm_test_model.rvt (Model paths). Without the model or a framing type, that run is inconclusive.

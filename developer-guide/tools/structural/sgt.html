DBTools.SGT

NAME

DBTools.SGT - the assembly behind Super Girt Tool

SYNOPSIS

source    src/Tools/Structural/SGT/        (MAP.md, manifest.yml)
assembly  DBTools.SGT                       (net10.0-windows; net10.0 portable build for pure tests)
entry     SgtToolModule
command   SgtCommand                        (run profile InlineUi)
hook      ContextualEditHook                (Edit SGT Wall on Modify | Structural Framing)
window    App/Views/SgtWindow.xaml          (raw embedded XAML; sandbox window DBTools.SGT.Main)
stable    src/DBTools.Presentation/Tools/SGT/, src/DBTools.Presentation/StructuralPreview/

DESCRIPTION

SgtCommand launches NewSessionWorkflow, which calls SgtWindowSession.RunModalFlowAsync. ContextualEditHook calls it directly with a WindowSessionLaunchRequest: New with a wall target, or Edit with a SystemId. The session owns one transaction group for the life of the modal window. Wall analysis builds a Plan; the window edits it through PlanStore; preview and placement read the same resolved member contracts.

The user page describes the behavior, and Structural Preview the 3D host.

STRUCTURE

Paths are under src/Tools/Structural/SGT/.

Path Contents

CONTRACTS

  1. One session group. SgtWindowSession.Start refuses an IRevitCallGate whose RunsInline is false, and a document whose IsModifiable is true, because a transaction is already open. It begins the group Super Girt Tool, then runs PurgeUnsupportedAsync inside it. A command uses ordinary transactions inside the group, and never starts or ends a group of its own. SgtWindowSessionTests checks the refusals.
  2. Commit only on success. WindowSessionLifecycle.FinalizeSession assimilates the group only when all of these hold: the close requests a commit, startup succeeded, no failure is recorded, and IsGroupHealthyAsync is true. Every other end rolls back: Cancel, the window's close box, a failed command, a handled UI error, and retirement of the window by its shell. WindowSessionLifecycleTests checks this.
  3. Plan admission. PlanStore.Initialize and Update change a detached copy and validate it with PlanAdmissionValidator before they replace the plan. A rejected or unchanged candidate keeps the plan and its Version. PlanStoreUpdatePolicyTests and PlanAdmissionValidatorTests check this.
  4. One segmentation. GirtSegmentBoundarySet.Split is the only girt segment computation. Plan-row segmentation, the preview, placement and the usable-span check all call it. GirtSegmentBoundarySetTests checks the rules, and PreviewPlacementParityTests the shared use.
  5. One resolved member. ResolvedMemberContractResolver builds one ResolvedMemberContract per member, and OpeningMemberContractCatalog lists the opening segments once. The preview modes and WallSystemWriter read these values and compute no transform of their own. PreviewPlacementParityTests compares the preview with the placed members.
  6. Write order. Profile warming places temporary instances (TemporaryTransactionRunner) to capture each section. It and placement set the cross-section rotation, then Flip, then Y and Z justification, then set the offsets to zero. Jambs add the WallRotationCompensationEvaluator angle to the rotation; the grid rows still show 0, 90, 180 or 270. FamilyInstanceMutatorTests and WallRotationCompensationEvaluatorTests check this.
  7. Storage format. SystemStorageMapper reads and writes format version 3 only. Every transport field is JsonRequired. It rejects unknown fields, numeric enum tokens and payloads over 4,000,000 characters. It migrates nothing: PurgeUnsupportedAsync removes the storage and member tags of other formats, and the tags of systems with no current storage. It keeps the members. SystemStorageMapperTests and SystemRepositoryTests check this.
  8. Ownership. SgtSchemaContract.TryGetOwnedSystemId owns an element only if it is Structural Framing and its tag has the marker SGT and a system ID. Selection, update, deletion and deconstruction use it. ContextualEditTargetEvaluatorTests checks this.
  9. Update by identity. WallSystemWriter indexes the owned members by role and tag identity. It moves each match in place, creates a member for a target without a match, and deletes owned members that no target uses. Two owned members with one identity fail with Update/DuplicateIdentity. WallSystemWriter.UpdatesTests checks this.
  10. Layers. Domain uses no App, Features, Persistence, WPF or Revit API code. Features use no App code, and Placement uses no WallAnalysis code. The portable net10.0 build has no Revit API, WPF or Presentation reference, and build/MSBuild/Portable.targets excludes .cs files under App/, Revit/, Views/ and DesignTime/. Other code that uses them does not build. Nothing checks the Domain-to-Features, Domain-to-Persistence or Placement-to-WallAnalysis rules.
  11. Raw XAML. The XAML is embedded as DBTools.ToolViews.SGT.<file>, with no x:Class and no WPF-derived type in the payload. RawXamlTierContractTests checks every payload view.

FLOW

  1. NewSessionWorkflow shows a prompt banner and calls WallTargetSelectionWorkflow.PickTarget. It asks for a linked wall (LinkedWallSelectionFilter), then, after Esc, for a host foundation wall (FoundationWallSelectionFilter). ContextualEditHook reads the selected system IDs instead, through ContextualEditTargetEvaluator.
  2. SgtWindowSession.Start begins the group and purges. WindowSessionBuilder composes the window, view model and SessionAnalysisOwner.
  3. PlanBuilder.BuildNewPlanAsync sets the framing mode, then runs FamilyCalibrationStep, WallAnalysisStep, ProfileWarmStep, PlanSeedingStep and admission. For an edit, StartupAnalysisWorkflow rebuilds the plan with PlanBaselineMapper and ChangeReviewPlanBuilder, and AnalyzeEditPlanAsync analyzes a copy of it against the wall. A stored system that does not load falls back to a wall pick (FallBackToPick).
  4. Grid edits reach PlanStore through PlanSynchronizationCoordinator. Preview edits go through PreviewEditingWorkflow, which records the window's Undo steps. PreviewRefreshCoordinator refreshes in UIEdit, PlanMutation or RenderOnly mode.
  5. After an edit startup, ChangeReviewWorkflow opens Change Review when ChangeReviewEvaluator reports NeedsAttention. Confirm analyzes the reviewed plan and saves only the decision ledger (SaveLedgerAsync).
  6. Place and Update synchronize and normalize the plan, run the preflight, then call PlacementWorkflow, PlacementExecutor and WallSystemWriter. The writer places members, tags them and calls ISystemRepository.Save in one transaction. A successful write closes the window with a commit; a failed or canceled write closes it with a rollback. A refused preflight keeps the window open.
  7. FinalizeSession releases the preview and window, then assimilates or rolls back the group. The UI state saves in the background.

DATA

Item Value
System storage One DataStorage per system, named DBTools_SGT_System_<SystemId> (GUID without hyphens), schema DBTools_SGT_SystemV2 (a schema name, not the format version). Its DataJson holds a SystemData envelope: Placed, the decision ledger and the settings.
Member tag Schema DBTools_SGT with Tag (SGT), SystemId, MemberRole (girt, head, sill, jamb_left, jamb_right) and ConfigJson.
Framing mode WallFramingMode.Standard for a linked wall, with the wall bottom as base. Foundation for a host foundation wall, with the wall top as base and a 20'-0" band. The JSON field is placementMode.
Rules MemberRules: AutoSeedSpacing 5'-0", MinimumLength 6".
UI state %APPDATA%\DBTools\Cache\SGT\ui-state.json: panel expansion, opening column widths and Bulk Edit fields. It never gates the model commit.

Revit element IDs are long in the plan, storage and placement records.

DIAGNOSTICS

SGT log messages use prefixes such as [SGT], [SGT.Preflight] and [SGT.Place.Cutback]. A plan rejection is a SpecFailure with the text [SpecFail/<area>/<rule>] <detail> (SpecFailureCodes). A UI error shows <action>: [SGT.UI.<area>.<name>] <detail> (UserErrorCodes). DiagnosticsPreflightLogger records analysis outcomes.

SGT is the structural wall-framing tool registered as DBTools.SGT. Its source is organized by runtime owner, not by the former Shell/ and Shared/ convenience buckets.

The feature owners are Openings, Orientation, Placement, Preview, WallAnalysis, and BulkEdit. Preview-owned editing lives under Features/Preview/Editing.

The remaining top-level owners have distinct responsibilities:

  • App/ owns command/window composition, modal sessions, startup, the live plan-store implementation and UI refresh coordinator, UI-only persistence, whole-window XAML hosting, view models, converters, and design-time binding shapes. AddAppStateServices is the App-state registration entrypoint; WindowSessionBuilder directly composes the one window session, and its runtime state remains private to the window view model.
  • Domain/ owns the required-target Plan aggregate, its IPlanStore port, PlanBaselineSnapshot, plan editing/projection, pure default/family resolution, and Revit-free wall/opening/orientation semantics. It has no dependency on App/, Features/, Persistence/, CommunityToolkit, or ObservableCollection.
  • Persistence/ owns ISystemRepository, the private storage transport, current-contract admission and serialization mapping, and the Revit-backed SystemRepository under Persistence/Revit. It has no dependency on App/.
  • Revit/ owns cross-feature Revit adapters that are not naturally owned by one feature.
  • Features/ owns feature-specific contracts, workflows, row mutation, observable UI items/collections, and Revit adapters. Features do not reference App/.

The generated SGT MAP is the current tracked folder and manifest-type index.

Application Boundary

manifest.yml binds the runtime front door in lockstep:

  • module: DBTools.SGT.App.Composition.SgtToolModule
  • command: DBTools.SGT.App.Composition.SgtCommand
  • window: DBTools.SGT.App.Views.SgtWindow
  • design-time view model: DBTools.SGT.App.DesignTime.SgtWindowDesignTimeViewModel (live Sandbox window consumer)

App/Views/SgtWindow.xaml, PreviewView.xaml, OpeningView.xaml, and GirtView.xaml are raw EmbeddedResource views. The stable ToolWindowFactory owns the modal shell; SgtWindow is a payload composition object that supplies the view model, composes the three child raw elements, attaches the preview presenter, and releases the view graph through the host session. The payload contains no XAML code-behind or WPF-derived view type. The compiled design-time resource page was retired, while SgtWindowDesignTimeViewModel and SgtWindowSamplePopulator remain as the live Sandbox window's manifest-selected design-time model. FeetInchesConverter was removed because no runtime consumer remains. There is no ShellWindow compatibility type or namespace forwarder.

The Sandbox creates the raw SgtWindow shell through its manifest entry and then invokes the stable ISgtSandboxViewComposer callback implemented by SgtWindowDesignTimeViewModel. The tool's SgtWindowRawViewComposer is shared by that callback and the live window, so the sample receives the same Girt, Openings, and Preview fragments, stable preview input behavior, and session-owned cleanup. The callback is declared in Presentation rather than Core because Sandbox and the candidate tool may use distinct host contexts while Presentation remains the stable WPF owner.

Revit-hosted window tests use modeless Window.Show() with a bounded DispatcherDrain. SgtWindowSessionTests drives the real run scope through RunWindowFlowAsync and keeps transaction rollback, plan-target, preview, DataContext, and overlay-cleanup assertions. Windows Pure WindowSessionLifecycleTests uses the real modal host and watchdog. It proves same-window re-entry after a pick without depending on another ContentRendered event.

App/Sessions/WindowSession/WindowSessionLifecycle.cs owns the lifecycle states, close intent, startup outcome, and finalization result. Its synchronous modal driver always returns a completed task because both production Revit command callers block immediately. A relink hides the window, executes the synchronous picker, then re-enters ShowDialog in the same command frame. One owned ContextIdle callback resumes target analysis after the window is visible. The driver rejects a modal return before the pick or shown handshake completes. It never posts modal re-entry.

WindowSessionStartupAnalysis observes the current initial-analysis or target-analysis producer. A completed producer delivers inline. A pending producer delivers through one owned dispatcher operation while the modal frame remains active. Closing during analysis cancels analysis and keeps the window and transaction group alive until its outcome arrives. Retirement revokes the producer callbacks and aborts the operation. No custom awaiter, scheduler, or nested task chain owns shutdown.

Forced retirement clears commit intent, releases payload resources, and publishes cancellation. If the synchronous picker is still on the stack, cancellation publication and transaction rollback wait until it returns; no target analysis or banner runs afterward. Ordinary Closed cleanup remains a distinct state and preserves an accepted commit. Native window and dispatcher references are captured before registration retirement. Transaction operations must complete through the inline Revit call gate, before the command returns.

App/Sessions/WindowSession/Revit/SgtWindowSession.cs supplies Revit picking and startup, window resource effects, and error-boundary integration to the lifecycle owner. Its RunModalFlowAsync is the production entry point. New/edit launch flows use a closed WindowSessionLaunchRequest: New requires a concrete WallTarget, and Edit requires a nondefault SystemId. The builder requires an inline Revit call gate and rolls back construction failures with ordered cleanup. The command consumes only completed lifecycle tasks. Cosmetic UI-state persistence has its own context-free observer and never delays transaction finalization.

Native X/Alt+F4 close reuses the WPF close already in progress. An active analysis delays close until its outcome settles. An accepted Closed releases mandatory preview/window resources and then finalizes the single owned Super Girt Tool transaction group inline. Successful close intent plus a healthy, successful session assimilates the group; Cancel, errors and forced retirement roll it back. SGT refuses an already-modifiable document at launch. A programmatic close that throws or returns without Closed rolls back once and leaves a close-only retry available to X, Alt+F4 and Cancel. The retry never finalizes again. No transaction is committed outside the session group.

The view model owns queued plan, preview, and render dispatcher operations. Disposal stops both refresh coordinators, drops the pending plan snapshot, and aborts queued callbacks before cancelling in-flight analysis. Late preview results cannot publish to a retired view. Girt/opening projection still publishes validation flags, but those derived notifications do not queue another UI edit; segment group display refresh uses the same suppression. This prevents invalid rows or refreshed group labels from feeding a perpetual preview queue.

Each analysis run owns its cancellation source until its finally completes. A newer run or view-model disposal cancels active work without disposing that source early. An idle source is cancelled and disposed immediately when replaced. Cancelled or superseded results cannot publish a plan or resume preview-mode changes after an asynchronous wait. A disposed view model creates no replacement idle source.

Model commit requires an explicit successful startup/model outcome and a healthy transaction group. UI-state persistence contains only cosmetic layout and bulk-edit preferences (expanded panels, column widths, and bulk defaults), so it is best-effort and does not gate model commit. Neither OK nor Cancel waits for cosmetic disk I/O. A successful model commit with a still-pending save logs that preferences are being saved in the background without showing a banner. An already-failed save reports a warning through the Revit/default-owner notifier after the accepted close. A finally block always attaches the context-free disk-task observer, including when transaction finalization throws. The deferred observer logs a later disk failure but does not touch the retired window. A Cancel path releases the transaction and window first, then observes the save task without changing its Cancelled outcome. Mandatory preview/window cleanup failures select rollback before assimilation. Synchronous transaction, cleanup, and finalization failures propagate; cosmetic save failures do not change a definite model commit. This cosmetic-save policy supersedes the pre-commit persistence gate introduced in 7e0c558faa. WindowInitializer attaches the exact per-window Core boundary, while WindowErrorBoundaryRegistry owns the dispatcher subscription and routes DBTools-owned failures (thrown from or passing through an assembly named exactly DBTools or starting with DBTools., which covers DBTools.HandyControl and the Helix merged into DBTools.Presentation; another add-in's raw HandyControl or Helix copy never qualifies) to the most recently attached active window, or the most recently attached window when none is active. The selected WindowErrorBoundary remains the sole classifier, presenter, and handled-state owner. SgtWindowSession subscribes to its exact boundary; a missing host fails session construction rather than entering a pending, global, or timing-dependent route. When Core routes and handles a failure on that SGT window, the session records the original exception and any presentation failure, requests rollback closure while preserving the modal frame, completes all owned cleanup, deterministically unsubscribes, and then propagates the original failure ahead of cleanup or modal-assertion failures through the command safe-execution boundary. Foreign dispatcher exceptions are neither handled nor signalled by Core, and SGT does not attach a competing dispatcher handler.

A direct ShowDialog failure before ContentRendered cannot have started analysis, so rollback, preview/window release, and transaction finalization are attempted synchronously on the current Revit UI thread before only context-free persistence can remain. Broken modal-continuation invariants are collected as finalization failures without short-circuiting mandatory rollback or owned cleanup. When the modal frame is already absent, the session records that invariant and does not knowingly await incomplete dispatcher-affine startup work; transaction admission downgrades an invalid modal lifetime to rollback and continues every safe owned cleanup step. UI-state persistence observes late failures without retaining the retired session and logs them without posting UI work after retirement. Opening-member snap endpoints are explicit: header/sill use Start or End, while jambs use Top or Bottom; the resolver rejects any mismatched role/endpoint request before resolving a target or creating an edit. WallGeometry is a Revit-free Domain contract for validated construction, point/face/center projection, and inclusive physical bounds. The safe-execution boundary owns user-facing reporting. No forwarding StartSession entrypoint, competing SGT dispatcher exception subscription, or window-owned fallback lifecycle remains.

Feature Boundaries

Placement

Features/Placement/Domain contains pure command-state values/evaluation, preflight/readiness rules, gaps, validation, and placement-only domain projections. Features/Placement/ViewModels/PlacementCommandStateProjector.cs adapts the live girt/opening view models into those pure inputs and applies their validation state. Features/Placement/Planning creates placement projections from the domain plan; Features/Placement/Operations/ModelWrite owns the inward writer port, write context, contract catalog, and opening target; Persistence/ElementTagSchema holds the element-tag schema constants; Features/Placement/Revit/ModelWrite implements model mutation. App/session workflow owns command-level analysis orchestration through App/Sessions/Workflow/AnalysisSessionWorkflow; Revit-backed wall analysis and plan construction live under Features/WallAnalysis/{Domain,Revit/Planning}. Placement has no dependency on WallAnalysis. The ModelWrite name identifies the external model-write boundary.

Recoverable plan rejections use SpecFailure results at the opening-segment, preview girt-snap, member-segment hydration, and placement-projection boundaries. Their UI callers show the exact typed rejection and do not publish a plan or preview change. Argument defects, cancellation, and unexpected projection/runtime faults remain exceptions and propagate unchanged through the established safe-execution boundary. Revit transaction/model-write owners may still use SpecFailureException where exception unwinding is required to roll back; callers must not translate unrelated runtime faults into ordinary validation results.

Plan admission rejects invalid updates with SpecFailureException carrying PlanValidationFailed and the validation details. Parent opening persistence and segment mutation translate only that code into their existing failure results. Rejection preserves the committed plan and version. Parent edits remain suppressed until a successful retry or cancellation. Rejected segment add, delete, and property changes show the typed failure in both the banner and preview status without requesting a refresh. Unrelated exceptions still propagate.

UI-to-plan synchronization reads the committed layer directly when the UI selection is absent. It constructs the girt projection at its consumer and lets opening persistence own opening projection. Segment lookup and deletion use canonical opening rows through the existing row resolver; no synchronization or segment context wrapper duplicates those owners.

PlacementElementTagStore owns element admission for contextual selection, update, removal, and deconstruction. An owned element must have the structural-framing category, a valid SGT schema entity, the exact SGT marker, and a nonblank system ID. Updates collect admitted instances once per transaction and decode each tag into a role-and-identity index. Each target consumes its matching entry. Unmatched admitted instances are retired only after all requested walls are processed. Wrong-marker elements remain outside SGT ownership even when their stored system ID matches.

PlacementWorkflow retains the command's SafeExecutionResult and returns one placement/removal outcome. Successful commands request successful close. A failed or cancelled model write requests rollback close. Declining removal confirmation leaves the window open because no write began. Revit/CommittedWrite/CommittedWrite maps Revit refusals and non-committed transaction status to Transaction/NotCommitted while retaining the original cause. Each command uses ordinary transactions inside the existing session group.

Placement-owned dialog ports are IDangerConfirmationDialog and IUpdateSummaryDialog under Features/Placement/Workflow. App/Sessions/WindowSession/WindowSessionDialogs.cs implements them. Placement does not depend on an App-owned dialog contract.

Change Review and physical acceptance

Features/ChangeReview owns the detached review candidate, row decisions, target precedence, decision ledger, relink pairing, and the raw dialog. The dialog is loaded as an embedded raw XAML view by the tool-window host; it has no payload x:Class or code-behind. Accept, Keep, and Ignore are the only decision terms exposed to users and code. Opening labels use source name and along-wall range; the canonical opening key remains an internal identity only.

ChangeReviewWorkflow synchronizes the accepted plan before capturing its revision, reads one live snapshot, and analyzes a confirmed candidate before publishing it. A review Confirm writes only the detached plan/ledger state. The later Place or Update command owns model writes and updates Placed from the actual write result. A successful review can therefore be followed by several ordinary model commands while the same session TransactionGroup remains open.

The session lifecycle owns the review child and any relink picker. It retires a child in finally, closes the child before hiding the parent for a pick, and resumes the same synchronous modal driver after the picker returns. Normal window Cancel, native close, command failure, and forced retirement roll back the one session group. Only a successful window close assimilates it, producing one Revit Undo entry named Super Girt Tool. No review or placement command starts an outside transaction group.

Preview

Features/Preview/Domain owns preview scene, palette, wall, girt, opening, grid, and computed segment-assignment state. Features/Preview/Rendering/Scene3D builds plain SGT mesh values; Features/Preview/Views/Rendering/Scene3D/StructuralPreviewSceneAdapter maps them to stable IStructuralPreview3D snapshot DTOs. WPF renderers and canvas layout live under Features/Preview/Views. The stable Presentation viewport owns Helix, camera navigation, fit/reset, hit testing, hover, and selection materials; SGT payload code has no Helix reference. PreviewPresenterBehavior retains 2D elevation/section drawing, handles, snapping, context menus, and row selection, while forwarding 3D scene and emphasis updates through the stable API. SgtWindow composes PreviewView.xaml into the stable host and retires the presenter before transaction finalization. Placement view models do not store Preview domain objects. Preview edits mutate the Domain plan and request FromPlan projection instead of mirroring state into Placement rows. PreviewServiceCollectionExtensions.cs registers the feature, and the App window-session builder binds it into the modal runtime. Preview edit workflows live under Features/Preview/Editing/MemberResolution/Segmentation; reusable plan-edit calculations live under Domain/PlanEditing.

StructuralPreviewSceneAdapter is the sole boundary from payload scene metadata to stable Presentation DTOs. Mesh IDs preserve source row, role, and segment identity so click selection, hover tooltips, sibling dimming, segment emphasis, and wall-context materials remain deterministic. SGT disables the stable viewport's own tooltip popup so the payload PreviewView overlay remains the sole user-visible tooltip surface; stable pointer events still feed payload formatting, including wall-only click tooltips and wall-hover clearing. Wall meshes remain pickable context hits but never select rows; member hits retain precedence when both are present. The adapter also emits the legacy transparent floor plane and clamps overlay thickness to the former minimum. Scene bounds and exterior normal preserve the previous home camera orientation; the stable presenter owns orbit/pan/zoom/fit and camera persistence for the lifetime of the hosted view.

Features/Preview/Refresh/PreviewProjectionService projects an explicit Plan without changing that plan or its store. App owns segmentation reconciliation for UiEdit and PlanMutation. A changed plan refreshes the UI and queues RenderOnly before any preview publication. RenderOnly reads the committed plan without reconciliation. PreviewRenderingService owns scene construction and its cache, not plan state. PlanSynchronizationWallSetupProjection projects the Layer selector items from the accepted plan; the preview projection does not own them.

PreviewRefreshCoordinator owns monotonic request, completion, and success sequences. Only Applied advances success. Blocked completes without success. Deferred completes without success and the coordinator queues one RenderOnly successor; readiness waits for it. Disabled previews, rejected UI synchronization, missing plans, canceled builds, and failed builds cannot satisfy publication readiness. A UI-dispatch rejection fails the attempted sequence and preserves any newer request for dispatch.

The production presenter acknowledges a scene only after the available viewport applies the scene, emphasis or reset, and selection highlight. Missing subscribers, unavailable presenters, and contained rendering failures return Blocked; failures clear the scene cache so a later refresh can retry. When the runtime presenter attaches after the view enters 3D mode, it invalidates the prior publication key and requests one render-only refresh through the scene event. A reused view model therefore redelivers its cached scene to the new presenter instead of treating the old delivery as current. App records a scene cache key only after publication succeeds. A matching cache hit can satisfy readiness without another publication. A cached but unpublished scene forces a new build. Cache clearing and failed publication invalidate this evidence. Analysis switches to elevation only after preview readiness succeeds.

Openings, Orientation, WallAnalysis, and BulkEdit

Opening keys are canonical GUID-N strings and survive source changes. OpeningLiveReference and WallTargetReference carry owning-document UniqueIds plus the host link-instance UniqueId where needed. OpeningRuntimeIdIndex assigns keys ordinal IDs 1..n within each projection; it never derives those IDs from key bits or Revit ElementIds.

Opening rows own along start/end distances in feet. OpeningGeometryResolver derives the normalized runtime frame from those distances and the current wall length, so a manual opening does not stretch with the wall. A local geometry edit converts Live to Manual while preserving its live reference and source name. Held and Unframed rows are read-only and show (awaiting review) or (not framed) respectively. Only Unframed excludes an opening from girt boundaries and opening members; disabling all roles still splits girts. OpeningRoleRules.ApplySeedDefaultsForEnabledRoles is the shared seeding core: geometry changes remove roles that cease to apply, seed newly applicable roles, and preserve still-applicable overrides and user-disabled roles.

GeometryFingerprint.Compare owns wall/opening change tolerances (0.01 ft and 1 inch), including type, layer material/function, frame, reflection and framing-mode changes. Live geometry captures material names from the owning document; no wall identity is stored in WallGeometryContext.

  • Openings owns Revit opening queries, editable-row mutation/sync/projection, and opening pane view models; stable opening identities, ranges, contracts, and feet geometry live beside EditableOpeningRow in Domain/Openings.
  • Opening bounds accept only complete finite source candidates. Complete cut-face bounds replace every fallback; otherwise solid bounds seed the result, width replaces solid horizontal bounds before profile union, and vertical precedence is profile, parameters, then solid. Absent geometry, solids, cut generators, or profile loops may fall through to the next source, but traversal, symbol-geometry, triangulation, transform, and non-finite-vertex faults retain their original exception identity and stack. If any supported insert exhausts every bounds source, the query returns one typed OpeningQuery/Incomplete failure and no partial opening list. Wall-context failures remain typed unchanged, and opening-row recovery recognizes the exact UI/PlanMissing code rather than exception message text.
  • Orientation/Revit/Analysis owns the Revit-backed family-orientation analyzer and solver inputs; Orientation/Analysis retains portable rotation math and solver results, while shared orientation value semantics remain in Domain/Orientation.
  • WallAnalysis owns its inward plan-builder contract plus Revit geometry extraction, calibration, profile warming, seeding, and plan construction under WallAnalysis/{Domain,Revit/{Geometry,Planning}}; WallContextResolver admits only a closed WallTarget, produces ResolvedWallContext, and that resolved context is the sole host/link input to the one production WallGeometryBuilder assembly path. Calibration checks cancellation before argument validation or cache access; argument defects throw, typed SpecFailureException failures become calibration results, and only successes are cached. Family calibration is a per-family preflight: it logs a failed family and continues, and each type of that family then carries the typed failure, with family and type names, as a per-role orientation failure. The orientation analyzer throws SpecFailureException for expected family incompatibilities and WallAnalysisFramingTypeAnalyzer converts them per role. Host and linked frame construction share one typed frame-failure boundary in WallGeometryBuilder. Cancellation, rollback failures, and invariant defects propagate. Live Plan Admission and Synchronization

Every Plan and PlanBaselineSnapshot has a required WallTarget. Host wall IDs, linked wall IDs, and link-instance IDs remain 64-bit through persistence, Revit lookup, hashing, opening identity, placement, and preview projections. Real opening element IDs and compound-wall material IDs also remain 64-bit through opening query/key resolution and material-name lookup; manual-opening surrogate IDs and layer indexes remain int. Plan.Clone() detaches each mutable collection consumed by UI projection: editable girt/opening rows, runtime member/opening definitions, baseline lists, type options, layer snapshots, orientation/profile maps, grid collections, and execution context. Shared leaf values are immutable.

PlanStore owns a detached accepted plan. Initialization copies its input before preparing or stamping it. Reads and notifications return detached snapshots. Update is the write boundary: rejected changes and mutator exceptions preserve content and version, while no-op updates publish no event. Accepted updates advance once and detach the callback's candidate before storage, so a retained mutator reference cannot change accepted state. Notifications occur outside the write lock. Shared wall-layer collections expose read-only storage.

Member segment replacement materializes and filters candidates before replacing the current segments. Empty or all-short input, and enumeration failure, preserve the prior segment set. Replacement from the member's own segment view remains valid.

Plan-change admission uses one lock and one latest-pending slot:

  1. Enqueue clones the accepted plan and assigns a monotonic request revision.
  2. An arrival while a dispatcher callback is already scheduled replaces the pending snapshot; the existing callback applies the latest revision.
  3. The apply turn clears the pending slot and marks itself applying before projecting.
  4. An arrival during apply fills the pending slot without recursing; completion schedules exactly one later Dispatcher.BeginInvoke turn.

The coordinator neither frame-pumps nor drops a busy arrival. Its request revision is the refresh-admission identity; Plan.Version remains plan data and diagnostic context, and no last-refreshed-plan-version cache participates in admission. If applying one snapshot fails while a newer snapshot is pending, it still attempts that pending dispatch. A failure of both operations is reported primary-first, and the failed dispatch resets admission so a later plan change can schedule normally.

PlanSynchronizationCoordinator.TryApplyPartialEdit owns every UI-originated partial plan write: the opening parent-row commit, the girt segment flyout, the opening segment flyout rows, the PreviewEditingWorkflow entry points (snap, typed gap, segment delete, merge) and jamb segment add and delete. Each such write, and SyncPlanFromUI (the UIEdit preview pass, Place and Update, Change Review), refreshes every pane from the written plan before it returns: it applies the refresh its own write queued (ApplyPendingPlanRefreshOnUI, inside the same ApplyPlanRefresh batch as every other plan refresh), so no queued preview pass or later write projects stale pane rows over the accepted edit, and a field typed after the write keeps its text. Before it projects, the coordinator applies a refresh still queued by a plan written outside it (Undo or Redo of a Preview-only edit, PlanStore.Initialize); it then projects the whole UI (TryProjectPlanFromUI) and writes the edit on top of that projection as one plan version: unsaved valid drafts are written with it, for example a wall offset pushed on LostFocus whose Background sync has not run when a Send-priority opening commit arrives, or an edit made while a 3D scene build runs. While any field is invalid it writes nothing, records no Undo entry and shows the status of a blocked sync (Fix invalid fields, Fix invalid rows or Preview blocked). Only such an outside write still refreshes at Background: a field typed after it and before its refresh takes the refreshed value. Each writer builds its change from a detached copy of the projection: a PreviewEditOutcome is a pair of plan changes that PreviewEditingWorkflow writes once through the coordinator and then records, so Undo and Redo replay only that change on the stored plan, and the drafts written with it stay; a rejected opening segment edit aborts the write. Deleting girt rows is a grid draft with no plan write and is never refused; GirtProjectionMapper.ApplyProjectedRowsToPlan normalizes every segment group in the projection with SegmentGroupRenumberer, so the next sync leaves no gap in the order, no parent key of a deleted row and no group of one row. Accepted typed gap edits enter the same history; undo and redo restore the prior raw override, and each accepted typed edit clears any redo branch. The 2D preview's gap editor (PreviewView2DGapEditor) survives redraws: PreviewView2DState.ClearCanvas is the only canvas clear and keeps an open editor, its anchor is re-placed under the current pan and zoom, and keys typed in it are its own. Undo and Redo bypass the admission by design: they replace the plan, and so every pane's fields. A refused type change (girt segment flyout, or an unavailable type in the girt grid) reports through GirtPaneViewModel.ShowRefusedTypeChange and sets no blocker. Only a girt grid row that keeps a rejected type, or an extent validation fault, sets the girt-pane blocker; the next girt row edit, a row add or delete, a bulk repair of that row or a plan refresh clears it.

EndpointAssociationOpeningEdgeSide is the sole live opening-edge semantic type across extents, member gaps, preview editing, and persistence transport. Domain/Extents/OpeningEdge owns the closed OpeningEdgeExtent, DualOpeningEdgeExtent, and OpeningEdgeEndpoint family: named wall, fixed-distance, grid, and neighbor-opening variants preserve the current persisted extent fields without a positional public factory. Strings exist only where a UI label or serialized composite key actually requires text; no plan/UI row stores a second string edge representation.

Preview girt segmentation carries MemberSpanEndpointKind directly from endpoint selection through both ordinary and opening-edge gap resolution; boolean conversion is not a gap-operation boundary.

Girt segment boundaries and endpoint anchors

Domain/Girt/SegmentBoundary/GirtSegmentBoundarySet is the single source of truth for where a girt may start, end and split. For a girt at elevation z, an opening blocks it when the opening spans z (inclusive, 1e-6 ft tolerance), is framed, is not bypassed by the row, is not the row's interior opening, and keeps a nonzero width after its span is clamped to the wall. Start-capable boundaries are the wall start and each blocking opening's higher edge; end-capable boundaries are each blocking opening's lower edge and the wall end. The row's interior opening adds its lower edge as start-capable and its higher edge as end-capable. GirtSegmentBoundarySet.Split is the only girt segment computation, and it omits every span shorter than MemberRules.MinimumLength (0.5 ft). Its callers are plan-row segmentation (GirtSegmentationReconciler), preview (PreviewGirtSegmentBuilder), placement (MemberSegmentResolver.ResolveGirtSegments), the usable-span check (MemberResolutionExtentsProjection.HasUsableGirtSpan) and the girt snap offer (GirtExtentSnapPlanEditor.ResolveBoundaryEdges). MemberSegmentResolver is an internal static girt-only resolver; WallHydrator resolves every member through it and rejects a non-girt member with MemberSegment/RoleUnsupported.

GirtSegmentBoundarySource supplies the wall length, openings, grid positions and the framing predicate. FromOpenings holds the only production predicate, which frames every opening: an opening with every framing role disabled still splits girts. FromPlan builds the source from plan rows (segmentation, the resolver and the snap editor); MemberResolutionExtentsProjection.GirtBoundaries builds it from runtime opening definitions (preview, placement and the usable-span check). TryResolveT clamps an opening edge to the wall exactly as the boundary set does.

GirtSegmentationReconciler splits each segment group from its first sibling's start to its last sibling's end (clamped to the wall) and reuses row identities by overlap. The first and last child keep the group's outer anchors and endpoint gaps, also when Split omits an outer pier shorter than the minimum length; only the ends between two children become opening-edge anchors. A group with one span collapses to one row; a group with no span keeps its rows as authored, and placement reports them. An interior row is its own row: it leaves the segment group it sat in, and SegmentGroupRenumberer.RenumberSegmentGroup normalizes the rows that remain (a group of one row dissolves).

Domain/Girt/EndpointAnchor/GirtEndpointAnchor is the stored anchor of one girt endpoint and the only reader of stored girt anchors. Its kinds are Wall (stored as ExtentKind.FullLength), Grid, and OpeningEdge (opening key + Left, the lower-T edge, or Right, the higher-T edge). Girt endpoints never use ExtentKind.MemberEdge; that kind remains only for opening-member (jamb, header, sill) segments. An opening-edge endpoint keeps its user gap only in OpeningEdgeGapOverridesFeet["<key>:<Left|Right>"]; otherwise its gap is derived live from the jamb at that edge and elevation (GirtGapResolver.GetDefaultOpeningEdgeGapFeet), and it is 0 when there is no jamb. GirtGapResolver.GetOpeningEdgeGapFeet is that one rule; preview, the gap editor and placement all call it. When the plan cannot resolve a gap handle's gap (for example the edge of an opening deleted before the preview redraws), PreviewEditingWorkflow.TryGetMemberGapFeet shows a Gap edit failed banner and no gap editor opens. StartGapOverrideFeet and EndGapOverrideFeet apply only to Wall and Grid anchors. The gap of such an end has one rule, GirtGapResolver.GetEndpointGapFeet, which preview (MemberGapResolver.GetEffectiveEndpointGapFeet), the gap editor and placement (GirtEndpointGapEvaluator.ComputeEndpointCutbackFeet) all call: the endpoint gap override when set; otherwise, when the end lies within 1e-4 T of an edge that can bound it (a start on the higher edge, an end on the lower edge of a boundary opening in the girt's own boundary set), the gap derived from that edge's jamb; otherwise 0. GirtPlanRow.SetAnchor clears the endpoint gap when it writes an opening edge, and GirtPlanRow.ReplaceAnchor (snap edits, merges) also clears the gap entries of the old and new edges. GirtPlanRow.Reanchor (the resolver) clears the endpoint gap and the lost edge's entry and keeps the entry of the edge it moves to. GirtPlanRow.AbsorbPayload is the one rule for taking in a merged row's payload: bypass lists are united and gap entries are added, and on a key conflict the receiving row's entry wins. The resolver merge (the survivor receives), the preview segment merge (the kept row receives) and the segmentation group proxy (the first sibling receives) use it. Interior intent is derived, not stored: a row whose start is the lower edge and whose end is the higher edge of one opening it does not bypass spans that opening (GirtEndpointAnchor.FindInteriorOpeningKey, exposed as GirtPlanRow.InteriorOpeningKey).

GirtEndpointAnchorResolver.Resolve is the only re-anchoring rule. MemberSegmentationReconciler.Recompute runs it after opening-role normalization and before opening and girt segmentation. Recompute runs on each UI-edit or plan-mutation preview refresh, after committed opening edits, and in PreparePlacementPlan before Place/Update preflight; a render-only preview draws the plan as stored. An endpoint is lost when its grid is gone (GridRemoved), its opening is gone (OpeningRemoved), or its opening edge is not capable for that end in the row's boundary set (OpeningNotBoundary, for example when the opening no longer spans the girt, lies outside a shortened wall, or is bypassed by the row). A lost end takes the row's other end as reference: a start moves to the nearest start-capable boundary at or before reference − minimum length, an end to the nearest end-capable boundary at or after reference + minimum length, and the wall ends are the fallback. When both ends are lost, the start moves to the wall start and the end to the first end-capable boundary at or after the minimum length. The re-anchored end loses its endpoint gap and the gap entry of its lost edge; the edge it moves to keeps its gap entry. Bypass keys and opening-edge gap entries of openings that are no longer in the plan are removed. Siblings of one segment group that now overlap merge into the earlier sibling: the survivor keeps its member key, each side keeps the outermost anchor that was not re-anchored (with its gap), bypass lists and gap entries are united with GirtPlanRow.AbsorbPayload, opening-member targets that named an absorbed row are rewritten to the survivor, and the group is normalized with SegmentGroupRenumberer. Segmentation then re-splits the plan and reuses identities by overlap. PlanSynchronizationCoordinator.NotifySegmentedStateRecompute reports MemberSegmentationSummary.ReanchoredGirtEndpoints ("Re-anchored N girt end(s) to the nearest opening or wall edge.") and MergedGirtRows ("Merged N overlapping girt segment(s) into their neighbors.").

GirtExtentSnapPlanEditor.Create accepts an opening edge for a girt's start or end only when IsBoundaryCapable finds it capable for that end in the boundary set of the edited row (GirtSnap/BoundaryInvalid otherwise). The snap removes that opening from the row's bypass list, and a start on the lower edge of the opening whose higher edge is the end makes that opening interior. An edit that leaves no span of the minimum length fails with GirtSnap/NoUsableSpan. Create and ResolveBoundaryEdges apply the same plan-side test (IsBoundaryCapable, then HasUsableSpanAfterEdit over GirtSegmentBoundarySource.FromPlan), so ResolveBoundaryEdges offers exactly the edges Create accepts; an edit whose other end does not resolve is rejected with GirtSnap/NoUsableSpan, and PreviewEditingWorkflow.ResolveGirtSnapEdges routes each drag handle: a handle on the row's own start or end gets that end's accepted set, and any other segment handle is unrestricted. The snap index has no free-along target.

Runtime resolution reports an opening-member split-label position more than 0.01 ft outside the wall through RuntimeHorizontalPositionResolution.OutOfRangeResult: clamped T for rendering, OutOfRange = true, and a SplitOutOfRange reason. Non-finite split text is invalid (MemberEdgeInvalid). A header or sill split label outside the wall fails placement with Extents/PositionResolutionFailed, while preview can draw the clamped member. Grid positions are clamped to the wall. Stored girt endpoints accept only Wall, Grid, or OpeningEdge; runtime AlongExtent still represents a resolved Wall↔Grid span.

Wall-analysis progress uses (string message, double? progress01) end to end. Non-null values are normalized to [0,1]; null denotes indeterminate progress. Framing orientation analysis returns one FramingTypeOrientationAnalysisResult data value; it never transports orientation records through progress. Profile warm-state extraction uses the caller-provided logger rather than creating global runtime logging state.

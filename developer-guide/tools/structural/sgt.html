dbtools.SGT

NAME

dbtools.SGT - the assembly behind Super Girt Tool

SYNOPSIS

source    src/Tools/Structural/SGT/        (manifest.yml)
assembly  dbtools.SGT                       (net10.0-windows; net10.0 portable build for pure tests)
entry     SgtToolModule
command   SgtCommand                        (run profile InlineUi)
hook      ContextualEditHook                (Edit SGT Wall on Modify | Structural Framing)
window    App/Views/SgtWindow.xaml          (raw embedded XAML; sandbox window dbtools.SGT.Main)
stable    src/dbtools.Presentation/Tools/SGT/, src/dbtools.Presentation/StructuralPreview/

DESCRIPTION

SgtCommand launches NewSessionWorkflow, which calls SgtWindowSession.RunModalFlowAsync. ContextualEditHook calls it directly with a WindowSessionLaunchRequest: New with a wall target, or Edit with a SystemId. The session owns one transaction group for the life of the modal window. Wall analysis builds a Plan; the window edits it through PlanStore; preview and placement read the same resolved member contracts.

The user page describes the behavior, and Structural Preview the 3D host.

STRUCTURE

Paths are under src/Tools/Structural/SGT/.

Path Contents
App/Composition/ SgtToolModule, SgtCommand, ContextualEdit/ and every service registration (ServiceCollectionExtensions and the feature *ServiceCollectionExtensions).
App/Startup/, App/Sessions/ NewSessionWorkflow, StartupAnalysisWorkflow, SgtWindowSession, WindowSessionLifecycle, WindowSessionBuilder, SessionAnalysisOwner.
App/State/PlanSynchronization/ PlanSynchronizationCoordinator writes grid values into the plan.
App/Views/, App/ViewModels/ SgtWindow, SgtWindowViewModel, and the preview view and presenter. The presenter is in App because it routes grid input through WindowSessionSurfaceCoordinator.
Domain/ Plan, PlanStore, geometry, segmentation, gaps and resolved member contracts.
Features/ BulkEdit, ChangeReview, Girt, Openings, Orientation, Placement, Preview, SegmentFlyout, WallAnalysis. Revit code is in their Revit/ folders.
Persistence/ SystemStorageMapper, StoredSystem, ISystemRepository, Revit/SystemRepository, Revit/SgtSchemaContract, ElementTagSchema.
Revit/ Shared adapters: family symbols, framing parameters and wall frames. TemporaryTransactionRunner rolls back probe edits; CommittedWrite runs a write that must commit, and maps a refusal to Transaction/NotCommitted.

Presentation holds the stable WPF side: the grid and preview behaviors and drag input in Tools/SGT/, and the Helix viewport behind IStructuralPreview3D. SGT code has no Helix reference.

PreviewLengthFormatter formats girt segment lengths and wall layer thicknesses in preview tooltips. It rounds to one decimal place in inches and carries 12.0 inches to the next foot. Wall layer labels show inches alone below one foot.

CONTRACTS

  1. One session group. SgtWindowSession.Start refuses an IRevitCallGate whose RunsInline is false, and a document whose IsModifiable is true, because a transaction is already open. It begins the group Super Girt Tool, then runs PurgeUnsupportedAsync inside it. A command uses ordinary transactions inside the group, and never starts or ends a group of its own. SgtWindowSessionTests checks the refusals.
  2. Commit only on success. WindowSessionLifecycle.FinalizeSession assimilates the group only when all of these hold: the close requests a commit, startup succeeded, no failure is recorded, and IsGroupHealthyAsync is true. Every other end rolls back: Cancel, the window's close box, a failed command, a handled UI error, and retirement of the window by its shell. WindowSessionLifecycleTests checks this.
  3. Plan admission. PlanStore.Initialize and Update change a detached copy and validate it with PlanAdmissionValidator before they replace the plan. A rejected or unchanged candidate keeps the plan and its Version. PlanStoreUpdatePolicyTests and PlanAdmissionValidatorTests check this.
  4. One segmentation. GirtSegmentBoundarySet.Split is the only girt segment computation. Plan-row segmentation, the preview, placement and the usable-span check all call it. Jamb extent resolution uses these spans to find girts that reach each jamb. A failed span lookup identifies the girt and endpoint. OpeningSegmentationReconciler splits usable pieces outside the default jamb span and preserves manual joints. It ends an extension 1/2" from the girt face when the next piece cannot fit. The requested mode and target remain the inputs to each recompute. The effective end supplies the preview status and the placed geometry. GirtSegmentBoundarySetTests checks the rules, and PreviewPlacementParityTests the shared use.
  5. One resolved member. ResolvedMemberContractResolver builds one ResolvedMemberContract per member, and OpeningMemberContractCatalog lists the opening segments once. WallFrameBuilder locates the wall center from the Revit side faces. It transforms linked faces into host coordinates and pairs side planes separated by the full compound thickness. It sums coplanar face areas on each side, then compares the smaller area of each pair first and the larger area second. A tie between distinct exterior planes or a missing pair fails wall analysis. A slanted or tapered cross-section also fails. WallTargetFrameBuilder adds WallOffsetFeet to the exterior face of the selected layer. The target plane serves analysis, preview and placement. The preview modes and WallSystemWriter read these values and compute no transform of their own. DirectionalGapEvaluator measures the gap at a jamb in the wall's along direction. PreviewPlacementParityTests compares the preview with the placed members. It measures the Section anchors and placed location lines against the selected layer plane. It checks section seating, channel toe direction and Z flange heights, and it measures two sizes of the same channel family on a compound wall. It measures placed header and sill clearances at jambs in every representative state and girt clearances in the seeded states.
  6. Framing analysis and write order. WallAnalysisFramingTypeAnalyzer groups types by family and cross-section shape. Square and rectangular HSS form separate groups. The analyzer calibrates one sample and solves each eligible role. Probe inputs are the type parameter values and the initial instance parameter values and Flip capability for the role's probe axis. They exclude Revit identity metadata and IFC export GUIDs. A type can reuse a failed role from the sample or from a previous variant with matching inputs. Each type verifies inherited settings against its own geometry. If those settings fail seating or the probe inputs differ, the analyzer solves only failed roles and verifies the new settings on the existing profile probes. FamilyOrientationAnalyzer checks visible framing solids against the target and role planes. The target plane allows 0.0005 ft of modelling tolerance. The geometry reader excludes solids identified as non-steel and lists their material names and classes if every visible solid is excluded. A channel jamb must have a measured toe direction away from the opening. A Z girt seats its exterior flange below its interior flange. An angle girt seats the back of its long leg flat on the target plane, facing the exterior, with the short leg at the bottom toward the interior. The analyzer captures each type's profile and reads its Start and End Extension limits in a rollback transaction. For each rotation and Flip, it measures the separate Y and Z justification translations and combines them for mixed settings. It checks that the samples share the same pose, section axes and outline. It measures solved defaults directly on Revit geometry to check seating and verifies the combined profiles for mixed defaults against those measurements. A saved row outside the orientation catalog can still supply a profile. The session reuses results while the type parameter values, target frame and sample settings match. The writer checks the recorded extension limits for each girt segment before member writes. Profile warming and placement set rotation, Flip, Y and Z justification, then zero the offsets. Jambs add the WallRotationCompensationEvaluator angle to the rotation. The grid shows 0, 90, 180 or 270. The writer regenerates the batch before it records the placed endpoints. FramingTypeProbeBudgetTests checks the analysis cost, and FamilyInstanceMutatorTests checks the written parameters.
  7. Storage format. SystemStorageMapper reads and writes format version 3 only. Every transport field is JsonRequired. It rejects unknown fields, numeric enum tokens and payloads over 4,000,000 characters. It migrates nothing: PurgeUnsupportedAsync removes the storage and member tags of other formats, and the tags of systems with no current storage. It keeps the members. SystemStorageMapperTests and SystemRepositoryTests check this.
  8. Ownership. SgtSchemaContract.TryGetOwnedSystemId owns an element only if it is Structural Framing and its tag has the marker SGT and a system ID. Selection, update, deletion and deconstruction use it. ContextualEditTargetEvaluatorTests checks this.
  9. Update by identity. WallSystemWriter indexes the owned members by role and tag identity. It compares each match's live curve, type, orientation, offsets, joins and girt extensions with the requested placement. It writes and reports a match as Moved when a value differs. It creates a member for a target without a match and deletes owned members that no target uses. Two owned members with one identity fail with Update/DuplicateIdentity. WallSystemWriter.UpdatesTests checks this.
  10. Layers. Domain uses no App, Features, Persistence, WPF or Revit API code. Features use no App code, and Placement uses no WallAnalysis code. The portable net10.0 build has no Revit API, WPF or Presentation reference, and build/MSBuild/Portable.targets excludes .cs files under App/, Revit/, Views/ and DesignTime/. Other code that uses them does not build. Nothing checks the Domain-to-Features, Domain-to-Persistence or Placement-to-WallAnalysis rules.
  11. Raw XAML. The XAML is embedded as dbtools.ToolViews.SGT.<file>, with no x:Class and no WPF-derived type in the payload. RawXamlTierContractTests checks every payload view.

FLOW

  1. NewSessionWorkflow shows a prompt banner and calls WallTargetSelectionWorkflow.PickTarget. It asks for a linked wall (LinkedWallSelectionFilter), then, after Esc, for a host foundation wall (FoundationWallSelectionFilter). ContextualEditHook reads the selected system IDs instead, through ContextualEditTargetEvaluator.
  2. SgtWindowSession.Start begins the group and purges. WindowSessionBuilder composes the window, view model and SessionAnalysisOwner.
  3. PlanBuilder.BuildNewPlanAsync sets the framing mode, then runs WallAnalysisStep, PlanSeedingStep and admission. GirtElevationBuilder supplies whole 5'-0" intervals from the base through the framing band. For an edit, StartupAnalysisWorkflow rebuilds the plan with PlanBaselineMapper and ChangeReviewPlanBuilder, and AnalyzeEditPlanAsync analyzes a copy of it against the wall. A stored system that does not load falls back to a wall pick (FallBackToPick).
  4. Grid edits reach PlanStore through PlanSynchronizationCoordinator. A girt elevation edit applies to its row at cell commit or focus loss. Other girt cell edits apply to selected girts. SGT checks a type change for every selected girt before applying it. An opening row commit updates Center Along for the edited opening and other edited fields for the selected editable openings in the same plan write. Other plan writes read the committed opening while its row has a draft. OpeningAlong converts between wall start in the plan and the exterior left end in the grid and elevation. Opening row refresh keeps default names by opening key as it sorts rows. PlanSynchronizationCoordinator records Wall Offset and wall layer changes, grid edits, Bulk Apply, segment flyout edits, opening segment commands, and edits from PreviewEditingWorkflow. Each commit normalizes segments and stores the editable state before and after the write in UndoRedoHistory. MemberSegmentationReconciler repeats its pass until the opening and girt segments settle. It fails if they still change after eight passes. A failed recompute blocks the preview and refreshes the accepted plan. Anchor repair captures inner girt grids before merging rows. Recompute tries the saved grids within each inner end's solid span, starting with the closest to its opening edge. The grid line must leave 6" of span and clear the resolved jamb by the default gap. A gap override adjusts the end from that line. Recompute reports discarded grid ends and uses the opening edge for a split without a valid saved grid. Parent ends keep their anchors and gaps when a short pier is omitted. Inner-end drags and opening-edge snap offers are limited to the current solid span, including end spans bounded by the wall. The opening draft and native grid edit end before the refresh. A refresh that changes girt row identities runs on the dispatcher after the edit. Each replay checks the current plan version in the same PlanStore.Update that restores the editable state. If another write supersedes that version, SGT clears the stale history when a commit or replay encounters a version conflict. SGT keeps the newer plan and reports the refusal. After an accepted write with a notification failure, recovery reports the failure, clears the history, and refreshes the accepted plan. The recovered write completes the grid edit or replay. Only a recovery failure propagates from that path. An active opening draft or invalid field blocks replay against the current plan. The grids and preview refresh from the restored plan. A no-op leaves both stacks as they are. UIEdit validates input and renders the stored plan. RenderOnly renders the stored plan. PlanMutation normalizes the baseline from analysis or Change Review, which starts a fresh history. A merge records the openings it joins as bypassed, so recompute preserves the merged member. With Live Preview on, startup waits for the elevation refresh and paint inside the analysis progress overlay. With Live Preview off, startup keeps the current preview mode and finishes without waiting for paint. SGT logs one warning when the elevation takes longer than 10 seconds. Click Cancel to close SGT without changes. A preview failure opens the session with a blocked preview.
  5. After an edit startup, ChangeReviewWorkflow opens Change Review when ChangeReviewEvaluator reports NeedsAttention. Confirm analyzes the reviewed plan and saves only the decision ledger (SaveLedgerAsync). It publishes the draft, clears the window's Undo history and shows an information banner. Opening measures and manual edits use OpeningAlong to convert between each wall's exterior left end and its plan start. ChangeReviewRowSuggestionBuilder infers spacing from the most frequent gaps of 6 inches or more at the start of the review. For a taller wall it uses that spacing to offer Add at the next whole intervals. When the accepted base changes, Move applies the draft rows' existing heights above the new base. Returning to Accept on the same wall restores the applied move. Add records each new row's chosen height above the accepted base and preserves it after Relink. ChangeReviewPlanBuilder calls GirtEndpointAnchorResolver on a copy for preflight at the new elevations. That leaves the original grid anchors available when the published draft goes through the same segmentation as ordinary edits. Segmentation splits spans at openings. Preflight offers Remove for rejected rows, including those above the accepted wall. Relink clears the applied move and derives a fresh suggestion from the new wall.
  6. Place, Update and Review Changes finish the active opening row before proceeding. A refused row commit preserves the draft and stops the command. Place and Update validate the input and stop if recompute would change the committed framing. SGT logs and displays a framing check exception once per plan version. Place and Update run preflight on the accepted plan, then call PlacementWorkflow, PlacementExecutor and WallSystemWriter. The writer places members, tags them and calls ISystemRepository.Save in one transaction. A successful write closes the window with a commit; a failed or canceled write closes it with a rollback. A refused preflight keeps the window open.
  7. FinalizeSession releases the preview and window, then assimilates or rolls back the group. The UI state saves in the background.

DATA

Item Value
System storage One DataStorage per system, named dbtools_SGT_System_<SystemId> (GUID without hyphens), schema dbtools_SGT_SystemV2 (a schema name, not the format version), GUID 87a71e39-0771-4e55-8575-084c51b2facc. Its DataJson holds a SystemData envelope: Placed, the decision ledger and the settings.
Member tag Schema dbtools_SGT, GUID 4a265d21-dc7d-4f58-a135-6620d53056a1, with Tag (SGT), SystemId, MemberRole (girt, head, sill, jamb_left, jamb_right) and ConfigJson.
Framing mode WallFramingMode.Standard for a linked wall, with the wall bottom as base. Foundation for a host foundation wall, with the wall top as base and a 20'-0" band. The JSON field is placementMode.
Rules MemberRules: AutoSeedSpacing 5'-0", MinimumLength 6".
UI state %APPDATA%\dbtools\Cache\SGT\ui-state.json: panel expansion, opening column widths and Bulk Edit fields. It never gates the model commit.

Revit element IDs are long in the plan, storage and placement records.

Both schemas use vendor input dbtools. Revit stores the vendor ID in uppercase. Data under earlier product schema identities is not migrated. Schema names compare without case, so PurgeUnsupportedAsync also removes the storage and tags that the earlier product spelling wrote.

DIAGNOSTICS

SGT log messages use prefixes such as [SGT], [SGT.Preflight] and [SGT.Place.Cutback]. A plan rejection is a SpecFailure with the text [SpecFail/<area>/<rule>] <detail> (SpecFailureCodes). A UI error shows <action>: [SGT.UI.<area>.<name>] <detail> (UserErrorCodes). DiagnosticsPreflightLogger records analysis outcomes. The orientation warning counts girt families and opening role/family groups with failed or missing orientation results for eligible types. Wall geometry build messages log at Debug. Per-segment preview cutbacks log at Trace, which the application log file omits.

Feature Contracts

Change Review session contract

Features/ChangeReview is a raw-XAML child hosted by the existing ToolWindowFactory/ToolWindowHost path. Its view-model and workflow are session-owned; no static stores candidate state or subscribes to a Revit event. The workflow compares one synchronized plan revision with one live snapshot, then analyzes a confirmed candidate before publishing the detached plan and ledger. Accept, Keep, and Ignore are the only decision vocabulary. ChangeReviewPlanBuilder is the one decision authority: it resolves each item's decision once and derives both the candidate plan and the ledger Confirm saves; rows display the resolved decision. Its AllowedDecisions is the allowed-decision matrix and ProposeDecision the one default rule: the dialog offers the matrix's decisions (SetInvalidated removes Ignore for a released user-created opening unless Ignore is already selected) and preselects an allowed proposal, and the builder applies a proposal to an undecided item that needs no attention only when the matrix allows it. An explicit Ignore returns a Placed opening to its Placed framing configuration, held, even when the draft carries a local edit; an opening that was never placed stays unframed, and a later Keep frames a never-placed manual opening again. Without a live observation a row offers only Keep and Ignore. The live snapshot carries the grid crossings along the Placed wall and the observed wall, and girt grid anchors resolve against the grids of the wall the review adopts. Review rows show the opening source name (or Manual opening for an unnamed detached manual row), source, status, and decision; effects appear in the selected row's details pane. Placement validation messages include the along-wall range when it is relevant. The canonical key is never user-facing.

The parent session owns the one TransactionGroup named Super Girt Tool. Review Confirm saves the decision ledger inside that group without changing framing. Place, Update, Delete System, and Deconstruct run ordinary transactions inside that group. A successful window close assimilates once; Cancel, an error, native close failure, or forced retirement rolls back once. A relink child is retired in finally, and active review-to-pick re-entry remains in the same synchronous modal driver. Unsupported SGT storage is purged, including its owned element tags, inside that group so the same close decision governs the purge.

The release acceptance uses real Revit commands, model elements, tags, and reloaded storage. Pure tests prove decision/evaluator transitions and relink pairing; RevitLocal tests prove physical placement/update/removal, target occupancy, unsupported-data purge, rollback after multiple inner writes, and the single Super Girt Tool Undo result. No test substitutes a fake transaction or Undo-history counter for the operator's Revit evidence.

Other Ratified Features

  • Features/Openings owns query, mutation, projection, synchronization, and row UI. Domain/Openings owns the editable row, durable live reference, physical bounds and runtime geometry resolver without a Features dependency.
  • Girt endpoints are GirtEndpointAnchor values (Domain/Girt/EndpointAnchor). The stored girt shape admits only FullLength, Grid and OpeningEdge endpoints, and an opening-edge endpoint carries no endpoint gap; storage rejects any other girt endpoint: SystemStorageMapper.DeserializeSystem returns Storage/InvalidJson, and the detail names the girt and the endpoint. MemberSpanEndpoint.TryGetOpeningAnchor reads direct OpeningEdge/DualOpeningEdge metadata only (nonblank key, defined edge side); no opening anchor is parsed from a label. MemberEdge runtime endpoints belong to opening members and resolve from direct opening-edge metadata or a numeric split label; a split label more than 0.01 ft outside the wall reports OutOfRange.
  • Opening geometry is all-or-fallback per source. OpeningBoundsCandidateComposer owns cut/solid/width/parameter/profile precedence without shared sentinel mutation. Unavailable individual geometry sources permit fallback. Invalid profile vertices, failed or non-finite wall projections, and exhausted bounds produce OpeningQueryIncomplete with wall or insert context instead of a successful partial opening list. Cancellation and unexpected Revit geometry faults propagate causally.
  • Opening-segment mutation, preview girt-snap planning, member-segment hydration, and placement projection return SpecFailure for expected domain rejection. UI synchronization maps only those typed failures to banners and must leave plan-store and preview state unchanged. Argument errors, cancellation, and unexpected runtime faults propagate with their original identity. Transactional Revit storage/model-write boundaries retain exception unwinding where rollback requires it.
  • TemporaryTransactionRunner records operation, accessor, and rollback failures before diagnostics. Snapshot and rollback logging failures join that list in attempt order, so logging cannot replace the probe or rollback cause. A lone operation failure keeps its original exception identity.
  • Placement command execution preserves the safe-execution status as one explicit result. Update success/cancellation closes the window, and update failure requests a rollback close; removal success clears the system and closes, while rejection/failure/cancellation retains it. Every removal result requests exactly one reactive preview refresh.
  • Features/Orientation/Revit/Analysis owns orientation analysis against Revit families and its solver inputs; portable math/results remain in Features/Orientation/Analysis; WallAnalysis consumes the named FramingTypeOrientationAnalysisResult data result while progress remains status-only.
  • Features/WallAnalysis/Domain owns the plan-builder port and Features/WallAnalysis/Revit/Planning owns wall analysis, calibration, target-geometry resolution, profile warming, seeding, and plan construction against the selected Revit wall. Calibration checks cancellation before validation and cache access, treats argument defects as argument exceptions, converts typed SpecFailureException failures to results, and caches only successes. Family calibration is a per-family preflight that logs a failed family and continues; each type of that family carries the typed failure, with family and type names, as a per-role orientation failure. The orientation analyzer throws SpecFailureException for expected family incompatibilities, and WallAnalysisFramingTypeAnalyzer converts them per role. WallGeometryBuilder converts typed frame failures for host and linked frames at one boundary. Cancellation, rollback failures, and invariant defects propagate after contextual logging. App/session workflow owns command-level orchestration.
  • New and edit plan builders apply the same admission rules before returning success. Admission rejects invalid configurations with PlanValidationFailed before plan-store publication. Edit analysis rehydrates stored values and analyzes current wall geometry. The session workflow owns UI reconciliation.
  • Initial seeding belongs only to PlanSeedingStep. Post-analysis App feedback reads existing row counts and never seeds or republishes a plan. No-opening feedback is suppressed for foundation mode. The initial preview completion barrier remains required.
  • Total profile-warming failure retains the first five type-specific causes, ordered by numeric type ID, and the omitted count. Its failure code remains ProfileLoopsAllFailed. Partial-success warnings and cancellation behavior are unchanged.
  • Features/BulkEdit owns the bulk-edit flyout workflow, centered on BulkEditFlyoutViewModel and its partial family.
  • Bulk apply mutates girt and opening rows under both reactive-sync suppressions. After a successful commit, the girt owner refreshes selected rows' Flip capability and option lists while still suppressed and clears a previous type-change preview blocker only if its own row now has valid orientation. Opening-only edits and failed applies do not dismiss that blocker. One UI-edit preview refresh then synchronizes the committed rows to the plan. A failed apply restores its row snapshots and reports one bulk error without projecting transient edits.
  • Collapsed segment-group deletion and undo each publish one accepted plan revision: row mutation, saved group metadata restoration on undo, and renumbering execute inside the same PlanStore.Update. Undo refuses a group changed after deletion without overwriting its later edits; the window keeps the editing session open, warns the operator, and clears stale edit history.

Dependency Facts

The baseline projection direction is inward: Features and App may use Domain/Plans/Projection/PlanBaselineMapper, which captures a Plan as PlanBaselineSnapshot and restores the editable desired plan from that snapshot plus PlacedSystem. Girt rows come from the stored girt members through PlanProjectionMapper; opening rows and wall geometry come from Placed; the runtime collections are derived from those rows, and the stored snapshot is retained in Plan.BaselineSnapshot. Edit startup reads one live snapshot, lets Change Review apply remembered decisions, and then the registered edit builder analyzes that desired plan against the current target. Persistence separately owns PlanData transport/admission in SystemStorageMapper.Plan.cs, plus StoredSystem, ISystemRepository, and the Revit repository adapter. Features do not depend on Persistence for pure baseline projection, and Persistence does not import App.

At the broader tool boundary, Domain has no dependency on App, Features, Persistence, CommunityToolkit, ObservableCollection, or WPF. Features have no App dependency. Feature-owned ports and behavior inputs are implemented or composed at the App/session boundary where needed.

EndpointAssociationOpeningEdgeSide is the sole semantic opening-edge representation in Domain, Features, App state, and the persistence transport. Stable text conversion occurs only at actual serialization, UI-label, or cache-key boundaries.

WallAnalysis may invoke Placement planning/model-write contracts while building an executable plan, but Placement has no WallAnalysis dependency. App/session composition depends on both and owns the analysis lifecycle; there is no Placement-to-WallAnalysis backedge.

Persistence Shape

Persistence/Revit/SystemRepository.cs is the repository implementation and Persistence/ISystemRepository.cs is its current contract. StoredSystem.cs, the private records in SystemStorageMapper.Data.cs, SystemStorageMapper*, and schema builders are co-owned there. Domain/Plans/Projection/PlanBaselineMapper.cs owns pure baseline capture and rehydration; SystemStorageMapper.Plan.cs owns only transport mapping and admission into the complete current PlanBaselineSnapshot contract. Runtime plan JSON is the private SystemData graph: OpeningDefinitionData, OpeningFrameData, OpeningFrameSpanData, MemberConfigData, MemberSpanData, and MemberSpanEndpointData carry the persisted opening/frame/member fields, then map into fresh Domain instances during admission. Nullable transport collections and entries are kept nullable so malformed storage is rejected by the mapper, not normalized by Domain constructors or clones. Current-shape validation is allowed; schema-version dispatch, legacy readers, compatibility forwarding, or Persistence-to-App imports are not. Persisted system-id schema and Revit tag values remain text; their single edit-launch conversion is fail-closed in App/Composition/ContextualEdit/ContextualEditHook.cs.

Every SGT DataStorage must have a valid entity whose SystemIdString parses as a nonempty SystemId. Its name must exactly match GetDataStorageName(parsedSystemId) using ordinal comparison. A lookup also requires the parsed ID to equal the requested ID. Invalid entities, invalid IDs, and mismatched identities return typed failures.

Each canonical storage name must identify exactly one row. Lookups reject duplicate names before reading or mutating either row. Save and Delete reject corrupt or ambiguous matching rows without changing them. GetAllSystemIds rejects invalid SGT-prefixed rows and duplicate system IDs instead of returning a partial or ambiguous list.

ISystemRepository.Exists returns Result<bool, SpecFailure> to distinguish absence from corrupt storage. A missing schema or system remains a typed Load failure. Exists returns false when no matching row exists. Deleting a missing row succeeds. Enumeration is empty when the schema or rows are absent. Cancellation and unexpected Revit faults continue to propagate.

Revit family/type/instance identities remain long from API conversion through plan state, caches, projections, selection, and storage. FamilyTypeId.Value, framing option IDs, selected plan IDs, member type IDs, and placement update IDs follow this contract. Existing JSON field names and ordinary positive integer tokens remain valid. Counts, indexes, rotations, category enums, manual-opening surrogates, and geometry face indexes remain 32-bit. Geometry face indexes must not be treated as document element identities.

Verification Anchors

The structural acceptance gates are:

  1. generated MAP consistency (.agents/work/canon_source_maps.py --check);
  2. manifest-type validation (ValidateManifestTypes);
  3. CANON source fidelity, including the sibling-family and parent-cadence checks (.agents/work/canon_source_fidelity.py --gate).

The pre-push hook runs all three; ValidatePrePush owns the manifest-type gate. The Loader bridge and MAP generators must be rerun after owner or front-door changes.

Feature contracts

Change Review

Features/ChangeReview is a raw-XAML child window hosted through ToolWindowFactory and ToolWindowHost. Its view model and workflow belong to the session; no static field stores candidate state and nothing subscribes to a Revit event.

  • The workflow compares one synchronized plan revision with one live snapshot, then analyzes a confirmed candidate before it publishes the detached plan and ledger.
  • Accept, Keep and Ignore are the only decisions.
  • ChangeReviewPlanBuilder decides: it resolves each item's decision once and derives both the candidate plan and the ledger that Confirm saves; rows show the resolved decision. AllowedDecisions is the matrix of allowed decisions and ProposeDecision the default rule. The dialog offers the matrix's decisions (SetInvalidated removes Ignore for a released user-created opening unless Ignore is already selected) and preselects an allowed proposal. The builder applies a proposal to an undecided item that needs no attention only when the matrix allows it.
  • An explicit Ignore returns a Placed opening to its Placed framing configuration, held, also when the draft has a local edit. An opening that was never placed stays unframed; a later Keep frames a never-placed manual opening again.
  • Without a live observation a row offers only Keep and Ignore.
  • The live snapshot carries the grid crossings along the Placed wall and the observed wall; girt grid anchors resolve against the grids of the wall the review adopts.
  • Rows show the opening source name (or Manual opening for an unnamed manual row), source, status and decision; effects appear in the details pane of the selected row. Placement validation messages include the along-wall range where it matters. The canonical key is never shown.

The parent session owns the one TransactionGroup named Super Girt Tool. Confirm saves the decision ledger inside that group without changing framing. Place, Update, Delete System and Deconstruct run ordinary transactions inside the group. A successful window close assimilates it once; Cancel, an error, a failed native close or forced retirement rolls it back once. A relink child is retired in finally, and re-entry from review to pick stays in the same synchronous modal driver. Unsupported SGT storage, including its owned element tags, is purged inside the group, so the close decision also governs the purge.

Pure tests cover decision and evaluator transitions and relink pairing. RevitLocal tests cover physical placement, update and removal, target occupancy, the purge, rollback after several inner writes and the single group. The Super Girt Tool Undo entry itself is checked by hand in Revit, because the API cannot enumerate the Undo stack.

Other features

  • Features/Openings owns opening query, mutation, projection, synchronization and row UI. Domain/Openings owns the editable row, the live reference, physical bounds and the geometry resolver, without a Features dependency.
  • Girt endpoints are GirtEndpointAnchor values (Domain/Girt/EndpointAnchor). Storage accepts only FullLength, Grid and OpeningEdge girt endpoints, and an opening-edge endpoint has no endpoint gap; any other endpoint makes SystemStorageMapper.DeserializeSystem return Storage/InvalidJson with a detail that names the girt and endpoint. MemberSpanEndpoint.TryGetOpeningAnchor reads only direct OpeningEdge or DualOpeningEdge metadata (non-blank key, defined edge side); it never parses an anchor from a label. MemberEdge endpoints belong to opening members and resolve from opening-edge metadata or a numeric split label; a split label more than 0.01 ft outside the wall reports OutOfRange.
  • Opening bounds are all-or-fallback per source. OpeningBoundsCandidateComposer applies the cut, solid, width, parameter and profile precedence. A missing source allows fallback. Invalid profile vertices, failed or non-finite wall projections and exhausted bounds return OpeningQuery/Incomplete with wall or insert context. Cancellation and unexpected Revit geometry faults propagate.
  • Opening-segment mutation, preview girt-snap planning, member-segment hydration and placement projection return SpecFailure for expected rejections. UI synchronization shows only those as banners and leaves the plan store and preview unchanged. Argument errors, cancellation and unexpected faults propagate with their original identity. Revit storage and model-write code keeps exception unwinding where rollback needs it.
  • TemporaryTransactionRunner records operation, accessor and rollback failures before diagnostics. Snapshot and rollback logging failures are added in attempt order, so logging cannot replace the probe or rollback cause. A single operation failure keeps its original exception.
  • Placement returns the safe-execution status as one result. Update success or cancellation closes the window; update failure requests a rollback close. Removal success clears the system and closes; rejection, failure or cancellation keeps it. Every removal result requests one preview refresh.
  • Features/Orientation/Revit/Analysis owns orientation analysis against Revit families and its solver inputs; portable math and results are in Features/Orientation/Analysis. WallAnalysis consumes FramingTypeOrientationAnalysisResult; progress carries status only.
  • Features/WallAnalysis/Domain owns the plan-builder port; Features/WallAnalysis/Revit/Planning owns wall analysis, calibration, target-geometry resolution, profile warming, seeding and plan construction. Calibration and orientation failure handling are described in the developer guide.
  • New and edit plan builders apply the same admission rules before they return success; invalid configurations fail with PlanValidationFailed before plan-store publication. Edit analysis restores stored values and analyzes the current wall geometry.
  • PlanSeedingStep is the only initial seeding owner. App feedback reads the existing row counts and never seeds or republishes a plan. Foundation mode suppresses the no-openings notice. Analysis waits for the first preview to complete.
  • When every profile fails to warm, ProfileLoopsAllFailed keeps the first five causes by numeric type ID and the omitted count.
  • Features/BulkEdit owns the bulk-edit flyout, centered on BulkEditFlyoutViewModel. Bulk apply changes girt and opening rows with both reactive-sync suppressions active. After a successful commit, the girt owner refreshes the Flip capability and option lists of the selected rows while still suppressed, and clears an earlier type-change blocker only when its own row now has a valid orientation. Opening-only edits and failed applies keep that blocker. One UI-edit preview refresh then writes the committed rows to the plan. A failed apply restores its row snapshots and reports one bulk error without projecting the transient edits.
  • Deleting a collapsed segment group, and undoing it, each publish one plan revision: the row change, the restored group metadata (on undo) and renumbering run inside one PlanStore.Update. Undo refuses a group that changed after deletion, without overwriting the later edits; the window keeps the session open, shows a warning and clears the stale edit history.

Dependencies

  • Features and App may use Domain/Plans/Projection/PlanBaselineMapper, which captures a Plan as a PlanBaselineSnapshot and rebuilds the editable plan from that snapshot and PlacedSystem: girt rows from the stored girt members through PlanProjectionMapper, opening rows and wall geometry from Placed, runtime collections derived from those rows, and the snapshot kept in Plan.BaselineSnapshot.
  • Edit startup reads one live snapshot, lets Change Review apply remembered decisions, and then the edit builder analyzes that plan against the current target.
  • Persistence owns the PlanData transport and admission (SystemStorageMapper.Plan.cs), StoredSystem, ISystemRepository and the Revit adapter. Features do not depend on Persistence for baseline projection; Persistence does not depend on App.
  • Domain does not depend on App, Features, Persistence, CommunityToolkit, ObservableCollection or WPF. Features do not depend on App. Feature ports are implemented or composed at the App boundary.
  • EndpointAssociationOpeningEdgeSide is the only opening-edge representation in Domain, Features, App state and the persistence transport. Text conversion happens only at serialization, UI labels and cache keys.
  • WallAnalysis can call Placement planning and model-write contracts; Placement does not depend on WallAnalysis. App depends on both and owns the analysis lifecycle.

Persistence

Persistence/ISystemRepository.cs is the repository contract; Persistence/Revit/SystemRepository.cs implements it. StoredSystem.cs, the private records in SystemStorageMapper.Data.cs, SystemStorageMapper* and the schema builders are in Persistence/.

  • Domain/Plans/Projection/PlanBaselineMapper.cs owns baseline capture and rebuild. SystemStorageMapper.Plan.cs owns only transport mapping and admission into the complete PlanBaselineSnapshot contract.
  • Plan JSON is the private SystemData graph: OpeningDefinitionData, OpeningFrameData, OpeningFrameSpanData, MemberConfigData, MemberSpanData and MemberSpanEndpointData carry the persisted fields and map into new Domain instances during admission. Transport collections and entries are nullable, so the mapper rejects malformed storage instead of Domain constructors normalizing it.
  • Only the current shape is accepted. There is no schema-version dispatch and no reader for other formats.
  • Persisted system IDs and Revit tag values are text; ContextualEditHook converts them once for an edit launch and fails on invalid text.

Storage rows:

  • Every SGT DataStorage has a valid entity whose SystemIdString parses as a non-empty SystemId. Its name equals GetDataStorageName(parsedSystemId) (ordinal). A lookup also requires the parsed ID to equal the requested ID. Invalid entities, invalid IDs and mismatched identities return typed failures.
  • Each storage name identifies exactly one row. Lookups reject duplicate names before they read or change a row. Save and Delete reject corrupt or ambiguous rows without changing them. GetAllSystemIds rejects invalid SGT-prefixed rows and duplicate system IDs.
  • ISystemRepository.Exists returns Result<bool, SpecFailure> to tell absence from corrupt storage: false when no row matches. A missing schema or system is a typed Load failure. Deleting a missing row succeeds. Enumeration is empty when the schema or rows are absent. Cancellation and unexpected Revit faults propagate.

Revit family, type and instance identities are long from API conversion through plan state, caches, projections, selection and storage: FamilyTypeId.Value, framing option IDs, selected plan IDs, member type IDs and placement update IDs. JSON field names and positive integer tokens are unchanged. Counts, indexes, rotations, category enums, manual-opening surrogates and geometry face indexes are 32-bit; face indexes are not element identities.

Checks

The pre-push hook (.githooks/pre-push) runs the structural checks:

  1. python3 .agents/work/canon_source_maps.py --check: the generated MAP.md files are current.
  2. python3 .agents/work/canon_source_fidelity.py --gate --mechanical-root testing --mechanical-root build: CANON source fidelity, including the sibling-family and parent-cadence checks.
  3. ./build.sh ValidatePrePush: BuildApp, then ValidateManifestTypes.

After an owner or front-door change, run python3 .agents/work/canon_source_maps.py to regenerate the maps.

NAME

dbtools.FoundationTags - update foundation tag data and move tag heads

SYNOPSIS

source    src/Tools/Structural/FoundationTags/ (manifest.yml)
assembly  dbtools.FoundationTags

commands  UpdateCombinedFoundationTagsCommand, MoveCombinedFoundationTagsCommand

DESCRIPTION

See Combined Foundation Tags for command usage.

STRUCTURE

Path Owner
App/Composition/ AddFoundationTags registers workflows, PrerequisiteRepairOffer, and view-activation tasks.
Features/ CombinedFoundationTagsUpdater writes parameters. FamilyNameClassifier uses FoundationTagPatterns to compile patterns.

CONTRACTS

  1. Both commands call PrerequisiteRepairOffer.EnsureReady before their workflows. It refuses a family document with SafeExecutionRefusedException and the message <command> works in a project. The active document is a family. It propagates that exception from a dead binding key. It converts a repair InvalidOperationException to SafeExecutionRefusedException and keeps the warning active. Successful Repair clears the warning and asks for a rerun. FoundationTagsFeatureOwnerTests checks these paths.
  2. The manifest warning points to Settings > Combined Foundation Tags > Install/Repair. The pack button calls InstallOrRepairRequiredParametersCommand. The warning card calls FixWarningAsync. FixLabel supplies Install/Repair. Both paths use RunInstallOrRepairRequiredParameters. SettingsPackContextWarningFixTests checks pack-button repair and refusal from the warning card without an active document. SettingsPackContextScheduleUseTests checks Cancel on both routes.
  3. UpdateParameterWriter skips changes to non-varying parameters in repeated groups. CombinedTagsTests.Run_GroupPlacements_SkipRestrictedMembersAndWriteOthers checks that footings can use the computed pier top after that skip. Run_InvalidPierTop_DoesNotReuseStoredTopForFooting checks the mark and stored footing elevation when Top Level is unconnected. Run_WithNoPierWithinThreshold_ClearsElevationOrReportsRefusal checks both bindings of Associated Pier Elevation. When no pier is in range, TryClearDouble calls SharedParameterValue.Clear and checks HasValue. RecordParameterWrite logs clear refusals with the element ID and parameter name. The updater shares one ten-entry warning limit across pier, footing and repeated-group details.
  4. RequireSourceUIDocument limits result selection to the source document (FoundationTagsFeatureOwnerTests).

FLOW

  1. PublishSelectionSets calls PruneSelectionSets to keep up to five dbtools - FoundationTags - sets by descending element ID. CombinedTagsTests.Run_SixRunsAtDistinctHours_PrunesTheOldestSelectionSet checks pruning. See CombinedFoundationTagsUpdater.Run for transaction order.
  2. SelectCornerByViewOrientation matches Top Right, Top Left, Bottom Right, and Bottom Left case-insensitively. TryGetTaggedFooting checks both host and loaded link references. TryGetFootingCornersInHost applies the link transform to linked corners. See GetDesiredCornerName and MoveTag for name and position handling. CombinedTagsTests.MoveCombinedTags_WithTransientTaggedFooting_ChangesTagHeadPosition checks the tag position in the active model.
  3. Both view-activation tasks use PanelScopedViewActivationTask for Structural. PrerequisiteMonitorTask checks on document changes and retries transient results on Idling. Auto-update admits floor and ceiling plans with AutoUpdateEnabled on and the warning inactive. See CombinedFoundationTagsAutoUpdateTask.ExecuteInternalAsync for execution.

Prerequisites and repair

EnsureInstalledAndValid asks before removing schedule fields or view filter rules. It replans project and family changes after confirmation. Repair migrates families first. It calls SharedParameterMigration with RemoveWithParameter when it replaces a project parameter. The migration formats project value failures with ElementDisplayName. Repair calls Assimilate after every status is OK. FoundationTagsScheduleFieldTests, FoundationTagsViewFilterTests, and FoundationTagsFamilyRepairTests check these paths.

DATA

Tools.FoundationTags stores AutoUpdateEnabled (default true), TagFamilyPatterns, PierFamilyPatterns, and FootingFamilyPatterns. Empty lists use FoundationTagsSettings defaults. FoundationTagPatterns skips invalid regexes and logs a Warning.

core.structural.combined_tags in structural.foundation_tags blocks both commands and Organize Foundation Types. PrerequisiteRequiredParameters and PrerequisiteSharedParameters.txt define the shared parameters.

DIAGNOSTICS

[CombinedTags] logs update skips. [MoveCombinedTags] logs move failures. [FoundationTags/Prereqs] logs prerequisite checks. [FoundationTags/SP] logs installer activity. SettingsPackContext.LoadRequiredParameters logs failures under [FoundationTags/Settings].

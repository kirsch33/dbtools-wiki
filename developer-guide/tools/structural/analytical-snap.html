dbtools.AnalyticalSnapToLevel

NAME

dbtools.AnalyticalSnapToLevel - the assembly behind Analytical Snap To Level

SYNOPSIS

source    src/Tools/Structural/AnalyticalSnapToLevel/   (MAP.md, manifest.yml)
assembly  dbtools.AnalyticalSnapToLevel
entry     manifest.yml ribbon tool, no moduleType
command   AnalyticalSnapToLevelCommand                  (run profile InlineUi)

DESCRIPTION

The command resolves AnalyticalSnapToLevelWorkflow. The workflow asks for a level, calls AnalyticalSnapper.Run and shows a summary alert. The tool has no settings, hooks or warnings. The user page describes the behavior.

STRUCTURE

Paths are under src/Tools/Structural/AnalyticalSnapToLevel/.

Path Contents
App/Composition/ AnalyticalSnapToLevelCommand, available through CommandAvailability.HasSelection
Features/AnalyticalSnapToLevelWorkflow.cs The level picker, the run and the summary alert
Features/AnalyticalSnapper.cs Run, which checks and writes each element, and the four skip reasons
Features/AnalyticalSegment.cs SnapTo, the end-point rule, without Revit types

CONTRACTS

  1. No module. The manifest has no moduleType. ToolModuleRibbonRegistrar registers the button, and AppToolModuleState.RegisterCommandServices adds the workflow from [CommandService]. AnalyticalSnapToLevelCommandTests checks the attribute.
  2. End-point rule. SnapTo sets both Z values of a Beam. For a Column, it sets the Z nearer the target, or the start on a tie. X and Y do not change. AnalyticalSegmentTests and AnalyticalSegmentEdgeCaseTests check this.
  3. Skips. Run checks OST_AnalyticalMember and AnalyticalMember, then TryResolveRole, GetCurve() is Line and the snapped length. The first failure is the reason. AnalyticalSnapperRevitTests and AnalyticalSnapToLevelWorkflowTests check NotStraight and WouldCollapse.
  4. One transaction. All writes run in one transaction, dbtools - Snap Analytical Elements to Level. Run catches nothing per element, so the transaction rolls back the whole run when SetCurve fails. No test checks the rollback.
  5. Refusals. An empty selection, a cancelled picker and a model without levels throw SafeExecutionRefusedException before any write. AnalyticalSnapToLevelWorkflowTests checks the first two.

FLOW

  1. Execute refuses an empty selection.
  2. PickTargetLevel sorts every Level by Elevation and calls IAlertService.SelectSingle. FormatLevel writes <name> (Elev: <elevation>) with F2 in the current culture.
  3. BuildAdjustedCurve returns null when the snapped line is shorter than Application.ShortCurveTolerance. Otherwise SetCurve writes it. The processed count includes members that do not move.
  4. The workflow groups the skips by reason, in first-seen order. It lists at most AnalyticalSnapToLevelWorkflow.MaxListedIds (10) IDs for each reason, and only the count for NotAnalyticalMember. Then it calls EnsureWindowIfDebugMode.

DATA

Item Value
Reads The selection, Level.Elevation, StructuralRole and GetCurve(), in internal feet
Writes AnalyticalMember.SetCurve only

DIAGNOSTICS

Log lines start with [AnalyticalSnap]. They are all Debug level: the target level, each snap or skip, and the totals.

TESTS

./test.sh test --tool AnalyticalSnapToLevel                         # pure scope, the default
./test.sh test --tool AnalyticalSnapToLevel --scope local -y 2026   # -y 2027 for Revit 2027

Pure tests cover AnalyticalSegment. Local tests cover the command attributes, the snapper and the workflow. They create temporary analytical members in gm_test_model.rvt (Model paths) and roll them back. Without the model, they are inconclusive.

View Template Comparer

View Template Comparer (VTC) compares two view templates in the open project, side by side. For each differing setting you choose which template's value to keep. VTC then writes the result to one of the templates or to a new merged template. It can also save templates to a library and load them back.

Synopsis

Ribbon: dbtools > Testing > View Template Comparer.

The Testing panel is shown when Testing tools is on in the settings (the default). If the project has no view templates, the command shows No view templates found in the document.

Usage

  1. Select the Left and Right templates. The Swap button exchanges them.
  2. Click a value in the comparison tree to choose a side for that setting. The Inspector shows the selected setting's values with Use Left, Use Right and Clear Row Selection.
  3. For a category row, use Edit Left or Edit Right (in the Inspector, from the row, or from the context menu Edit Override...) to stage a local graphic-override edit. The comparison row marks which side has a staged edit.
  4. Review the values and source sides in the Preview tab. Select a preview row to go to its comparison row when one exists.
  5. Click Process and choose the target.

Comparison tree

The tree has these top-level groups: Display Settings, Template Parameters, Model Categories, Annotation Categories, Analytical Model Categories, Imported Categories, Filter Overrides, Revit Links and Worksets. Design Options are not listed because Revit exposes document options, not template-specific option visibility.

The tree shows a short value for each side. Select a row to see the captured fields for both templates in the Inspector. The tree fills differing cells with green on the Left and red on the Right. The Inspector uses those colors on the left edge of each value card. When only one side has a value, that side has a difference marker and the missing value is muted. In the tree, a border and checkmark mark the value selected for processing. None means Revit returned no value for a supported setting. Not applicable means the view does not support the setting. Not captured means the snapshot has neither a value nor an observation for that setting. The Color Fill Schemes count includes every supported category in the snapshot. The Inspector shows the assigned scheme or None for each category.

A category row or a Filter Overrides row is configured in a template when that template hides it or overrides any of its graphics. A Template Parameters row is configured when the template includes the parameter. The Filter modes are:

  • Configured (default): rows configured in either template.
  • Configured in Left and Configured in Right: rows configured in that template.
  • Different and Same: rows with differing or matching values, respectively.
  • All: all settings in the comparison.

The configured modes always show other kinds of settings. Select Left and Select Right select every differing row that the filter and search show. Under Configured in Left, Select Left can select a row that both templates hide when only Right overrides its graphics. Processing that row to the right template keeps it hidden and clears those overrides.

Template parameters and display settings

Template Parameters show each parameter's inclusion state and, when Revit exposes a writable value, its number, whole number, text or element value. VTC applies a value only when the selected side includes the parameter and the snapshot contains the value. A shared parameter with a captured GUID matches by GUID and data spec. Other parameters with captured identity match by unique name and data spec. Revit ignores the spec version suffix. Older snapshots without parameter identity or value data resolve by unique name and apply only the inclusion state. Element values map by name and kind when project IDs differ. A missing or ambiguous required match is a row conflict.

Display Settings include category-kind visibility, View Display Model, background, depth cueing, sketchy lines, shadow and sunlight intensity, plan view range, color-fill schemes, point-cloud overrides and coordination-model overrides. View-range levels, color-fill schemes, line styles and graphics patterns are matched by name when project IDs differ. A missing or ambiguous match is a conflict.

VTC matches a silhouette style by its name, kind and category across projects. Revit checks whether the style is valid for the target view.

Filter Overrides include each filter's enabled state. Filter Order applies after all filter rows. The target must contain the same filters as the selected order. VTC removes and re-adds them in source order, restores visibility, graphic overrides and enabled state, then checks the order by filter name.

Process

Process applies the selected rows and the eligible staged edits in one batch. A staged edit is eligible when its row has a selected side and that side is the edited side, or when its row is not in the current comparison. An edit on a visible row with no selected side, or with the other side selected, is not applied. Choose the target under Apply changes to and review the values under Selected changes.

Option Effect
Overwrite <Left name> Writes the selected values into the Left template.
Overwrite <Right name> Writes the selected values into the Right template.
Create Merged Template Creates a new template named in Merged template name. The name is required before Process can run.

A merged template starts as a copy of the Left template. Settings outside the selected changes keep their Left values. Use Swap to choose the other base.

For a row that has a selected side, the target takes that side's captured value. An absent category row resets visibility and graphic overrides. An absent filter row removes that filter. An absent workset or Revit-link row resets that setting to its default. An absent template-parameter row excludes that parameter. A missing optional display member is uncaptured, so VTC skips it. A display setting unsupported by the target view type is a row conflict. VTC always applies the template-parameter inclusion state. It writes a parameter value only when the selected side includes the parameter and the snapshot contains that value.

VTC reports a setting it cannot apply as a conflict and continues with other rows. If a category supports graphics changes but refuses the requested visibility, VTC keeps the graphics changes and reports the visibility conflict. An unexpected failure rolls back the batch. Overwriting a template makes one Undo entry. Create Merged Template makes one Undo entry named Create Merged View Template.

Imported categories

Imported categories (DWG, DXF and other imports) appear under their own Imported Categories group. They use the same compare, edit, preview and process flow as other categories.

Revit links

Revit link settings appear under Revit Links, grouped by link. Type-level and instance-level link targets are listed separately. VTC lists only the settings that the running Revit version lets add-ins both read and write:

Visibility Mode, Linked View, Filters, Nested Links, Object Styles, Color Fill, View Range, Phase, Phase Filter, Detail Level, Discipline.

Line Weights appears in live comparisons in Revit 2027. If its new value differs from Visibility Mode, VTC sets Visibility Mode to Custom. VTC applies the supported settings individually.

VTC matches links between the two templates by link name and target kind. If two links of the same kind have the same name, VTC stops with an error.

Action Effect
Open Revit Link Settings Opens Revit Link Settings for one link target. The window lists all supported settings of that target, even if you open it from one row. Apply to Template writes the selected settings in one undo entry.
Copy Revit Link Settings To... Copies the supported settings to other link targets. Linked View is matched by name and view type. Phase and Phase Filter are matched by name in the target linked model. If a name is unavailable because the linked document is unloaded, the raw ID is reused only when source and target reference the same linked model. Otherwise, the copy fails for that target. The copy is one undo entry. A target that cannot accept the settings is reported and the others are copied. Any other failure leaves every target unchanged.

Loading a saved template from the library remaps Linked View by name and view type. VTC checks for a unique match even when that row's displayed value already matches the target. It remaps Phase and Phase Filter by name. A missing or ambiguous name is a row conflict. A linked-element ID without a saved name is refused because VTC cannot prove that it identifies the same linked element.

When only one template contains the link row, VTC uses that template. When both do and you have not selected a side, VTC asks which template to use. The link actions are available in the Inspector and the tree context menu for a link group or setting.

Library

The Library tab saves template snapshots to disk and applies them back to a template.

  • Save Template > Left Template, Right Template or Merged Template. Set Saved template name (optional) above the list to choose a name. When blank, the saved name comes from the source templates.
  • Select a saved template in the list, choose Left template or Right template, then select Load. The confirmation defaults to Cancel because loading overwrites the template's settings in Revit.
  • Delete removes the selected library copy. The refresh button reloads the list.

VTC stores snapshots under %APPDATA%\dbtools\Cache\VTC\ and creates the folder on the first save. Saved names ignore case and surrounding spaces. Saving under an existing name asks Replace saved template 'X'?. A save without confirmation leaves an existing file in place, including a file another Revit session creates at the same time. VTC accepts snapshots without optional values and rejects missing required data or malformed values.

Library Load applies captured rows that differ from the target. It reports the number of applied settings and names rows with conflicts. An expected conflict leaves the other rows eligible for apply. If VTC cannot rebuild the comparison after applying the settings, one warning gives the apply result and the reason the comparison failed.

If a save or delete succeeds but the list cannot refresh, VTC shows a warning that names the template. A save or delete that fails shows an error.

Result

Process, Apply to Template and Copy Revit Link Settings To... each make one undo entry. VTC reports each result in an alert titled View Template Comparer. Use Conflicts under Process Results to see rows that failed to apply. Success includes applied rows whose values now match, subject to the current comparison filter.

Limitations

  • VTC compares templates in the open project. It does not compare templates across projects, except through the library.
  • Link settings that Revit does not let add-ins read and write are not shown.
  • VTC cannot apply a background of type None because Revit exposes no public setter for that value.
  • Coordination-model reference-level overrides are not enumerated by the public API used by VTC.
  • Design-option visibility, link Custom-tab tables, and link Visible, Halftone and Underlay values are not available through the supported API path.
  • Create Merged Template copies the Left template, so use Swap to base the merge on the other template.

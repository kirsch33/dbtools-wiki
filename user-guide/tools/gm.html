Global Mapper

Global Mapper (GM) replaces project content in bulk. You map a source (a family, a type, a line style, an object style, a material or a parameter) to a target, review the plan, and apply every mapping in one operation. GM also finds likely duplicates, ranks replacement candidates by name and property similarity, and adds shared parameters to families and categories.

Synopsis

Ribbon: dbtools > Common > Global Mapper.

GM opens as a modeless window and needs an open, active project. It works on the active document only. Linked files are not changed.

GM opens on the Families tab with only Generic Annotations checked. It restores Search, sort mode, Threshold, Hide Unused, Hide Unscanned, and Applied Only for the project. It restores the Shared Parameters category and type when available, duplicate selections and exclusions, and saved mappings. Family rows start collapsed.

Tab Purpose
Duplicates Finds likely duplicate elements and lets you choose which one to keep.
Families Maps families and their types, parameters, object styles and materials to other families.
Line Styles Replaces line styles.
Object Styles Replaces Detail Items object styles.
Materials Replaces materials.
Shared Parameters Adds shared parameters to families and categories, or maps existing parameters to them.

The Shared Parameters tab needs a Revit shared parameter file with at least one group. Without one, GM disables the tab and explains why.

Startup waits for all category and parameter-group reads to finish. If a read fails while another is canceled, GM reports the failure. Startup clears the loading state after the reads finish.

Usage

  1. Open a tab. Choose the source rows to change and the target for each. A target can be chosen by hand or by the similarity ranking.
  2. Check Apply on each mapping to include in this run.
  3. Click Review Plan. GM opens Commit Review as a modal window and shows the plan. The model is not changed until you click Apply there. If the plan has nothing to apply, GM shows the reason in a banner and does not open Commit Review.
  4. Click Apply. Then choose Keep + Continue, Keep + Close GM or Roll back (see Commit Review).

Save the project before a bulk change.

Similarity and threshold

GM scores each target against its source. Scores use the same theme roles in every pane: 90–100 Success, 70–89 Secondary, 50–69 Warning, and 0–49 Muted. Options without a score use Body. At a threshold, an unchanged row selects the highest-scoring target at or above it. If no target qualifies, the row stays empty. A manual target choice stays when you change the threshold. Opening a list and closing it without picking another entry keeps the current selection.

Use Apply to include a mapping with a valid target. Clear Apply to exclude a mapping and keep its target. GM remembers that choice when you change the threshold or category, change the parent target, or refresh or rescan the project.

On the Duplicates tab, the threshold controls which keep-target candidates appear for each source row.

Duplicates tab

The tab scans automatically when you open it. It groups elements that look like duplicates by name and property similarity. Styles and materials are matched on their previews. Material previews must match in shading color, transparency, and each surface and cut pattern layer. GM does not report two styles or materials as duplicates when it cannot read their previews.

Line-style detection covers the whole line-style catalog, including styles with no family usage. Detect refreshes the catalog and the Usage rows and keeps your keep targets. Usage indexing decides which keep targets every restylable curve of a source can accept. While indexing runs, rows show line-style targets pending Usage indexing. A saved keep target stays visible, and Review Plan validates the targets after indexing.

Steps

  1. Scope the rows. Category limits family rows and follows the category selected elsewhere in GM. Kind filters sources: All, Families, Materials, Line Styles, Object Styles or Shared Params. The status bar filters groups by All, Open, Resolved, Excluded or Conflicts. Group nodes show resolved counts, for example Families (133) · 45 resolved.
  2. For each source row, choose the Keep Target. A target must be in the same domain and category as the source.
  3. Click Accept in the inspector for each mapping to stage.
  4. Click Review Plan.

Columns

Column Description
Apply Commit flag for this session. It is off when the tab opens and is never restored from saved state.
Source The element to replace, with its Kind, Suggestions and Highest Score.
Keep Target The one element that remains.
Save Off makes the choice apply to this run only. On saves the keep target for later sessions.

A row is Ready when Apply is on, the keep target is not the source itself, the row is not excluded, and it has no validation or conflict flag. Choosing the source itself as the keep target marks the row as the keeper and turns Apply off.

The inspector pane shows candidate details and a Metadata section with the Source ID and instance count. Its Accept split button accepts the selection. The drop-down Accept Once keeps it for this session only. For a family row, Accept prefers a keep type with the same name and case, then the same name with different case, then the best match at or above Threshold. Automatic matching requires the names of both types. Edit Type Mapping... in the context menu overrides these type mappings. Changing the category on the Families tab keeps accepted mappings. The Families tab shows them in its Apply column, with a From the Duplicates tab chain badge. Shared-parameter duplicate rows can drive the selections on the Shared Parameters tab (Map From and Apply).

Accept and Accept Once include the rows they map, including rows you previously unchecked. For families, only matched types or types set to Create are included. The type badge counts the included mappings. An active Material or Object Style mapping accepted in Duplicates includes matching Families rows with the accepted target or no target selected. A Families row with a different target keeps its choice and Apply setting. For Shared Parameters, GM includes rows that have the matching Map From option. When family targets conflict, the accepted type choices take effect if you choose Use Duplicate. An exclusion made after Accept survives refresh and Use Duplicate. Accept the mapping again to include its rows.

Keep targets, the one-time-save choice, ignored candidates and exclusions are restored with the saved state. Exclusion badges (Saved, Session, Saved (Overridden)) show the exclusion time in a tooltip when it is known.

A chain badge on a candidate shows that its source is already mapped. The tooltip reads Accepted as duplicate → <target>. when the candidate is accepted, or Mapped on the <tab> → <target>. when another tab maps the source. Accepting a candidate whose source another tab maps to a different target raises a Duplicate vs Manual conflict.

Conflicts

A blocking conflict prevents Review Plan. An advisory conflict (a restored saved choice that is not applied) shows in the conflict list only. The conflict button appears when any conflict exists. If one source is accepted to more than one target, GM raises a duplicate multi-target conflict and offers one-click cleanup. Choosing Keep Manual for a duplicate-versus-manual conflict clears the duplicate row's keep and apply state, so the same conflict does not return.

Families tab

The tab maps families to replacement families.

Use Family categories to show one or more categories. The curated list is Detail Items, Generic Annotations, Generic Models, Structural Framing, Structural Columns, Structural Foundations, Structural Connections, Specialty Equipment, Mechanical Equipment, Doors, Windows, Furniture, Casework and Title Blocks. Generic Annotations is available in every project. The other categories appear when the project has a loadable family in that category. The Family table includes families from every checked category.

Each family and type row offers targets from its source family's category. The target lists disable incompatible curve-based placements and show the reason. Review Plan rejects incompatible mappings.

Columns

Column Description
Expand (+) Shows the row details.
Quantity Instances of the family in the project.
Apply Shows and changes which of the family’s types are included.
Source The family.
Target The replacement family.

Choose the family categories to show, then choose a target for each row. The target dropdown shows its similarity score. Checking a family’s Apply box checks each type with a valid target. Clearing it unchecks every type. The box is partly checked when some types are checked and others are unchecked. Changing the target family keeps the types you excluded unchecked. Commit Review replaces only checked types. The source family remains loaded, and the instances of its excluded types keep their original types.

The Quantity column counts family instances in the project, including sheet-owned instances and instances hidden in their own view. A family with no instances can still be mapped. When Revit reports a family as unused, the selected family row has a Purge action. Choose Purge to add it to Commit Review, or Cancel Purge to remove it. Commit Review checks that Revit still reports the family as unused before deleting it. The deletion joins the same apply group as the other operations and returns with the rest if the apply is rolled back. After deletion, GM checks that the family and its types are gone. If any remain, GM reports up to three names and IDs and rolls back the apply group.

While the Views Panel shows, Views Containing Selected Family lists up to 50 views, in name order, that show an instance of the selected family. GM reads the list once per family and keeps it until the next family scan or until Commit Review applies changes. Double-click a view to open it and zoom to an instance of the family.

Row details

Expand a row to map its parts. The detail tabs are Types, Object Styles, Materials and Parameters. Object Styles and Materials are disabled when empty. The nested target lists use the same sort mode and threshold as the parent list. When you change the parent target, nested lists refill and keep the rows you changed by hand.

  • Types: choose a target type and check Apply for each replacement. To create a type in the source family, select Create on the type row, enter a New Type Name that is unique in that family, and check Apply. Review Plan rejects a name that matches an existing type or another new type, regardless of case. The refresh after type creation shows the new type and keeps pending replacements for types that are still available.
  • Parameters: choose a target name and check Apply. The examples come from the selected source type. Instance and type parameters are separate mappings, labeled (Instance) and (Type). A parameter maps only to a target of the same scope. GM copies parameter values only through these mappings, and they run with the type replacements. A red ! badge marks a conflict, such as a duplicate target parameter or a missing type-write policy. Resolve it before Review Plan.
  • The Parameters tab shows Parameter scanning is unavailable; parameter mapping is disabled. when scanning is unavailable, and No mappable parameters detected for this family. when it finds none. A scan refresh reopens expanded rows and updates their Object Styles and Materials usage. While a target list is open, the mouse wheel scrolls that list, not the grid behind it.
  • Type-scope writes: if a type-scope mapping writes into a target type that already has instances, GM blocks the commit until you choose Keep target type values (skip type-scope copies) or Overwrite target type values (copy them). GM takes the decision from the model state before the replacement batch starts. Moving the target's instances away earlier in the batch does not cancel Keep target type values. When overwriting is allowed, each mapping copies the original source values, even if an earlier mapping changed that source type.
  • Object Styles and Materials: usage found by walking one placed instance. Rows from a deep scan carry a DS badge.

Previews

The Preview column of the Object Styles and Materials details shows the source and the target as Revit draws them, on a white canvas like Revit's drawing area. Hover a preview for a larger view.

  • A style is one line in its line color and line pattern. Widths and dash lengths are those of a Revit view at 1/8" = 1'-0", shown at twice the printed size: one paper inch is 192 pixels at 100% display scaling. A line wider than the preview fills it.

  • Line widths come from the line weights of a Revit project that starts from no template (Imperial). The Revit API cannot read the Line Weights table of a project, so a project with its own table shows these widths.

  • A material is a swatch. The left half is the surface: the shading color, with its transparency over white, under the surface background and foreground patterns. The right half is the cut: the cut background and foreground patterns on white. Patterns are shown at the printed size, model patterns at 1/8" = 1'-0", with lines one pixel wide.

  • A preview follows its target. A target that GM sets, for example after a refresh, shows its preview as a target that you choose does.

  • GM reads previews again after it rebuilds usage data, for example after a commit.

Line Styles tab

The tab replaces one line style with another.

Column Description
Apply Includes the mapping.
Source The current line style.
Target The replacement.
Qty The curves in this document that a commit can restyle from this style.
Preview The style as one line. See Previews.

GM captures each source's curves before it applies any line-style mapping, so a swap A to B and B to A exchanges the two populations, and a chain A to B to C leaves A's curves on B and B's curves on C. The mappings commit one after another inside the single undo step of the apply. A failed mapping rolls back the whole apply.

GM restyles a grouped curve only when its group, and every enclosing group, has exactly one placed instance of its group type. Curves in groups with more than one instance are not counted and not replaced, because Revit requires Edit Group mode for them. GM does not enter that mode and does not ungroup elements. Ordinary curves with the same style are counted normally.

A target has to be usable by every restylable curve of the source. A saved target that is not usable stays in the saved intent, shows a warning and is left out of the plan until you choose a valid target and check Apply. On the Line Styles, Object Styles and Materials tabs, an unavailable saved or chosen target stays visible as a disabled entry with a reason. A refresh keeps it; choose another target to replace it.

Object Styles tab

The tab replaces object styles of Detail Items subcategories (styles that are not line styles).

  • Selecting a style lists the families that use it. A preview pane shows the style.
  • Checking Apply marks the affected families with an OS badge on the Families tab. Unchecking it removes the badge when no other object style mapping affects the family.
  • A chain badge beside the source shows that another tab, an accepted duplicate or a saved mapping file set the mapping. Its tooltip names the origin, for example From the Duplicates tab. Edit to override. Choosing another target overrides the mapping and removes the badge. The Line Styles and Materials tabs show the same badge.

At commit, GM opens each affected family document and ensures the target style exists in it, creating the style when it is missing. It copies the core style appearance from the project target, rewrites the references to the source style, and reloads the family into the project.

Before commit, GM leaves out a top-level mapping whose source style has no family usage and no deep-scanned family reference. A mapping found only by a deep scan is kept and appears in Commit Review. A nested mapping whose owner family no longer shows the source in the usage or deep-scan data is left out with a warning.

Shared Parameters tab

The tab adds shared parameters to families and categories, maps existing parameters to shared parameters, and repairs a shared parameter that has the company name but another GUID.

The header has a By family / By parameter switch to the left of SP Group. SP Group applies to both views. The tab opens in By family each time. GM does not save the choice.

View Use it to
By family Work on one family: add parameters, set Map From or a Formula, look at sampled values and instances.

The first visit to the tab loads the shared parameter groups and the categories, with a loading overlay once. Later expanding and collapsing, searching, and conflict updates do not show the overlay.

Categories

The tree lists each category that holds a loadable family in the project, annotation categories included. In-place families are not loadable, so they are not listed. Category labels show counts such as Mechanical Equipment (12). An empty category shows (0) and is dimmed.

By default, the tree shows only the categories that hold a family with work to do, and the selected category. A family has work to do when one of these is true:

  • It carries a parameter with the name of a definition in SP Group and another GUID.
  • The last use scan in By parameter finds another GUID in the family, including movable Revit 2027 labels and uses that need a hand fix.
  • A definition of SP Group is missing from the family, and a family parameter scores at or above Threshold as its Map From source. A family whose parameter discovery is incomplete does not count for this reason.
  • A mapping of the family has Apply on and Map From with no source, or the mapping has a conflict.

The category tool tip counts the reasons, for example 2 families to map · 1 wrong GUID. The selected category shows No work to do when it has none. The tree computes the list again when the SP Group, the threshold, a mapping or a scan result changes. The selected category stays in the list until you select another one.

Check Show all categories above the tree to show every category. The check box is off when the tab opens. In By parameter, the family table lists the families of the categories that the tree shows, so the check box applies to both views.

By family

The left panel shows the category tree, then families, then types, then up to five sampled instances of each type, labeled for example Instance #1 (id:123456). The SP Authoring pane on the right shows a card for each shared parameter of the selected type. Close hides the pane.

  1. Select a group in SP Group.
  2. Expand a category and a family, and select a type. The panel shows the existing parameters with sampled values, and the shared parameters of the group.
  3. For each parameter to add, check Apply. Choose Embed In Family or leave it clear, and choose Instance Parameter or Type Parameter for Binding.
  4. Optionally fill the new parameter from an existing one: set Source to Map From and choose the parameter in From, or set it to Formula, enter it in Fmla and click Set.
  5. Click Review Plan.

Formula requires Embed In Family. If you try to clear it, the card shows Embed required and explains why in its tooltip. You can still review the existing formula.

A Map From card shows ← <name> with the source name. The source card shows the FROM badge.

Each card has the link Every use of this parameter →. It opens By parameter with that definition selected.

When the project holds a definition of SP Group with a GUID that differs from the company file, the SP Authoring pane shows a warning above the cards:

  • This project has "<name>" with a GUID that differs from the company file.
  • This family carries "<name>" with a GUID that differs from the company file. when GM knows that the selected family carries it.

The link Review every use → opens By parameter in repair mode for that name.

Embed In Family Effect
Clear Adds the parameter to the category as a project parameter. If the parameter already has a binding, GM adds the category to it and keeps its group. See Binding rules.
Checked Adds the parameter inside the family document, so it travels with the family.

Plan validation checks that each selected type still belongs to its family and category. It rejects a mismatched or stale selection with an error before apply.

Map From writes the value that the Examples column shows:

  • For an instance target, GM reads the source on the instance. If the instance lacks the source parameter, GM reads it on the type.
  • If both lack the source, GM skips the instance. Commit Review reports the number skipped. The warning details record up to five example element IDs.
  • For an instance mapping, GM checks every instance of the type before it copies values. If an instance lacks the target, the operation fails and GM rolls back the whole apply. The error reports the missing target count and any missing sources found in the operation.
  • Between two parameters of the same type (Length to Length, Text to Text, Yes/No to Yes/No), the stored value is copied exactly.
  • Into a Text parameter, GM writes the source as shown, with the document's units (300 mm, Yes, or the name of a phase or level).
  • Into a Length, Area or other measured parameter, GM reads the source as Revit reads typed input, in the document's units. In a millimeter project, 12 is 12 mm.
  • Text read into a Number or Integer parameter uses the decimal separator of your Windows number format and no thousands separators. With a decimal point, 1.5 is 1.5, and 1,5 or 1,500 is not written. With a decimal comma, 1,5 is 1.5, and 1.5 or 1.500 is not written. An Integer parameter takes only whole numbers, so 2.5 is not written.
  • A value that cannot be read this way fails the operation. Examples are a Yes/No into a Number, 300 mm into an Integer, or a level or phase name into another element parameter. Commit Review lists the value, the parameter and the reason. GM rolls back the whole apply.

The Formula preview reads values by the same rules, including a measured value in the unit it shows. When a value cannot be read as a number, the preview shows that it is unavailable and names the parameter. The preview cannot evaluate functions such as if; it shows that it is unavailable and names the function.

The instance navigator, beside SP Group, steps through the sampled instances of the selected type with the previous and next buttons, and selects that instance in the tree. Zoom shows the current instance in Revit, even when it is not in the active view. With Auto-zoom checked, each step also zooms to the new instance. The instance navigator, Auto-zoom and Zoom show in By family only.

Repair a parameter with another GUID

A parameter has a wrong GUID when it has the name of a company definition but another GUID. Revit treats the two as different parameters. GM moves each use of the old GUID to the company definition, keeps every value, or refuses.

When you select a definition with Two GUIDs in this project, GM scans the project and opens every editable loadable family, under a progress overlay (Scanning shared parameter uses...). The overlay has Cancel. When you cancel the first scan of a definition, or it fails, the table shows Scan the families first. GM keeps a finished result until a Scan again finishes, you keep an apply, or you close GM.

The repair table has the title Every use of the old GUID, the hint Tick the uses to move. and Re-point to <name> (company GUID). Its columns are Move, Use, Where, Reason and Go to.

Use Move
Move project binding Tick it to move the project parameter, its binding, its values, its schedule fields and its view filter rules. It can be ticked only when every other use is ready (see the steps below). Reason names what keeps it closed.
Move family parameter One row for each family. Tick it to move the family parameter, its formulas, dimension labels and associated parameters. On Revit 2027, its annotation labels move with it.
Move labels Revit 2027: one row for a family whose labels use the old GUID directly. Tick it to move the listed entries.
Ungroup and repair Revit 2027: the Move labels row of a family whose labels are in detail groups. Tick it to ungroup every placement of each listed group in the family, delete the group type and move the labels. The elements stay in place, outside any group. Unticked, the family does not change.
Labels · fix by hand Not ticked. A label failed a check, has a measurable unit format or another data type than the company parameter, is in a family that already has the company GUID with another data type, is in a detail group that GM does not ungroup, or is in a family with a nested or uninspected use. Where lists its family and groups. Reason gives the cause and the steps.
Family use · fix by hand Not ticked. A nested or uninspected family, an unread direct use or a family parameter repair that failed verification.
Copy stored values Follows Move project binding. You cannot change it.
Move schedule uses Follows Move project binding. You cannot change it.
View filters Follows Move project binding. You cannot change it.

A row that GM cannot move safely shows the reason and has no tick. Open in By family on a family or label row selects that family in By family.

Scan again, next to Re-point to, runs the full scan again for the selected definition, for example after you fix a family by hand. A tick stays when the new scan lists the row again and the row can still be ticked. GM clears every other tick. If the scan fails or you click Cancel, the table keeps the earlier result.

The repair runs in two phases, because deleting the old project parameter also removes it from the labels of loaded families:

  • Phase 1 moves the ticked family parameters and, on Revit 2027, annotation labels. The old project parameter, its binding, schedule fields, filter rules and values stay. GM refuses phase 1 alone while a schedule field, filter rule or moved label uses the old GUID. Move the project binding in the same apply. The Move project binding reason names any selected label that needs phase 2. If the binding cannot move, do not move that label. A tag label shows the value of the tagged element. GM therefore refuses to move a label while a family that is not ticked uses the old GUID and holds a value for it, and to move a family parameter while a family that is not ticked has a label with the old GUID that GM can move. The message names those families; tick them in the same apply. A label that you must fix by hand keeps the old GUID, so GM also refuses to move a family parameter whose family holds values of that GUID while such a label remains; the message lists the labels. GM does not change linked models, so it refuses to move a label while a tag of that family shows an element of a linked model that holds a value of the old GUID. After the repair, GM compares the text of every tag in the project with its text before the repair. A tag that shows other text rolls back the whole repair. A tag whose label shows the company GUID may also show the moved value, as long as it still shows everything that it showed before.
  • Phase 2 moves the project binding. It runs only when Move project binding is ticked, every movable family and label row is ticked, and no use is left to fix by hand or blocked.

To repair a parameter:

  1. Select the definition with Two GUIDs in this project, or click Review every use → in By family. Wait for the scan.
  2. If the table shows Scan the families first., the scan did not finish or Revit did not open every editable family. Close any family that is open in the Family Editor, then click Scan families.
  3. Tick Move family parameter or Move labels on each family that can move.
  4. Read each Labels · fix by hand and Family use · fix by hand row. These uses keep Move project binding closed.
  5. Tick Move project binding if it is open.
  6. Click Review Plan, then Apply in Commit Review.

On Revit 2027, GM changes annotation labels through Revit's internal label API. It checks the entry count, order, parameter GUIDs, prefix, suffix, sample text, leading spaces, line breaks and non-breaking spaces. The scan trials the change and rolls it back. A missing API member, unread label or failed check leaves a hand-fix row with the reason. Nested-family labels also need a hand fix. A detail group type keeps its own copy of its labels, so GM ungroups a group before it moves its labels. GM does not ungroup an attached detail group, a group that is nested in another group, holds a group or is pinned, a group with an element whose location GM cannot read or with a sketch that belongs to no other element of the group, or a group whose type or placements have a parameter value that ungrouping would delete. A zero or No counts as a value. It does not move a label in a family that has a detail group type with no placements, because such a type keeps a copy of its members that GM cannot check. The row then reads Family '<family>' shows '<name>' with GUID <GUID> in labels in detail group(s) '<group>'. dbtools ungroups such groups before it moves the labels, but <reason>. and says what to change in the family. At apply, GM checks every label and every former group member after the family change and again in the reloaded family, where it counts every element of their kinds at each place. Revit adds automatic sketch dimensions to the former group elements, and GM keeps them. A member that moved or is missing, or any other element that the change adds or deletes, rolls back the repair. A Revit warning or error during the family change or the reload, or a failed check, rolls back the whole repair and shows the description.

When labels remain, fix them by hand. If GM refuses to move a family parameter whose values those labels show, fix the labels first; the tags then show no value until the repair moves the family parameter. Otherwise, apply any available phase 1 moves first.

  1. Click Open in By family on the label row, or open the family in the Family Editor.
  2. Edit each listed label. In a detail group, edit the group first. Replace the parameter with the parameter of the same name and the company GUID, and keep its formatting.
  3. Load the family into the project again, and close it in the Family Editor.
  4. Click Scan again. Move project binding opens when no hand-fix use remains.

Revit 2026 does not let dbtools read annotation labels. In Revit 2026, an annotation family that contains the old GUID directly shows a Family use · fix by hand row, with Family '<family>' contains unread label uses of '<name>'. The row stays while the family contains the old GUID, even after you fix every label. Fix the labels, then use Purge Unused in the Family Editor to remove the unused parameter, and load the family again.

A repair must be the only change in a plan. When other mappings are pending, Review Plan shows Apply the repair on its own: clear the other mappings, or apply them first. and Apply is disabled.

In Commit Review, the repair shows in the Shared Parameters section as Old GUID uses → <name> (company GUID), in the stage Shared Parameters (Repair). Each selected label entry also lists its family, detail group and formatting. Each group that the repair ungroups adds Group '<group>' in '<family>' is ungrouped. Its elements stay in place. At Apply, GM scans again. If the project changed after Review Plan, the repair fails with The project changed after Review Plan. Review the plan again. and changes nothing. A failure or Cancel in either phase rolls back the whole attempt, phase 1 included. When hand-fix uses remain after a successful repair, Commit Review shows Completed with Warnings, with one Manual shared parameter repair remains: <text> warning for each use.

Keep + Continue and Keep + Close GM clear the repair ticks and the use scan results. GM does not save repair ticks.

Deep scan

Some family details, such as embedded parameters and nested families, need a deep scan. A deep scan opens the family document. It is always started by you; GM does not scan when you expand a row.

A deep scan is needed to:

  • unlock the expanded details of a family with no instances (Scan required);
  • read embedded definitions, such as nested family graphs, that a placed instance does not expose.

Moving an instance keeps its family’s Deep Scan results. Refresh Cache checks the family definition and the number of placed instances of each type before reusing a result.

For a family with instances, GM reads Object Styles and Materials from one placed instance. Materials also include the placed shared components inside it. When planning a material replacement, GM checks one placed instance of each type for the source. During Apply, nested children are eligible when the parent contains the source material by name or one of its categories or subcategories takes that material from project Object Styles. GM checks eligible shared children already loaded in the project against their current definition.

Action Effect
Scan Family (in the expanded details) Always runs a fresh deep scan. A complete result replaces the cache entry. An incomplete result removes the previous reusable entry.
Deep Scan Unscanned (top-bar icon, Families tab) Scans eligible unscanned families with no instances across the project, after confirmation.
Clear Deep Scan Cache Checks saved and loaded results. If the cache is empty, GM reports that without asking for confirmation. After you confirm a clear, GM deletes the results and refreshes the display.

The progress overlay shows the project read, the number of families scanned, cache preparation, and the display refresh. Select Cancel while GM scans families to stop after the current family. GM discards the run's results and skips opening the next family. If cancellation reaches GM after it writes the cache and before it applies the scan, the cache keeps its changes. The display keeps its previous results.

Results are cached across sessions. At startup GM restores cached results for eligible families with no instances. The restore is strict: if the cache entry does not resolve in the current document (for example a missing or ambiguous style or material), GM logs a warning and leaves the family unscanned. No banner appears. If you clear the cache while the restore runs, the cleared families stay unscanned until you scan them again.

If Revit reports an error while GM reads a family parameter, GM keeps the names it read as diagnostics and marks parameter discovery incomplete. Those names are not offered as mapping choices and are not used for duplicate scoring. GM also removes the older reusable cache entry for that family. A separate successful read of the host can still fill the mapping choices. Otherwise, scan again after you fix the reported problem.

If GM cannot fully resolve nested-family or material usage during a scan, it keeps the extracted details and warnings visible as a partial result, and does not cache or restore the family as complete. Scan again after you fix the reported references.

A malformed or incomplete cache entry is deleted and needs a new scan. The cache is disposable and is not migrated between formats.

Saved state

GM saves your mappings and window state for each project, by its file path. Each unsaved document has its own state, so unsaved documents with the same title do not share state.

On reopen, saved targets are restored with Apply off. An explicit exclusion is saved with its target and stays in effect until you check Apply again.

Menu item (Clear...) Effect

If GM cannot write the saved mappings, it logs the failure and shows an error banner, and your mappings may not persist. A saved row with no target restores as excluded. An exclusion is saved separately from the last committed mapping for that row. An invalid saved-mappings file produces an error banner and stays on disk. GM flags a saved target that is unavailable so you can choose it again. A Shared Parameters Map From choice stays pending while its source is unavailable. A style target must belong to the scope of its source (Line Styles or Object Styles). Each of the Materials, Line Styles and Object Styles tabs lists only its own kind of element.

When a family and a project tab map the same Material or Object Style source, the family uses its own mapping. Result

Commit Review

While GM builds the plan, its overlay names the current step. Review Plan then opens Commit Review centered on the GM window. Revit is blocked and the GM window is dimmed while it is open. The window shows:

  • the planned operations, by section (Plan Overview, Planned Operations, Host Replacements, Family Changes, Nested Families, Shared Parameters, Validation Issues); sections that do not apply are hidden;
  • after apply, Commit Results, Stage Summary (succeeded, failed and skipped counts per stage, with affected references, family and timing context) and Family Breakdown;
  • an Operation Results table with a status for each operation (Pending, Succeeded, Failed, Skipped), its operation id, stage and timing.

Failed operations are summarized per mapping rule, with the source and target display names rather than element ids. The status bar shows the apply phase before the commit and the Applied, Skipped and Failed counts after it. Right-click a report table for Copy Selected or Copy All. Copy Report copies the whole report.

Failed in the rules summary counts failed mapping rules. One rule can run across many families. Use the Families line (Planned / Attempted / Failed) and the Failed Operations row, which adds up the per-family failures.

Apply and keep

Apply runs the plan as one operation. The changes stay provisional while Commit Review shows the results. The commit continues after a failed operation: failures are recorded and the remaining operations run. The progress overlay shows on Commit Review, and its Cancel button requests cancellation at once.

After a run in which no operation failed, GM checks that no references to a source remain. After a failed operation it does not check: the failure is the reason.

Outcome What you can do
Every operation succeeded and verification found no remaining source Choose Keep + Continue, Keep + Close GM or Roll back.
An operation failed, verification found a remaining source, or the apply was canceled GM rolls the attempt back. Nothing is kept. Inspect the errors and choose Retry Apply to run the reviewed plan against the current model.
Succeeded with nonfatal warnings Labeled Completed with Warnings. The Operation Warnings section lists each distinct instance, parameter and reason. Review it before you keep the changes. Keep remains available when verification succeeds.
  • Keep + Continue records the mappings and returns to GM. GM refreshes the mapped data in place and restores the expanded row context. Types created with Create appear in the refreshed rows. Deep Scan results stay for families the commit did not change. Scan a changed family again to restore its details.
  • Keep + Close GM records the mappings and closes GM.
  • Roll back restores the model and creates no undo entry.
  • A kept apply is one undo entry named Global Mapper: Apply. Press Ctrl+Z to revert it.

If Revit closes Commit Review during shutdown, GM rolls back any apply you have yet to keep.

Do not leave Commit Review open after Apply. Choose Keep or Roll back first.

Closing the window with the X:

  • during apply, requests cancellation and cleanup, then closes. If the cleanup fails, the window stays open and shows the error;
  • after a successful apply, asks whether to keep or roll back, with Roll back as the default;
  • after an apply that kept nothing (failed or canceled), closes without asking.

After any apply, GM re-reads the affected rows and counts from the model, whether the apply was kept or rolled back.

A banner reports the outcome:

  • A successful apply shows a green banner with the Applied, Failed and Skipped counts. If the apply or the plan has warnings, the banner is a warning banner that ends with Warnings: <n>.
  • A failed apply shows a red banner that starts with Apply failed. Nothing was changed. and names the first failed mapping and its reason, for example DB WWF / Wire Mesh → DB Rebar Horizontal Mat / DB Rebar Horizontal Mat: Can't change type of "DB Rebar Horizontal Mat : DB Rebar Horizontal Mat" from line based to non-line based or vice-versa. When Revit refuses a change, the reason is Revit's own text. Commit Review stays open.
  • A canceled apply shows Apply was canceled. Nothing was changed.

If an apply seems to stall near 90%, Revit is still processing one operation. Click Cancel once and wait. GM cancels and cleans up when that operation ends. If it does not recover, report it with the newest dbtools log.

How replacement batches behave

  • Line styles, host materials, family materials, family object styles, types, host symbols and nested-family replacements use each mapping's original source population. A swap A to B and B to A exchanges the populations. A chain A to B and B to C leaves the original A population on B and the original B population on C. References moved by an earlier mapping do not become a later mapping's source.
  • A shared nested family can appear under several selected roots. GM combines its applicable mappings and changes each original reference once. Later family reloads keep the result. Equivalent duplicate mappings get a merged notice. Conflicting targets for the same family source need your attention. A source that is absent from a traversed family is zero work, not a failed mapping.
  • When a family reload cannot complete, every family operation that ran in that traversal is shown as failed, including equivalent shared-family aliases. The report keeps the affected count for writes completed before the failure and shows the reason. GM rolls the whole apply back, and you can choose Retry Apply. A failed operation can report writes that succeeded before it failed. Those counts are diagnostics, and the rollback discards the writes.
  • If one half of a swap fails, the successful half could leave both populations on one target. For that reason GM rolls back the whole apply.
  • Unchanged shared children stay on the project version during another family's reload. Shared children that the current traversal changed are reloaded from the edited family document.
  • The family-document counts in Commit Review include the examined root and nested family documents, including documents where a source has no references.
  • A parent-only material mapping leaves a shared child's material defaults unchanged. Map the child itself, or include it in the traversal, to change those defaults.

Limitations

  • GM changes the active document only.
  • Line style and object style scopes are limited as described above: curves in multi-instance groups are not restyled, and the Object Styles tab covers Detail Items subcategories only.
  • Commit time grows with the number of elements and families. A few dozen changes finish at once; thousands can take minutes. The progress overlay shows the state.
  • Revit 2027 repairs annotation labels when the internal API is available and every check passes. A failed check leaves a hand-fix row with its reason.
  • Revit 2026 does not let dbtools read annotation labels. An annotation family that contains an old GUID keeps the binding move closed until the family no longer contains it.
  • A repair changes the families loaded in the project, not the family files on disk. A family loaded again from an old file brings the old GUID back.
  • A repair moves uses only to the company definition with the same name. To move values between two names, use Map From.
  • GM does not repair these cases. The row shows the reason and has no tick:
    • The project already binds the company GUID.
    • More than one other GUID with the name has a project parameter.
    • A combined parameter schedule field, a schedule with a calculated field (Revit counts a percentage field as one), or a schedule filter value that GM cannot carry.
    • A view filter rule or evaluator that GM cannot carry and verify.
    • A non-editable nested family that dbtools cannot inspect, in a family that uses the old GUID directly (not as a family parameter).
  • GM moves a family parameter even when its family has a non-editable nested family. If a hidden use keeps the old GUID after the reload, GM refuses the move and rolls the attempt back.
  • A schedule field that shows totals, a minimum or a maximum that the company parameter's field cannot show refuses the binding move at apply.
  • By parameter has no Formula source. Write formulas in By family.

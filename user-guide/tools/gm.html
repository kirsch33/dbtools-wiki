Global Mapper

Global Mapper (GM) replaces project content in bulk. You map a source (a family, a type, a line style, an object style, a material or a parameter) to a target, review the plan, and apply every mapping in one operation. GM also finds likely duplicates, ranks replacement candidates by name and property similarity, and adds shared parameters to families and categories.

Synopsis

Ribbon: DB Tools > Common > Global Mapper.

GM opens as a modeless window and needs an open, active project. It works on the active document only. Linked files are not changed.

Tab Purpose
Duplicates Finds likely duplicate elements and lets you choose which one to keep.
Families Maps families and their types, parameters, object styles and materials to other families.
Line Styles Replaces line styles.
Object Styles Replaces Detail Items object styles.
Materials Replaces materials.
Shared Parameters Adds shared parameters to families and categories, or maps existing parameters to them.

The Shared Parameters tab needs a Revit shared parameter file with at least one group. Without one, GM disables the tab and explains why.

Usage

  1. Open a tab. Choose the source rows to change and the target for each. A target can be chosen by hand or by the similarity ranking.
  2. Check Apply on each mapping to include in this run.
  3. Click Review Plan. GM opens Commit Review as a modal window and shows the plan. The model is not changed until you click Apply there.
  4. Click Apply. Then choose Keep + Continue, Keep + Close GM or Roll back (see Commit Review).

Save the project before a bulk change.

Sort mode (Similarity / A-Z) Orders target lists by similarity, with colored scores, or alphabetically with no scores. One setting covers the top-level and nested target lists.

The status line at the bottom left shows the loading state, the number of visible rows and the number of applied and conflicting rows of the current tab. A grid shows Loading... while data loads and a No ... message when a loaded result is empty.

Similarity and threshold

GM scores each target against its source. Scores are colored green (high), orange (medium) or red (low). At a threshold, an unchanged row selects the highest-scoring target at or above it. If no target qualifies, the row stays empty. A manual choice is never changed by the threshold. Opening a list and closing it without picking another entry is not a manual choice. <Do Not Map> is an explicit choice.

On the Duplicates tab, the threshold controls which keep-target candidates appear for each source row.

Duplicates tab

The tab scans automatically when you open it. It groups elements that look like duplicates by name and property similarity. Styles and materials are matched on their previews. GM does not report two styles or materials as duplicates when it cannot read their previews.

Line-style detection covers the whole line-style catalog, including styles with no family usage. Detect refreshes the catalog and the Usage rows and keeps your keep targets. Usage indexing decides which keep targets every restylable curve of a source can accept. While indexing runs, rows show line-style targets pending Usage indexing. A saved keep target stays visible, and Review Plan validates the targets after indexing.

Steps

  1. Scope the rows. Category limits family rows and follows the category selected elsewhere in GM. Kind filters sources: All, Families, Materials, Line Styles, Object Styles or Shared Params. The status bar filters groups by All, Open, Resolved, Excluded or Conflicts. Group nodes show resolved counts, for example Families (133) · 45 resolved.
  2. For each source row, choose the Keep Target. A target must be in the same domain and category as the source.
  3. Check Apply for the rows that are ready to commit.
  4. Click Accept Applied to stage the rows that are ready.
  5. Click Review Plan.

Columns

Column Description
Apply Commit flag for this session. It is off when the tab opens and is never restored from saved state.
Source The element to replace, with its Kind, Suggestions and Highest Score.
Keep Target The one element that remains.
Save Off makes the choice apply to this run only. On saves the keep target for later sessions.
Status Ready, Accepted, Mapped, or blank.

A row is Ready when Apply is on, the keep target is not the source itself, the row is not excluded, and it has no validation or conflict flag. Choosing the source itself as the keep target marks the row as the keeper and turns Apply off. Accept Applied stages the rows that are Ready, not every row with Apply on.

The inspector pane shows candidate details and a Metadata section with the Source ID and instance count. Its Accept split button saves the selection. The drop-down Accept Once keeps it for this session only. For a family row, Edit Type Mapping... in the context menu sets which source types map to which keep types. Shared-parameter duplicate rows can drive the selections on the Shared Parameters tab (Map From and Apply).

Keep targets, the one-time-save choice, ignored candidates and exclusions are restored with the saved state. Exclusion badges (Saved, Session, Saved (Overridden)) show the exclusion time in a tooltip when it is known.

Conflicts

A blocking conflict prevents Review Plan. An advisory conflict (a restored saved choice that is not applied) shows in the conflict list only. The conflict button appears when any conflict exists. If one source is accepted to more than one target, GM raises a duplicate multi-target conflict and offers one-click cleanup. Choosing Keep Manual for a duplicate-versus-manual conflict clears the duplicate row's keep and apply state, so the same conflict does not return.

Families tab

The tab maps families in the selected category to replacement families. A family can be replaced only by a family of the same category.

Columns

Column Description
Expand (+) Shows the row details.
Quantity Instances of the family in the project.
Apply Includes the mapping.
Source The family.
Target The replacement family.

Choose the category first, then the target. Select the target with the dropdown; entries show their similarity score.

Row details

Expand a row to map its parts. The detail tabs are Types, Object Styles, Materials and Parameters. Object Styles and Materials are disabled when empty. The nested target lists use the same sort mode and threshold as the parent list. When you change the parent target, nested lists refill and keep the rows you changed by hand.

  • Types: map each source type to a target type, or select <Do Not Map>. To create a type in the target family, check Create on the type row and enter New Type Name. Created types appear after the refresh that follows a commit.
  • Parameters: map parameter names, with example values. Instance and type parameters are separate mappings, labeled (Instance) and (Type). A parameter maps only to a target of the same scope. GM copies parameter values only through these mappings, and they run with the type replacements. A red ! badge marks a conflict, such as a duplicate target parameter or a missing type-write policy. Resolve it before Review Plan.
  • The Parameters tab shows Parameter scanning is unavailable; parameter mapping is disabled. when scanning is unavailable, and No mappable parameters detected for this family. when it finds none. Expanded rows restored from saved state refresh their Object Styles and Materials usage automatically once usage data is loaded. While a target list is open, the mouse wheel scrolls that list, not the grid behind it.
  • Type-scope writes: if a type-scope mapping writes into a target type that already has instances, GM blocks the commit until you choose Keep target type values (skip type-scope copies) or Overwrite target type values (copy them). GM takes the decision from the model state before the replacement batch starts. Moving the target's instances away earlier in the batch does not cancel Keep target type values. When overwriting is allowed, each mapping copies the original source values, even if an earlier mapping changed that source type.
  • Object Styles and Materials: usage found by walking one placed instance. Rows from a deep scan carry a DS badge.
  • An instance cycler, with previous and next buttons and a zoom button, moves to the sampled instance, even when it is in another view.

Badges

Badge Meaning
OS, MAT, OS+MAT The family Apply state is linked from the Object Styles or Materials tab.
LK (OS/MAT) Marks the nested rows that currently drive that link.
DS Row data came from a deep scan. A tooltip shows partial-scan warnings.

A linked Apply marks the family row, but family-owned operations (type swaps, parameter maps, type creation) run only when you checked that family row yourself.

A saved target that is no longer among the options is flagged as incompatible. Choose the target again.

Line Styles tab

The tab replaces one line style with another.

Column Description
Apply Includes the mapping.
Source The current line style.
Target The replacement.
Qty The curves in this document that a commit can restyle from this style.
Preview A swatch of the style.

GM captures each source's curves before it applies any line-style mapping, so a swap A to B and B to A exchanges the two populations, and a chain A to B to C leaves A's curves on B and B's curves on C. The mappings commit one after another inside the single undo step of the apply. A failed mapping rolls back the whole apply.

GM restyles a grouped curve only when its group, and every enclosing group, has exactly one placed instance of its group type. Curves in groups with more than one instance are not counted and not replaced, because Revit requires Edit Group mode for them. GM does not enter that mode and does not ungroup elements. Ordinary curves with the same style are counted normally.

A target has to be usable by every restylable curve of the source. A saved target that is not usable stays in the saved intent, shows a warning and is left out of the plan until you choose a valid target or Do Not Map. On the Line Styles, Object Styles and Materials tabs, an unavailable saved or chosen target stays visible as a disabled entry with a reason. A refresh keeps it; choose another target to replace it.

Object Styles tab

The tab replaces object styles of Detail Items subcategories (styles that are not line styles).

  • Selecting a style lists the families that use it. A preview pane shows the style.
  • Checking Apply links the affected families on the Families tab. Unchecking it removes the link. A family keeps its Apply if you checked it or another source links it.
  • A lock badge only tells where a mapping came from. To override a mapping that a duplicate seeded, edit its target.

At commit, GM opens each affected family document and ensures the target style exists in it, creating the style when it is missing. It copies the core style appearance from the project target, rewrites the references to the source style, and reloads the family into the project.

Before commit, GM leaves out a top-level mapping whose source style has no family usage and no deep-scanned family reference. A mapping found only by a deep scan is kept and appears in Commit Review. A nested mapping whose owner family no longer shows the source in the usage or deep-scan data is left out with a warning.

Materials tab

The tab replaces materials.

Column Description
Apply Includes the mapping.
Source The material to replace.
Target The replacement.
Color Preview A swatch of the material color.
Families Count Families that use the material.
  • Families affected by a mapping are linked on the Families tab with the badge MAT or OS+MAT. In Families Using This Material, the Apply indicator shows the active link, so a linked family stays marked when a filter hides it from the Families list.
  • At commit, GM updates material parameters in the project and in the affected family documents. When the target material is missing in a family document, GM creates it, copies its core properties and rewrites the references. It then reloads the family.
  • A mapping whose source or target cannot be resolved in the project is ignored before commit and shown as a warning.
  • Revit does not support formulas for parameters of the Material data type. GM migrates writable material defaults for each family type. It leaves formula-determined parameters outside the replacement.
  • A replacement material takes over the appearance and the physical and thermal properties of the new material everywhere the old one was used.

Shared Parameters tab

The tab adds shared parameters to families and categories, or maps existing parameters to shared parameters.

The left panel shows a tree of curated categories (Doors, Mechanical Equipment, Walls, Windows), then families, then types. Category labels show counts such as Mechanical Equipment (12), and empty categories show (0) and are dimmed. The right panel shows an authoring card for each shared parameter of the selected type.

  1. Select a group in SP Group.
  2. Expand a category and a family, and select a type. The panel shows the existing parameters with sampled values, and the shared parameters of the group.
  3. For each parameter to add, check Apply and choose the binding mode.
  4. Optionally choose Map From (or enter a formula) to fill the new parameter from an existing one.
  5. Click Review Plan.
Binding mode Effect
Host-level Adds the parameter to the category as a project parameter. If the parameter already has a binding, GM adds the category to it, keeps its group and refuses a change between instance and type.
Embed-in-family Adds the parameter inside the family document, so it travels with the family.

Plan validation checks that each selected type still belongs to its family and category. It rejects a mismatched or stale selection with an error before apply.

Map From writes the value that the Examples column shows:

  • Between two parameters of the same type (Length to Length, Text to Text, Yes/No to Yes/No), the stored value is copied exactly.
  • Into a Text parameter, GM writes the source as shown, with the document's units (300 mm, Yes, or the name of a phase or level).
  • Into a Length, Area or other measured parameter, GM reads the source as Revit reads typed input, in the document's units. In a millimeter project, 12 is 12 mm.
  • Text read into a Number or Integer parameter uses the decimal separator of your Windows number format and no thousands separators. With a decimal point, 1.5 is 1.5, and 1,5 or 1,500 is not written. With a decimal comma, 1,5 is 1.5, and 1.5 or 1.500 is not written. An Integer parameter takes only whole numbers, so 2.5 is not written.
  • A value that cannot be read this way is not written. Examples are a Yes/No into a Number, 300 mm into an Integer, or a level or phase name into another element parameter. Commit Review lists the operation as Failed, with the value, the parameter and the reason, and writes none of its values.

The Formula preview reads values by the same rules, including a measured value in the unit it shows. When a value cannot be read as a number, the preview shows that it is unavailable.

The first visit to the tab loads the shared parameter groups and the curated categories, with a loading overlay once. Later expanding and collapsing, searching, and conflict updates do not show the overlay.

The instance navigator, between SP Group and the authoring pane, steps through sampled instances. Zoom to Instance goes to an instance even when it is not in the active view.

Deep scan

Some family details, such as embedded parameters and nested families, need a deep scan. A deep scan opens the family document. It is always started by you; GM does not scan when you expand a row.

A deep scan is needed to:

  • unlock the expanded details of a family with no instances (Scan required);
  • read embedded definitions, such as nested family graphs, that a placed instance does not expose.

For a family with instances, the Object Styles and Materials details come from walking one placed instance, so a deep scan is usually not needed. That walk records whether a source appears directly in the root family or only inside nested family content, and planning reuses that.

Action Effect
Scan Family (in the expanded details) Always runs a fresh deep scan. A complete result replaces the cache entry. An incomplete result removes the previous reusable entry.
Deep Scan Unscanned (top-bar icon, Families tab) Scans all unscanned families with no instances in the current category, after a confirmation, with a progress overlay.
Clear Deep Scan Cache Deletes the cached results and refreshes the display before it reports success.

Results are cached across sessions. At startup GM restores cached results for eligible families with no instances. The restore is strict: if the cache entry does not resolve in the current document (for example a missing or ambiguous style or material), GM logs a warning and leaves the family unscanned. No banner appears. If you clear the cache while the restore runs, the cleared families stay unscanned until you scan them again.

If Revit reports an error while GM reads a family parameter, GM keeps the names it read as diagnostics and marks parameter discovery incomplete. Those names are not offered as mapping choices and are not used for duplicate scoring. GM also removes the older reusable cache entry for that family. A separate successful read of the host can still fill the mapping choices. Otherwise, scan again after you fix the reported problem.

If GM cannot fully resolve nested-family or material usage during a scan, it keeps the extracted details and warnings visible as a partial result, and does not cache or restore the family as complete. Scan again after you fix the reported references.

A malformed or incomplete cache entry is deleted and needs a new scan. The cache is disposable and is not migrated between formats.

Saved state

GM saves your mappings and window state for each project, by its file path. Each unsaved document has its own state, so unsaved documents with the same title do not share state.

On reopen, saved targets are restored as suggestions. Apply is left off, so nothing is enabled for commit.

Menu item (Clear...) Effect
Clear Saved Mappings Removes the mapping and duplicate selections for this document. The mappings do not return from an older saved file or from an open GM window.
Clear Saved UI State Removes the tab, search, filter and scroll state. The next GM window for the document starts with default state. An open window does not write its older state back when it closes.
Clear Deep Scan Cache Removes deep-scan data and the DS badges.

If a deletion fails or is canceled, GM does not report success. If GM cannot write the saved mappings, it logs the failure and shows an error banner, and your mappings may not persist. If the saved-mappings file has a format that this GM version cannot read, GM shows a banner and continues without restoring it. A saved target, or a saved Shared Parameters Map From source, that no longer exists is flagged as incompatible and must be created again.

A style target must belong to the scope of its source (Line Styles or Object Styles). Each of the Materials, Line Styles and Object Styles tabs lists only its own kind of element. Family-usage counts stay with the correct style after you reopen GM or refresh.

Result

Commit Review

Review Plan opens Commit Review. Revit is blocked while it is open. The window shows:

  • the planned operations, by section (Plan Overview, Planned Operations, Host Replacements, Family Changes, Nested Families, Shared Parameters, Validation Issues); sections that do not apply are hidden;
  • after apply, Commit Results, Domain Summary (succeeded, failed and skipped counts per stage, with affected references, family and timing context) and Family Breakdown;
  • an Operation Results table with a status for each operation (Pending, Succeeded, Failed, Skipped), its operation id, stage and timing.

Failed operations are summarized per mapping rule, with the source and target display names rather than element ids. The status bar shows the apply phase before the commit and the Applied, Skipped and Failed counts after it. Right-click a report table for Copy Selected or Copy All. Copy Report copies the whole report.

Failed in the rules summary counts failed mapping rules. One rule can run across many families. Use the Families line (Planned / Attempted / Failed) and the Failed Operations row, which adds up the per-family failures.

Apply and keep

Apply runs the plan as one operation. The changes stay provisional while Commit Review shows the results. The commit continues after a failed operation: failures are recorded and the remaining operations run. The overlay Cancel button requests cancellation at once.

After the run, GM verifies that no references to a source remain.

Outcome What you can do
Every operation succeeded and verification found no remaining source Choose Keep + Continue, Keep + Close GM or Roll back.
An operation failed, verification found a remaining source, or the apply was canceled GM rolls the attempt back. Nothing is kept. Inspect the errors and choose Retry Apply to run the reviewed plan against the current model.
Succeeded with nonfatal warnings Labeled Completed with Warnings. The Operation Warnings section lists each distinct instance, parameter and reason. Review it before you keep the changes. Keep remains available when verification succeeds.
  • Keep + Continue records the mappings and returns to GM. GM refreshes the mapped data in place and restores the expanded row context. Types created with Create appear in the refreshed rows. Deep Scan results stay for families the commit did not change. Scan a changed family again to restore its details.
  • Keep + Close GM records the mappings and closes GM.
  • Roll back restores the model and creates no undo entry.
  • A kept apply is one undo entry named Global Mapper: Apply. Press Ctrl+Z to revert it.

Do not leave Commit Review open after Apply. Choose Keep or Roll back first.

Closing the window with the X:

  • during apply, requests cancellation and cleanup, then closes. If the cleanup fails, the window stays open and shows the error;
  • after apply, asks whether to keep or roll back, with Roll back as the default.

After any apply, GM re-reads the affected rows and counts from the model, whether the apply was kept or rolled back.

A banner reports the outcome. A successful apply with operation warnings shows a warning banner that ends with Operation warnings: <n>. Otherwise a green banner with the Applied, Failed and Skipped counts; a red banner that starts with the reason, for example Apply was rolled back: 1 operation(s) failed. No changes were kept. or Apply failed; no changes were kept.; or Apply was canceled. No changes were kept. If the apply fails, Commit Review stays open.

If an apply seems to stall near 90%, Revit is still processing one operation. Click Cancel once and wait. GM cancels and cleans up when that operation ends. If it does not recover, report it with the newest DB Tools log.

How replacement batches behave

  • Line styles, host materials, family materials, family object styles, types, host symbols and nested-family replacements use each mapping's original source population. A swap A to B and B to A exchanges the populations. A chain A to B and B to C leaves the original A population on B and the original B population on C. References moved by an earlier mapping do not become a later mapping's source.
  • A shared nested family can appear under several selected roots. GM combines its applicable mappings and changes each original reference once. Later family reloads keep the result. Equivalent duplicate mappings get a merged notice. Conflicting targets for the same family source need your attention. A source that is absent from a traversed family is zero work, not a failed mapping.
  • When a family reload cannot complete, every family operation that ran in that traversal is shown as failed, including equivalent shared-family aliases. The report keeps the affected count for writes completed before the failure and shows the reason. GM rolls the whole apply back, and you can choose Retry Apply. A failed operation can report writes that succeeded before it failed. Those counts are diagnostics, and the rollback discards the writes.
  • If one half of a swap fails, the successful half could leave both populations on one target. For that reason GM rolls back the whole apply.
  • Unchanged shared children stay on the project version during another family's reload. Shared children that the current traversal changed are reloaded from the edited family document.
  • The family-document counts in Commit Review include the examined root and nested family documents, including documents where a source has no references.
  • A parent-only material mapping leaves a shared child's material defaults unchanged. Map the child itself, or include it in the traversal, to change those defaults.

When an action fails unexpectedly, GM shows an error banner titled with the action, for example GM Duplicate Type Mapping, GM Deep Scan or GM Clear Saved Mappings, followed by the error text. The action changes nothing. Retry it, and read the DB Tools log if it fails again.

If Review Plan is disabled, no mapping is applied, or a blocking conflict exists. If the target list is empty, the category has no other family. If some instances were not replaced, open the family and check that every type is mapped.

Limitations

  • GM changes the active document only.
  • A family can only be replaced by a family of the same category.
  • Line style and object style scopes are limited as described above: curves in multi-instance groups are not restyled, and the Object Styles tab covers Detail Items subcategories only.
  • Commit time grows with the number of elements and families. A few dozen changes finish at once; thousands can take minutes. The progress overlay shows the state.
  • The Shared Parameters tab lists the curated categories only: Doors, Mechanical Equipment, Walls and Windows.

Super Girt Tool (SGT)

The Super Girt Tool automates the placement of horizontal girts and opening framing (headers, sills, and jambs) on foundation walls. Instead of manually placing each structural member one at a time, SGT lets you configure an entire wall's worth of girts in one operation.

When to Use It

Use the Super Girt Tool when you need to:

  • Add horizontal girt members to a foundation wall at regular spacing
  • Frame out openings (doors, windows, penetrations) with headers, sills, and jambs
  • Place multiple girt rows at once instead of one-by-one
  • Ensure consistent spacing and alignment across a wall
  • Edit or update previously placed girt systems

Common scenarios:

Scenario SGT Helps By...
New foundation wall with multiple window openings Auto-detecting openings and framing them
Girts at 5'-0" vertical spacing Pre-seeding rows at correct intervals
Mixed girt sizes at different elevations Configuring each row independently
Updating girt types after initial placement Editing the existing system in place

Quick Start

Basic workflow in 4 steps:

  1. Launch - Click "Super Girt Tool" from the DB Tools ribbon tab
  2. Select Wall - Pick the foundation wall or linked wall you want to frame
  3. Configure - Adjust girt elevations, types, and opening framing as needed
  4. Place - Click "Place" to create all the structural members

That's it for basic use. The tool handles the technical details of rotation, justification, and positioning automatically.

The SGT Window

When you launch SGT and select a wall, the main window appears with these sections:

Top Bar

Control Purpose
Offset Distance from the wall face to place girts (0'-0" means directly on the target layer)
Layer Which wall layer to align girts to (for compound walls with multiple layers). The list shows the analyzed wall's layers and follows the current plan, even when the preview cannot update.

Girt Elevations Section

This is where you configure your horizontal girts. Each row represents one girt at a specific elevation.

Column What It Does
Elevation Height above the base reference (editable)
Girt Type Family and type to use (e.g., "C Shapes : C10X15.3")
Rotation Cross-section rotation (0, 90, 180, or 270 degrees)
Y-Just Lateral positioning (Left, Center, Right, Origin)
Z-Just Vertical positioning (Top, Middle, Bottom, Origin)
Flip Flip Facing (mirror the member orientation) if needed
Left Extent Where the girt starts - Full Length or at a grid line
Right Extent Where the girt ends - Full Length or at a grid line

Add Row: Type an elevation in the "Add" field and click "Add" to create a new girt row.

Segmented girts: Auto-segmented girts show a chevron in the first column. Click it to open the MemberSegment Flyout, where you can edit Type/Rotation/Y/Z/Flip (and delete) per segment. Selecting a segment in the flyout highlights it in the preview so it’s clear which segment you’re editing. The flyout opens to the right of the chevron and centers vertically in the window; resizing primarily expands the Type field. The background behind the flyout is lightly dimmed so the preview remains visible. The chevron now follows the materialized segmented plan state: if opening analysis or later opening edits split a girt into multiple segments, the chevron appears; if recomputation collapses that group back to one segment, the chevron is removed. While another field is invalid, flyout edits are refused and nothing is lost (see the rule under Openings Section).

Openings Section

This section shows detected openings in Linked mode and also lets you add manual openings. In host foundation mode, SGT ignores physical/Revit wall openings entirely, so the grid is manual-only.

Column What It Does
Opening Name/ID of the opening
Center Along Horizontal position along the wall
Bottom Elevation Vertical position of the opening bottom
Width Opening width
Height Opening height
Left Jamb Enable/disable left vertical framing
Right Jamb Enable/disable right vertical framing
Header Enable/disable top horizontal framing
Sill Enable/disable bottom horizontal framing

Use the chevron on each opening row to open the MemberSegment Flyout for opening members. The flyout shows role-level fields (Type/Rotation/Y/Z/Flip) and (when segmented) per-segment child rows for that role. Selecting a segment highlights it in the preview. The flyout opens to the right of the chevron, centered vertically in the window, with the same resizing rules as the girt segment flyout. While another field is invalid, segment edits in this flyout are refused (see below).

Parent-level opening edits are draft-scoped. While you are editing Center Along, Bottom Elevation, Width, Height, or the parent role checkboxes, SGT keeps the last committed plan/preview visible. Leaving the row or pressing Enter commits one sync/re-segmentation/preview refresh; Esc cancels the draft (see the exception below). If you enable an opening role and then change that role's Type/Rotation/Y/Z/Flip before leaving the row, SGT preserves those explicit settings on commit instead of snapping the role back to seed defaults. If the row is still invalid, SGT keeps that row in edit mode and leaves the last committed plan/preview intact until you fix the highlighted fields or cancel the edit. When linked-wall analysis finds no openings, SGT now shows a neutral info banner instead of an error banner.

The opening commit, segment flyout edits and preview canvas edits (snap, gap, delete, merge) each save your other unsaved field edits with them, in one step: for example a wall offset you typed just before clicking another opening row, or a field you changed while the 3D preview was still building. While any wall setup, girt or opening field is invalid, SGT refuses such an edit and writes nothing: the opening row stays in edit with its values, the gap editor stays open with the typed gap, also when the preview redraws, until you press Enter again or Esc, a refused flyout choice shows the saved value again, your other unsaved field edits stay, and the preview status says why (Fix invalid fields, Fix invalid rows or Preview blocked). Undo reverts a canvas snap, typed gap change, delete or merge; typed gap undo restores its prior override, while saved field edits stay. An accepted typed gap clears any existing redo action. Deleting girt rows in the grid, the invalid row included, is never refused; the next sync renumbers the segment group the deleted row left, and a group left with one row becomes a plain girt. If SGT writes the window while the opening row is still in edit (you fix the other field, or make another edit), that row's draft is written too, so Esc can no longer fully cancel it: the row shows its old values again, but the plan keeps the draft and a later refresh can bring it back (known issue).

A successful linked-wall detection with no openings clears stale detected rows and keeps manual openings. In Change Review, saved live openings missing from a successful observation require an Accept, Keep or Ignore decision; an incomplete observation remains Unreadable and cannot become a deletion.

Bulk Edit Flyout

Double-click a row in either grid to open the Bulk Edit flyout. The flyout is an in-window overlay (not a detached WPF Popup), so it stays bound to the SGT window during minimize/restore and does not float above other apps.

  • Targets: Choose which member roles the bulk operation applies to (e.g. Girt, Left Jamb, Right Jamb, Header, Sill).
  • Flip Facing: Tri-state; indeterminate means “don’t apply Flip” for this bulk operation.
  • Apply (N): N is the number of active fields that will be applied (Type/Rotation/Y/Z/Flip).

Preview editing notes:

  • Drag/snap edits from elevation preview handles (girt extents/segments and jamb/header/sill extents) now participate in the SGT window's Undo/Redo buttons. Undo and Redo restore the plan, so they also replace unsaved field edits, an invalid field included.
  • Typed gap edits in the 2D gap editor also participate in Undo/Redo. An accepted typed change clears any redo action from an earlier edit.
  • Drag/snap edits are association-locked: handles snap only to valid associations (other elements, grids, or wall edges). They do not create arbitrary free-along points.
  • A drag only commits when you are inside snap threshold on an accepted target; until then, preview border/guide feedback stays in the invalid state.
  • Snap guides now render continuously while dragging: dim bands for available targets plus an active guide line (cyan when valid, red when invalid).
  • Opening geometry is not draggable in preview: opening rectangles/edges do not expose drag/snap handles.
  • For segmented opening members, jamb/header/sill endpoint handles are created per segment; dragging one endpoint updates that specific segment's extent association.
  • For bisected girts, only the true outer endpoints move member extents (first-left/start and last-right/end). Other segment endpoints edit opening-edge gaps.
  • Interior bisected endpoints commit by opening-edge identity (opening key + edge side), so mirrored/rotated links do not move the opposite endpoint.
  • A girt's outer endpoints snap only to opening edges that can bound them. An opening's lower edge is the edge nearer the wall start; its higher edge is the edge nearer the wall end. The start snaps to the higher edge of an opening that crosses the girt, the end to the lower edge, or the start to the lower edge and the end to the higher edge of one opening for a girt inside that opening. An edge of an opening the girt bypasses is offered too: snapping to it clears that bypass. An edge that would leave the girt no span of 6" (0.5 ft) or longer is not offered. A snap to an edge that cannot bound that end is rejected with GirtSnap/BoundaryInvalid, and a snap that leaves no usable span with GirtSnap/NoUsableSpan.
  • When a girt endpoint is snapped to a new association, any explicit gap override for the touched endpoint/edge is cleared so geometry-aware defaults apply for the new association.
  • A girt end on a wall edge or grid that lies exactly on the edge of an opening the girt stops at gets that edge's jamb gap, in the preview and in the placed girt alike. A gap override you set for that end replaces it.
  • When you merge adjacent girt segments, any opening-member extents that targeted either segment are automatically re-targeted to the merged segment key, so snap-to-girt semantics remain stable after merges.
  • If re-segmentation recomputation yields fewer than 2 segments, SGT collapses the segment group back into a single standalone row and shows a banner summarizing how many groups were collapsed.
  • If geometry-aware gap computation fails (missing profile or transform failure), SGT reports an error. Re-run Analyze to refresh warmup data.
  • A gap handle on an opening you just deleted can stay on the canvas until the preview redraws; double-clicking it then shows a "Gap edit failed" banner instead of a gap editor (known issue).
  • Gap override fields reject NaN / Infinity values (negative values are allowed); invalid overrides surface as plan validation failures before placement.
  • Placement validation failures remain explicit before commit and are reported without being converted into generic placement exceptions; unexpected Revit placement faults surface through the tool error boundary with their original cause.
  • A girt segment that cannot be placed reports its own failure, with the same text on Place and Update; for example, a girt family without Start/End Extension parameters reports Writer/ExtensionParamMissing when an end gap needs them. A missing opening framing type reports Plan/EligibleOpeningTypesMissing, not an orientation failure.
  • A girt whose start is on an opening's lower edge and whose end is on the same opening's higher edge spans inside that opening; every other girt is split at each opening it crosses unless it bypasses that opening. Girt pieces shorter than 6" (0.5 ft), such as a narrow pier between two close openings, are left out.
  • Jamb, header and sill handles, and girt segment handles other than the girt's own start and end, are offered all eligible opening edges in the active preview, not only the currently selected opening row. A girt's outer endpoints follow the boundary rule above.
  • An opening splits every girt it crosses even when all of its framing roles are turned off.
  • When the opening or grid a girt end was attached to is removed, or that opening no longer crosses the girt (for example after an opening edit or a shortened wall), SGT moves that end to the nearest opening edge that is at least 6" (0.5 ft) from the girt's other end, or to the wall edge when there is none, and clears that end's gap override. A gap override you set for the opening edge it moves to is kept. The banner states how many ends moved ("Re-anchored N girt end(s) to the nearest opening or wall edge."). When two segments of one girt then overlap, SGT merges them into the first segment and the banner also states "Merged N overlapping girt segment(s) into their neighbors."
  • A header or sill split position beyond the wall fails Place/Update with a message that names the opening.
  • Grid markers in elevation preview now use a white bubble (white fill, black outline) with centered black label text for dark-theme readability.
  • When multiple handles overlap, press Tab to cycle candidates; Enter confirms the highlighted handle and Esc cancels.
  • Right-click on a segmented opening member now opens a segment-specific context menu (delete that segment only). Row-level delete actions appear only when you open the row menu itself.
  • Deleting the last segment of a single opening role removes that role; the opening row itself remains until all roles for that opening are removed.

Debug Log Volume (2026-03-08)

When Debug mode is enabled, SGT now favors condensed summaries instead of per-probe noise:

  • Step 1/2/3 preflight summaries report total/success/failure counts.
  • Step 2 opening detection/merge logs stay summarized, with small opening samples instead of one line per internal probe.
  • Orientation logging keeps concise per-role Debug summaries; detailed probe attempts are folded into those summary diagnostics instead of being emitted separately.
  • Temporary probe transactions log only when they captured diagnostics, and blocking probe failures still surface as warnings/errors.

This keeps long manual sessions readable while preserving the main breadcrumbs needed for parity triage.

Step-by-Step Workflows

Creating a New Girt Plan

  1. Launch the tool

    • Go to the DB Tools ribbon tab
    • Click "Super Girt Tool"

  2. Select your wall

    • A prompt appears asking you to select a wall
    • Click on a foundation wall or linked wall
    • The tool analyzes the wall and populates the window

  3. Review auto-seeded girts

    • SGT automatically creates girt rows at approximately 5'-0" spacing
    • Review the elevations and adjust as needed
    • Change girt types if you need different sizes at certain elevations

  4. Configure openings (if any)

    • Linked walls: Openings are auto-detected
    • Foundation walls: Click "Add Opening" to manually define openings; SGT ignores any physical/Revit wall openings on the host wall in this mode
    • Check/uncheck the boxes for which framing members you want

  5. Preview your layout

    • Switch between Elevation, Section, and 3D views
    • Verify everything looks correct before placing

  6. Place the girts

    • Click "Place"
    • The tool creates all members in Revit

Adjusting Girt Elevations

To change an existing row's elevation:

  1. Click in the Elevation cell for that row
  2. Type the new elevation (e.g., "7'-6"")
  3. Press Enter - the preview updates automatically

Elevation and offset fields accept invariant decimal feet (7.5), feet marked with an apostrophe (7'), feet plus quoted inches (7'-6" or 7'-6 1/2"), and quoted inches (18", 6.5", or 6 1/2"). Spaces may surround the marks, hyphen, and fraction slash. One leading + or - applies to the entire value. Named units (ft, in, metric units), localized commas, exponents, component signs, unquoted fractions, and trailing text are rejected.

To add a new girt at a specific elevation:

  1. Find the "Add" field at the bottom of the Girt Elevations section
  2. Type your elevation (e.g., "12'-0"")
  3. Click "Add"
  4. A new row appears with default settings

To remove a girt row:

  1. Select the row
  2. Press Delete (or right-click and choose Remove)

Working with Grid Extents

If your project has grids that intersect the wall, you can limit girts to specific grid-to-grid spans:

  1. Look at the "Left Extent" and "Right Extent" columns
  2. By default, both show "Full Length" (wall end to wall end)
  3. Click the dropdown to see available grid lines
  4. Select a grid to start or end the girt at that location

Example: A wall runs from Grid A to Grid D, but you only want girts between Grid B and Grid C:

  • Set Left Extent to "Grid B"
  • Set Right Extent to "Grid C"

Configuring Opening Framing

For each opening, you control which framing members are created:

Opening members (header, sill, and jambs) use Channel or HSS types only. Zee and L-Angle types are girt-only and are not offered for opening roles.

Member When to Use
Header Almost always - provides support above the opening
Sill Usually for windows; often omitted for doors at grade
Left/Right Jambs Usually both enabled; disable if opening is at wall end

To customize an opening's framing:

  1. Find the opening in the Openings section
  2. Check/uncheck the boxes for Header, Sill, Left Jamb, Right Jamb
  3. The preview updates to show your changes

Editing an Existing Girt System

If you've already placed girts using SGT, you can edit them:

  1. Select any girt from the system in Revit
  2. The "Modify - Structural Framing" tab appears
  3. Click "Edit SGT Wall" (only visible when SGT members are selected)
  4. The SGT window opens with your existing configuration
  5. Make changes as needed
  6. Click "Update" to apply changes, or "Remove" to delete everything

During edit/update:

  • Opening rows show Live or Manual source. Editing a live opening's position or size makes it Manual. Its distance from the wall start stays fixed when the wall length changes.
  • A completed session creates one Super Girt Tool Undo entry. Cancel, an error, or a Dev Mode reload rolls back the session's model edits.
  • Update tries to move existing members in place first. If any required existing member cannot be matched or moved, Update stops with an error instead of retrying through delete/recreate.
  • Place and Update set each girt's Start/End Extension from its end gaps (0 where the girt has no gap), so placed girts match the preview. A family default extension is replaced at the next Place or Update. An extension typed on a placed SGT girt is replaced at its next Update. If Update must change an extension whose parameter is missing or read-only, the Update fails and rolls back its model changes.

Change Review

When an edited wall or opening differs from the stored observation, SGT opens Change Review before it writes the proposed update. Each row shows its source opening name (or Manual opening when a detached manual row has no name), its source, status, and decision. Change effects appear in the details pane for the selected row. Along-wall ranges appear in placement validation messages when an opening is outside the effective wall bounds. Choose one of the decisions shown by the row:

  • Accept adopts the current live observation and applies its framing on the next Update.
  • Keep keeps the placed/manual geometry and framing configuration for this session.
  • Ignore leaves the existing framing untouched and asks about the item again on a later review. An opening you edited in this session returns to its placed geometry and framing. A manual opening that was never placed stays unframed; choose Keep on a later review in the same session to frame it again. Update does not save an ignored manual opening that was never placed.

The review also lists wall and layer changes, remembered decisions, accepted removals waiting for Update, and girt ends that will be re-anchored. A missing live opening can be paired with a current opening by choosing Same as and clicking Pair. Unpair restores the previous pairing and its draft row. Locate selects the source element when it is available.

Relink starts a wall pick for a system whose wall reference has changed. The selected wall is analyzed and the review draft is rebuilt before any decision is saved. Delete System removes the stored system and its placed members. Deconstruct removes the stored system and SGT tags while keeping the placed members in the model. These operations run inside the same session transaction group, so Cancel, an error, or forced retirement rolls them back.

Review Confirm saves the detached plan and decision ledger inside the current SGT session. It does not place or update Revit members by itself; use Update after confirming. Cancel closes the review without saving its decisions. The main window's Cancel — Close without placing anything rolls back all model and storage writes made during the window, including a review confirmation. A successful window close assimilates the session as one Super Girt Tool Undo entry.

An unreadable current SGT payload fails with a typed storage error. If an owned storage entity or element tag uses an unsupported schema or format version, the session purges that entity and its SGT tags inside the same transaction group. It also purges current-schema tags that point to a system that no longer exists. A successful close keeps the purge; Cancel, an error, or forced retirement restores it. Native framing is not deleted. Re-place the system after an unsupported-data message.

Preview/Placed Alignment Notes

Recent parity fixes align preview and placement behavior for linked walls and opening framing:

  • Preview visuals (text/lineweights/preview styling) are normalized to a fixed visual scale (matching the “good HiDPI” look). Interaction hit-testing (snap thresholds, hit radii) remains DPI-scaled.

  • Section preview renders compound wall layers as labeled thickness bands, and strongly highlights the selected depth-plane layer.

  • 3D preview renders compound wall layers as wireframe-like context geometry: very low wall fill opacity with selected-layer emphasis.

  • 3D preview uses brighter crease outlines (cyan-gray wall edges, luminous steel edges) and a stronger 4-light rig so concavities stay readable in dark theme.

  • 3D preview draws thin wireframe opening extents for all detected openings (subtle and non-distracting).

  • The default 3D floor plane is more transparent and rendered as transparent geometry so members below/within it remain visible.

  • 3D click-to-inspect now resolves on mouse-up (click-only, not pan-drags), and navigation cancels if capture is lost or the window deactivates.

  • Opening extents in linked mode now map with frame-direction inversion detection so preview/placement use the same wall direction convention.

  • 3D preview now uses the same depth-plane offset helper as placement.

  • Opening-edge trimming now applies gap-only cutbacks in both preview segmentation and final placement, removing oversized girt-to-jamb gaps; geometry-aware bisection gaps use calibrated profile transforms so cutbacks align with placed output for nested families.

  • Preview no longer reconstructs member transform/sign/depth semantics locally; Elevation, Section, and 3D all consume the same final resolved contract used by placement.

  • Opening-member preview meshes now enumerate the same materialized segment-contract list used by placement, so segment order/index stay aligned across elevation, section, 3D, and placed components.

  • Preview profile transforms now run with the same operation order as placement (rotation then Flip Facing then justification), improving jamb rotation/depth parity in linked-wall previews.

  • Opening members now resolve orientation semantics in role-first order (role metadata first, then type fallback), improving left/right/head/sill consistency for shared types.

  • 3D opening members now use the same final resolved contract path as 2D previews, so head/sill/jamb profile orientation stays consistent across preview modes.

  • Elevation, Section, and 3D now all read the same final line, basis, and loop data, so preview modes stay synchronized without preview-only orientation helpers.

  • 3D debug logging now includes projection mapping for left/right jamb, header, and sill previews to make WW/WS mismatch diagnosis faster.

  • Horizontal members (girts/headers/sills) now keep their canonical warmup sign rules, while jamb preview and girt-to-jamb gap ordering use the selected per-rotation vertical calibration data for the current canonical rotation.

  • Preview now corrects secondary-axis direction when transform and projection semantics differ, so WW/WS walls render girts/headers/sills with the same up/down facing as placed members.

  • Opening-role elevation/3D preview now applies this semantics mapping deterministically (no centroid-based correction pass), so 0/180 or Flip changes update orientation without side-translation artifacts from heuristic post-correction.

  • Dragging a bisected girt interior endpoint now keeps endpoint ownership on the dragged side (no opening-edge side remap), so opposite-end movement is avoided.

  • Dragging a bisected girt interior endpoint to the opposite edge of the same opening now auto-joins into a single continuous girt by marking that opening as bypassed.

  • Snapping a girt endpoint directly to an opening edge for that same opening clears the bypass marker so normal opening-edge segmentation behavior is restored.

  • Analyze now supports rotated linked walls with role-aware probing: horizontal members stay on canonical quarter-turn probes, while jamb probing applies azimuth compensation internally; resulting row defaults remain canonical quarter-turn values.

  • Linked opening T mapping now follows detected frame direction swap directly, without an extra mirrored-link parity branch, to prevent mirrored+rotated opening side inversion.

  • Analyze now also handles mirrored-link orientation gating in Step 2 by applying reflection-aware flange seating side rules, preventing mirrored runs from failing all girt types during orientation detection.

  • Square HSS families now run through symmetric orientation seating (all non-endcap section faces), preventing false orientation rejection during Analyze.

  • Rectangular HSS role mapping is now explicit and calibration-backed: deep/shallow face sets are captured during calibration, then horizontal roles seat deep faces to the exterior plane while jamb roles seat deep faces to opening-edge planes.

  • Step 2 now re-fetches square-HSS non-endcap faces inside each Y/Z probe pass (after justification regenerate), preventing stale-candidate reuse that can make all Y/Z pairs evaluate identically.

  • Angle girts now use short-leg/long-leg semantics during orientation analysis (short leg seats assigned elevation, long leg seats exterior plane), and Z-girt validation enforces exterior flange down / interior flange up ordering.

  • Analyze now uses explicit shape/role web seating mode resolution in Step 2: open-section horizontal members use edge-contact web seating, while HSS and jamb paths retain full face-coplanar seating. This restores girt orientation viability without loosening closed-section checks.

  • Step 2 now logs per-pair [SGT.Orientation.YZ.PairProbe] diagnostics in Debug output, and face lookup deduplicates by face id before seating comparisons.

  • Step 2 analyzer diagnostics now explicitly reject non-finite (NaN/Infinity) Y/Z candidates and report candidates, finiteCandidates, and rejectedNonFinite counts when no valid pair is found, improving fatal-step root-cause triage in logs.

  • Opening-role Analyze gating now anchors Head/Sill/Jamb web seating planes to the same structural target origin as exterior seating, preventing layer-offset origin drift from causing false OpeningOrientationAllFailed fatals.

  • Analyze temp probes now surface Revit blocking failures as explicit type warnings/failures (instead of silent probe success), so problematic families/types are clearly identified in preflight outcomes.

  • Post-Analyze refresh now runs as a deterministic two-pass UI dispatch (Loaded then Background) only after successful Analyze hydration; failed/canceled runs skip that extra refresh burst.

If preview still appears wrong after editing row settings, re-run Analyze to refresh wall/opening direction context before placing.

Settings Explained

Offset

The offset controls how far from the wall's target layer the girts are placed:

  • 0'-0" = Girt exterior flange is directly on the target layer face
  • Positive values = Girts are offset outward from the wall
  • Negative values = Girts are offset inward into the wall

Use the same signed input grammar described under Adjusting Girt Elevations; the sign belongs at the start of the complete value (for example, -6 1/2").

Layer (Compound Walls)

For walls with multiple layers (e.g., concrete + insulation + finish), the Layer dropdown lets you choose which layer surface the girts align to:

  • The tool defaults to the most-exterior structural layer
  • Change this if you need girts on a different layer face

Rotation

Rotation controls how the girt cross-section is oriented:

  • 0 = Default orientation (web vertical, flanges horizontal)
  • 90 = Rotated 90 degrees
  • 180 = Flipped from default
  • 270 = Rotated 270 degrees (same as -90)

Most C-channels and I-beams use 0 or 180 rotation for horizontal girts.

Y-Justification

Controls lateral positioning of the member:

  • Left = Member shifted toward wall start
  • Center = Member centered on the placement line
  • Right = Member shifted toward wall end
  • Origin = Uses the family's origin point

Z-Justification

Controls vertical positioning of the member:

  • Top = Top of member at the elevation
  • Middle = Center of member at the elevation
  • Bottom = Bottom of member at the elevation
  • Origin = Uses the family's origin point

Flip Facing

Mirrors the member using Revit Facing flip semantics. Useful when the auto-detected orientation isn't what you need. Flip Facing is enabled only when the selected type supports Revit facing flips (detected during Analyze).

Tips and Tricks

Keyboard Shortcuts

  • Tab - Grid: move to next cell. Preview: cycle overlapping handles near the cursor (Shift+Tab reverses); otherwise Tab behaves normally.
  • Enter - Confirm an edit and move down
  • Delete - Remove selected row
  • Escape - Cancel current edit

Efficient Workflows

  1. Start with defaults, then refine

    • Let SGT auto-seed the girt rows first
    • Then adjust individual rows as needed

  2. Use the preview constantly

    • Switch to 3D view to check member orientations
    • Elevation view shows the overall layout quickly

  3. Work from bottom to top

    • Configure lower girts first
    • They're less likely to change if you add/remove upper girts

  4. Batch similar changes

    • If multiple rows need the same girt type, change them together
    • Multi-select rows in the grid when possible

Performance Tips

  • For large walls with many openings, the analysis step may take a moment
  • The progress overlay shows which step is running
  • Don't close the window during analysis - let it complete

Troubleshooting

"No structural framing families found"

Cause: Your project doesn't have any structural framing families loaded.

Fix: Load at least one structural framing family (like C Shapes or W Shapes) before using SGT.

Girts not appearing at expected location

Possible causes:

  • Wrong wall layer selected
  • Offset value is pushing girts off the visible area
  • Rotation/justification settings are incorrect

Fix:

  1. Check the Layer dropdown - make sure you've selected the correct layer
  2. Verify the Offset is 0'-0" or a small value
  3. Try switching to 3D preview to see where members actually are

Preview shows nothing

Possible causes:

  • No girt rows configured
  • All opening checkboxes are unchecked
  • Analysis failed

Fix:

  1. Make sure at least one girt row exists with a valid type selected
  2. Check that at least one opening role (Header/Sill/Jamb) is enabled
  3. Close and reopen the tool to re-run analysis

"Place" button is disabled

Cause: There's nothing to place - either no girt rows or all rows have invalid settings.

Fix:

  1. Add at least one girt row
  2. Make sure each row has a girt type selected
  3. Ensure elevations are valid numbers

Girts placed but openings not framed

Cause: Opening checkboxes were unchecked, or openings weren't detected.

Fix:

  1. In Edit mode, check the Openings section
  2. Enable the checkboxes for Header, Sill, Left Jamb, Right Jamb as needed
  3. Click Update

Members have wrong orientation

Cause: Auto-detected rotation/justification doesn't match your intent.

Fix:

  1. Try toggling the "Flip" checkbox for that row
  2. Change the Rotation value (try 0, 90, 180, 270)
  3. Adjust Y-Just and Z-Just if the member position is off

Note (2026-03-06):

  • Preview parity on WW/WS walls now comes from the same final resolved contract used by placement.
  • If preview still looks wrong after editing row settings, rerun Analyze or reopen the tool so the current wall/opening runtime state is rebuilt before placing.
  • Manual validation and the exhaustive Revit-hosted parity harness now agree again when Revit is loading the correct loader/dev-driver payload.

Can't edit existing SGT system

Cause: You may have selected non-SGT members, or members from a different system.

Fix:

  1. Make sure you select a member that was placed by SGT
  2. If you have multiple SGT systems on different walls, select from the correct wall

FAQ

Q: Can I use SGT on any wall type?

A: SGT works best on foundation walls and linked architectural walls. It's designed for walls where you need horizontal girts at regular intervals.

Q: What structural framing families are supported?

A: Any standard structural framing family should work, including:

  • C Shapes (channels)
  • MC Shapes (misc channels)
  • HSS (hollow structural sections)
  • Angles (girts only)

Z-shapes and angles are supported for girts only (not for opening framing).

Q: Can I have different girt types at different elevations?

A: Yes! Each row is independent. You can use C10X15.3 at 0'-0", C8X11.5 at 5'-0", etc.

Q: What happens if I change the wall after placing girts?

A: The girts don't automatically update. You'll need to use Edit mode to adjust or remove and re-place.

Q: Edit mode says the stored SGT data is incompatible. What do I do?

A: The stored runtime payload no longer matches the current SGT data shape. Remove and re-place the SGT system so DB Tools can write a fresh compatible runtime payload.

Q: Can I place girts on only part of a wall?

A: Yes, use the Left Extent and Right Extent options to limit girts to a portion of the wall length.

Q: Do girts automatically avoid openings?

A: Yes. When you place girts, they automatically segment around openings with proper gaps.

Q: What's the minimum girt length?

A: Girt pieces must be at least 6" (0.5 ft) long. Shorter pieces (for example a narrow pier between two close openings) are left out of the preview and placement, and a girt with no piece of 6" or longer cannot be placed.

Q: Can I use SGT on curved walls?

A: SGT is designed for straight walls. Curved walls are not currently supported.

Q: How do I delete all SGT members from a wall?

A:

  1. Select any SGT member from that wall
  2. Click "Edit SGT Wall"
  3. Click "Remove"

This deletes the entire girt system for that wall.

Q: Why are some rotation/justification options grayed out?

A: Some combinations don't produce valid placements (member would be off the wall or incorrectly oriented). SGT disables invalid options automatically.

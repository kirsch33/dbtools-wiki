Organize Foundation Types

Organize Foundation Types renames pier, footing and pile cap types by their dimensions, assigns sequential type marks, and merges eligible types of the same size. It changes types and keeps placed instances in position.

Synopsis

Ribbon: dbtools > Structural > the foundation tags split button (with Update Combined Foundation Tags and Move Combined Tags).

The command processes the whole model. It is disabled while the Combined Foundation Tags Disabled warning is active (see Combined Foundation Tags).

Usage

  1. Save the model.
  2. Run Organize Foundation Types.
  3. If a processed type has a Type Mark, choose Overwrite Existing Marks or Preserve Existing Marks. Choose Cancel, or close the question, to stop without changing the model.
  4. Read the Organize Foundation Types result dialog.

When no processed type has a Type Mark, the command runs without asking.

Choice Effect
Overwrite Existing Marks Regenerates the Type Mark of each retained type.
Preserve Existing Marks Keeps every existing Type Mark. Assigns new marks only to types with blank marks and skips every existing mark when choosing a new one. Keeps equal-size types with different marks separate.
Cancel or close Stops the command without changing the model.

Processed types

The tool processes types of these families (exact names, case-sensitive):

Family Category Dimension parameters Mark prefix
Foundation Pier Structural Columns b, h P
Foundation Pier - Round Structural Columns d RP
Footing-Rectangular Structural Foundations Width, Length, Foundation Thickness F
Pile Cap-Rectangular Structural Foundations Width, Length, Foundation Thickness CAP

Types of other families are not processed.

Naming and marks

Each type is renamed as <dimensions> (<mark>). Dimensions are formatted in feet and fractional inches.

Family Name format Example
Foundation Pier <b>x<h> (<mark>) 2'-6"x2'-6" (P-1)
Foundation Pier - Round <d> DIA. (<mark>) 2'-0" DIA. (RP-1)
Footing-Rectangular <width>x<length>x<thickness> (<mark>) 3'-0"x3'-0"x1'-0" (F-3.0)
Pile Cap-Rectangular <width>x<length>x<thickness> (<mark>) 4'-0"x4'-0"x2'-0" (CAP-4.0)

Types are processed in ascending order of size, and marks are assigned in that order:

  • piers: section area b x h, then b and h when areas match;
  • round piers: diameter;
  • footings and pile caps: width, then length, then thickness.

Pier and round pier marks are P-1, P-2, ... and RP-1, RP-2, .... Footing and pile cap marks are <prefix>-<w>.<n>, where <w> is the width in whole feet (rounded down) and <n> counts from 0 within that width: F-3.0, F-3.1, CAP-4.0.

Preserve Existing Marks reserves every existing mark before assigning new ones. Overwrite Existing Marks assigns new marks in size order and reserves old marks when a type is skipped. If a skipped type keeps a mark already assigned in this run, the result dialog names the duplicate.

Merging

The tool compares exact stored dimensions within each family. A merge requires every dimension to have a value. Overwrite Existing Marks groups all types of the same size. Preserve Existing Marks keeps different marks separate. In Preserve, a blank type joins a marked group if the size has one distinct mark. Otherwise, blank types of that size form their own group and receive a new mark.

In Preserve Existing Marks, the marked type with the lowest element ID is the merge target when the group has marked types. In other groups, the type with the lowest element ID is the target. The tool reassigns instances and deletes duplicate types before renaming the target.

Result

The run is one undo entry. The result dialog shows the number of types renamed, duplicates merged and types skipped:

Organized pier and footing types.
• N types renamed
• N duplicates merged
• N types skipped

When types are skipped, the first line reads Organized pier and footing types with skipped types. and the dialog adds up to 5 lines <type id>: <reason>. A type is skipped when Revit rejects its change, for example when the new name already exists. The remaining types are still processed. If a merged type cannot be deleted, the command fails and changes nothing.

If a skipped type retains a mark assigned to another type during the run, the dialog adds Duplicate Type Marks. It shows the count and lists up to five examples with the shared mark and both type IDs.

Press Ctrl+Z to undo the whole run.

Limitations

  • The tool changes the type name, the Type Mark parameter, and the type of merged instances. If the tool must assign a mark and Type Mark is missing, read-only, or uses storage other than text, it skips the whole type.
  • The tool skips a type with a missing or unreadable dimension. The skip details identify the dimension parameter.
  • Linked models are not processed.
  • A stale name on another type in the same family can block a rename. This includes equal-size types with different marks in Preserve Existing Marks. The skipped type keeps its name and mark. Run the tool again once the name is free. If two types hold each other's proposed names, rename one manually to an unused name before rerunning the tool.
  • Different stored dimensions can round to the same text in a type name. The tool keeps these types separate to preserve the exact size of placed foundations. If their marks also match, Revit can reject one of the renames.

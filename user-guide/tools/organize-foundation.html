Organize Foundation Types

Organize Foundation Types renames pier, footing and pile cap types by their dimensions, assigns sequential type marks, and merges types that have identical dimensions. It changes types. It does not move placed instances.

Synopsis

Ribbon: DB Tools > Structural > the foundation tags split button (with Update Combined Foundation Tags and Move Combined Tags).

The command processes the whole model. It is disabled while the Combined Foundation Tags Disabled warning is active (see Combined Foundation Tags).

Usage

  1. Save the model.
  2. Run Organize Foundation Types.
  3. Answer Do you want to overwrite existing type marks?
  4. Read the Organize Foundation Types result dialog.
Answer Effect
Yes Regenerates the type mark of every processed type.
No Keeps existing type marks. Types with an empty type mark receive a new one.

Processed types

The tool processes types of these families (exact names, case-sensitive):

Family Category Dimension parameters Mark prefix
Foundation Pier Structural Columns b, h P
Foundation Pier - Round Structural Columns d RP
Footing-Rectangular Structural Foundations Width, Length, Foundation Thickness F
Pile Cap-Rectangular Structural Foundations Width, Length, Foundation Thickness CAP

Types of other families are not processed.

Naming and marks

Each type is renamed as <dimensions> (<mark>). Dimensions are formatted in feet and fractional inches.

Family Name format Example
Foundation Pier <b>x<h> (<mark>) 2'-6"x2'-6" (P-1)
Foundation Pier - Round <d> DIA. (<mark>) 2'-0" DIA. (RP-1)
Footing-Rectangular <width>x<length>x<thickness> (<mark>) 3'-0"x3'-0"x1'-0" (F-3.0)
Pile Cap-Rectangular <width>x<length>x<thickness> (<mark>) 4'-0"x4'-0"x2'-0" (CAP-4.0)

Types are processed in ascending order of size, and marks are assigned in that order:

  • piers: section area b x h;
  • round piers: diameter;
  • footings and pile caps: width, then length, then thickness.

Pier and round pier marks are P-1, P-2, ... and RP-1, RP-2, .... Footing and pile cap marks are <prefix>-<w>.<n>, where <w> is the width in whole feet (rounded down) and <n> counts from 0 within that width: F-3.0, F-3.1, CAP-4.0.

Merging

Types of one family with equal dimension values are duplicates. The tool keeps the first in the sort order, changes every instance of the other types to the kept type, and deletes the other types. Equality is exact on the stored values, so types that differ by a small amount are not merged. Instances stay where they are.

Result

The run is one undo entry. The result dialog shows the number of types renamed, duplicates merged and types skipped:

Successfully organized pier and footing types.
- N types renamed
- N duplicates merged
- N types skipped

When types are skipped, the first line reads Organized pier and footing types with skipped types. and the dialog adds up to 5 lines <type id>: <reason>. A type is skipped when Revit rejects its change, for example when the new name already exists. The remaining types are still processed. If a merged type cannot be deleted, the command fails and changes nothing.

Press Ctrl+Z to undo the whole run.

Limitations

  • With No, the tool does not compare new marks with preserved marks that come later in the sort order, so two types can end with the same mark. Use Yes for a consistent set.
  • The tool changes only the type name and the Type Mark parameter, and the type of merged instances. The type mark is written only when the Type Mark parameter is a writable text parameter.
  • Linked models are not processed.
  • Types that Revit rejects are skipped, not retried.

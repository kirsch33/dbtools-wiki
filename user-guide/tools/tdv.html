Transfer Drafting Views

Transfer Drafting Views (TDV) copies drafting views between the open project and a library file. A library is a Revit project (.rvt) that holds standard drafting views. TDV imports views from a library into the open project and exports views from the open project into a library.

Synopsis

Ribbon: DB Tools > Common.

Command Effect
Import From Library Copies drafting views from a library into the active project.
Export To Library Copies drafting views from the active project into a library.

Both commands are disabled while the Library Paths Invalid warning is active (see Library settings).

Library settings

TDV reads its libraries from DB Tools > Settings > Library Files.

Control Effect
Add Library File Adds a .rvt file as a library entry.
Add Fallback Path Adds an alternate path to the selected entry. TDV uses the fallback only when the main path is not valid.
Remove Selected Removes the selected entry or fallback path.
Validate Libraries Checks every path.
Alias Name shown in the library picker. When empty, the picker shows the file name up to the first _R.

Each entry in the list shows a check mark (valid path) or a cross (invalid path), its alias or file name, and its full path. A fallback path appears under its entry as Fallback: <file name>.

A path is valid when the file exists, has the .rvt extension, and was saved in the same Revit version as the running session. A file from another Revit version is rejected with Revit version mismatch (file: <year>, current: <year>). TDV refuses to open a library from another version, so it never upgrades a library file. A file whose saved Revit version cannot be read is invalid on its own: TDV reports Could not read the library file's Revit version metadata. Re-save the library in Revit to fix it.

If a saved path is invalid, the warning Library Paths Invalid disables both commands. Correct the paths and save the settings to enable them again.

Several libraries can be configured. When you run a command, you choose one library from the picker. The picker lists only valid paths. If some paths are invalid, TDV shows a banner with their number. If no library is configured, the command fails with No library files configured. Configure library paths in Settings. If every path is invalid, it fails with All configured library files are inaccessible (<n> path(s) failed validation). Check library paths in Settings.

Usage

  1. Run Import From Library or Export To Library.
  2. Select a library in the picker. TDV opens it in the background; the project you started from stays active.
  3. In the Transfer Drafting Views window, check the views to transfer.
  4. Resolve name conflicts (see Conflicts).
  5. Click Transfer Selected.
  6. Read the result dialog.

For an import, the source is the library and the destination is the project. For an export, the source is the project and the destination is the library.

The status bar shows <views> | Selected: <n> | Replace: <n> | Adds: <n>, and during a transfer the count of finished views.

A status icon in front of each name shows the row state: pending, success, failure, or conflict. Success icons appear when the whole transfer is committed, not when a single view finishes.

Conflicts

A checked row has a conflict, and a warning bar asks you to resolve it before continuing, when:

  • the destination name is empty;
  • the destination already has a drafting view with that name and Replace is off; or
  • two checked rows have the same destination name.

Rename the row, or turn on Replace, to resolve it.

View types

With Retain Original, TDV looks for a destination drafting view type with the source type's name. When it is missing, TDV creates it by duplicating an existing drafting view type of the destination. A row shows a warning mark when the source type name cannot be read; select a type explicitly in that case.

With a named type, the type must exist in the destination. TDV does not create it.

What is transferred

For each checked view the transfer:

  1. finds or creates the destination view: a new drafting view, or, with Replace and an existing view of that name, the existing view with its type changed and its content deleted;
  2. copies the view scale and the View Description parameter;
  3. copies the view's elements with Revit's copy mechanism, one element at a time. Groups are copied as groups. Duplicate type names resolve to the types of the destination;
  4. copies the per-element graphic overrides.

Not copied: viewports, title blocks, schedules, guide grids, other views, and view templates. The transfer copies the view's type but not a view template assignment.

If a family used in the view is missing in the destination, Revit copies the family with the element. A detail array arrives as its groups, without the editable array association.

The transfer is processed row by row and is one undo entry named Transfer Drafting Views. A failed view is rolled back alone: nothing from that view is added, and a view you chose to replace keeps its old content. The other views still transfer. If Revit discards the whole transfer, TDV reports All attempted changes were rolled back, and no view is added.

You can cancel a running transfer from the progress overlay. The views processed so far are rolled back.

Result

The dialog title is Transfer Completed or, if any view failed, was not attempted or the run was canceled or rolled back, Transfer Completed with Issues. Its text is:

Selected <n>, Processed <n>, Added <n>, Replaced <n>, Failed <n>, Not Attempted <n>

followed by (All attempted changes were rolled back) or (Cancelled by user) when that applies. A Per-View Issues table lists each failed view with the error code and reason. Copy Details copies the table to the clipboard.

Error code Cause
DestinationNameRequired The destination name is empty.
DuplicateTargetName Two checked rows have the same destination name.
DestinationNameConflict The destination view exists and Replace is off.
SourceTypeNameUnavailable, DestinationTypeMissing The destination drafting view type cannot be found or created.
CreateViewFailed, ClearDestinationViewFailed The destination view cannot be created, renamed or cleared.
MetadataCopyFailed The scale or description cannot be set.
CopyElementsFailed Revit cannot copy an element.
OverridesFailed A graphic override cannot be copied.
TransactionRolledBack Revit discarded the whole transfer.

Click Accept and Transfer More to keep the window open, or Close Tool to close it.

Import

TDV closes the library without saving after the dialog closes. If it cannot close the library, a banner asks you to close it manually. Press Ctrl+Z to undo an import; the transfer is one undo entry unless Revit discarded it.

Export

After the window closes with at least one view added or replaced:

  • a workshared library is synchronized with central, relinquishing all borrowed elements, with the comment DB TOOLS - ADDED [<n>] DETAILS AND REPLACED [<n>] DETAILS.;
  • a library that is not workshared is saved in place.

If the library cannot be saved, synchronized or closed, the export fails and the error report names each failure. TDV then reactivates the project you started from. An export cannot be undone with Ctrl+Z once it is saved or synchronized. If nothing was added or replaced, the library is closed without saving.

Library files and worksharing

For a workshared library, TDV creates a temporary local copy named <library>_<user>.rvt under %APPDATA%\DBTools\Cache\TDV\LibraryLocals\<id>\, opens it with all worksets, and deletes the copy after it closes. A library that is not workshared is opened directly.

If two users export to the same library at the same time, one synchronization can fail. Coordinate export times.

To create a library, create a Revit project in the same Revit version, add the drafting view types you need, save it where your team can reach it, and add it in the settings.

Limitations

  • The library has to be saved in the Revit version that is running.
  • Only drafting views are listed.
  • A view with an element that Revit cannot copy fails as a whole.
  • The names of the views and types in the destination decide conflicts; there is no rename-on-conflict option.
  • The project and the library must be different documents.

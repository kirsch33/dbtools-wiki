Foundation Tags

Foundation Tags prepares and positions the combined pier and footing tags (family DB Pier and Foundation Combined Tag). It has two commands:

  • Update Combined Foundation Tags computes the data that the combined tag displays and writes it to shared parameters on piers and footings.
  • Move Combined Tags moves combined tags to a corner of the footing they tag.

The tool does not place tags. Place the tags with Revit's tag commands.

Synopsis

Ribbon: DB Tools > Structural > the foundation tags split button. The split button also contains Organize Foundation Types.

Command Effect
Update Combined Foundation Tags Writes Foundation Pier Top on piers, and Associated Pier and Associated Pier Elevation on footings, in the active view.
Move Combined Tags Moves each matching tag in the active view to the corner of its footing that the tag's name specifies.

Both commands are enabled when a view is active and process the active view only. Both are disabled while the shared-parameter prerequisites are not met (see Prerequisites).

Prerequisites

The update command needs three project parameters, bound as instance parameters and identified by GUID:

Parameter Type Category Group
Associated Pier Text Structural Foundations Identity Data
Associated Pier Elevation Length Structural Foundations Identity Data
Foundation Pier Top Length Structural Columns Constraints

DB Tools checks the parameters when the active model changes and before each command. If a parameter is missing, has another GUID, has the wrong data type, is bound as a type parameter, or is bound to the wrong category, DB Tools raises the warning Combined Foundation Tags Disabled. The warning disables Update Combined Foundation Tags, Move Combined Tags and Organize Foundation Types.

To repair the parameters:

  1. Open DB Tools > Settings and select the Combined Foundation Tags pack.
  2. Click Refresh to list the status of each required parameter.
  3. Click Install/Repair (or Fix on the warning card).

Install/Repair needs an active Revit document. It loads the definitions from the embedded shared parameter file, binds them to the required categories as instance parameters, and clears the warning. It also resolves conflicts: it deletes parameters that have the same name with another GUID, or duplicate definitions with the same name, and reinstalls the DB Tools definitions. It keeps any other categories bound to these parameters and their values. If one of those bindings is a type parameter, Install/Repair changes it to an instance parameter and Revit drops its type values.

Status values include MISSING, GUID_MISMATCH, DUPLICATE_NAME, WRONG_DATA_TYPE, UNBOUND, WRONG_BINDING_TYPE and WRONG_CATEGORY.

Update Combined Foundation Tags

Usage

  1. Open a plan view that shows the piers and footings.
  2. Run Update Combined Foundation Tags.
  3. Read the banner.

With Auto-Update Enabled on (the default), the update also runs each time you activate a floor plan or ceiling plan. Automatic runs show no result banner.

What it does

The command considers the family instances visible in the active view. A family instance is a pier when its family name matches a pier pattern. It is a footing when its family name matches a footing pattern (see Settings).

  1. For each pier, it computes Foundation Pier Top = the Top Offset parameter (0 if absent) plus the elevation of the level in the Top Level parameter, and writes it to the pier.
  2. For each footing, it finds the pier nearest in plan (X and Y of the location points) and within 2 ft. It writes the pier's Type Mark to Associated Pier and the pier's Foundation Pier Top to Associated Pier Elevation.
  3. A footing with no pier within 2 ft gets an empty Associated Pier.

A value is written only when it differs. Lengths are compared after rounding to two decimals.

Revit cannot clear a length value. A footing with no pier in range keeps its previous Associated Pier Elevation and counts as skipped on every run until a pier is within 2 ft.

Result

The update is one undo entry. A transaction group wraps the parameter writes and the selection sets. If a Revit write fails unexpectedly, the whole update is rolled back and the error is shown. A failure while creating the selection sets keeps the parameter writes and is reported.

The banner reads Updated N element(s); M failed/skipped. or No elements modified. An element is counted as skipped when a pier lacks a valid Top Level, a footing or pier has no location point, a parameter is missing or read-only, or a length cannot be cleared.

Outcome Banner
At least one element modified Stays open. Has Select Modified, and Select Skipped when some elements were skipped.
Nothing modified, some skipped Warning that closes after 10 seconds. No buttons.
Nothing modified or skipped Info that closes after 6 seconds.

The buttons select the elements of the run that just finished. They work only while the model that ran the update is active.

Each run also creates selection sets named DB Tools - FoundationTags - Modified Elements (<timestamp>) and DB Tools - FoundationTags - Skipped Elements (<timestamp>) when the respective list is not empty. The timestamp is in Eastern time. A second run in the same second adds a suffix such as (2). The model keeps the 5 most recently created sets with the prefix DB Tools - FoundationTags - .

If an automatic update fails, DB Tools shows the error and stops automatic updates for that model until you close and reopen it. After Save As, or the first save of a new model, it tries once more. The commands remain available.

Move Combined Tags

Usage

  1. Open a plan view with combined tags.
  2. Run Move Combined Tags.

What it does

The command examines the independent tags in the active view. It moves a tag when:

  • the tag tags a Structural Foundations element (in the model or in a linked model);
  • the tag's family or type name matches a tag family pattern; and
  • the tag's name is a corner name.

The corner name is the name of the tag, or the name of its type when the tag has no name: Top Right, Top Left, Bottom Right or Bottom Left (case-insensitive).

The command computes the footing's bounding rectangle from its geometry in the footing's own X and Y axes. It selects the corner by the view's orientation, so Top Right is the corner at the top right of the view even in a rotated view. It sets the tag head position to that corner. The Z value of the tag head is unchanged. Linked footings are transformed into the host model's coordinates. The tag's leader is not changed.

Result

The banner reads Moved N; skipped M of K candidate tags. A candidate is skipped when the corner name is not valid, the tagged element is not a family instance with a location point, or it has no geometry. When no candidate exists, the banner says why:

Message Cause
No tags were found in the active view. No independent tags in the view.
No tags in the active view are currently tagging structural foundation elements. The view's tags tag other categories.
No tags matched the configured Tag Family Patterns. Check Combined Foundation Tags settings. Sample rejected tag families/types: <list> Tags tag foundations, but no tag family pattern matches.

The move is one transaction. If an unexpected Revit geometry or write error occurs, the whole move is cancelled and no tag stays moved.

Settings

Open DB Tools > Settings and select the Combined Foundation Tags pack.

Setting Default Used by
Auto-Update Enabled On Update (runs on floor plan and ceiling plan activation)
Tag Family Patterns ^DB Pier and Foundation Combined Tag(?: No Elevations)?$ Move
Pier Family Patterns ^Foundation Pier(?: - Round)?$ Update
Footing Family Patterns ^(?:Footing\|Pile Cap)-Rectangular$ Update

Each pattern list holds up to 3 regular expressions. Matching is case-insensitive. An empty list uses the default. An invalid expression is skipped and logged. When no valid pier or footing pattern exists, the update does nothing. When no valid tag pattern exists, the move does nothing.

Limitations

  • Both commands work on the active view only.
  • Only family instances that are visible in the active view are updated.
  • The nearest-pier search is 2D and has a fixed 2 ft radius.
  • Piers and footings are recognized by family name only. Families with other names need a matching pattern.
  • The corner a tag moves to is taken from its name. A tag with another name is skipped.

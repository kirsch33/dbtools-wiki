Remarks

When the document is already modifiable, BeginAsync(string, CancellationToken) creates no owned group, but IsActive still becomes true, IsGroupHealthyAsync(CancellationToken) returns true, and FinalizeAsync(TransactionGroupFinalization, CancellationToken) only resets state. Otherwise Commit assimilates the group into one undo entry and Rollback discards it. Revit rolls back a group still open when the API callback that started it returns, so Begin and Finalize in separate calls keep one group only under an inline gate inside one callback (a modal command). Queued modeless work uses RunAsync<T>(string, Func<CancellationToken, Task<T>>, Func<T, bool>, CancellationToken). The service is not thread-safe.

RunAsync<T>(string, Func<CancellationToken, Task<T>>, Func<T, bool>, CancellationToken)

Begins the group on the active document, runs work, then assimilates the group when keep accepts the result and rolls it back otherwise. An exception, or cancellation seen at any point before finalization, rolls the group back and propagates. The work must complete within the callback: its call-gate calls run inline. A document with an open transaction is refused before any work. Unless Revit confirms the rollback, the call throws TransactionGroupOutcomeUnknownException.

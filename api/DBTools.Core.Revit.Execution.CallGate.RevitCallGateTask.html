Remarks

Each native Execute runs the work that was queued when it started, in order, until the DBTools.Core.Revit.Execution.CallGate.RevitCallGateTask.DrainBudget is used. Work queued during the turn, or left by the budget, waits for the next raise, which is posted to the dispatcher and so runs after Execute returns. Revit discards what a callback leaves open only when the callback returns. A call ends the turn when it leaves a transaction open in any document, or when it creates a transaction group, which every production group owner reports through DBTools.Core.Revit.Execution.CallGate.RevitCallGateTurnBoundary. No later call of the turn then runs inside state that an earlier call left open. Every raise is posted, also from the dispatcher thread, so a caller never waits on native Raise. Turn timing is logged at Debug level, throttled by DBTools.Core.Revit.Execution.CallGate.RevitCallGateTurnStatistics.

Retirement drops queued delegates and registrations without completing their tasks. Such tasks never finish: a worker synchronously waiting on one would remain blocked. Callers must use asynchronous lifetimes and must not wait for retired work during shutdown. Failed-startup cleanup uses CancelPending instead, so callers in the live process observe cancellation.

Remarks

This host primitive applies none of the synchronous-delegate admission rules from IRevitCallGate. Queued work that has not started when the owning call-gate task retires is dropped, and its task never completes, even if its cancellation token is cancelled later. Callers must not await or block on such a task during shutdown. Failed-startup cleanup cancels pending work instead.

Remarks

Both operations change the project only when they can carry over every value. Before any change they plan one write per value: an instance-bound parameter keeps each element value; a type-bound parameter copies each type value to every instance of that type. A type value without an instance cannot be carried, so the call refuses. Migrate(Document, ParameterElement, ExternalDefinition, IReadOnlyCollection<Category>, SharedParameterUseHandling) also requires the source and target specs to match (ForgeTypeId.NameEquals).

One transaction group then changes the binding, writes the values and reads each one back. Revit refuses a changed value on a member of a group placed more than once when the parameter does not vary between group instances, so such writes run with the variance on, the original variance comes back after them, and every value is read back again; a parameter that Revit does not let vary is refused. If any write or read-back fails, or any step throws, the group rolls back and the project keeps the original parameter, binding and values. A refusal or a rollback after failed writes throws SharedParameterMigrationException with every value that could not be carried; each is also logged.

Migrate(Document, ParameterElement, ExternalDefinition, IReadOnlyCollection<Category>, SharedParameterUseHandling) deletes the source parameter. A loaded family that defines the source GUID keeps it in its own definition, and its labels and formulas then refer to a parameter the project no longer has; run SharedParameterFamilyMigration first. The target may already exist without a binding, because loaded families define it; the migration then binds it. Each source-bound element keeps the value that is not empty. The migration also records target-only values on elements in categories added to the binding, and restores them if binding changes them. Two different values refuse before any change.

Bind(Document, SharedParameterElement, IReadOnlyCollection<Category>, ForgeTypeId) handles a shared parameter that already exists in the project but has no binding. It records values that loaded families expose in the categories to bind, binds the parameter as an instance parameter, restores values that binding changes, and reads them back. A placed family type parameter refuses when the repair needs an instance binding. An unplaced family type parameter stays on its type. CheckBind(Document, SharedParameterElement, IReadOnlyCollection<Category>, ForgeTypeId) runs the same plan without a lasting change.

Every operation reads bindings through SharedParameterBindingLookup, so a dead key in Revit's binding map refuses it with SafeExecutionRefusedException before any change.

A check that changes the project in a transaction that always rolls back (the group variance check, and the family ownership check of SharedParameterFamilyMigration) requires Revit to report the rollback. When Revit does not, or the rollback throws, the check throws SharedParameterRollbackException, a failure that is not a refusal.

Remarks

Each rule names its parameter and reads in plain words, such as equals 'P-1', is greater than 2.5 or has no value. Numbers are in Revit's internal units. Category rules name their categories. A filter use that the API does not show as a rule gets an additional a rule entry. Nothing recreates the rules; the user adds every listed rule to each filter again.

Rebind(Document, SharedParameterElement, IReadOnlyCollection<Category>)

Binds the shared parameter parameter as an instance parameter of its categories and requiredCategories. It keeps the GUID, the parameter group, the variance between group instances and every value: an instance-bound parameter keeps each element value; a type-bound parameter copies each type value to every instance of that type.

public SharedParameterRebindReport Rebind(Document document, SharedParameterElement parameter, IReadOnlyCollection<Category> requiredCategories)

Parameters

document Document
parameter SharedParameterElement
requiredCategories IReadOnlyCollection<Category>

Returns

SharedParameterRebindReport

Remarks

Revit's ReInsert resets the variance between group instances and aligns grouped values, so the rebind records every value first, restores the variance, writes the values back and verifies them, with the same group handling as Migrate(Document, ParameterElement, ExternalDefinition, IReadOnlyCollection<Category>, SharedParameterUseHandling).

Exceptions

ArgumentException

The parameter is unbound, or not in this project.

SharedParameterMigrationException

A project type value has no instance, a rebar container overrides the parameter, a placed family exposes the parameter only as a type parameter, or a value cannot be kept. The project is unchanged.

InvalidOperationException

Revit refused a step. The project is unchanged.

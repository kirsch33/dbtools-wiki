API reference

This section is generated from the XML documentation comments in the source code. It lists the public types and members of the DBTools assemblies.

Generating the reference

Run the documentation build from the repository root:

bash .github/scripts/build-docs.sh full-api

Use the SDK pinned by global.json. The script restores DocFX 2.78.5 from wiki/.config/dotnet-tools.json. It builds the Release product and Sandbox for Revit 2026 to supply build tasks, dependency assemblies and generated WPF source. The build runs on Linux with Windows targeting enabled. It does not start Revit.

The script restores each non-test project in src/ with the metadata properties from wiki/docfx.json. DocFX's automatic restore is disabled because version 2.78.5 does not pass these properties to dotnet restore:

Property Value Purpose
Configuration Release Match the prerequisite builds and DocFX's default configuration.
RevitYear 2026 Select the Revit API packages and year-specific restore assets.
EnableWindowsTargeting true Resolve Windows and WPF reference packs on Linux. Set for every project by Directory.Build.props.
DesignTimeBuild false Include Revit source excluded by XAML designer builds.
DBT_IsDesignerBuild false Use normal project paths and source inclusion.
_DBT_MergeDesigner true Retain public package references for DocFX's unmerged project symbols.

_DBT_MergeDesigner controls package visibility separately from source inclusion. The product build merges public dependencies into their owning assemblies. DocFX reads project source, so its compilation needs those dependencies as package references. Keep the restore properties in the script aligned with the metadata properties in wiki/docfx.json.

DocFX reads the projects in src/, excludes test projects, writes metadata to wiki/api/, and builds the site into wiki/_site/. Compilation errors fail the build. The conceptual script mode uses docfx-conceptual.json and builds the articles without API metadata or product builds.

The reference covers the namespaces of DBTools.Core, DBTools.App, DBTools.Presentation and the tool assemblies (DBTools.GM, DBTools.SGT and others). Members without an XML comment appear without a description.

Writing documentation comments

Document each public type and member with /// comments. Give a <summary> for every member, a <param> for every parameter, <returns> for non-void methods and <exception> for exceptions that callers handle:

/// <summary>
/// Runs an action inside a Revit transaction.
/// </summary>
/// <param name="action">The action to run in the transaction.</param>
/// <returns><see langword="true"/> if the transaction committed; otherwise <see langword="false"/>.</returns>
/// <exception cref="InvalidOperationException">No document is active.</exception>
public bool Execute(Action action)

Use <remarks> only for constraints that a caller must know.

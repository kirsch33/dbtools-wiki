Interface ITransactionRunner

Namespace
dbtools.Core.Revit.Transactions

Runs synchronous work in a Revit transaction, or in a subtransaction when the target document already has an open transaction.

public interface ITransactionRunner

Remarks

A rejected delegate shape throws InvalidOperationException from the call itself. Every other failure arrives through the returned task. The work runs synchronously inside one Revit API callback of the call gate.

The token is checked before the transaction starts and before and after the work runs. Cancellation alone rolls back an open transaction and cancels the task without faulting it. An erased Task or boxed ValueTask result, for example a task returned as object, is rejected after the work runs, and the transaction rolls back.

A start status other than Autodesk.Revit.DB.TransactionStatus.Started, or a commit status other than Autodesk.Revit.DB.TransactionStatus.Committed, raises TransactionFailureException. TransactionName and Status identify the transaction. For a transaction commit, Warnings lists the suppressed warnings, and BlockingFailures, BlockingFailureDefinitionIds and BlockingFailureDefinitionGuids describe the errors that blocked it. The GUIDs follow the IDs in order; Core does not classify them.

An InvalidOperationException refuses a missing active document, a target document that differs from a modifiable active document, and a call that the gate cannot run in its context.

A work or Revit exception propagates unchanged after cleanup. When the rollback or the disposal also fails, an AggregateException holds the first failure followed by the cleanup failures. A disposal failure after a commit does not fail the call: Core logs it at Error and returns the committed result.

Remarks

A loaded family keeps its own definition of a shared parameter. Its formulas, dimension labels and annotation labels refer to the parameter by GUID, so a project that replaces its own parameter leaves them on the old GUID. Deleting that parameter from the project also removes it from the labels of loaded families. Callers therefore run this migration before Migrate(Document, ParameterElement, ExternalDefinition, IReadOnlyCollection<Category>, SharedParameterUseHandling) or any delete of the old parameter.

Plan(Document, IReadOnlyList<SharedParameterFamilyTarget>) changes nothing. It opens each editable loadable family that may use a target and closes it unsaved. It also opens editable nested families recursively. A non-editable nested family is checked through its symbols and instances. Every SharedParameterFamilyTarget defaults to refusing a direct shared-parameter element that no family parameter carries. GM repair opts in to direct label moves. In Revit 2027, that path requires readable labels, the internal writer members, the target's spec, a non-measurable spec, no family record of the target GUID with another spec, no detail group type without placements, and no nested or uninspected family use. A label in a plain detail group moves after the change ungroups the group; an attached, nested or pinned group, a group with a member whose location cannot be read, or one with an assigned value that ungrouping would delete, refuses. It trials all changes for one family together, in apply order, in a transaction that commits with the failure handling of Migrate(Document, SharedParameterFamilyPlan) inside a transaction group that always rolls back. A family parameter still uses FamilyManager.ReplaceParameter(FamilyParameter, string, ForgeTypeId, bool) and Revit moves its label entries. This path does not require dbtools.Core.Revit.SharedParameters.SharedParameterLabels.CanWrite. A failed family-parameter trial is a family refusal. A failed direct-label trial remains a hand-fix label row. Revit 2026 refuses direct shared-parameter elements because it cannot read annotation labels. Other refusals: a nested shared family, another data type, a type parameter in a category that the target binds as an instance parameter, an element whose old and new values differ, and an in-place or non-editable top-level family that defines the parameter or may define it. Revit does not open such a family; when its elements show the parameter and a project binding could explain that, the plan rebinds the project parameter without the family's category in a transaction that always rolls back and reads the elements again.

Migrate(Document, SharedParameterFamilyPlan) runs in one transaction group. A family that was reloaded or deleted after the plan refuses. Before writing, it opens each family and compares the planned label state, including label IDs, group membership and group type. A changed label refuses before the family write. For each family it records the old values of its types or elements, opens the family, replaces the parameter through a temporary family parameter (FamilyManager.ReplaceParameter(FamilyParameter, string, ForgeTypeId, bool), then the target definition) with the same group and instance or type kind, and checks in the family that every formula, value, dimension label, associated element parameter and label entry follows. For direct label changes it updates only the selected entries through the internal parameter-ID setter, validates them and checks their public formatting and the internal leading-parameter flag. It refuses measurable specs because Revit does not expose the label's unit format for comparison. It also checks for a remaining family parameter, nested-family symbol or instance, or readable label that uses the old GUID. Project view-filter rules are handled by FindFilterRules(Document, ParameterElement) when the project parameter is deleted. The family transaction and the reload delete no Revit warning outside a fixed list; any other warning or error rolls back and refuses with its description. Migrate compares every label with its expected state again after the commit, with every element of the family after an ungroup, and, by owner view, detail group name and position, in the reloaded family, where it also counts every element of the former group members' kinds at each place. An unused Autodesk.Revit.DB.SharedParameterElement may remain after replacement. In Revit 2026 it refuses an annotation family when that element remains because the family may use the GUID in a label that dbtools cannot read. It reloads the family over the loaded one, writes each recorded value that the reload did not keep and reads every value back. Any refusal or failure rolls the group back; the project keeps its families and values.

Family files on disk do not change. A family loaded again from such a file brings the old GUID back.

Remarks

Only a family parameter shows on types or elements, and only when the family has a placed element for an instance parameter; a label that uses the parameter directly does not. Plan(Document, IReadOnlyList<SharedParameterFamilyTarget>) opens each family and finds every use.

Remarks

The project must not be modifiable: Revit opens and reloads families only between transactions. Every target definition of the plan must come from the shared parameter file that is still open.

Exceptions

SharedParameterMigrationException

The plan has a refusal, or a value or reference cannot be kept. The project is unchanged.

InvalidOperationException

Revit refused a step. The project is unchanged.
